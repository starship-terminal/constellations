# refero/

A snapshot of every style published at <https://styles.refero.design>
(1,342 styles, fetched 2026-10-20). This is **third-party interpreted data**,
not measured evidence: Refero normalizes source measurements and interprets
roles and recommendations, and their component HTML is a reconstruction. Treat
every value here as lower-confidence than the packages under `systems/`.

## Layout

- `refero.db` — canonical store. `styles` table holds one row per style:
  `uuid` (the primary key), slug, name, tagline, `page_url` (the refero.design page), `source_url`
  (the product site), theme, `extracted_at`, `fetched_at`, every artifact
  (`design_md`, `variables_css`, `theme_css`, `tokens_json`,
  `design_system_json`, `prompt_txt`), the full `result_json` the artifacts
  were generated from (component `html` resolved from its `$<hexid>` flight
  refs at fetch time), `screenshot_url`, the media columns
  (`video_url`, `video_poster_url`, `video_detail_url`,
  `video_detail_poster_url`, `media_fetched_at`), the component columns
  (`components_json`, `components_at`; NULL unless upstream shipped
  component markup), and the label columns
  `product_type`, `design_style`, `tags` (a JSON array of secondary labels;
  `tags` is TEXT in the db, an array in `meta.json`). `fetch_errors` records
  pages that failed. (`raw-result.json` is not stored: it is derivable from
  `result_json` with `generateRawResultJson` in
  [../tools/refero/generators.js](../tools/refero/generators.js).)
  `meta.json` repeats the media fields plus `has_components`, and the three
  label keys sit after `theme`. Older files may still carry `video_w`,
  `video_h` and `video_ms`: keys the db dropped, kept on disk because
  `write_meta` preserves existing keys. Two derived stores also live in the
  db: `similar` (Refero's "similar businesses" per style, `matched_slug`
  resolved to our slug where it can be), `collections` +
  `collection_styles` (Refero's curated collection pages and their ordered
  style memberships, `section` carrying the editorial heading), and
  `screens` (one row per preview screenshot of the refero.design paid
  catalog — shot URL, thumbnail, extracted palette, the exact captured
  `page_url` for web entries, `page_id` for iOS screens, and NULL
  `patterns_json`/`elements_json` pending a tag pass).
- `.dump/` — `refero.db` as committed, line-oriented text: the db's merge
  surface (see [Merging](#merging)). `schema.sql` holds the PRAGMAs and every
  `CREATE` statement verbatim; `styles/<uuid>.json` holds one styles row per
  file, one column per line; every other table is `<table>.jsonl`, one row
  per line. Rows are sorted by primary key (or a natural key, then every
  column, for the keyless tables), so the same db always writes the same
  bytes. Written by [../tools/refero/dump.py](../tools/refero/dump.py); every
  script that writes the db refreshes it when it finishes, and `check.py`
  fails when it and the db disagree. It is plain text, not LFS (about 110 MB
  on disk, about 21 MB gzipped, no file over 250 KB), and a dot folder so
  nothing mistakes it for a style folder.
- `<slug>/` — per-style files: `DESIGN.md`, `variables.css`, `theme.css`
  (Tailwind v4 `@theme`), `tokens.json` (DTCG-style), `design-system.json`,
  `meta.json`. `prompt.txt` lives only in the db. `components.json` — the
  style's `designSystem.components` verbatim with reconstructed markup —
  exists only for the ~55 styles upstream has enriched so far.
- `catalog.json` — flat index of every style with its URLs, labels,
  `has_components`, `similar` (matched slugs) and `collections`
  (collection slugs the style appears in).
- `similar.json` — the same graph in flat-file form for consumers without
  sqlite: per style, Refero's `business`/`why` pairs plus the matched slug
  or null when the cited business is not in the snapshot.
- `collections.json` — the collections index: slug, url, title, description
  and ordered sections (`heading` + style uuid/slug pairs).
- `directory.json` — the refero.design *paid* catalog directory (iOS apps +
  web sites) with each entry's five preview screenshots embedded (`uuid`,
  `url`, `thumb`, `page_url` where it exists, `page_id`, `palette`). Index
  data only; the screenshot library and flows are not mirrored.
- `coverage.json` — which catalog sites a `systems/` package covers, matched
  on root domain (`name_match` flags same-domain different-product hits) and
  which package domains the web catalog lacks (`ios_guess` checks their iOS
  catalog by name). Derived, not a store.

## Provenance

Artifacts are generated by Refero's own export code, extracted from their
public client bundle into [../tools/refero/generators.js](../tools/refero/generators.js),
so the files match what the site's export tabs produce. `DESIGN.md` is taken
verbatim from each page.

## Refreshing

```bash
python3 tools/refero/fetch.py            # fetch new/changed styles, re-export
python3 tools/refero/fetch.py --force    # re-fetch everything
python3 tools/refero/fetch.py --enrich-media   # backfill video/poster URLs into db + meta.json
python3 tools/refero/backfill_components.py  # re-fetch styles missing component html; writes components.json + has_components
python3 tools/refero/classify.py         # label unlabeled styles into product_type/design_style/tags
python3 tools/refero/classify.py --stats # print the label distribution
python3 tools/refero/index_similar.py    # rebuild the similar table + similar.json from stored results
python3 tools/refero/fetch_collections.py # scrape the collections sitemap → collections.json + collections tables
python3 tools/refero/fetch_screens.py    # fetch the paid-catalog directory → directory.json + screens table
python3 tools/refero/coverage.py         # diff the catalog against systems/ → coverage.json
make refero-dump                         # rewrite .dump/ from refero.db (every writer above already does)
make refero-db                           # rebuild refero.db from .dump/, then rewrite .dump/ canonically
python3 tools/refero/check.py            # assert refero.db, the style folders, catalog.json and the derived stores agree (make check runs it)
```

Labels come from [../tools/refero/classify.py](../tools/refero/classify.py):
an Anthropic API pass over each style's name, domain, upstream `industry` and
tagline, validated against the two vocabularies defined there (24 product
types, 16 design styles). `product_type` is what the organisation is;
`design_style` is the page's dominant aesthetic; `tags` holds up to four
secondary labels from either vocabulary and feeds gallery search, not the
filter dropdowns. Run `classify.py` after a fetch so new styles get labeled
(it only touches rows missing a label unless `--force`).

Requires node. Fetched result objects are cached in `.work/` (gitignored) and
persisted in `refero.db`, so `--export-only` can re-materialize files offline.

## Merging

`refero.db` is a binary LFS object, so git cannot merge two branches that
both changed it: it reports a conflict on the pointer, and taking either side
silently drops the other side's rows. `.dump/` holds the same rows as text,
committed in the same commit as the db, and that is what you merge.

1. Commit the db and its dump together. Every writer refreshes `.dump/` when
   it finishes; after anything else that touches the db, run
   `make refero-dump`. `make check` fails while the two disagree.
2. On a merge or rebase that conflicts on `refero/refero.db`, take either
   side of the db (`git checkout --theirs refero/refero.db`, or `--ours`);
   it is about to be rebuilt.
3. Merge `refero/.dump/` as text. Git merges most of it on its own, because
   each style is its own file and every other row its own line; resolve any
   conflict left by hand, keeping each line a whole JSON object.
4. Run `make refero-db`. It rebuilds `refero.db` from the merged dump (the
   previous file is kept at `refero/.work/refero.db.bak`), checks the row
   counts, and rewrites `.dump/` in its canonical order. It refuses a dump
   that still holds conflict markers or has lost a table's file (an empty
   table is an empty `.jsonl`; `styles/_table` marks the styles folder).
   It copies the new pages into the live db through sqlite, so it waits for
   a writer's open transaction, and it shares `refero/.work/dump.lock` with
   the writers' dump refresh; still, stop running writers first, because
   rows they commit later are not in the dump you merged.
5. Regenerate the files derived from the db that conflicted too:
   `python3 tools/refero/fetch.py --catalog-only` for `catalog.json`,
   `index_similar.py` for `similar.json`. Run `make check`, then commit the
   db, the dump and those files together.

`make refero-db` also builds a working db on a clone without `git lfs pull`.
Building the same dump twice gives byte-identical files with the same
sqlite library (over a live db only the header counters differ); the rebuilt db can still differ in bytes from the committed one
(page layout follows the file's history, and the header names the sqlite
version that wrote it) while every query returns the same rows. No git merge
driver is configured: git-lfs owns `*.db`'s attributes, and a driver would
need per-clone config, so the steps above are the procedure.

## Media mirror

The app's `/refero` pages serve media from a host-side mirror, not the
repo: `tools/refero/mirror_media.py` downloads screenshots, video posters,
scroll-preview and detail videos with their posters, and favicons into
`~/services/design-systems/media/refero/` (`DESIGN_SYSTEMS_MEDIA` moves it).
The web app serves that folder at `/media/refero-media/` when the media base
is empty; by default `DESIGN_SYSTEMS_MEDIA_BASE` points those paths at the
public R2 bucket instead (`tools/refero/upload_r2.py` fills it). Media is
deliberately outside git — the videos are ~1–2 GB. Anything in neither place
falls back to the images.refero.design URL in the browser.

```bash
python3 tools/refero/mirror_media.py                    # everything missing
python3 tools/refero/mirror_media.py --only favicons    # one kind
python3 tools/refero/mirror_media.py --check            # exit 1 if an expected file is absent
python3 tools/refero/mirror_media.py --compress-videos  # 960px/crf28 shrink
```

`--compress-videos` needs ffmpeg on PATH (it also tries
`~/.nix-profile/bin/ffmpeg`); without it the run warns and mirrors the videos
uncompressed.

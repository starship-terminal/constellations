# Handover: capture batches

Everything a fresh agent needs to pick up the web-capture program
(batch-2 onward). Read [AGENTS.md](../AGENTS.md),
[CAPTURE.md](CAPTURE.md), and [FIELD-NOTES.md](FIELD-NOTES.md) first —
this file is the program-level glue, not a replacement.

## The queue

[webapps-manifest.json](../webapps-manifest.json) on `main` is the
source of truth: 418 catalog domains, `batch` 1–20 per app, ~20 per
batch. Batch 1 is done (`status: "captured"`, `package:
"systems/<slug>"`). Work the next `pending` batch in order. When a PR
merges, set `status: "captured"` + `package` in the same commit as the
last merge train (one manifest PR per batch is fine).

The signed-out queue's other half is [GATED.md](GATED.md): every surface
a capture skipped because it sits behind sign-in, account, checkout or
submission, generated by `tools/gated.py` from each package's
`capture.gaps` + `access` (`make check` fails if it goes stale). It is
the queue for an authenticated pass, which needs the owner's accounts
and a capture contract for authenticated regions — do not start it
without both.

## Per app

1. **Worktree, always.** `git worktree add /private/tmp/ds-<slug> -b
   capture-<slug> origin/main` from the repo root. Never share a
   checkout between agents. Reuse an existing worktree's partial work
   if a prior run died.
2. Copy `tools/kit/` → `systems/<slug>/tools/`, adapt the page
   runners/selectors to the site's real DOM.
3. Playwright lives at `PLAYWRIGHT=~/.design-systems/pw/node_modules/playwright`;
   run `make setup` (or point `PYTHON` at the repo `.venv`) for Pillow.
4. Capture public surfaces honestly: desktop 1440×900 + mobile 390×844,
   consent/overlays handled per FIELD-NOTES (hide, never click a
   consent POST), authenticated regions documented as boundaries —
   never inferred. Write `capture.gaps` lines that name the gated
   surfaces specifically: they are what lands in GATED.md.
5. `make brief && make design-md && make grade && make check` green;
   `python3 tools/refero/coverage.py` when check flags it stale; all
   binaries are LFS.
6. **Rubric review before done** — `python3 tools/grade.py --write
   --review <slug>=<grades.json> --method "<how>"`; every non-`yes`
   criterion gets a written justification (AGENTS.md rule).
7. One PR per app (`gh pr create`); catalog `capture` block carries
   `pr`, `durationMin`/`durationNote`, `route`, `model`, `date`.
8. Greptile will review: fix valid comments in the package's own
   builders, reply `in_reply_to` on every comment, resolve every
   thread via GraphQL `resolveReviewThread`. Then merge
   `origin/main` (`--theirs` for catalog.json/README.md/AGENTS.md/
   scorecard/refero-coverage/media-taxonomy; re-append your package's
   catalog entry + category keys; bump AGENTS "the packages (N)" to
   the real `systems/` dir count), regenerate, re-check, push.
9. Merge when every thread is resolved (`gh pr merge --squash`), then
   **clean up**: `git worktree remove`, delete `~/.design-systems/<slug>`,
   delete the merged branch.

## Running on the Linux homeserver

The whole public pipeline runs headless on `ssh home` (Ubuntu 24.04,
`~/designs` clone). Deel was captured, built, OCR-scanned, committed
and PR'd there end-to-end — the Mac only needs to be involved when you
want to eyeball an image locally.

- **Worktree:** `GIT_LFS_SKIP_SMUDGE=1 git -C ~/designs worktree add
  ~/ds-<slug> -b capture-<slug> origin/main`. The skip matters: a
  plain checkout tries to fetch every package's LFS images and stalls.
  New captures produce their own LFS objects, nothing else is needed.
- **Toolchain (all verified):**
  - Node 22, git, git-lfs, authed `gh` — on PATH.
  - `PLAYWRIGHT=~/.design-systems/pw/node_modules/playwright/index.mjs`;
    browsers in `~/.cache/ms-playwright` (validated).
  - `PYTHON=/usr/bin/python3 make …` — the committed `.venv` is a
    symlink to a Mac path, dead on Linux; leave it alone.
  - Pillow is in system python; numpy/anything else via `uv run
    --with pillow --with numpy python3 …` (`uv` lives at
    `~/.nix-profile/bin/uv`).
  - Tesseract 5.5.3 via nix: `/nix/var/nix/profiles/default/bin/nix
    profile install nixpkgs#tesseract --profile ~/.nix-profile`.
    **Every non-interactive `ssh home` needs `export
    PATH=~/.nix-profile/bin:$PATH`** — nix is installed but not on the
    default PATH.
- **Redaction on-server:** `uv run --with pillow --with numpy python3
  tools/redact_images.py check systems/<slug> --patterns
  ~/.design-systems/<slug>-redact.json`. Verified identical to the Mac
  (deel: 96 package images + 20 raw originals, 0 matches both sides).
- **Fonts:** Liberation (metric-compatible Arial/Helvetica clones) and
  Noto Color Emoji installed via nix, symlinked into
  `~/.local/share/fonts`, `fc-cache` refreshed. `fc-match Arial` →
  Liberation Sans, `fc-match Helvetica` → Nimbus Sans. Residual:
  `-apple-system`/SF stacks and Apple-emoji artwork still differ from
  the Mac — if recon (`document.fonts`, computed stacks) shows the
  site leaning on Apple system fonts, capture that one on Mac instead.
- **Render parity (measured):** same page shot on both OSes — identical
  dimensions, ~1–3% of pixels differ in thin text-AA bands only,
  invisible after quantization; computed styles are identical. The one
  large diff ever seen was a video carousel's poster frame — media
  timing, not OS. Expect run-to-run noise in animated/lazy regions
  anywhere.
- **Async pattern:** long captures run fine detached (`ssh home '…'`
  backgrounded); rsync `systems/<slug>` back to a Mac worktree only if
  you need local tools. Scratch dirs (`~/.design-systems/<slug>/`)
  live on whichever machine ran the capture — clean up there.
- Same egress network as the Mac, so geo-IP content matched; still
  smoke-test each site once (Cookiebot variants, CDN, bot challenges).

## Batch-1 lessons (verified)

- ~200 Greptile comments across 19 packages clustered into a dozen
  recurring patterns — they are all in FIELD-NOTES.md; fixing them in
  the kit/tools once beats patching each package.
- GitHub's `mergeable` lags: after each squash merge, sibling PRs go
  CONFLICTING on the shared generated files. Budget one
  merge-main+regen cycle per PR; the procedure above is mechanical.
- CI (check/app/build/web jobs) fails fast on a repo billing issue —
  known, not a code failure; local `make check` is the gate.
- Parallelism: one worktree per app + background subagents works;
  transcripts die on session churn but worktrees survive on disk.
- Scratch dirs can fill the disk (an unbounded tiler once wrote
  111 GB) — the kit caps tiling at 8 chunks; delete dead runs' scratch.

# Fingerprint design reference

A token set and component reference for Fingerprint's public surfaces — for building developer-product marketing pages, pricing grids, docs-site chrome and the sign-in edge in the style of the real thing. It was read from **fingerprint.com** on **2026-11-15**, signed out, in headless Chromium at 1440 x 900 and 390 x 844. Captured: the home page, /products/identification/, /products/smart-signals/, /products/ai-agent-detection/, /use-cases/payment-fraud/, /ai/, /pricing/, /demo/, /contact-sales/, /blog/, /case-studies/, /resources/, /security/, /integrations/, /sdk-libraries/, /bot-directory/, /about-us/ and /careers/, the header's Product, Use Cases and Resources dropdowns, three docs.fingerprint.com pages (the Mintlify docs landing, the Quick Start Guide and the Smart Signals overview — including the docs' own dark theme preference), the dashboard.fingerprint.com /login and /signup auth shells, and 390px passes on home, pricing, demo, contact-sales and a docs article.

Fingerprint is worth a capture because it ships two declared token layers to the browser: the marketing Astro + Tailwind v4 app declares the FPDS palette as `--fpds-color-*` HSL channel triplets — ten-step ramps for gray, blue, green, orange, pink, purple, red, teal and yellow plus black/white and a syntax-highlighting set — with Tailwind aliases (`--color-*`, `--text-*`/`--font-*`, `--radius-*`, `--spacing`, `--shadow-*`, `--ease-*`, `--leading-*`, `--tracking-*`) and a small semantic layer (`--primary`, `--primary-hover`, `--primary-active`, `--border`, `--surface-raised`). Four self-hosted voices: **Inter** for everything, **Petrona** for editorial display, **JetBrains Mono** for code and signal values, and **Geist Pixel** for pixel display. The docs site is a different stack (Mintlify) with a real light/dark theme preference — the only genuinely painted dark surface in the capture; the marketing site declares only the `.dark`-scoped `--fpds-color-syntax-*` re-pointing and resolves identically under an emulated dark probe. **Boundary:** the dashboard and every post-login surface was never reached — the /login, /signup, contact-sales, newsletter and demo fields were measured as forms, never submitted; every link, SSO button and CTA was measured, never followed; the 'Open the chat' launcher was never opened.

### Principles

1. Do let the declared palette carry the colour.
2. Do spend the accent on the action.
3. Do keep surfaces near-white.
4. Do pair the four voices on purpose.
5. Don't style the signed-in dashboard from this package.
6. Don't treat the dark set as a dark theme.
7. Don't fabricate form outcomes.
8. Don't copy the brand or the live signals.

Each rule links the screenshot or crop that shows it, under [Do and don't](#do-and-dont).

## How the values were read

| Step | What ran |
|---|---|
| Screenshots | `tools/capture/public/public.mjs` — 22 desktop routes at 1440 x 900 (default + stitched `-full`, capped at 8 chunks) and 5 at 390 x 844, plus the three header dropdowns and the docs dark-theme preference |
| CSS harvest | `tools/capture/vars.mjs` — every custom property in the site's stylesheets (linked bodies + inline CSSOM), resolved in `:root` and `.dark` probes — 322 resolved values each — plus 24 `@font-face` rules; Tailwind `--tw-*` internals and one-off utility variables were collected but kept out of the resolved set |
| Measurements | `tools/capture/public/measure.mjs` — 70 components on public routes only; hover/focus-visible/pressed/opened/focused/filled states; nothing signed into, submitted or followed |
| Tokens | `tools/build_component_tokens.py` → `raw/component-tokens.json` → `tools/build_tokens.py` → `tokens.json` |
| Docs | `tools/build_components_md.py`, `tools/build_style_guide.py`, `tools/capture/public/build-measurements.mjs` |

- **Provenance.** Every token leaf names its source in `$extensions.source`: `css-var --…` or `declared design-system variable …` for the site's own declared variables, `measured <component/state/property> …` for computed-style readings. FPDS triplets are emitted twice: the raw `H S% L%` primitive under `core.fpds.*` and the resolved `hsl(...)`→hex under `core.color.*`.
- **Privacy.** The /demo live panel and the home/identification `IdentifySection` demos paint the capture machine's real visitor ID, IP address and geolocation (including a map tile). Those regions are masked in the committed images by `tools/redact-rules/fingerprint.json` (applied with `tools/redact_images.py`); public placeholder text such as `name@email.com` and `john@company.com` is allow-listed and left intact. Raw unmasked captures live outside the repo under `~/.design-systems/fingerprint/raw-shots`.

## What to distrust

- **The signed-in product.** The dashboard, API keys, events explorer, playground and billing need an account this capture does not have. dashboard.fingerprint.com /login and /signup are the product auth shell — a different stack that does not share the marketing token layer; its measured values sit under `component.productShell.*`, honestly labelled.
- **The dark set.** The only dark declaration the marketing stylesheets ship is the `.dark`-scoped `--fpds-color-syntax-*` set — eleven code-highlighting colours re-pointed at lighter ramp steps. No marketing page carries `.dark` or a theme control, and a `prefers-color-scheme: dark` probe resolved `:root` identically. The `dark` set is declared-not-painted evidence; the genuinely painted dark surface is the Mintlify docs' own theme preference, captured as `docs-*-light-theme-dark` screenshots — a different stack whose values are not folded into the marketing sets.
- **The live demo.** /demo and the IdentifySection panels call the real Fingerprint API and paint this machine's signals (visitor ID, IP, geolocation). The controls were measured; 'Analyze my browser again', 'Place Order' and the demo 'Log In' were never pressed; the signal regions are masked in committed shots.
- **Animated surfaces.** Heroes, the AI page's particle canvas and product demos hold live canvas/video content; a screenshot freezes one frame. Sparse-looking panels are a capture artifact, not the design.
- **The forms.** Contact-sales, footer/blog newsletter and the demo's fake checkout were typed into then cleared — validation, error, loading and success states are unverified because nothing was submitted.
- **Detail pages.** The blog, case-studies, resources, integrations, bot-directory, careers and docs lists were captured as indexes or exemplars; individual posts, jobs, bots, integrations and most docs articles were not opened.
- **Quantised screenshots.** `screenshots/` are 256-colour PNGs; read exact colours from tokens or the raw values, never the pixels.
- **Unpainted fills are not tokens.** The docs code block and the hero pill compute a transparent `backgroundColor`, so `core.component.docs.code-bg` and `light.surface.pillBg` were dropped in the 2026-11 audit.

## Do and don't

1. **Do let the declared palette carry the colour.** Fingerprint ships ten-step ramps for nine hues plus its semantic triplets: use `core.color.*` and the `light.theme.*` roles rather than restating hex. See [tokens.json](tokens.json) and [home-light-default](screenshots/home-light-default.png).
2. **Do spend the accent on the action.** The orange `#f35820` (`light.theme.action.primary`) belongs to primary CTAs, focus rings and active marks — hover deepens to `#bd400f` (`theme.action.primaryHover`), pressed to `#78361c` (`primaryActive`). Secondary actions stay ink-on-white. See [nav-cta](components/crops/nav-cta-default.png) and [plan-cta](components/crops/plan-cta-default.png).
3. **Do keep surfaces near-white.** The page field is `#ffffff`; raised surfaces and plan cards sit at `#fbfbf9`/`#f8f8f6` (`theme.surface.raised`, `surface.planCardBg` → `color.gray.100`) behind a `#e4e5e1` hairline — never grey fills. See [plan-card](components/crops/plan-card-default.png).
4. **Do pair the four voices on purpose.** Inter carries UI text, Petrona the editorial display, JetBrains Mono code and signal values, Geist Pixel the pixel display. See [hero-h1](components/crops/hero-h1-default.png) and the docs code blocks.
5. **Don't style the signed-in dashboard from this package.** The post-login product was never reached; `component.productShell.*` marks the auth-shell measurements that do not share the marketing layer. See [login-light-default](screenshots/login-light-default.png).
6. **Don't treat the dark set as a dark theme.** The eleven `dark.syntax.*` tokens are `.dark`-scoped code-highlighting declarations no public page painted; the docs' dark preference is a different stack captured as screenshots only. See [docs-quickstart-light-theme-dark](screenshots/docs-quickstart-light-theme-dark.png).
7. **Don't fabricate form outcomes.** Contact-sales, newsletters, the demo checkout and the auth cards were typed into then cleared — validation, error and success states are unverified. See [contact-email](components/crops/contact-email-filled.png).
8. **Don't copy the brand or the live signals.** The Fingerprint mark, product glyphs, partner logos and the visitor-ID/IP/geolocation panels in captures are Fingerprint's published content (the live-signal regions are masked); borrow structure and proportion, not identity. See [mkt-logo](components/crops/mkt-logo-default.png).

## Rebuild

Run from the package directory (`systems/fingerprint/`); the redact step reaches back to the repo's shared tools:

```sh
RAW=~/.design-systems/fingerprint/raw-shots PLAYWRIGHT=<playwright index.mjs> node tools/capture/public/public.mjs   # -> RAW full-colour shots
python3 tools/capture/quantize.py ~/.design-systems/fingerprint/raw-shots           # stitches + quantises -> screenshots/
PLAYWRIGHT=<playwright index.mjs> node tools/capture/vars.mjs                       # raw/css-vars.json
PLAYWRIGHT=<playwright index.mjs> node tools/capture/public/measure.mjs             # raw/components-computed.json
PLAYWRIGHT=<playwright index.mjs> node tools/capture/public/build-measurements.mjs
python3 ../../tools/redact_images.py apply . --rules ../../tools/redact-rules/fingerprint.json
python3 tools/build_component_tokens.py && python3 tools/build_tokens.py
python3 tools/build_style_guide.py && python3 tools/build_components_md.py
```

All deterministic: same inputs, byte-identical outputs.

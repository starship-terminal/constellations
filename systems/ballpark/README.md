# Ballpark design reference

A token set and component reference for Ballpark's public site — for building product-research marketing, pricing and sign-in surfaces in the style of the real thing. Tokens were read from **ballparkhq.com** on **2026-11-11**, signed out, in headless Chromium at 1440 x 900 and 390 x 844. On **2026-11-21** the public tree was mapped from the homepage and re-photographed at the same widths: every nav target, the Platform and Solutions menus, the phone sheet, and the auth walls (photographed, not submitted). The map is [site-tree.md](site-tree.md).

Ballpark is worth a capture because it is a current reference for a clean, editorial SaaS marketing surface: a white ground, display type in **Inter Display** at up to 96px/800, one near-black CTA recipe (`#111827`, 7px radius, 36px pills) repeated from the nav to the pricing page, a coral flame ramp (`#fc4a2b` family) reserved for the "NEW" chip and small accents, a hairline-bordered ghost button next to it, and a full Framer `--token-*` palette — the Tailwind v3 ramps plus the product's own colours — declared on `body`.

## Brief

Read this before designing in this style. Take every value from [tokens.json](tokens.json), never from the screenshots; `python3 tools/catalog.py export ballpark` prints them all with aliases resolved.

### Principles

1. Do ground on white.
2. Do use one CTA recipe.
3. Do pair it with a hairline ghost.
4. Do set display type in Inter Display.
5. Don't spread the flame.
6. Don't invent a dark theme.
7. Don't read link colour off the anchor.
8. Don't shrink the mobile menu.

Each rule links the screenshot or crop that shows it, under [Do and don't](#do-and-dont).

## How the values were read

Every value came off the running signed-out site in headless Chromium:

- **Tokens.** [tools/capture/vars.mjs](tools/capture/vars.mjs) captured every stylesheet body — the Framer bundle ships most of its CSS inline — re-parsed them, and wrote every custom property to [raw/css-vars.json](raw/css-vars.json) binned `token`/`app`/`framer`. The 213 `--token-<uuid>` declarations on `body` are the site's palette: 191 of them are the Tailwind v3 default ramp under Framer's uuid names (emitted under their Tailwind names, `color.gray.50` … `color.rose.950`), the rest are Ballpark's own — an 11-step coral/flame ramp (`color.flame.*`), two brand blues, a deep teal and six translucent greys. Each name is resolved in a probe carrying the real sheets. [tools/build_component_tokens.py](tools/build_component_tokens.py) writes the spec [raw/component-tokens.json](raw/component-tokens.json) that [tools/build_tokens.py](tools/build_tokens.py) renders.
- **Components.** [tools/capture/public/measure.mjs](tools/capture/public/measure.mjs) opens each route in a fresh context and reads `getComputedStyle`, painted layers and boxes per element in default, hover, focus-visible and a CDP-forced pressed state, plus `opened` on the Solutions flyout and the mobile menu, and `focused`/`filled` on fields (text typed then deleted, nothing sent). Framer mounts a section only while its band is near the viewport, so the Coach demo widget and the carousel dots are hunted by a scroll sweep that marks them in place (the demo's ask field is a painted placeholder, not a real input, and is recorded missing). Results in [raw/components-computed.json](raw/components-computed.json) and [raw/measurements.md](raw/measurements.md); each entry also carries the painted text child's style, because the anchors themselves inherit the browser's unvisited-link colour.
- **Screenshots.** [tools/capture/public/public.mjs](tools/capture/public/public.mjs) takes viewport and full-page shots per route, including the opened Solutions menu and the mobile menu, with `.capture.json` sidecars; [tools/capture/quantize.py](tools/capture/quantize.py) posterises them to 256 colours for the repo.
- **Fonts.** Nine webfonts are declared in the bundle ([raw/css-vars.json](raw/css-vars.json) `fonts`): **Inter Display** for headlines, **Inter** for the UI, **Source Serif 4**, **Nanum Pen Script** (handwritten notes), three monospace faces (**Geist Mono**, **IBM Plex Mono**, **Fragment Mono**) and display faces **Bebas Neue**, **Rozha One**, **Comico** — the last few mostly inside template and customer artwork.

Nothing was sent, downloaded, signed into or trialled. The only presses were local UI toggles: the Solutions nav menu, the mobile menu and the carousel dots (never clicked — measured only). The sales form and the sign-in form were never submitted.

## What to distrust

- **One painted theme.** Every captured route paints light; the bundle declares no dark variant, so no dark set is emitted.
- **Framer uuid token names.** `--token-<uuid>` names are unstable build artefacts; tokens.json emits them under readable Tailwind/brand names while each leaf keeps the real variable in `$extensions.source`.
- **Anchor `color` reads `#0000ee`.** Framer paints link/button text on inner spans; the anchor's own computed colour is the UA default. `light.accentText`/`link` read the text child (`textStyle` in the raw file), never the anchor.
- **`component.*` tokens are measured**, not site variables.
- **oklab/lab values.** Framer computes some greys in oklab/lab; tokens carry the converted sRGB.
- **Quantised screenshots.** `screenshots/` are 256-colour PNGs; read exact colours from tokens or the raw JSON.

## Fonts

Declared in `raw/css-vars.json` (`fonts`, 336 faces): **Inter Display** 600–900 italic+normal — every headline measured (`"Inter Display", "Inter Display Placeholder", sans-serif`) — **Inter** 400–900 — the sign-in/contact pages and body UI — **Source Serif 4** 300–800, **Nanum Pen Script** (the handwritten annotations), **Geist Mono**, **IBM Plex Mono**, **Fragment Mono**, **Bebas Neue**, **Rozha One** and **Comico**. The guide renders system fallbacks; the webfonts themselves are not committed.

## Do and don't

1. **Do ground on white.** `#ffffff` page, near-black `#111827` ink, `#f9fafb` (`gray.50`) alternate bands. See [home-light-default](screenshots/home-light-default.png).
2. **Do use one CTA recipe.** The near-black `#111827` pill, 36px, 7px radius, white text — nav, hero and pricing all use it. See [nav-cta-default](components/crops/nav-cta-default.png) and [plan-cta-default](components/crops/plan-cta-default.png).
3. **Do pair it with a hairline ghost.** Sign in / the SSO buttons are white with a `#e5e7eb` (`gray.200`) hairline at the same 36px/7-8px recipe. See [nav-signin-default](components/crops/nav-signin-default.png).
4. **Do set display type in Inter Display.** 96px/800 hero, 42px/700 sections, tight leading. See [hero-title-default](components/crops/hero-title-default.png).
5. **Don't spread the flame.** The `#fc4a2b` coral ramp marks the "NEW" chip and small accents only, never a button. See [announcement-bar-default](components/crops/announcement-bar-default.png).
6. **Don't invent a dark theme.** The bundle declares none; every route paints light.
7. **Don't read link colour off the anchor.** Framer anchors keep the UA `#0000ee`; the painted text lives on the inner span (`textStyle` in the raw JSON).
8. **Don't shrink the mobile menu.** At 390px the menu is a full sheet of stacked groups, not a dropdown. See [mobile-home-light-menu-open](screenshots/mobile-home-light-menu-open.png).

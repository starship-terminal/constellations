# Manus design reference

Public site tree, dated 2026-11-22, is [site-tree.md](site-tree.md). That pass photographed the signed-out marketing pages and the empty login dialog. It did not replace the signed-in tokens, crops, or screenshots below. `catalog.json` was left alone. `login-extracted` stays not-started.

A token set and component reference for Manus's web app (manus.im/app), for rethinking self-learn's shell and its content management: the multi-section sidebar that replaces a top bar, and the Library that organises every kind of file an agent made by type and by the day it was made. It was read on 2026-10-04 from the owner's signed-in account, in both themes, at 1440 wide and 390 wide: the home, the Library (list, grid, grouped by task, the Slides and Images type tabs, the row menu, the view options, the document previewer), Creations, Computers, Agents, Automations, Plugins, a project page, a finished task (the thread, the deliverable card, the files dialog, the split view with its Files tab), the user menu, Settings (General and Shortcuts), search, notifications, every sidebar menu, and the phone layout (app gate, home, drawer, Library, task). It was refreshed on 2026-10-17 on the same free account, at 1440 wide in both themes, against the library scorecard: Settings' Developers pane (the API key table, its row menu, the delete confirmation, the Create API Key form empty and filled, its select open), Personalization (text fields and text areas), Usage & Billing while its history loads, and the invite dialog with its email field; the stylesheets were read again for the values Manus keeps in utility classes (named shadows, spacing, z-index, border widths, focus and reduced-motion rules).

The earlier references cover learning products (Duolingo, Brilliant, NotebookLM, Coursera, Gauth). Manus is an agent product whose output is files, which is what self-learn has become too: notes, diagrams, videos, sessions and courses that pile up with no date to hang them on. Its Library is the model for that problem.

## Brief

Read this before designing in this style. Take every value from [tokens.json](tokens.json), never from the screenshots; `python3 tools/catalog.py export manus` prints them all with aliases resolved.

### Principles

1. Do keep the chrome grey and let the content bring the colour.
2. Do mark the current item with a neutral fill alone.
3. Do keep the filled button for the main action of a block and outline the rest.
4. Do separate surfaces on the page with hairlines and fill steps, and save shadow for what floats.
5. Do label sections with small grey text in normal case.
6. Do confirm a destructive action in a small dialog, with the red button last.

Each rule links the screenshot or crop that shows it, under [Do and don't](#do-and-dont).

## How the values were read

Manus is a Next.js app styled with Tailwind utilities over CSS variables: a class reads `bg-[var(--background-nav)]` or `rounded-[var(--ui-density-row-radius)]`, and nearly every colour on a page is a `var()` of one of the 210 names a single stylesheet chunk declares on `:root` (light), 141 of which it declares again on `.dark` (dark). So there was no palette to infer: the token file's `light` and `dark` sets are those two blocks, the `core` set is the `--ui-font-size-*` / `--ui-line-height-*` scale and the `--ui-density-*` scale from the main chunk, and only a dozen layout numbers (the 300 px sidebar, the 52 px rail, the 48 px bars, the 800 px thread column, the 28 px avatar) had to be measured on the elements. The stylesheets are served from files.manuscdn.com, cross-origin to the app, so the page's own CSSOM refuses to read them; [vars.mjs](tools/capture/vars.mjs) fetches the chunks and parses them in a headless Chromium instead.

The pages were captured without handing the account to a headless browser. In the signed-in tab, [snapshot.js](tools/capture/signed-in/snapshot.js) copied each page state's DOM with the same-origin styles inlined and the cross-origin stylesheets kept as links, replaced the account's name with "Learner" and its avatar photo with a plain disc (the redaction file lives outside the repository, shaped like [redact.example.json](tools/capture/signed-in/redact.example.json)), cut every signed URL back to its path, inlined the Library's thumbnails (the account's own files, served from a private CDN with a signed query, which the page may fetch) as small JPEG data URLs, and recorded the position of every inner scroller. [unsnap.py](tools/capture/signed-in/unsnap.py) refuses a copy in which a redacted string or a signing parameter survived. [render.mjs](tools/capture/signed-in/render.mjs) then renders each copy at 2x, and renders the light theme by removing the `dark` class from `<html>`, which is all Manus's own theme switch does, so no account setting was changed: the account was on Auto with a dark system, and every capture started dark.

Two things a static copy cannot do. The task thread is a virtualised list inside its own scroller: only the turns near the live scroll position exist in the copy, so the renderer restores that position (or scrolls to the first rendered turn), and a `-full` shot of a task page would be mostly empty, so there is none. And the slide preview inside a deliverable card is an iframe, which the copy keeps as a same-size dark box; the card's chrome is real, its contents are not.

Component values are computed styles read per state with Playwright from the rendered copies ([measure.mjs](tools/capture/signed-in/measure.mjs)): hover with the pointer, focus-visible with a real keyboard focus, both themes by toggling the class. States that need JavaScript (an open menu, the files dialog, the typed composer, the collapsed rail, the grid view, the group-by-task view) were each captured as their own copy in the live tab, so they are measured in the state they were captured in. The task titles and document titles in the screenshots are the owner's own; nothing was created, sent, deleted or changed in the account beyond opening menus, switching the Library's view options (and switching them back), typing a line into the composer and deleting it, and toggling the sidebar. On the 2026-10-17 refresh nothing was sent, saved or deleted either: the forms were typed into and cancelled. The one submit, with the owner's go-ahead, was "not-an-email" in the invite form, to show its error; Manus answered with a toast about 50ms after Send, and there was no deliverable address. One click there landed on a popover's "Continue in new task" by mistake and branched an existing task; the owner was told and the branch is theirs to remove.

The 2026-10-17 refresh used the same route. The owner's session was already signed in to the browser pane; the copies went through the same snapshot, now ported from the Linear kit to scrub task, project, file and key names by selector (each becomes "Sample task 1" and so on), strip the session and project ids, blank the account's own slide images and drop the page title. The stylesheet chunk names had all changed since 2026-10-04, so [vars.mjs](tools/capture/vars.mjs) reads the new list: no variable changed value, 24 were added and 2 removed. Pressed is now measured too (the pointer held down on the element), for the new components and for the home page's parts from a fresh copy of home; the other 2026-10-04 copies no longer exist.

Screenshots are stored as 256-colour PNGs to keep the folder small. Flat UI colours are exact; read values from the tokens, not the images.

## Colour roles, ramps and elevation

Manus names colours by what they do (`text.primary`, `background.menu-white`, `fill.tsp-white-main`, `function.error`), so the checklist roles are a mapping, kept in each theme under `role` as aliases:

| Role | Token | Where it was measured |
|---|---|---|
| Page | `background.gray-main` | every page's main column, and the Settings and other modal dialogs |
| Surface | `background.nav` | the sidebar |
| Raised | `background.menu-white` | the composer, Library grid cards, the Computers bands |
| Overlay | `background.menu-white` | menus, popovers, the select listbox, the search dialog |
| Scrim | `background.dialog-mask` | behind every dialog, with a 4px backdrop blur |
| Text: primary, secondary, tertiary, disabled | `text.primary`, `text.secondary`, `text.tertiary`, `text.disable` | placeholders are `text.disable` |
| Text on accent, link | `text.onblack`, `text.blue` | the primary button's label; Upgrade and Documentation |
| Border: subtle, default, strong, focus | `border.light`, `border.main`, `border.dark`, `border.input-active` | table rules, dividers, control outlines, focused fields |
| Accent: default, hover, pressed | `button.black`, then 90% opacity | Create, Copy invitation link, Upgrade |
| Danger: fill, text, border | `function.error-tsp`, `function.error`, `button.border-error` | the Delete menu item and the danger button |
| Success, warning: fill, text | `function.success(-tsp)`, `function.warning(-tsp)` | no border token for either |

The primary action is black in light and near-white in dark, not blue. Hover is `opacity: 0.9`; the button's classes also ask for `active:opacity-80`, but `hover:opacity-90` comes later in the stylesheet and wins, so a pressed button reads 0.9 too (measured on button-primary, button-danger and button-blue). `role.accent.hover` and `role.accent.pressed` are that 90% composited over the page colour (Derived). Blue is the link and selection colour and the one a user can swap for green, yellow, pink, orange, purple or black in Settings.

Manus declares no colour ramps: Tailwind's palette is not shipped and every variable is semantic. `core.palette` assembles them (Derived): every colour literal the light and dark blocks and the accent palettes declare (433 declarations, 165 of them translucent) goes on the ramp of its hue, neutral first, then red, orange, yellow, green, teal, blue, purple and pink. A translucent token is its ramp step at that alpha, so every declared colour sits on a ramp, the danger red and the link blue included. Each hue has two views: `palette.<hue>` is a 50 to 950 ramp of up to 11 stops, each the declared colour nearest that lightness (neutral runs #f8f8f7 to #171717), and `palette.<hue>-all` is the full list, lightest first (71 neutrals, 28 blues). Every step names the variables that hold it.

Elevation is six levels, each tied to its use, in each theme under `elevation`. Three are Manus's own named utilities:

| Level | Value (light) | Used on |
|---|---|---|
| `card` | `shadow-card`: 1px highlight ring, 1px ring, 0 1px 2px, 0 2px 4px | the stylesheet's card style; not on a captured element |
| `raised` | 0 3px 10px `shadow.S` | the Computers bands |
| `composer` | 0 12px 32px rgba(0,0,0,0.02) | the composer on home, a project and a task |
| `layer` | `shadow-layer`: rings plus 0 24px 24px -12px, 0 3px 3px -1.5px, 0 10px 20px 1px | a Library grid card on hover |
| `menu` | `shadow-menu`: as `layer` with a 1px ring | every menu, popover, listbox and dialog (17 measured) |
| `panel` | 1px ring plus 0 4px 32px `shadow.S` | the notifications panel |

Dialogs do not get a deeper shadow than menus; the scrim sets them apart. In dark the shadow colours are stronger and `shadow.Highlight` adds a white 14% ring.

## Spacing, shape and layout

Spacing is Tailwind's scale on a 4px base, read from the classes on the elements of the refresh's copies (`raw/css-rules.json`, `spacing`). `core.space` keys each step by its class step, so `space.2` is gap-2 or p-2, 8px, and `space.2_5` the 10px half step; it runs from `space.0_5` (2px) to `space.15` (60px), each with its element count, and 8px (632), 4px (525), 2px (425), 12px (327) and 10px (216) lead. The few values off the grid (1px rules and arbitrary 7, 9, 11 and 34px) are kept apart in `core.space.$extensions.offGrid`: 73 of 2809 spacing class uses. The density variables (`core.density`) hold the paddings Manus sets by variable.

Border widths are 0.5px (the share banner, the grid card ring), 1px (59 measured components) and 2px (the active underline tab), in `core.borderWidth`; illustrations draw their frames at 1.2px. Radii are in `core.radius`; dialogs are 16, cards and menus 12, rows 10, buttons and icon buttons 8.

z-index (`core.zIndex`): 1 to 5 inside components, 10, 20 and 30 for raised, sticky and overlaid rows, 999 for tooltips (Manus's named `z-tooltip`), 1050 for the toast viewport and the status notice. Dialogs, menus and popovers carry no z-index: they mount in portals and stack in the order they open.

Pages sit on fixed column widths inside a centred box, not a 12-column grid (`core.layout.grid`): home's 490 + 270 cards, Computers' three 312 columns, Plugins' two 378 columns, a project's 740 column and 320 rail. Breakpoints are Tailwind's 640, 768, 1024 and 1280.

## Focus, states and motion

Focus is mostly invisible. Of 64 components given a real keyboard focus, 51 show no visible change, 10 change their outline, ring or border (the composer, the promo card and its dot, the Build card, the Computers setup card and Customize band, the Settings and Plugins search fields and two settings form fields) and 3 cannot take focus. Of the 51, 45 read exactly as at rest and 6 change only something that paints nothing (a 0px ring on the search dialog's field and the text area, an outline offset under `outline: none` on four links). [components.md](components.md) tallies the same readings by element (50 of 66 draw no outline at all, most of the rest keep a resting 1px hairline), and the blue 2px ring (`text.blue`, offset 2) appears only on the promo card, the setup card and the Customize band; the send button and the theme cards draw none. That was checked in the live app, not only in the copies: eight Tab stops on the home page all matched `:focus-visible` and none drew an outline ([raw/focus-live.md](raw/focus-live.md)). Where Manus does draw one it is a 2px outline 2px out (`core.focusRing`), or on fields a 1px ring in `border.dark`; the composer swaps its border to `border.dark` in dark and to black at 20% in light.

States captured, beyond hover and focus: pressed, disabled (the Create button until a name is typed, the Send button while the email field is empty, the disabled toggle), selected (nav tab, type tab, theme card, settings nav item, underline tab, segmented control, select option), open (menus, select, row button), loading (the Usage spinner, the sidebar skeleton), typed and error.

Pressed was read on every part with an `active:` style or `:active` rule on the pages copied on 2026-10-17 (the refresh's forms and dialogs, and home: the buttons, the Settings nav row, the sidebar's section headers, Upgrade, the composer's chips): 28 readings, 14 parts in both themes, and recorded as skipped on the 31 parts there that have none. A fifteenth part, the promo card on home, was not found in the fresh copy. 19 parts elsewhere carry an `active:` style but have no pressed reading, because their pages were not copied again (Computers, Creations, Automations, Agents, Plugins, Project, Settings General and Shortcuts, the task page, the account menu) or they are measured at rest only. Only the Settings nav row looks different pressed (its fill goes from 4% to 8% white); everywhere else pressed paints exactly like hover, because `hover:opacity-90` comes after `active:opacity-80` in the stylesheet. The home page's pressed readings come from a fresh copy of it at rest.

The error state is a toast. An invalid address in the invite form leaves the field untouched and raises "Invalid email address." with a red alert icon at the top of the window, for about 6.3 seconds, with no close button ([invite-dark-email-error](screenshots/invite-dark-email-error.png), [toast](components.md#toast)). The stylesheets also carry a field ring, 1px `button.border-error` on focus (`focus-within:shadow-[0px_0px_0px_1px_var(--Button-border-error)]`), which this form does not use.

Motion is short: colour transitions 150ms, the sidebar 200ms, resizes 300ms on `cubic-bezier(.22, 1, .36, 1)`. Under reduced motion, every animation and hover lift is a `motion-safe:` variant and does not run (spinners, pulses, fades, slide-ins, hover scale and lift), `motion-reduce:` variants hide marquees and stop transforms, and the resize transition is cut to none; colour transitions stay. The 51 rules are listed in `raw/css-rules.json` under `reducedMotion`.

## Do and don't

1. **Do keep the chrome grey and let the content bring the colour.** Text, icons, buttons and selected states are all neutral; blue (`text.blue`, #1a93fe dark, #0081f2 light) is kept for Upgrade, switched-on toggles and the odd status dot. The rest of the colour on a screen is file-type icons, brand logos and illustrations. See [home-dark](screenshots/home-dark.png), [plugins-dark](screenshots/plugins-dark.png), [settings-light-general](screenshots/settings-light-general.png) and [upgrade-button-task-light](components/crops/upgrade-button-task-light.png).
2. **Do mark the current item with a neutral fill alone.** The current nav tab, settings nav item and type tab sit on white or black at 6 to 8%, and the type tab and the settings nav item also step from 400 to 500 weight (the nav tab stays at 400); the chosen theme card swaps its 12% border for a solid one. No accent colour or underline marks a selection anywhere. See [library-light](screenshots/library-light.png), [type-tab-selected](components/crops/type-tab-selected.png) and [theme-card-light-selected](components/crops/theme-card-light-selected.png).
3. **Do keep the filled button for the main action of a block and outline the rest.** Each creation card has one black "Locate in task" beside two 1px outlined buttons, and Automations ends in a single "Get started"; header actions, even Plugins' Create, are outlined, and the project rail's Add buttons are too. The filled button is black in light and near-white in dark; Agents' two download buttons are the only pair seen side by side. See [creations-light](screenshots/creations-light.png), [automations-light](screenshots/automations-light.png), [plugins-dark](screenshots/plugins-dark.png), [project-light](screenshots/project-light.png) and [agents-light](screenshots/agents-light.png).
4. **Do separate surfaces on the page with hairlines and fill steps, and save shadow for what floats.** Cards and plugin rows rest on a 1px border at 6 to 14% or a 4% fill with no shadow, and Library rows are split by a single 1px rule. Menus and popovers get the layered shadow and a 1px ring; a grid card gains it only on hover. See [library-dark](screenshots/library-dark.png), [computers-dark](screenshots/computers-dark.png), [home-light-model-menu](screenshots/home-light-model-menu.png) and [plugins-light-more-menu](screenshots/plugins-light-more-menu.png).
5. **Do label sections with small grey text in normal case.** Projects, Tasks and the settings groups (Account, Capabilities, Assets) are 13/18 in `text.tertiary` and never uppercase; the Library's date headings are 14/20 regular with the count in grey beside them. See [home-light](screenshots/home-light.png), [settings-light-general](screenshots/settings-light-general.png) and [library-light](screenshots/library-light.png).
6. **Do confirm a destructive action in a small dialog, with the red button last.** Delete sits alone in the row's popover in `function.error` with a trash icon; the dialog that follows asks the question, says "This action cannot be undone.", and ends with an outlined Cancel and a red filled Delete. Red appears nowhere else in Settings. See [settings-dark-key-menu](screenshots/settings-dark-key-menu.png), [settings-light-delete-confirm](screenshots/settings-light-delete-confirm.png) and [button-danger-default](components/crops/button-danger-default.png).

## What to distrust

- `core.palette` is assembled, not declared: Manus has no ramps. The hue families, the 50 to 950 stop names and the choice of colour for each stop are this package's; every value is one Manus declares.
- `role.*` is this package's mapping of checklist roles onto Manus's tokens, chosen from where each token is used; the values are Manus's.
- `role.accent.hover` and `.pressed` are computed (90% over the page colour); the opacity is measured.
- Pressed on the older components was read from a fresh copy of the home page (2026-10-17) while their other states come from the first copy; 19 parts on the other pages have no pressed reading, since those copies are gone. The promo card changed in between and was not found.
- One toast was measured, the validation error; the "Creating new task…" toast with a spinner was only seen. The checkbox was seen only in the stylesheets (antd checkboxes in the website builder's data tables, checked fill `icon.blue`), not on a captured page, and those rules were not kept: nothing in `raw/` records them, so that description cannot be checked against this folder.
- The opening line of [raw/focus-live.md](raw/focus-live.md) says the copies showed 39 of 64 components unchanged on focus. No committed version of `raw/components-computed.json` gives that count: it reads 45 unchanged and 51 with no visible change (see Focus, states and motion). The note's table of live Tab stops is a separate reading and is unaffected.
- Values from 2026-10-04 were not re-measured; the 2026-10-17 stylesheets declare the same values for every variable that existed then.
- Avatar fills are this package's grey disc; only their size and shape are Manus's.

## Rebuild

```bash
python3 tools/build_tokens.py
```

```bash
python3 tools/build_style_guide.py
```

```bash
python3 tools/build_components_md.py
```

`build_tokens.py` reads `raw/css-vars.json`, `raw/css-rules.json`, `raw/components-computed.json` and `raw/component-tokens.json` and writes `tokens.json`; it refuses an alias that points at nothing. `build_style_guide.py` renders `style-guide.html` from `tokens.json` and `tools/style-guide.template.html`, turning every token into a CSS variable so the page cannot drift from the file. `build_components_md.py` writes `components.md` from `raw/components-computed.json`, `raw/layout.json`, `tokens.json`, the screenshots and `icons/INDEX.tsv`. All three are deterministic.

`tools/capture/` holds the kit the captures came from. The Playwright scripts take `PLAYWRIGHT` as the path to any Playwright install's `index.mjs` (this repository does not ship one), and the signed-in scripts take `SNAPS` as the directory of page copies, which are not committed since they hold the owner's content.

```bash
PLAYWRIGHT=/path/to/playwright/index.mjs node tools/capture/vars.mjs
```

```bash
PLAYWRIGHT=... SNAPS=<dir> node tools/capture/signed-in/render.mjs <dir> library-dark full light
```

```bash
PLAYWRIGHT=... SNAPS=<dir> node tools/capture/signed-in/measure.mjs
```

```bash
SNAPS=<dir> node tools/capture/icons.mjs
```

```bash
python3 tools/capture/rules.py <dir of the .css chunks> <dir of page copies>
```

```bash
python3 tools/capture/name_icons.py
```

`python3 tools/capture/quantize.py <dir of renders>` stores renders into `screenshots/`. To take a new page copy: open the page in a signed-in tab, paste `snapshot.js` into its console, call `await __inline()` on a page with thumbnails, then `__snap('<page>-dark-<state>', REDACT)` with the redaction file's contents, save the returned string to a file and run `SNAP_REDACT=<redaction file> unsnap.py <file> <dir>`.

## Use in Figma

Import `tokens.json` with Tokens Studio and choose the Light or Dark theme. Set the UI font to Inter or SF Pro (the system face Manus relies on is not a web font) and the display font to Libre Baskerville.

# Airtable design reference

A token set and component reference for Airtable's public marketing site, for building a SaaS marketing page or pricing/lead form in the style of a real app-building platform. It was read from www.airtable.com on 2026-11-10/12, signed out, in headless Chromium at 1440 wide and 390 wide: the home page, /platform and /platform/ai, /solutions and /solutions/enterprise, /pricing, /contact-sales, /customer-stories, /templates, /marketplace, /whatsnew and /about. The look is friendly and capable: Haas text on white with #181d26 ink, a 13-colour brand accent system painting 32px-radius tiles, a dark ink pill for every primary action, and a 710px slide-in nav drawer.

Airtable the product — the workspace, base editor, interfaces and automations at app.airtable.com — is a different, signed-in world; this package is the marketing surface only. Nothing was signed into, registered, submitted or bought, the contact-sales form was never sent, and the third-party Qualified "Riley" chat widget and Google One Tap prompt are swept out of every capture.

### Principles

1. Do use the ink pill for the primary action.
2. Don't reach for the brand blue on chrome.
3. Do let coloured tiles do the decorating.
4. Do keep the two focus rings.
5. Don't draw heavy shadows.
6. Do watch the face per page.

## How the values were read

Airtable's marketing pages are React apps with CSS modules and readable suffixes (`*_cardCell`, `*_arrowButton`, `Drawer-module_*`), so the kit selects by class-suffix and role probes rather than atoms. The pages ship a real token layer on `:root` — the `--color-primitive-*` ramps, `--color-surface/text/border/icon-*` semantics, `--spacing-*`, `--radius-*`, `--type-*`, `--font-*`, `--shadow-*`/`--elevation-*`, `--motion-*` and a per-section `--theme_*` set — captured whole by [vars.mjs](tools/capture/vars.mjs) into [raw/css-vars.json](raw/css-vars.json), where each token's `var` leaf resolves. Values the vars do not cover (the measured button, card, drawer, field and chip colours) carry `measured <component>` sources instead.

Component values are computed styles read per state with Playwright ([measure.mjs](tools/capture/public/measure.mjs), gap-filled by [remeasure.mjs](tools/capture/public/remeasure.mjs)). Hover used the pointer, focus-visible a real keyboard Tab, and pressed was forced through DevTools (`CSS.forcePseudoState`), so no button was clicked for real. The only presses were local UI state: the Platform nav trigger, the promo close, the Country combobox, two FAQ accordions, the mobile menu and the stories carousel's next arrow (the previous arrow only renders off the first slide). The whatsnew release gallery is Airtable's own published interface embedded at `airtable.com/embed/appL2oaKxSWg9qz8y`; its cards and filter buttons were measured inside the frame. Nothing was signed into, registered, submitted or bought.

Third-party UI is swept out of every capture ([lib.mjs](tools/capture/public/lib.mjs)): the Qualified "Riley" messenger (iframe + launcher + panel) and the Google One Tap prompt are hidden before each shot and are not design-system components. Screenshots were lazily scrolled to settle lazy-loaded media, then stored quantised to 256 colours; the unquantised originals stay in the capture scratch dir.

## What to distrust

- **Readings past a masked bot signal.** The committed screenshots and readings were taken with `navigator.webdriver` masked, the flag bot checks read to spot automation. The capture scripts no longer mask it (not run since), so a recapture may record a walled route as a boundary instead of a reading.
- **Screenshots are 256-colour PNGs.** Gradients and photography band slightly; read exact colours from tokens.json or the raw files.
- **Type varies by page.** Most pages run Haas/ATSeasonSans, but /pricing is Inter Display and /marketplace GT Eesti Display — check `core.typography.display-pricing` before styling a pricing page.
- **Field borders are painted by the container.** The contact-sales fields' visible border sits on the field box, not the `<input>`; `component.field-border` is the measured `rgba(0, 14, 38, 0.23)` of that container, not a reading of the input itself.
- **The whatsnew gallery is an embed.** Its cards and filters are real measurements taken inside the airtable.com/embed iframe, but the embed can drift independently of the page chrome.
- **`layout.json`'s whatsnew content column reads 350px** — the gallery iframe's internal max-width, not the page's.
- **Hover reads "same" on several controls by design** (the tile cards, tab list). The entries are not missing a state.
- **`component.embed-card-shadow` is a placeholder note**, not a shadow token: the real stack is `core.shadow.low`.
- **`about-card` was read from the wrong element.** It is the 1342 x 116 stats list on /about ("50M+ apps and agents ..."), not a card. Needs a recapture; the script now skips lists and full-width blocks (not run since).
- **The FAQ readings and the script disagree.** The committed `faq-item` and `faq-item-open` were read on /platform/ai (their `page` and `url`), but the committed script measures those keys on the home page only, so a rerun would replace them with a different FAQ. Rerun, or restore the platform-ai FAQ probe, before trusting a rebuild against them.
- **Five icons are blank.** `add-on.svg`, `icon-57cfd5d9.svg`, `icon-8c4f578a.svg`, `icon-2e816604.svg` and `icon-8c628be4.svg` hold only a `<use>` pointing at the page's `/icons/icon_definitions.svg` sprite, which the harvest did not copy, so they render nothing on their own. Each `<use>` still names the sprite glyph it stood for (`#Plus`, `#MagnifyingGlass`, `#Buildings`, `#ChevronDown`, `#Check`, in that order); a recapture with a harvester that inlines `<use>` targets is needed.

## Do and don't

1. **Do use the ink pill for the primary action.** Every primary CTA is the same dark `#181d26` rounded-12 pill on white (Sign up for free, hero CTAs, the form's Submit) — `#040e20b0` on hover, `#070c14d1` pressed. See [nav-signup-default](components/crops/nav-signup-default.png) and [submit-button-default](components/crops/submit-button-default.png).
2. **Don't reach for the brand blue on chrome.** `#2572ff` paints accents and illustrations; chrome actions stay ink-dark and links run `#0768f8`/hover `#254fad`. See [platform-card-default](components/crops/platform-card-default.png) vs [nav-trigger-hover](components/crops/nav-trigger-hover.png).
3. **Do let coloured tiles do the decorating.** The signature surface is a 32px-radius tile in a flat pastel (`#c7e5f2` blue, `#fcab79` orange) with dark coloured text — never a gradient, never a shadow. See [tile-card-default](components/crops/tile-card-default.png) and [resource-card-default](components/crops/resource-card-default.png).
4. **Do keep the two focus rings.** Nav and buttons draw a 2px `rgba(4,14,32,.69)` ring offset 2–4px; fields and filter rows draw a 1px `#005fcc` outline. See [nav-signup-focus-visible](components/crops/nav-signup-focus-visible.png) and [country-selector-focus-visible](components/crops/country-selector-focus-visible.png).
5. **Don't draw heavy shadows.** The system is flat: cards separate with 1px `#e0e2e6`/`#e0dcdb` keylines or a pastel fill; `core.shadow.low` is a hairline lift, and nothing glows. See [solutions-card-default](components/crops/solutions-card-default.png) and [whatsnew-item-default](components/crops/whatsnew-item-default.png).
6. **Do watch the face per page.** Platform-page headlines are ATSeasonSans 550; marketing display is Haas Groot Disp 700 or Haas 600; pricing is Inter Display 475. See [platform-title-default](components/crops/platform-title-default.png), [templates-title-default](components/crops/templates-title-default.png) and [pricing-title-default](components/crops/pricing-title-default.png).

## Rebuild

```bash
python3 tools/build_tokens.py
```

```bash
python3 tools/build_style_guide.py
```

```bash
python3 tools/build_components_md.py
```

`build_tokens.py` reads `raw/component-tokens.json` and writes `tokens.json`; it refuses a value that is not the DTCG type it claims and an alias that points at nothing. `build_style_guide.py` renders `style-guide.html` from `tokens.json` and `tools/style-guide.template.html`, turning every token into a CSS variable so the page cannot drift from the file. `build_components_md.py` writes `components.md` from `raw/components-computed.json`, `raw/layout.json`, `tokens.json`, the screenshots and `icons/INDEX.tsv`. All three are deterministic: re-running them on this commit reproduces their files byte for byte. Edit the raw inputs or the builders, never the generated files.

`tools/capture/` holds the kit the captures came from. The Playwright scripts take `PLAYWRIGHT` as the path to a Playwright install's `index.mjs` when `playwright` is not resolvable from where they run.

```bash
PLAYWRIGHT=/path/to/playwright/index.mjs node tools/capture/public/public.mjs
PLAYWRIGHT=/path/to/playwright/index.mjs node tools/capture/public/measure.mjs home platform mobile
PLAYWRIGHT=/path/to/playwright/index.mjs node tools/capture/public/remeasure.mjs pricing whatsnew
```

`public.mjs` re-takes the screenshot set into `RAW` (a scratch dir outside the repository); `python3 tools/capture/quantize.py <dir>` stores the quantised copies in `screenshots/`. `measure.mjs` takes page names and merges into `raw/components-computed.json`; `remeasure.mjs` is the gap-fill pass that re-reads only the entries it is pointed at; `node tools/capture/public/build-measurements.mjs` then rewrites `raw/measurements.md`. `vars.mjs` and `icons.mjs` rewrite their raw or icon files whole. `lib.mjs` holds the shared helpers, including the Riley/One-Tap sweep (it no longer masks `navigator.webdriver`).

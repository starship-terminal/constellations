# Anam design reference

A token set and component reference for Anam, the real-time AI avatar platform — for building marketing, pricing and documentation surfaces in the style of the real thing. Three public surfaces, one accent, all captured: the **marketing pages** are a Framer site (white ground, black ink and pill buttons, the orange #ff6200 accent, persona cards that are live avatar videos with frosted-glass controls); the **app pages** /pricing, /get-demo and /tools are Next.js and declare a small semantic set on `:root` (`--bg`, `--surface`, `--text`, `--border`, `--brand`); the **docs** are Mintlify (a warm-stone gray ramp, Inter and Paper Mono, the same orange as `--primary`, and the only surface with a dark theme). It was read on 2026-11-09, signed out, in headless Chromium at 1440 wide and 390 wide (the component readings were refreshed on 2026-11-10 during review): the home, api, interactive-avatars, about, research, case-studies, blog, changelog, tools, pricing and get-demo pages, two docs pages plus the docs' dark theme, and the mobile home, pricing and docs.

The reason Anam is worth a capture at all: it is one of the most disciplined one-accent systems on the public web — a single #ff6200 does every branded job (badge, active item, link underline, primary icon) while the product stays black and white — and its signature surface, a card that is a live talking face with frosted-glass controls, is a pattern few libraries hold.

## Brief

<!-- brief:start. Generated by tools/brief.py from catalog.json, the tokens file and this README; `make brief` rewrites it. Do not edit. -->

Read this before designing in this style. Take every value from [tokens.json](tokens.json), never from the screenshots; `python3 tools/catalog.py export anam` prints them all with aliases resolved.

### Principles

1. Do let one orange do every branded job.
2. Do make the primary button black, not orange.
3. Do round generously.
4. Do float controls on video in frosted glass.
5. Do keep surfaces flat and separated by hairlines.
6. Don't expect a second theme on the marketing pages.
7. Don't reach for a display face for headings.

Each rule links the screenshot or crop that shows it, under [Do and don't](#do-and-dont).

## How the values were read

All three surfaces are public, so every page was captured signed out in headless Chromium. `public.mjs` tours each route in a real browser at 1440 x 900 and 390 x 844, hiding the cookie consent card (never clicked — a consent choice is a submission) for the clean shots and recording it first for the consent state; nav submenus are opened by real hover, the docs ⌘K dialog and ⌘I sheet by keyboard, the billing toggle by a local click, and the docs dark theme by the theme menu. `vars.mjs` dumps every custom property from the sheets each page serves — 844 Framer/`--token-*`, 248 app-page and 983 docs declarations — plus font faces, loaded fonts and dark-theme checks. `measure.mjs` tags each component live (the Framer carousel re-renders and parks cards off-screen, so candidates are filtered to on-screen elements and re-resolved per state), forces `:active` with DevTools for pressed states so nothing is ever really pressed, and writes computed styles plus a crop per state. Values marked `css-var` come from the site's own variables; `measured` values are computed styles of the real element.

Two themes are captured: `light`, what every surface paints by default, and `dark`, what the docs paint under their theme menu (`.dark` on html). The marketing and app pages declared no dark values and did not change under prefers-color-scheme (`themeChecks` in [raw/css-vars.json](raw/css-vars.json)), so `dark` is the docs' theme only — Mintlify's gray ramp shared between themes, `--default-border-color` switching gray-100 for gray-800, the accent unchanged.

## What to distrust

- **The Framer pages give almost no variables.** Three `--token-*` names on `body` are the whole declared palette (#fff8ed, #4a1c00, #ff6200); every other marketing value in the package is a computed-style measurement of a real element, and Framer's hashed `--framer-*` internals were treated as noise, not tokens.
- **The cream pair is barely used.** `--token-…-#fff8ed` and `--token-…-#4a1c00` are declared on body but the pages paint white; they are kept as accent grounds, not the page's bg.
- **The persona crops are video frames.** Each card is a live talking face; a crop shows whichever frame the page was painting.
- **Mobile docs.** The docs sidebar is not reachable at 390 wide without opening the menu sheet; `m-docs-sidebar` is missing by design.
- **Pressed is forced.** `:active` was applied by DevTools, so a state a script adds on real mousedown (if any) is missing; the plan CTA's scale-press was captured, other controls paint no change.

## Fonts

- **Inter** (400/500/600/700) is the UI face on all three surfaces — self-hosted on the marketing pages, `--font-inter` on docs, free under OFL and loaded in the style guide.
- **IBM Plex Mono** (400/500) covers code and metrics on the marketing and app pages (`--mono`); free, loaded in the guide.
- **Paper Mono** is the docs' code face (`--default-mono-font-family`); a commercial Mintlify face, not redistributable — the guide falls back to the mono stack.
- **MD Thermochrome 0.4 Trial** loads on the home page for display accents — a licensed trial face, not redistributable; substitute a close free face when reproducing the style.

## Do and don't

- **Do let one orange do every branded job.** #ff6200 is the hero badge text and dot, the docs' active sidebar fill and link underline, the primary icon colour and the API method marker; there is no second accent ([home-light-default](screenshots/home-light-default.png), [docs-nav-active](components/crops/docs-nav-active-default.png)).
- **Do make the primary button black, not orange.** On the marketing site the CTA is a black 50px-radius pill with white 15/500 text; the gray pill is the secondary and the frosted pill is for controls over video ([hero-cta](components/crops/hero-cta-default.png), [nav-signin](components/crops/nav-signin-default.png), [demo-cta](components/crops/demo-cta-default.png)).
- **Do round generously.** Persona cards and the footer's dark panel take 32px, the consent card and docs cards 16, docs controls 12, and marketing buttons are full pills ([persona-chip](components/crops/persona-chip-default.png), [footer](components/crops/footer-default.png), [consent-card](components/crops/consent-card-default.png)).
- **Do float controls on video in frosted glass.** Over a live avatar face the chrome is white-at-50% fill, a 2px white-at-12% ring, and black-at-70% icons — never a solid button ([demo-cta](components/crops/demo-cta-default.png), [persona-chip](components/crops/persona-chip-default.png)).
- **Do keep surfaces flat and separated by hairlines.** The marketing pages are white-on-white with fills, not shadows; depth is reserved for the floating consent card and the long soft shadow under the persona videos ([consent-card](components/crops/consent-card-default.png), [persona-chip](components/crops/persona-chip-default.png)).
- **Don't expect a second theme on the marketing pages.** Only the docs go dark (pure #000 with warm-stone text); the marketing and app pages are light-only — don't invent a dark palette for them ([docs-dark-main](components/crops/docs-dark-main-default.png)).
- **Don't reach for a display face for headings.** Display lines are Inter at 500 weight with tight tracking, not a serif or the licensed Thermochrome; Thermochrome accents only ([hero-title](components/crops/hero-title-default.png), [cta-band](components/crops/cta-band-default.png)).

## Rebuild

The kit under [tools/capture/](tools/capture) re-reads the live sites; the builders re-derive the package from `raw/`:

```sh
cd systems/anam
PLAYWRIGHT=~/.design-systems/pw/node_modules/playwright/index.mjs \
  node tools/capture/public/public.mjs        # page screenshots into ~/.design-systems/anam/raw-shots (RAW)
PLAYWRIGHT=... node tools/capture/vars.mjs    # raw/css-vars.json
PLAYWRIGHT=... node tools/capture/public/measure.mjs   # raw/components-computed.json + crops (+ layout.json)
python3 tools/capture/quantize.py ~/.design-systems/anam/raw-shots   # screenshots/; originals stay out of the repo
node tools/capture/public/build-measurements.mjs       # raw/measurements.md
python3 tools/build_tokens.py                 # tokens.json from component-tokens.json + css-vars.json
python3 tools/build_components_md.py          # components.md
python3 tools/build_style_guide.py            # style-guide.html
```

Then `make design-md` at the repo root refreshes [DESIGN.md](DESIGN.md), and `make check` re-grades the package. The icon is a repo-level fetch, run from the repository root: `python3 tools/fetch_icon.py anam`.

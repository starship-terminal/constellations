# Conductor desktop design reference

A token set and component reference for Conductor's desktop app for macOS (bundle id `com.conductor.app`), version 0.91.2, captured on 2026-10-25 from the owner's signed-in account on the Free plan. Conductor runs coding agents (Codex and Claude Code) in parallel workspaces: each workspace is a git worktree of a repository with its own chats, a file tree, a change list, run and setup scripts and a terminal. Home, the workspace and its chat, the composer and its menus, the command palette, diffs, the file view, dialogs, the update toast and every Settings pane were captured in Conductor's Light and Dark themes, at the window size the app was in: 1400 x 800 pt.

Conductor is a Tauri app: its binary links AppKit and WebKit and carries `wry` and `tauri://localhost`, so the interface is HTML and CSS drawn in a WKWebView, with no Chromium debugging port. The web view is inspectable, so everything was read live through Safari's Web Inspector: every custom property the stylesheets declare, as it computes and paints in each theme, and the computed style of every captured part in every state, with full-window screenshots of each screen. It is the first package captured this way, for [issue 107](https://github.com/c-wenlong/designs/issues/107). Use it to build a warm, dense desktop tool for agents: stone-brown neutrals instead of grey, a quiet sidebar, chat tabs over a plain conversation, ink for the primary action, and a tan accent for links and focus.

This package contains no Conductor code, icons or artwork; the screenshots and the visual system they show are Conductor's ([docs/RIGHTS.md](../../docs/RIGHTS.md)). Borrow structure and proportions, not the brand.

## Brief

Read this before designing in this style. Take every value from [tokens.json](tokens.json), never from the screenshots; `python3 tools/catalog.py export conductor-desktop` prints them all with aliases resolved.

### Principles

1. Do use ink, not a hue, for the primary action.
2. Do keep the neutrals warm.
3. Do give tan the small jobs.
4. Do fold an agent's work into one line.
5. Don't outline or fill selection.
6. Do ask before deleting, and only then.

Each rule links the screenshot or crop that shows it, under [Do and don't](#do-and-dont).

## How the values were read

**Getting in.** `Contents/MacOS/conductor` is a Rust binary (Tauri 2 on wry 0.55); its `Resources` hold a sidecar runtime and the bundled agent binaries, not a browser. The binary carries `setInspectable:` and `developerExtrasEnabled`, the strings wry uses when it builds with devtools, and with Safari's Settings > Advanced > Show features for web developers on, Safari's Develop menu lists Conductor's page under this Mac (Conductor > localhost). The setting showed as on but the Develop menu was missing; turning it off and on again made Safari apply it. No System Settings, SIP or Gatekeeper setting was touched. The owner was already signed in; nothing was typed into a sign-in screen.

**Reading the page.** Safari's Web Inspector has no scripting interface the capture could use without changing security settings, so the capture drives its console. [rjs.sh](tools/capture/inspector/rjs.sh) puts a JavaScript function body on the clipboard, [console.applescript](tools/capture/inspector/console.applescript) raises the inspector window, opens the console and pastes and runs it, and the result comes back through the console's `copy()` and the clipboard. Every call first installs [cap.js](tools/capture/inspector/cap.js) (readers for custom properties and computed styles, and helpers that click, type and send keys with script events) and [prelude.js](tools/capture/inspector/prelude.js) (Conductor's parts, found by role, aria-label, icon and UI words, never by account text). [shots.py](tools/capture/inspector/shots.py) works through [shots.json](tools/capture/inspector/shots.json): reveal a state, measure the shot's parts, then capture the window with [shot.sh](tools/capture/inspector/shot.sh) (`screencapture -l` on Conductor's window while it is frontmost, then `sips` to sRGB; the Display P3 original stays outside the repo). The web view fills the window at a device pixel ratio of 2, so a part's CSS box times two is its box in the screenshot. A folder picker is native, so [open_project.sh](tools/capture/inspector/open_project.sh) and [key.applescript](tools/capture/inspector/key.applescript) send real keystrokes to it, each only after checking that Conductor is frontmost and the panel is on screen.

**The theme.** Conductor's web view is React with Tailwind CSS 4 and Base UI. Tailwind's theme layer declares a palette that is the same in both themes: Conductor's own warm grey ramp (`--color-gray-0` to `-900`, hex, from `#fff` to `#2c2826`) and the Tailwind hues it uses (oklch). The theme itself is about 115 hex values on `:root, .light` and on `.dark`, shadcn's names plus Conductor's own; `html.dark.low-contrast-dark` overrides 13 of them for Settings > Appearance > Low-contrast dark mode (off here; recorded under `dark.$extensions.lowContrastDark`). The app writes the font stacks (Geist, Geist Mono) and the Code theme's colours inline on `<html>`. `vars()` in [cap.js](tools/capture/inspector/cap.js) lists every declaration, then read each name on `<body>` as it computes and as it paints (a probe element's `color: var(--x)`); [build_tokens.py](tools/build_tokens.py) keeps a declared hex as the value, makes a token an alias when its declaration is a plain `var()` of another name that paints the same, and converts oklch and oklab with [colour.py](tools/colour.py).

**Themes.** The owner's Theme setting was Dark (Conductor's default; no theme had been chosen before). For the light pass it was set to Light in Settings > Appearance > Theme, as approved; at the end it was set back to Dark. Choosing a theme stores `melty-theme-selected-mode` in the app's local storage; it now holds `"dark"`, which behaves as the default did. System and the colour-vision themes (Settings > Appearance > Accessible colors) were not captured.

**States.** Hover, focus-visible and pressed could not be forced the usual way: Safari's console has no command for it, and the pointer was not moved because another app on the Mac was being driven by pointer at the time. Instead [cap.js](tools/capture/inspector/cap.js) copies every stylesheet rule that uses `:hover`, `:focus-visible`, `:active` or `:focus` into a capture stylesheet with the pseudo-class replaced by an attribute, and sets that attribute on the part. The values painted are Conductor's own declarations. Two shots forced focus-visible on one part and hover on the others; that part's reading is filed under its own focus-visible entry (`<shot>~focus` in `raw/components.<theme>.json`, same screenshot). Focus is real focus given by `focus()`; typed is text set in the field and cleared after. Tooltips opened on script pointer events. The validation error was reached with real keystrokes (a repository name that already exists on the owner's GitHub account) in the GitHub repository offer, which was then cancelled.

**The agent runs.** The owner approved test prompts on 2026-10-25 in a fresh chat on the scratch folder `~/.design-systems/harness-scratch/conductor`. Conductor needs a git repository, so that folder was made one, with a local bare remote inside it (`.origin.git`) so Conductor would not offer to create a GitHub repository, and added as a project; Conductor then made its first workspace, as it always does, as a git worktree under `~/conductor/workspaces/conductor/`. [run.py](tools/capture/inspector/run.py) typed and sent each prompt from the composer, then screenshotted and read the chat about every 3.5 s until the send button had shown the send arrow (not the stop square) three times. Dark ran "List the files in this folder" and "Create hello.txt here with one line" in the workspace's first chat; light ran "List the files in this folder" and "Create hello-light.txt here with one line" in a second chat. The default agent, GPT-5.6 Sol (Codex, High effort), listed the files and wrote the two one-line files in the workspace. No approval prompt appeared and nothing was approved.

**What was created, changed and put back.**
- Created, and left: the scratch repository and its bare remote in `~/.design-systems/harness-scratch/conductor/` (with a second folder, `no-remote/`, used only to open the GitHub repository offer); the Conductor project `conductor` for it; one workspace (first Dalat, renamed by Conductor to Folder files list, branch `c-wenlong/folder-files-list`, at `~/conductor/workspaces/conductor/dalat`) with three chats, two of them holding the test prompts, and the files `hello.txt` and `hello-light.txt` in it.
- Created by mistake and removed: an Add project keystroke sequence sent while the folder panel was not yet open picked the scratch repository a second time, so Conductor added it again as `conductor-v1` with a workspace, Biarritz. It was removed through Settings > conductor-v1 > Misc > Remove repository (its confirmation named conductor-v1), its worktree record pruned and its branch deleted. Removing it while it was open left the window on Workspace not found, which was captured as the error state. The GitHub repository offer was opened three times and cancelled each time; no repository was created.
- Changed and put back: the Theme (Light for the light pass, Dark again after). Clicking the diff's Split toggle and back stored `using_split_view = false` in Conductor's settings table; that row was deleted after Conductor was quit. Safari's Develop menu is now on.
- Not changed: the model (GPT-5.6 Sol High), `~/.conductor/settings.toml`, the account, notifications, approvals and every other setting. Conductor and Safari were quit at the end and not reopened; no agent process from the capture is running.

## What to distrust

- **States are rule copies.** A forced state paints Conductor's own declarations but not through the browser's own pseudo-class, so two kinds of rule did not apply: `!important` utilities inside a cascade layer (`focus:!border-special` on text fields beats the unlayered copy) and rules whose class name contains `:focus-visible` itself (`[button,a]:focus-visible:ring-3`). Text-field focus (`component.*` has no focus value) is recorded from the class list in components.md: the edge turns `base.special`. Buttons carry `focus-visible:ring-none` and draw no ring; switches and chat tabs carry `focus-visible:ring-2 ring-ring ring-offset-2`: under the forced rule the switch draws a 2px `base.ring` ring outside a 2px offset (`core.focusRing.*`, [switch-on-focus-visible](components/crops/switch-on-focus-visible.png)), and the chat tab computes the same ring but the tab strip clips it. The model button shows a 1px inset ring ([workspace-focus](screenshots/dark/workspace-focus.png)).
- **The scrim is sampled.** The element measured as the dialog backdrop was a portal wrapper with no fill, so `role.scrim` (black at 50%) is read off the screenshots: white page under the backdrop shows as #808080. Labelled Sampled.
- **Light and dark differ in content.** The dark workspace shots are the first, empty chat (You're in a new copy of conductor called dalat, with suggestion chips); the light ones are a second chat (New chat in /folder-files-list), so the suggestion chips and the new-workspace card were measured in dark only and sit under `dark.$extensions.notTokenised`. changes-empty is empty in dark only: by the light pass the agent had written a file.
- **The window shows a scratch project.** The repository has no GitHub remote, so the right panel shows Couldn't load PR info and Checks has no checks; a real project shows PR status there.
- **Component values are one element each.** `component.*` and components.md read the first element that matched each part (or the shot named in [prefer.py](tools/prefer.py)); they are not counts across pages.
- **Run frames are timed, not chosen.** The `run-*` screenshots are frames about 3.5 s apart; the agent finished each prompt within 10 s, so few frames show it working.
- **Toasts keep Sonner's colours.** The update toast is `#000000` with a `#333333` edge in dark and white in light, not the app's tokens.
- Screenshots are 256-colour PNGs. Flat UI colours are exact; read values from tokens.json.

## Do and don't

1. **Do use ink, not a hue, for the primary action.** The primary button and the on switch paint `base.foreground` (`role.accent.default`: a warm near-black in light, near-white in dark); no button is blue. See [repo-dialog](screenshots/dark/repo-dialog.png), [repo-dialog light](screenshots/light/repo-dialog.png) and [settings-general](screenshots/light/settings-general.png).
2. **Do keep the neutrals warm.** Every grey is the stone-brown ramp (`core.color.gray.*`, `#2c2826` to `#eae8e6`), and the prompt sits on a rose tint (`base.highlight`), so nothing in the window is a neutral grey. See [conversation](screenshots/dark/conversation.png) and [conversation light](screenshots/light/conversation.png).
3. **Do give tan the small jobs.** File links, the special accent and a focused field's edge are the tan `link.foreground` and `base.special`, never a blue. See [conversation-top](screenshots/dark/conversation-top.png) and [repo-dialog-focus](screenshots/light/repo-dialog-focus.png).
4. **Do fold an agent's work into one line.** Tool calls collapse to "2 tool calls, 1 message" once a turn ends, the reply is plain text, and the change is a small diff chip under it. See [run-write-finished](screenshots/dark/run-write-finished.png) and [conversation-expanded](screenshots/light/conversation-expanded.png).
5. **Don't outline or fill selection.** Selected sidebar rows, settings panes and menu items take a 5% wash of the foreground (`sidebar.accent`, `base.popover-accent`), with no border or colour. See [workspace](screenshots/dark/workspace.png) and [workspace-context-menu](screenshots/light/workspace-context-menu.png).
6. **Do ask before deleting, and only then.** Removing a repository opens a confirmation with a red Remove; archiving a workspace, which can be undone, asks nothing. See [remove-confirm](screenshots/dark/remove-confirm.png) and [workspace-context-menu](screenshots/dark/workspace-context-menu.png).

## Rebuild

From this folder. The capture needs Conductor running with a Web Inspector window open on its page (Safari > Develop > this Mac > Conductor > localhost), the terminal allowed to use System Events and to record the screen, and the scratch project added; it writes outside the repo to `~/.design-systems/conductor-desktop/raw-shots/`.

```bash
python3 tools/capture/inspector/shots.py dark --vars            # custom properties, in the theme on screen
python3 tools/capture/inspector/shots.py dark                   # every shot in shots.json
CHAT=new python3 tools/capture/inspector/run.py dark list "List the files in this folder"
# switch Settings > Appearance > Theme, then the same with light
/opt/homebrew/bin/python3.14 tools/capture/quantize.py ~/.design-systems/conductor-desktop/raw-shots   # Pillow: screenshots/ and raw/
python3 tools/build_tokens.py
python3 tools/build_components_md.py
python3 tools/build_style_guide.py
/opt/homebrew/bin/python3.14 tools/crops.py                     # Pillow
python3 -m unittest discover -s tools
git status --short .
```

The builders run from the committed `raw/` and need no capture. A rebuild that changes nothing proves the outputs still match their inputs. From the repository root, `make design-md` regenerates DESIGN.md and the Brief.

## Compared with the Electron harnesses

[cursor-desktop](../cursor-desktop/README.md) and [orca-desktop](../orca-desktop/README.md) were read over Chromium's debugging port, where CDP forces pseudo-classes and takes the screenshot; here Safari's Web Inspector reads the same things, but states are rule copies and screenshots are window captures. In look, Conductor sits between them: Orca's shadcn structure and ink primary, with a warm stone palette where Orca is neutral and Cursor is cool, and tan where Cursor uses blue.

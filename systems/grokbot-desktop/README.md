# Grok Bot desktop design reference

A token set and component reference for Grok Bot's desktop app for macOS (SpaceXAI; bundle id `com.anysphere.sand`), version 0.75.5 (Electron 42.11.16, Chrome 148), captured on 2026-10-25 from the owner's signed-in account. Grok Bot is a messenger for AI agents ("Bots"): one window with a sidebar of Bots (a pinned grid, then groups), one conversation per Bot, an inspector pane for the open Bot, and Settings as a dialog. The window was captured in full in the app's Light and Dark themes, at the size it was in: 1120 x 760 pt.

Everything was read live from the running app over Chromium's remote-debugging port, with the capture scripts [cursor-desktop](../cursor-desktop/README.md) piloted for this route: full-window screenshots of every screen and state, the custom properties of both colour layers as they compute and paint, and the computed style of every captured part in every state. Use it to build a calm desktop chat or agent app: a near-black or white window, a darker sidebar of characters and grouped rows, pill controls, raised bubbles with no borders, an ink primary button, and one colour per Bot that fills the owner's messages and the voice button. For Grok Bot's iOS app see [grokbot](../grokbot/README.md); [How desktop differs from iOS](#how-desktop-differs-from-ios) compares them, and no value here was taken from it.

This package contains no Grok Bot code, icons, Bot characters or artwork; the screenshots and the visual system they show are SpaceXAI's ([docs/RIGHTS.md](../../docs/RIGHTS.md)). Borrow structure and proportions, not the characters or the brand.

## Brief

<!-- brief:start. Generated by tools/brief.py from catalog.json, the tokens file and this README; `make brief` rewrites it. Do not edit. -->

Read this before designing in this style. Take every value from [tokens.json](tokens.json), never from the screenshots; `python3 tools/catalog.py export grokbot-desktop` prints them all with aliases resolved.

### Principles

1. Do give each agent one colour and let it fill the owner's side.
2. Do separate surfaces by fill, not by lines.
3. Do make the primary action ink, and red only for destruction.
4. Do make every control a pill or a circle.
5. Do show what an agent is doing in one muted line under its mark.
6. Don't show a focus ring to pointer users, and do show it after Tab.

Each rule links the screenshot or crop that shows it, under [Do and don't](#do-and-dont).

## How the values were read

Grok Bot is an Electron app (`Contents/Frameworks/Electron Framework.framework`). It was not running; it was opened with `open -a "Grok Bot" --args --remote-debugging-port=9403`, which it accepted on the first launch, and Playwright attached with `chromium.connectOverCDP`. The account was already signed in; nothing was typed into a sign-in screen. The scripts in [tools/capture/electron/](tools/capture/electron) are the cursor-desktop set: [cdp.mjs](tools/capture/electron/cdp.mjs), [shots.mjs](tools/capture/electron/shots.mjs), [vars.mjs](tools/capture/electron/vars.mjs) and [run.mjs](tools/capture/electron/run.mjs) are unchanged, and [product.mjs](tools/capture/electron/product.mjs) is Grok Bot's. Screenshots are CDP's `Page.captureScreenshot`, the window's own backing store.

**Two colour layers.** A `sand-cursor-theme` style element writes the theme on `:root`. Grok Bot's own layer, sand, is a flat list of literal colours (`--sand-bg-pane: #161616`): backgrounds (pane, chrome, sidebar, elevated, the scrim, primary and secondary fills with hover, active and disabled steps), twelve hues at bright, primary and secondary, borders and text in translucent tiers, icon tiers, bubble fills per hue, specular highlights and an eight-colour dataviz palette. Under it sits the anysphere-ui kit Cursor is built on: the same element writes its seeds (`--cursor-base`, nine hues, status and git colours) and re-points most of its neutrals at sand (`--cursor-bg-elevated: var(--sand-bg-elevated)`). [vars.mjs](tools/capture/electron/vars.mjs) lists every declaration, then reads each name three ways: the computed token stream, the colour it paints (a probe element's `color: var(--x)`) and, for shadows, the painted `box-shadow`. [build_tokens.py](tools/build_tokens.py) keeps a literal colour as its value, makes a token an alias when its winning declaration is a plain `var()` of a token that paints the same, and otherwise keeps the painted value with the formula beside it. The sand groups are the top level of each set; the kit is `kit.*`.

**Themes.** Grok Bot's theme does not follow an emulated `prefers-color-scheme` (CDP `Emulation.setEmulatedMedia` left `html[data-theme="cursor-dark"]` in place): its Follow System setting follows Electron's native theme. The owner's Settings > General > Theme was Follow System with macOS dark, so the dark pass was taken as it was. For the light pass the setting was switched to Light, then set back to Follow System; nothing else in Settings was changed, and a check after the capture read every General and Computer setting back as it was before.

**Components and states.** Grok Bot has no `data-component` attributes, so [product.mjs](tools/capture/electron/product.mjs) finds parts by its semantic class names (`sand-agent-item`, `sand-settings-row`, `ui-menu__row`), roles and aria-labels, never by account text. Each shot opens the capture's own test Bot (below), scrolls the sidebar to the top, reveals one state, takes the screenshot and reads the computed style of every listed part. Hover is a real pointer over the part. Pressed is `:active` forced through CDP's `CSS.forcePseudoState`; nothing is clicked. Focus-visible is a real Tab press and then `focus()`: Grok Bot paints no focus ring (`:root:not([data-sand-keyboard-nav]) :focus-visible { outline: none !important }`, and its focus colour tokens are `transparent`) until a Tab press sets `[data-sand-keyboard-nav]` on the root, and that is what a keyboard user does. Before and after every shot the script compares every Bot and group name in the sidebar and stops if one changed.

**Sizes.** The window renders at a zoom of 1.1 (`--sand-zoom-factor`, set inline on the root), so its 1120 x 760 pt is a 1018 x 691 CSS px viewport at a device pixel ratio of 2.2. Every px value in tokens.json and components.md is a CSS px before that zoom, the value the stylesheets declare; Borders are 1px (`borderWidth.default`, computing as 0.91px, two device pixels) or 0.5px (`borderWidth.hairline`: the composer, the confirmation, text fields, computing as one device pixel).

**The agent run.** The owner approved test prompts on 2026-10-25 in a fresh agent only, pointed at the capture's own folder `~/.design-systems/harness-scratch/grokbot`. Grok Bot has no folder or project to point a chat at, and one conversation per Bot, so the capture created a fresh Bot for it: New Bot, named "Design Capture", with the dialog's default shape and colour (a magenta cloud). A new Bot opens with its own first message, a question card about what it is for; that is the `conversation-top` screen. [run.mjs](tools/capture/electron/run.mjs) then sent, in the dark theme, "List the files in ~/.design-systems/harness-scratch/grokbot on this Mac.", "Create notes.txt in ~/.design-systems/harness-scratch/grokbot on this Mac with one line: second file from the design capture" and "In three short bullet points, with one inline code example, what is a design token?", and in the light theme "Show me what hello.txt in ~/.design-systems/harness-scratch/grokbot on this Mac says." and "Show a three-line CSS example of a colour token in a code block, nothing else.", screenshotting and measuring every 0.9 s until each finished. An earlier dark trial also sent the list prompt and asked for `hello.txt` there, and one probe sent "In one line: what is a design token?" to learn which element marks a running Bot; those messages are in the same conversation. The Bot ran its commands on this Mac and wrote `hello.txt` and `notes.txt` in the scratch folder, nothing else. No approval prompt appeared: the owner's Settings > Computer > Execution on this computer is Always allow, and nothing was changed to force one.

**Nothing else was changed.** Menus, dialogs, selects and the palette were opened and closed with Escape or Cancel; text typed into the composer, the palette and the New Bot name field was cleared without sending or creating. The delete confirmation was opened on the test Bot and cancelled. The only conversation other than the test Bot's that was opened is Chief of Staff, the one open when the capture began (already read), and it was left open at the end. Things that changed on their own during the capture: other Bots' routines posted messages, so some sidebar rows gained unread dots, and the Chief of Staff conversation gained a morning brief. Grok Bot was quit at the end and not reopened.

## What to distrust

- **The accent follows the open Bot.** Settings > General > Accent is Bot color on this account, so the owner's bubbles, the voice button and the inspector's switches take the open Bot's hue (magenta for the test Bot and Chief of Staff). `role.accent.*` is the default accent (`bg.accent-primary`, blue), which the Settings switches and the Update button show. Each hue's bubble fill is `fill.<hue>-bubble-user`.
- **Focus rings need a Tab press.** The `-focus-visible` crops show the ring after one; with the mouse alone Grok Bot draws none, and its five focus colours (`border.focus-primary`, `transcript.bubble-user-focus`, `transcript.page-focus`, `kit.stroke.focus-ring` and `kit.stroke.focused`) paint transparent in the readings. Their tokens hold the colours the root switches to.
- **Dark has almost no shadows.** Every `--sand-shadow-*` colour is fully transparent in Dark (`shadow.*` composites have no layers there); surfaces are separated by fill alone. Light paints them, but of the parts measured only the chat header carries one (`shadow.inline`, `usedBy`); the menus, dialogs and palette carry no box-shadow on their own element. The composer carries its own small shadow in both themes, and every bubble a 0.5px inset specular line (`specular.*`).
- **Two parts were measured off screen.** The reply link and the pull request pill in `conversation-history` sat above the window when it was shot, so their values are real but no crop or screenshot shows them.
- **Component values are one element each.** `component.*` and components.md read the first element that matched each part; container parts (a settings row, a tile) report the box's inherited font size, so the type roles keep only parts whose own style is their text.
- **Run frames are timed, not chosen.** The `run-*` screenshots are frames 0.9 s apart; the dark and light runs asked different things, so dark has the file edit and light has the "Typing…" state.
- **The sidebar's unread dots and the test Bot are not the owner's state before the capture.** Unread dots came from routines that ran meanwhile; the Unassigned group with "Design Capture" exists because the capture made the Bot.
- Screenshots are 256-colour PNGs. Flat UI colours are exact; read values from tokens.json.

## Do and don't

1. **Do give each agent one colour and let it fill the owner's side.** The owner's bubbles and the voice button take the open Bot's hue (`fill.<hue>-bubble-user`); the Bot's own replies stay neutral. See [conversation](screenshots/dark/conversation.png) and [run-answer](screenshots/light/run-answer.png).
2. **Do separate surfaces by fill, not by lines.** Sidebar, pane and raised fills step from `bg.sidebar` to `bg.pane` to `bg.elevated`; bubbles and settings groups have no border, and bubbles only a 0.5px specular highlight. See [home-default](screenshots/dark/home-default.png) and [settings-general](screenshots/light/settings-general.png).
3. **Do make the primary action ink, and red only for destruction.** Create is filled with the theme's text colour (`bg.primary`); Delete in the confirmation is `bg.danger-primary`; everything else is a pill on a 4% wash. See [new-bot-dialog-filled](screenshots/dark/new-bot-dialog-filled.png) and [delete-confirmation](screenshots/light/delete-confirmation.png).
4. **Do make every control a pill or a circle.** Buttons, the composer, filter pills, tabs and icon buttons are fully rounded; only menus (12px), dialogs (14px), bubbles (18px) and rows (6 to 10px) have corners. See [connect-apps](screenshots/dark/connect-apps.png) and [button-secondary-hover](components/crops/button-secondary-hover.png).
5. **Do show what an agent is doing in one muted line under its mark.** While a Bot works the transcript ends in its character and a shimmering label (Listing the directory files); the line is replaced by the reply. See [run-tool-call](screenshots/dark/run-tool-call.png) and [run-typing](screenshots/light/run-typing.png).
6. **Don't show a focus ring to pointer users, and do show it after Tab.** The ring is `focusRing.width` in `border.focus-primary`, turned on by the first Tab press. See [settings-nav-focus-visible](components/crops/settings-nav-focus-visible.png) and [settings-nav-hover](components/crops/settings-nav-hover.png).

## Rebuild

From the package folder:

```bash
python3 tools/build_tokens.py && python3 tools/build_style_guide.py && python3 tools/build_components_md.py
```

`build_tokens.py` reads `raw/css-vars.*.json` and `raw/components.*.json` and writes `tokens.json`; it refuses a token without a source, an alias that points at nothing, a dimension that is not one px length and a colour that is not hex or rgba, and moves a name present in only one theme to `$extensions.notTokenised`. `build_style_guide.py` renders `style-guide.html`; `build_components_md.py` writes `components.md`. All three are deterministic, standard library only. `python3 tools/crops.py` (needs Pillow) cuts `components/crops/` from the screenshots.

To capture again (Grok Bot must not be running; Playwright from `~/.design-systems/pw`; the test Bot "Design Capture" must exist, since every shot starts on it):

```bash
open -a "Grok Bot" --args --remote-debugging-port=9403
SLUG=grokbot-desktop PORT=9403 INTERVAL=900 TIMEOUT=240000 node tools/capture/electron/run.mjs dark
PORT=9403 KEEP='^--(cursor|sand|ui|grok|shiki|rte)-' node tools/capture/electron/vars.mjs ~/.design-systems/grokbot-desktop/raw-shots/css-vars.dark.json "Grok Bot" ':root'
SLUG=grokbot-desktop PORT=9403 node tools/capture/electron/shots.mjs dark
SLUG=grokbot-desktop PORT=9403 node tools/capture/electron/shots.mjs --set-theme="Light"
```

Repeat the run, vars and shots with `light`, set the theme back with `--set-theme="Follow System"`, quit Grok Bot (`osascript -e 'tell application "Grok Bot" to quit'`), copy the two `css-vars.*.json` into `raw/`, then `python3 tools/capture/quantize.py ~/.design-systems/grokbot-desktop/raw-shots` (which copies the other readings into `raw/`), the builders and `crops.py`. The dark theme here is Follow System on a dark Mac; on a light Mac set Dark first and restore Follow System after.

## How desktop differs from iOS

[grokbot](../grokbot/README.md) is the iOS app (1.16.0, iPhone Mirroring, pixels only). The two share the product: Bots as coloured characters, one conversation each, the owner's bubbles in the Bot's colour, an ink primary button, grouped settings cards. The desktop app differs in what it shows and in how it was read.

| | iOS ([grokbot](../grokbot/README.md)) | Desktop (this package) |
|---|---|---|
| Navigation | A home list and pushed screens, sheets, a tab bar | One window: a 400px sidebar (pinned grid over groups), the conversation, an inspector pane, Settings as a dialog |
| Controls | iOS 26 glass controls floating over content | Flat pills and circles on translucent washes; no glass |
| Values | Sampled from screenshots, so each colour is a pixel reading | Read from the stylesheets: 970 named tokens per theme, with formulas, plus computed styles |
| Type | SF Pro at iOS sizes | System font at a 420 regular weight and Grok Bot's own eight-step scale (11 to 26px) |
| States | Few (touch) | Hover, focus-visible and pressed per control, captured |
| Agent runs | Not captured | Captured, with the activity line and file work on the Mac |

## The Electron route, as it went

| Step | What happened |
|---|---|
| Port | Grok Bot accepted `--remote-debugging-port=9403` on the first launch and kept its session; one page, titled Grok Bot |
| Screenshots | `Page.captureScreenshot` gives the exact window at its 2.2 pixel ratio |
| Values | Same as Cursor: every colour is a custom property, and the probe element resolves color-mix and oklch. Grok Bot adds its own layer (sand) of literal colours above Cursor's kit |
| Hover | A real pointer, as for Cursor; some rows only change under `[data-pane-row-item]:hover` |
| Focus | A real Tab press sets `[data-sand-keyboard-nav]` and turns the ring on; Cursor needed the capture to set its attribute |
| Theme | Did not follow emulated media; the app's own setting was switched to Light and restored to Follow System, with no settings file to clean |
| Run | No folder to choose: the capture created a fresh Bot and named the scratch folder in the prompts. The capture detected a working Bot by its activity mark (`.sand-activity-mark`) alone; after review, `RUN.state` also waits for the Bot's answer to follow the prompt and for two idle samples, so a slow start cannot end a step early. That stricter check has not been run, since the app stays closed |
| Side effects | Creating a Bot is the only change; the guard on Bot and group names found nothing else. Two traps: the closed inspector stays mounted off screen (so "is it visible" is a position check), and the inspector's Bot name is a live text field |
| Generic scripts | Unchanged, with one workaround: `shots.mjs --set-theme` connects to the window keyed `agents`, so product.mjs lists the one window under that key too |

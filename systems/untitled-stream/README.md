# untitled.stream design reference

A token set and component reference for Untitled (untitled.stream), a music collaboration product — "a sacred place for your work-in-progress music" — for building in the style of a real creator-tool marketing system. It was read from untitled.stream on 2026-11-08, signed out, in headless Chromium at 1440 x 900 and 390 x 844: the home page, the pricing page, the trust page, and the login card. Nothing was signed into, submitted, bought or consented to; /terms, /privacy and /cookie-policy stayed behind Cloudflare's waiting room and were never read.

Untitled is the library's first creator-tool web capture, and its first package where a product's two themes come from different evidence: `light` was measured on the live marketing site, while `dark` is the app's semantic remap read from the shipped `[data-theme="dark"]` stylesheet — the authenticated app behind the login card was never introspected, and the dark tokens are CSS source values, not measurements. The design itself is spare and confident: an almost-whitespace page, bracketed wordmark-less chrome (`[membership]`, `[starter]`), a black-gradient pill for the one primary action, iridescent CD renders as the hero artwork, a frosted pill bar pinned to the viewport bottom, and the dark consent card as the only inverted element. Type is Untitled Sans with a tight negative-tracking `super-title`/`body`/`subhead`/`footnote` scale and IBM Plex Mono for timestamps and notes.

### Principles

1. Do keep one black-gradient pill for the primary action.
2. Do pin a frosted pill bar to the viewport bottom.
3. Do set display type in `super-title` with negative tracking.
4. Do bracket the chrome.
5. Do let the discs carry the colour.
6. Do invert only the consent card.
7. Don't introduce marketing colour.
8. Don't ship the marketing site dark.

Each rule links the screenshot or crop that shows it, under [Do and don't](#do-and-dont).

## How the values were read

Everything was read from the running site, signed out, in headless Chromium.

- **Bot wall.** untitled.stream sits behind Cloudflare's managed challenge. Headless pages only clear it with `navigator.webdriver` masked before first paint (`tools/capture/public/lib.mjs` seeds it via `addInitScript`), and `/trust` and `/login` are flakier — the runner gives each page its own browser context so one challenged navigation cannot poison the rest. Routes that stayed behind the waiting room after retries are recorded as blocked, never screenshotted.
- **Theme variables.** `tools/capture/public/vars.mjs` walked the live CSSOM and resolved every custom property. The site declares its full semantic set twice — `:root`/`[data-theme="light"]` (what the marketing site renders) and `[data-theme="dark"]` (the app's remap, shipped in the same stylesheet) — and both land in `raw/css-vars.json` next to the `@font-face` rules and the per-selector transition index. The `dark` token set is built from that CSS source; no dark UI was navigated.
- **Component measurements.** `tools/capture/public/measure.mjs` opened each route in a fresh context, detected the in-body "Performing security verification" marker (the title stays `untitled.stream`, so title checks alone miss it), hid the consent card, then read computed styles, rects and paint layers per component in each state (default, hover, focus-visible, pressed, open, selected) and cropped them at 2x into `components/crops/`. Results merge into `raw/components-computed.json`; re-running a single page updates only its entries.
- **The consent card was never answered.** Clicking "Reject all" (or "Accept all") POSTs to `/settings/cookies`, which returns 403 to the capture client and crashes the page into Remix's "Something went wrong" error boundary — every early screenshot of that card is that crash, not the product. The card is measured as a component (it is the only dark element on the light site and carries real tokens), then hidden for the page captures. No consent state was mutated.
- **Safe interactions only.** The pricing billing selector (Yearly/Monthly) was toggled — it swaps rendered prices locally. Nav links, the Enter App pill, the login OAuth buttons and every consent control were left unclicked; the login card was measured, never submitted.
- **Generated from those readings.** `tools/build_tokens.py` writes `tokens.json` from `raw/component-tokens.json` (the token tree spec, each leaf naming its `css-var` or measured source) with `raw/css-vars.json` resolving the vars; the spec's `component` section folds into `core.component`. `tools/capture/public/build-measurements.mjs` writes `raw/measurements.md`. `tools/build_style_guide.py` and `tools/build_components_md.py` write the guide and the inventory. `tools/capture/quantize.py` re-encodes screenshots to 256-colour PNGs.

## What to distrust

- **The `dark` set is stylesheet evidence, not a measurement.** The app behind the login card was never captured (see Coverage); the dark tokens are the site's own `[data-theme="dark"]` declarations resolved through the CSSOM, real and complete, but unverified against rendered app screens. One glance at the signed-in onboarding (a dark "Welcome / Choose a disc" screen with six iridescent disc options, seen in the owner's signed-in browser) is consistent with them, but that screen was not measured and is not in this package.
- **The consent card's buttons have no measured live behaviour** — answering consent was deliberately skipped because the endpoint 403s for the capture client (above). The card's styling is measured; what a real "Reject all" does is not.
- **The billing rail is genuinely 122 x 536.** `billing-toggle` looks like a measurement bug but isn't: the Yearly/Monthly buttons are direct children of a full-height column left of the plan grid.
- **Legal pages were never read.** /terms, /privacy and /cookie-policy stayed behind Cloudflare; anything about Untitled's legal styling or content in this package is absent, not summarised.
- **Hydration windows.** Remix routes occasionally render the error boundary a beat after first paint; the runner polls before declaring a page clean, and a measurement flagged `missing` means it was not on that run's page, not that it does not exist.
- **Screenshots are 256-colour PNGs.** Read exact colours from tokens.json or the raw files, never off a PNG.

## Fonts

Two families, both self-hosted woff/woff2 (`fonts` in [raw/css-vars.json](raw/css-vars.json)): **Untitled Sans** for everything — titles, body, buttons, the bracketed chrome — and **IBM Plex Mono** for timestamps, notes and mono accents (`font.family.plex-mono`). Untitled Sans is the site's own licensed face (not on Google Fonts); the style guide falls back to the system sans. IBM Plex Mono is OFL and widely available.

## Do and don't

1. **Do keep one black-gradient pill for the primary action.** Enter App, We're hiring (inverted) and the pricing Subscribe CTA all take `component.button.primary` — a `#242424`→`#101010` vertical gradient, white `subhead` label, fully rounded. No other element is painted that dark on the light site. See [pricing-light-default](screenshots/pricing-light-default.png).
2. **Do pin a frosted pill bar to the viewport bottom.** Home floats a `component.pill-bar` (92 px) above the footer: `background.action-secondary` pills at 44 px, the platform pills' icons in `text.primary`. See [home-light-default](screenshots/home-light-default.png).
3. **Do set display type in `super-title` with negative tracking.** Hero and page titles are `typography.super-title` — 26/32 medium at `-0.78px` — and everything below it keeps the scale's tight negative trackings (`font.tracking.*`). Rounded or loosely-tracked titles are off-brand. See [home-light-default](screenshots/home-light-default.png).
4. **Do bracket the chrome.** The site has no wordmark on home; chrome and plan names read `[membership]` and `[starter]` in `body-semibold`. The brackets are the brand voice, not placeholders. See [pricing-light-default](screenshots/pricing-light-default.png).
5. **Do let the discs carry the colour.** The only saturated hue on the marketing site is the CD artwork (iridescent webp renders on `component.disc`, nominal 656 px — the strip animates them larger) — the UI itself is grayscale plus `shading` alphas. Keep functional colour to `untitled-blue` links and the pink surfaces. See [home-light-default](screenshots/home-light-default.png).
6. **Do invert only the consent card.** The frosted near-black card (`component.consent-card` `surface-frost` at 90%, 16 px radius, white text) is the site's one dark element; its buttons stay pill-shaped with the accept filled white. See [consent-card-default](components/crops/consent-card-default.png).
7. **Don't introduce marketing colour.** `untitled-pink`, `unwrap-red` and the `daw-*`/`tape-*` ramp are production-workspace colours (tape labels, track lanes, warnings); on the marketing site only `untitled-pink-background` surfaces appear. Bright CTAs are wrong. See [pricing-light-default](screenshots/pricing-light-default.png).
8. **Don't ship the marketing site dark.** `dark` is the app's semantic remap — `background.page #191919`, white `action`, rgba shading — declared for the workspace, not the landing pages. See [login-light-default](screenshots/login-light-default.png) for the public chrome.

## The consent card, measured not answered

The one thing this package captures but deliberately does not exercise is consent. Untitled's cookie card is real measured material — it is in `components-computed.json`, its tokens are `component.consent-*`/`component.consent-card.*`, and its crop is in `components/crops/` — but its buttons POST to an endpoint that returns 403 to this client and crashes the page's Remix boundary. The package keeps the card and refuses the click: consent is a user action, and a crash shot would be worse evidence than none.

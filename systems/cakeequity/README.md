# Cake Equity design reference

A token set and component reference for Cake Equity's public surface — for building marketing and signup-adjacent pages in the style of the real thing. It was read from **cakeequity.com** on **2026-11-11**, signed out, in headless Chromium at 1440 x 900 and 390 x 844. Captured: the home, pricing, feature (/features/cap-table), blog, demo-request and product-tour pages, the hosted login card app.cakeequity.com hands off to, and a 390px mobile pass over home and pricing.

Cake is worth a capture because a startup-equity product paints an unusually confident colour system: a declared Webflow token layer — `--blackberry--*` ink alphas, a six-step `--plum--*` ramp whose `#4823ff` bright plum fills every primary action and whose `#2b1599` dark plum answers every hover and press — beside four bright secondary ramps (berry `#99cefe`, lemon `#e7ff6e`, lime `#9aff91`, tangerine `#ffa360`) spent mostly on accents and illustration. 100px pills on every button and the region select, a 999px billing toggle, 20-28px cards, Exposure Light display type at 60/66 -2px over Inter 300-600 text — then three breaks from the scheme: the `#0e0d12` Cake-MCP band with lemon eyebrows, the `#18161a` footer, and the hosted Kinde login card with its own `#5a38fd` primary and 8px controls. **Boundary:** the equity-management app lives behind app.cakeequity.com; the workspace, cap table, grants, documents, checkout and every signed-in surface were never reached and are never inferred.

## Brief

<!-- brief:start. Generated by tools/brief.py from catalog.json, the tokens file and this README; `make brief` rewrites it. Do not edit. -->

Read this before designing in this style. Take every value from [tokens.json](tokens.json), never from the screenshots; `python3 tools/catalog.py export cakeequity` prints them all with aliases resolved.

### Principles

1. Do let one violet do the work.
2. Do pair the fill with the ring.
3. Do run pills to 100px.
4. Do set headlines in Exposure at -2px.
5. Do tint featured cards with plum, not shadow.
6. Do let the lemon out only on dark.
7. Don't blend the auth palette into marketing.
8. Don't style the app from this package.

Each rule links the screenshot or crop that shows it, under [Do and don't](#do-and-dont).

## How the values were read

Every value came off the running signed-out site in headless Chromium:

- **Tokens.** [tools/capture/vars.mjs](tools/capture/vars.mjs) captures every stylesheet body (the `cakester.shared.*` Webflow bundle plus the inline `<style>` blocks, re-parsed with `CSSStyleSheet` since the cross-origin CSSOM hides them) and writes every custom property to [raw/css-vars.json](raw/css-vars.json). cakeequity.com declares a real design-token layer — the blackberry ink ramp, six plum steps, the berry/lemon/lime/tangerine accents and their alphas — so most tokens are declared variables resolved the way the browser resolves them; the Kinde auth card, the mint save-pill, the field borders and the dark surfaces declare nothing, so their tokens are measured computed values. [tools/build_component_tokens.py](tools/build_component_tokens.py) writes the spec, [tools/build_tokens.py](tools/build_tokens.py) the sets.
- **Components.** [tools/capture/public/measure.mjs](tools/capture/public/measure.mjs) opens each route in a fresh context and reads `getComputedStyle`, painted layers and boxes per element in default, hover, focus-visible, pressed (CDP-forced) and opened states. Results in [raw/components-computed.json](raw/components-computed.json) and [raw/measurements.md](raw/measurements.md). The mega-nav is measured open (the hover state is held through the reading); the FAQ card is measured both closed and opened.
- **Screenshots.** [tools/capture/public/public.mjs](tools/capture/public/public.mjs) takes viewport and full-page shots per route with `.capture.json` sidecars, including the local UI toggles: the Yearly/Quarterly billing switch on /pricing (`pricing-light-quarterly`), the Product mega-nav (`home-light-menu`), the FAQ accordion (`home-light-faq-open`) and the mobile menu (`mobile-home-light-menu`, a programmatic `.click()` — a real tap pans the widened page). [tools/capture/quantize.py](tools/capture/quantize.py) posterises them to 256 colours.

Nothing was signed into, bought or submitted: the login card was captured as a surface, never filled or submitted; every Get-started-free, Start-free and Book-a-demo action was measured, never followed; the billing switch, mega-nav, FAQ and mobile menu were toggled as local UI state; the Chatbase chat widget was hidden, never opened — no consent, chat or form control was ever activated.

## What to distrust

- **Captured with the automation flag masked.** The public capture (`tools/capture/public/`) hid `navigator.webdriver` from every page, so the committed readings and screenshots it took were taken past that mask. The scripts no longer hide it (edited, not run); a recapture that meets a bot check records it as a boundary.
- **This is the public site, not the product.** The Cake workspace — cap table, grants, scenario models, documents, stakeholders, reports — sits behind app.cakeequity.com and is uncaptured. Treat the app's own design system as unknown.
- **Two dark regions, not a theme toggle.** The marketing pages are light-only; the `#18161a` footer and `#0e0d12` Cake-MCP band are dark regions painted on the light page. `tokens.json` keeps their roles in the `dark` set — read them as surfaces, not a user-selectable mode.
- **The login is a different toolchain.** authentication.cakeequity.com is a hosted Kinde page: `#5a38fd` primary (not `#4823ff`), 8px controls, a 2px `#0054f0` focus ring, its own system stack. Do not blend its values into the marketing system.
- **The mobile page is wider than the phone.** `.comparison-grid{min-width:700px}` forces a ~745px layout viewport at 390 visual width: the hamburger sits off-screen at x~660 and the page pans. The mobile shots record what a phone paints; they are not a clean 390px layout.
- **Quantised screenshots.** `screenshots/` are 256-colour PNGs; read exact colours from tokens or the raw files.
- **No url on the login and mobile entries.** Those pages are opened with their own url, which the capture did not record, so their components carry `url: null` in `raw/components-computed.json` (login: app.cakeequity.com/login, redirected to the hosted Kinde page; mobile: the home page at 390 wide). The script now records the opened url (edited, not run).
- **Missing components.** `calc-field` is recorded missing — the pricing calculator's inputs sit in `.pp-hidden-fields` (display:none) — and `story-card`'s quote cards are hover-revealed layers whose rest state is `opacity:0`.

## Fonts

Two painted faces do almost everything. **Exposure Light** runs every display headline (the 60/66 h1s, the 44/44 h2s, the blog card titles) — a light high-contrast face tracked -2px at display sizes. **Inter** runs everything else on the marketing pages: 300 ledes and footer links, 400 body, 500 pills and plan names, 600 menu links and eyebrows. The **Kinde auth card** runs Inter over a system-ui stack at its own 24/16 scale. Exposure Bold, **Youth**, **Cabinetgrotesk**, **Inconsolata** and **Plus Jakarta Sans** are served `@font-face`s nothing measured painted — recorded as declared, not observed. None is distributed with the package — the style guide falls back to Times/system sans.

## Do and don't

1. **Do let one violet do the work.** Every primary action on the page is the same `#4823ff` fill that darkens to `#2b1599` on hover and press — the site never reaches for a second action colour. See [hero-cta](components/crops/hero-cta-default.png).
2. **Do pair the fill with the ring.** Every primary button has a ghost twin — transparent, 1px violet border, violet label — that fills `#2b1599` on hover. See [hero-demo](components/crops/hero-demo-default.png).
3. **Do run pills to 100px.** Buttons, the region select, the announcement chip and the nav actions all sit on 100px radii; the billing toggle goes to 999px. Restraint in radius variety is the look. See [country-select](components/crops/country-select-default.png).
4. **Do set headlines in Exposure at -2px.** The 60/66 display and 44/44 section heads in the light face with tight tracking are the site's voice; Inter never takes a headline. See [pricing-light-default](screenshots/pricing-light-default.png).
5. **Do tint featured cards with plum, not shadow.** The featured plan draws a 25% plum border and an `#ede9ff` ribbon — elevation comes from colour, not drop shadows. See [plan-card](components/crops/plan-card-default.png).
6. **Do let the lemon out only on dark.** The acid `#e7ff6e` lives exclusively on the `#0e0d12` MCP band's eyebrows — a deliberate one-off accent. See [dark-section](components/crops/dark-section-default.png).
7. **Don't blend the auth palette into marketing.** The Kinde card's `#5a38fd` primary, 8px controls and `#1c029d` links are a different system; keep them apart.
8. **Don't style the app from this package.** Every value is the public site's; the workspace behind app.cakeequity.com is uncaptured.

## Rebuild

Everything derived regenerates offline from the raw readings (run from `systems/cakeequity/`):

```sh
python3 tools/build_component_tokens.py        # raw/components-computed.json -> raw/component-tokens.json
python3 tools/build_tokens.py                  # -> tokens.json
python3 tools/build_style_guide.py             # -> style-guide.html
python3 tools/build_components_md.py           # -> components.md
node tools/capture/public/build-measurements.mjs  # -> raw/measurements.md
python3 tools/capture/quantize.py <raw-dir>    # full-colour PNGs -> screenshots/
```

Then `make brief && make design-md && make grade && make check` from the repo root refreshes the generated sections and validates the catalog.

Live recapture (needs the site; Playwright at `PLAYWRIGHT=~/.design-systems/pw/node_modules/playwright/index.mjs`):

```sh
node tools/capture/vars.mjs                    # stylesheet harvest -> raw/css-vars.json
node tools/capture/public/measure.mjs          # computed styles + crops -> raw/components-computed.json
RAW=<scratch> node tools/capture/public/public.mjs   # screenshots -> <scratch> (incl. the billing/nav/FAQ/mobile-menu toggles)
```

cakeequity.com loads headless from this client; the Chatbase widget is hidden in every context. The app stays behind app.cakeequity.com.

# Peerlist design reference

A token set and component reference for Peerlist's public web product, the professional network at https://peerlist.io/. Captured signed out on 2026-11-21 with headed Playwright (Chromium), desktop 1440×900 at 1x and phone 390×844 at 2x, light and dark. Dark is the `dark` class on `html`, which the app shell exposes through a theme button. Marketing pages were also captured with that class set, and labelled as such.

The signed-in app (posting, launching, following, settings, messages) was not entered. `/login` and `/signup` ask for email and password, or Google. Those walls were screenshotted and not submitted. No email, phone, or location was typed.

This package contains no Peerlist code. Screenshots and the visual system they show belong to Peerlist ([docs/RIGHTS.md](../../docs/RIGHTS.md)). Borrow structure and proportions, not the logo or the green.

### Principles

1. Do use one green for the action that creates something.
2. Do set marketing headlines in the serif display face.
3. Do keep the app shell as a left rail with a green edge on the current item.
4. Don't invent a signed-in composer.
5. Do use the near-black fill for the login submit, not the green.
6. Don't treat a dark screenshot of a marketing page as the product's default.

Each rule links the screenshot or crop that shows it, under [Do and don't](#do-and-dont).

## How the values were read

Headed Chromium, signed out, 2026-11-21. Custom properties were read from the homepage stylesheet: `:root` for light and `.dark` for dark (`--gray-*`, `--border`, `--shadow-*`, `--chart-1`). Green, red and orange ramps were read from Tailwind utility rules in the same sheet (`.bg-green`, `.bg-red-300`, `.text-orange-500`). Component sizes, radii and type were computed styles on real elements: Log in, Post, Launch, login email, homepage h1, rail links. Readings are in [raw/readings.json](raw/readings.json). Screenshots are 256-colour and are not a measurement source.

A first pass that added `dark` without removing `light` painted black pages. Those shots were retaken with an exclusive class. Sidecars in the scratch folder record `innerWidth`. Full-page shots of the blog were dropped: the PNG width was 1432 because of a scrollbar, so they are not labelled 1440.

## What to distrust

Dark semantic colours are the `.dark` custom properties, not a second measurement of every control. The dark Post button was not measured. Hover on Post did not change the computed background. Focus-visible, pressed, disabled and error were not held. `--shadow-focus` is declared and was not seen on a focused field. Display type uses Instrument on the live site; the style guide falls back to Georgia. Phone shots are light only.

## Fonts

Body and UI are Geist (`Geist, "Geist Fallback"`), weights 300–900 in `@font-face`. Display headlines on the marketing home are Instrument, 48px / 57.6px / 400. Geist Mono, Departure Mono, Cooper Lt BT, Libre Baskerville, Staatliches and Roboto are also declared and were not used as the measured UI face. The fonts are Peerlist's. Tokens name the families; the files are not in this package.

## Do and don't

- **Do use one green for the action that creates something.** Post and Create Profile are `#00aa45`. Log in stays a quiet bordered button. [screenshots/scroll-light-default.png](screenshots/scroll-light-default.png)
- **Do set marketing headlines in the serif display face.** The home h1 is Instrument at 48px. UI chrome stays Geist. [screenshots/home-light-default.png](screenshots/home-light-default.png)
- **Do keep the app shell as a left rail with a green edge on the current item.** [screenshots/scroll-light-default.png](screenshots/scroll-light-default.png)
- **Don't invent a signed-in composer.** Post, Launch and Follow open the login dialog. [screenshots/scroll-light-login-dialog.png](screenshots/scroll-light-login-dialog.png)
- **Do use the near-black fill for the login submit, not the green.** Login is `#0f172a`. [screenshots/login-wall-light-default.png](screenshots/login-wall-light-default.png)
- **Don't treat a dark screenshot of a marketing page as the product's default.** Dark is a class on the app shell. The home default is light. [screenshots/home-light-default.png](screenshots/home-light-default.png)

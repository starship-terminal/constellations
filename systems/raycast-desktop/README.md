# Raycast desktop design reference

A token set and component reference for Raycast, the launcher, version 2.9.0 for macOS (`/Applications/Raycast.app`), captured on 2026-10-25 from the owner's signed-in account (free plan, AI trial ended) on macOS 26. It was captured for [issue 107](https://github.com/c-wenlong/designs/issues/107). The launcher (root search, results, the calculator, the action panel, the app menu, the fallback list, Emoji & Symbols as a grid) and the Settings window (General, Launcher, Shortcuts, Keyboard, Advanced, About, AI, Account, an extension's command table, settings search, an open dropdown) were captured in the owner's two themes, Raycast Dark and Raycast Light, at the windows' own sizes: 750 x 475 pt and 800 x 864 pt.

Raycast 2.9 looks native but is not drawn natively: its AppKit shell hosts web views, and the app bundle ships the stylesheets and theme definitions they use. Every colour, size and type value here is Raycast's own declaration, read from those files on disk (nothing was injected into the running app), and checked against the window's pixels: all 22 comparisons agree within 2 per channel. Only the painted window fills come from pixels, because the windows are translucent. Use it to build a keyboard-first launcher or command palette: one floating window, a borderless search field, rows that are the foreground colour at 5% (hover) and 10% (selected) over a neutral grey, one action bar, and a 13/11 Inter scale.

The screenshots and the visual system they show are Raycast Technologies' ([docs/RIGHTS.md](../../docs/RIGHTS.md)). This package keeps none of Raycast's icons, artwork or font files; `raw/` holds readings extracted from its stylesheets, not the stylesheets. Borrow structure and proportions, not the brand.

### Principles

1. Do keep one window and put everything in its list.
2. Do draw state as the foreground at an alpha, never as a colour.
3. Do let the search field be the whole header.
4. Do name the primary action and hide the rest behind Command-K.
5. Do keep the accent for on-states.
6. Don't leave an empty result.

Each rule links the screenshot or crop that shows it, under [Do and don't](#do-and-dont).

## How the values were read

**What Raycast is built with.** `Contents/MacOS/Raycast` links AppKit, SwiftUI and WebKit, plus a Rust host library (`Frameworks/libraycast_host.dylib`) and a Node backend. Its windows are WebKit views: `Contents/Resources/macos-app_RaycastDesktopApp.bundle/Contents/Resources/frontend/` holds one HTML page per window (main, settings, AI chat, notes, welcome, theme studio) and about 1,400 built files, 160 of them stylesheets. The binary carries `setInspectable:`, but the capture did not try Safari's Web Inspector; the shipped files already hold the declarations.

**Colours: the shipped theme definitions and stylesheet.** [tools/capture/read_bundle.py](tools/capture/read_bundle.py) reads the bundle without running anything. The built-in themes are object literals in one frontend chunk: Raycast Dark is background `#000000`, foreground `#FFFFFF`, accent `#4FA3F8` and seven hues; Raycast Light is `#FFFFFF`, `#000000`, `#138AF2` and seven darker hues (`theme.*`, Measured). A template in the same chunk writes them to `.theme-root` as `--bg`, `--fg`, `--theme-accent` and so on. The token stylesheet then declares every step as the base at an alpha (`--fg-60: rgb(from var(--fg) r g b / 60%)`) and every role as a step (`--color-text-secondary: var(--fg-60)`). `build_tokens.py` writes the steps as `#RRGGBBAA` (`alpha.*`, Derived from the declaration) and the roles as aliases of them, so `text.secondary` is `{alpha.foreground.60}`.

**Is there a published theme source?** Not one with these values. [ray.so/themes](https://ray.so/themes) (source: [raycast/ray-so](https://github.com/raycast/ray-so), commit `2e6a328`) publishes community themes in the same 12-colour shape, but not the built-in Raycast Dark and Raycast Light. Raycast's developer docs ([Colors](https://developers.raycast.com/api-reference/user-interface/colors)) show the `Color` values only as 48 px swatch images of a tinted icon over a wallpaper, with no hex values, so they cannot be compared. The app bundle is the only source that states them, and it is Raycast's own.

**The window fills: pixels.** The windows are translucent: `--color-window-bg: var(--bg-40)`, with a gradient to `--color-window-bg-secondary`, over the macOS window material. No declaration gives the colour a window paints, so `page` (launcher), `settingsPage` and `sidebar` are Sampled from the captures: the launcher paints `#1A1A1A` in dark and `#F2F2F2` in light, flat across the window. Raycast's own contrast code assumes a material grey of 80/255 (dark) and 192/255 (light) under the 40% tint, which would paint `#303030` and `#D9D9D9`; the window on this Mac is darker in dark and lighter in light than that.

**The pixel check.** [tools/measure.py](tools/measure.py) reads flat fills and glyph colours off the full-colour captures: the selected and hovered rows, three text roles, a settings card, its separator, the selected sidebar row, both switch tracks. `build_tokens.py` composites each declared translucent token over the painted fill under it and refuses to build if any differs from the pixel by more than 2 per channel. All 22 comparisons (11 per theme) agree within 2: 15 exactly, 6 by 1 (rounding of a 10% or 5% composite), and the light switch track reads `#158AF2` for `#138AF2`. The switch reading also shows that `--accent: var(--color-system-accent, var(--theme-accent))` resolves to the theme accent on this Mac. See [raw/pixel-check.json](raw/pixel-check.json).

**Sizes, radii, spacing and type: declarations.** Sizes in the stylesheets are written as `round(calc(N * var(--spx)), 1px)` with `--spx: calc(1px * var(--zoom))`; the owner's Interface Size is the smallest, and the launcher measures 750 pt wide, which is `--main-window-width` at zoom 1, so every N is taken as px. Font sizes, weights and letter spacing come from the Text component's table of named styles (`text` is Inter 13/400, `small-text` 11/400, `heading1` 24/600) and the `text` CSS module. Component sizes, paddings and state colours come from the component modules (`components-css.json`). Two values are set by script, not CSS, so they are pixels: the list row height (38 pt, `--list-item-height` set inline) and its corner (the script passes 10 on macOS; the corner fit reads 9.25 pt).

**Fonts: declarations.** `[macos]:root{font-family:InterVariable,system-ui,sans-serif}` and `@font-face` rules load `InterVariable.woff2` and `JetBrainsMono-Regular.woff2` from the bundle. The size the root search field uses is Derived: its capital reads 13.5 pt, which at Inter's 0.727 cap height is 18.6, so it is the 18 px style.

**Driving.** Raycast was already running and was not quit. The launcher was summoned with Raycast's URL scheme (`open raycast://`) and closed with Escape; Settings opened with Command-comma from the launcher. Keystrokes went through System Events and pointer moves and clicks through CGEvents ([tools/capture/drive.py](tools/capture/drive.py)), each sent from a script that first checked that Raycast was the frontmost app; the launcher is a panel that System Events does not report as frontmost, so the check asks AppKit (`NSWorkspace`). The launcher hides when it loses focus, so each step summons it, acts, captures and closes it in one run. [tools/capture/shot.sh](tools/capture/shot.sh) captures one Raycast window (`screencapture -o -l` on its id, from [rwin.swift](tools/capture/rwin.swift)) only while Raycast is frontmost, then converts Display P3 to sRGB with `sips`. Root search was given harmless queries (`12*7+2`, `color`, `raycast`, `emoji`, `heart`, `qqzzxv`), cleared after each.

**Themes.** The owner's setting was Settings > General > Follow System Appearance on, Dark Theme Raycast Dark, Light Theme Raycast Light, with macOS in dark mode; the dark captures ran on it. For the light pass, Follow System Appearance was turned off and Theme set to Raycast Light; afterwards Theme was set back to Raycast Dark and Follow System Appearance turned on, and a capture confirmed Dark Theme Raycast Dark and Light Theme Raycast Light again. macOS appearance was not touched.

**What was changed and put back.** Only the theme, as above. No command, extension, hotkey, alias or other setting was changed; nothing was installed, run, copied or pasted; no AI prompt was sent (AI needs Pro on this account). Settings was closed and the launcher dismissed at the end; Raycast is still running.

**Masking.** Nothing was masked. The captures show application names, file names and paths from root search, the owner's name, avatar and email (Account page, sidebar), and the emoji the owner uses; AGENTS.md allows all of these. No credential, phone number, address or other person's contact detail appears. `redact_images.py check` against the shared pattern file found nothing.

## What to distrust

- **The window fills are this Mac's.** `page`, `settingsPage` and `sidebar` are what the translucent windows painted over this Mac's window material and desktop; another wallpaper, Reduce Transparency, or macOS 27 may paint a different grey. The declared roles on top of them (every `alpha.*`) do not change.
- **Light-theme Settings ran with Follow System Appearance off,** so Settings > General shows one Theme row in light where dark shows two; every other screen has the same layout in both.
- **Contrast-adjusted hues are not tokenised.** `--red-contrast`, `--red-on-tint-10` and the like are worked out at runtime by Raycast's contrast code from the theme and an assumed window grey; this package keeps the base hues and notes where a component uses the adjusted form.
- **The action bar pills are system glass on macOS 26.** Their painted fill varies across the pill (86% of a box is one colour); the declared fill is white at 5%.
- **Type roles beyond the Text table are Derived.** The search field's 18 px comes from a capital; the list title and section header sizes are declared (`text`, `small-text`) and agree with their capitals.
- **States not seen.** Disabled, pressed, focus-visible, loading and error are declared in the stylesheets (and in the tokens) but none was captured; the settings sidebar showed no hover change, so that capture was dropped.
- **Screenshots are 256-colour PNGs.** Read values from tokens.json.

## Do and don't

1. **Do keep one window and put everything in its list.** Apps, commands, files, calculations and fallbacks all arrive as rows in the same list under small section headers; a command with its own view replaces the list in the same window instead of opening another. See [00-root](screenshots/dark/00-root.png), [01-root-calculator](screenshots/dark/01-root-calculator.png) and [11-emoji-grid](screenshots/dark/11-emoji-grid.png).
2. **Do draw state as the foreground at an alpha, never as a colour.** Hover is `selection` at 5%, selection at 10%, controls at 10%, separators at 10%, cards at 2.5%; the same tokens work on any theme's window. See [04-root-hover](screenshots/dark/04-root-hover.png) and [04 light](screenshots/light/04-root-hover.png).
3. **Do let the search field be the whole header.** No box, no border, no focus ring: 18 px text across a 64 pt header, with the caret as the only focus cue. See [02-root-results](screenshots/dark/02-root-results.png).
4. **Do name the primary action and hide the rest behind Command-K.** The action bar always says what Return does; every other action sits in one filterable panel with its key caps. See [06-actions-menu](screenshots/dark/06-actions-menu.png).
5. **Do keep the accent for on-states.** The theme blue fills switches that are on and links; selection, buttons and badges stay neutral or use a hue at 10%. See [20-settings-general](screenshots/dark/20-settings-general.png).
6. **Don't leave an empty result.** A query with no match lists the fallback commands to run it with. See [09-root-no-results](screenshots/dark/09-root-no-results.png).

## Rebuild

From this folder. `read_bundle.py` needs Raycast 2.9.0 installed; `measure.py` needs the full-colour captures, which live outside the repo in `~/.design-systems/raycast-desktop/raw-shots/`; the other builders run from the committed files.

```bash
python3 tools/capture/read_bundle.py   # raw/bundled-themes.json, css-tokens.json, text-styles.json, components-css.json
python3 tools/measure.py ~/.design-systems/raycast-desktop/raw-shots
python3 tools/build_tokens.py          # also writes raw/pixel-check.json
python3 tools/build_style_guide.py
python3 tools/build_components_md.py
python3 tools/crops.py                 # needs Pillow
python3 -m unittest discover -s tools
git status --short .
```

To capture again: compile the helpers into `~/.design-systems/raycast-desktop/bin/` (`swiftc -O -o ~/.design-systems/raycast-desktop/bin/rwin tools/capture/rwin.swift`, the same for `wins.swift` and `mouse.swift`), then run `python3 tools/capture/drive.py dark <step> ...` (its steps are the shot list: `root calc results commands actions appmenu empty emoji settings settings-launcher ...`). Switch the theme in Settings > General for the light pass and put it back after. `python3 tools/capture/quantize.py ~/.design-systems/raycast-desktop/raw-shots` writes `screenshots/`. ## Raycast beside the other desktop packages

Raycast is the one launcher in issue 107's set; the others are coding harnesses, editors and Notion. Like [conductor-desktop](../conductor-desktop/README.md) it is a native shell around web views, but its values were read from the files it ships rather than from a live inspector. It sits under `productivity`; its list, action panel and settings cards are the closest the library has to a command-palette system.

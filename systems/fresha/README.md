# Fresha design reference

A token set and component reference for Fresha's signed-out public surfaces — for building marketplace, booking-boundary and marketing pages in the style of the real thing. It was read from **www.fresha.com** and **partners.fresha.com** on 2026-11-15, signed out, in headless Chromium at 1440 x 900 and 390 x 844. Captured: the consumer home, /user-flow and /auth sign-in shells, the partners.fresha.com professional sign-in (light and its painted dark theme), a public venue profile, the booking wizard at the service-selection boundary, /pricing, /for-business, the legacy /lp category and Singapore browse pages, /help-center, /careers, /blog, /download-app and /cookies, plus 390px passes on home, auth, LP browse and venue.

Fresha is worth a capture because it ships **one Panda CSS system** (`--made-with-panda`) across four different signed-out stacks — the consumer Next.js marketplace, the B2B marketing app, the partner portal's sign-in, and the legacy `/lp/` microsite (its own var-free stylesheet) — with **two parallel token vocabularies**: the hashed Panda vars every host shares (`--cNjPpP` = `colors.foreground.neutral`), mapped back to readable names through the atomic classes, and the partner app's readable `--color-*`/`--typography-*`/`--sizing-*` layer, declared per `data-theme`. The signature look: white pages, near-black `#0d0d0d` ink, giant display headings, and **999px pills** everywhere — the black primary buttons, the split search bar, the category chips — with a violet `#6950f3` accent reserved for the B2B/accent scopes and a `Roobert`/`AktivGroteskVF`/`Tartuffo` font stack. **Boundary:** everything post-login — the customer account and the whole partner app (calendar, sales, clients, marketing) — was never reached; the sign-in fields were typed into then cleared, never submitted; the booking wizard stops at service selection, with Continue never pressed; no search, booking, payment, OAuth, SSO or link-following into gated flows.

## Brief

<!-- brief:start. Generated by tools/brief.py from catalog.json, the tokens file and this README; `make brief` rewrites it. Do not edit. -->

Read this before designing in this style. Take every value from [tokens.json](tokens.json), never from the screenshots; `python3 tools/catalog.py export fresha` prints them all with aliases resolved.

### Principles

1. Do draw buttons, chips and the search bar as full pills (radius 999px)
2. Do put near-black `#0d0d0d` text on white/`#f5f5f5` grounds
3. Do set display headings in Roobert bold
4. Don't give cards heavy borders or shadows
5. Do borrow Fresha's `::before` focus ring

Each rule links the screenshot or crop that shows it, under [Do and don't](#do-and-dont).

## How the values were read

Every colour, radius, length and font on this package is one of three kinds, and `$extensions.source` on each token says which:

- **Declared / resolved css-var** — `css-var <name> … resolved in the <scope> probe`: a custom property in the surfaces' own stylesheets, harvested by `tools/capture/vars.mjs` from the live pages' network sheets (consumer, B2B, partner and LP), re-parsed with CSSStyleSheet and resolved in probe documents carrying the real sheets at 1440 x 900 — once plain (light), once under `data-theme="dark"`, once under `data-theme="accent"`. Hashed Panda vars are mapped back to their readable token names through the atomic class names (`bg-c_background.page`, `bdr_m`, `trs-tmf_easeInOut`); the 120 hashed vars no class names still appear, under `hashed.*`.
- **Measured** — `measured <component> <state> on <page>`: a computed style or bounding box read from the live DOM by `tools/capture/public/measure.mjs`, with a matching crop in `components/crops/`.
- **Motion** — `raw/motion.json`: every element with a transition or animation read at rest on eight public pages, twice per page (`prefers-reduced-motion: no-preference` then `reduce`), by `tools/capture/motion-probe.mjs`.

The light set is the painted palette of every signed-out surface. The dark set is painted evidence on the partner sign-in (`data-theme="auto"` under `prefers-color-scheme: dark`) and declared-only elsewhere; the accent set is a declared scope no signed-out element was observed using. Both facts are marked on the tokens themselves (`$extensions.painted`) — read them before treating dark/accent values as shipped product.

## What to distrust

- **Only the partner sign-in paints dark.** The consumer and B2B sheets declare a full dark palette but nothing signed out sets `data-theme` there; emulating a dark preference leaves every consumer/B2B page light (`live` in raw/css-vars.json). The `dark` set is real where the partner app is concerned, declared-only elsewhere.
- **Accent is declared, not seen.** `[data-theme=accent]` (the violet section theme) exists only in the partner/B2B sheets; no signed-out element carried it at capture.
- **The two vocabularies are the same system spelled twice.** `colors.foreground.neutral` (hashed layer) and `partner.color.foreground-neutral` (named layer) resolve to the same paint; do not mix them as if they were two palettes. The `app.b2b.*` group is the same named layer the b2b sheet declares unscoped on `:root`.
- **Presses are forced.** `pressed` states were read with `CSS.forcePseudoState` — any script-driven mousedown look is uncaptured.
- **The LP microsite is a different system.** Literal values, hashed class names, its own 16px card radius and pill chips; its two panel-offset vars are the only custom properties it declares.
- **The focus ring is a `::before` shadow, not the outline.** Most Panda controls declare a 2px *transparent* outline that never colours in; the visible ring is a `::before` layer (a white 2px + near-black 4px pill shadow) that fades in on focus-visible. Read the Focus block in components.md — a plain outline check misses it.
- **The consumer home's app-install dialog never mounted** during measurement (`appDialog` stayed unmounted); menu, search and the flyout are the captured overlay evidence.

## Coverage

- 15 desktop routes and 4 mobile routes captured signed out (see the catalog's `capture.routes`), every page at 1440 x 900 with `.capture.json` dimension sidecars; the partners sign-in was captured light and under an emulated dark preference, the only surface that paints dark.
- 78 components measured in ~180 states across the four stacks, with element crops in [components/crops/](components/crops): the opened menu drawer, the hero search's suggestions popover, the Business types flyout, the pricing FAQ disclosure, a ticked booking service (unticked again after), filled-then-cleared auth email fields and forced-pressed controls.
- Foundations: the full declared `light`/`dark`/`accent` token sets per stack (painted vs declared marked per token in `$extensions`), the Panda spacing/sizing/radius/duration/easing scales, the Roobert/Tartuffo font roles, and a measured motion pass over 8 pages (reduce honoured on the consumer and LP pages, ignored on pricing, for-business, help, auth and the partner sign-in).
- Missing surfaces and states, each with its reason, are listed under [Gaps](components.md#gaps) in components.md and in the catalog's `capture.gaps`: every post-login surface; submitted-form, search-results, disabled, loading, error and toast states; the booking wizard past service selection; the LP map overlays; individual blog and careers articles; terms.fresha.com pages.
- Icons: layout gap — no standalone SVG set lifted; the Fresha wordmark, search and gallery glyphs, SSO brand marks and category icons are visible in the crops and screenshots.

## Do and don't

- **Do draw buttons, chips and the search bar as full pills (radius 999px)** — the CTAs, the menu button, the category chips and the split search bar all are; text fields are the exception, at 12px corners on both sign-in email fields. ![Primary button](components/crops/b2b-cta-default.png)
- **Do put near-black `#0d0d0d` text on white/`#f5f5f5` grounds** — reserve violet `#6950f3` for accent scopes and B2B highlights, not for primary buttons. ![Accent card](components/crops/review-card-default.png)
- **Do set display headings in Roobert bold** — the captured consumer (64px/68px 700) and B2B (56px/60px 700) heroes both use `Roobert, AktivGroteskVF, sans-serif`; the Tartuffo/Changa/PlayfairDisplay stack is only declared (`--font-display`, the partner `--typography-display-*` vars) — nothing captured paints it. ![Display heading](components/crops/b2b-hero-title-default.png)
- **Don't give cards heavy borders or shadows** — venue, plan and review cards sit on a hairline `#e5e5e5`/`#d3d3d3` ring or a faint `#f0f0ff` accent fill, with `shadows.level1/level2` reserved for popovers. ![Venue card](components/crops/lp-venue-card-default.png)
- **Do borrow Fresha's `::before` focus ring** — most Panda controls fade in a pill-shaped double ring (a `rgb(255,255,255) 0 0 0 2px` + `rgb(13,13,13) 0 0 0 4px` shadow, opacity 0 to 1) on focus-visible instead of colouring their 2px transparent outline; only the LP pages paint a solid 2px outline ring. ![Focus ring](components/crops/shell-login-link-focus-visible.png)

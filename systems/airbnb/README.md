# Airbnb design reference

A token set and component reference for Airbnb's public site — for building travel-gallery, listing and marketing surfaces in the style of the real thing. It was read from **www.airbnb.com**, which geo-redirected to **www.airbnb.com.sg** from this network (the same design system on a regional mirror), on **2026-11-09 and 2026-11-10**, signed out, in headless Chromium at 1440 x 900 and 390 x 844: the home page with its search pill open, the Experiences and Services landings, a Tokyo search-results page, a public listing page the results linked, the Help Centre and the Host landing page, plus the mobile home and results.

The reason Airbnb is worth a capture at all: it is the marketplace reference almost every travel, rental or gallery product is compared against — one brand pink (Rausch, #FF385C) doing all the work over an otherwise black-white-grey surface, the 66px capsule search bar that splits into Where/When/Who, photo-first listing cards with the semi-transparent wishlist heart, hairline-separated surfaces instead of shadows, and a complete set of declared dark values that the site never applies.

## Brief

<!-- brief:start. Generated by tools/brief.py from catalog.json, the tokens file and this README; `make brief` rewrites it. Do not edit. -->

Read this before designing in this style. Take every value from [tokens.json](tokens.json), never from the screenshots; `python3 tools/catalog.py export airbnb` prints them all with aliases resolved.

### Principles

1. Do use the brand pink only for the actions that end a flow.
2. Do make the search bar a 66px capsule.
3. Do round listing photos ~20px and keep cards chrome-free.
4. Do separate surfaces with hairlines and fills, not shadows.
5. Do use medium 500 weight for nearly all UI text.
6. Do draw focus as the white halo + #222 ring shadow on controls
7. Don't add a second accent colour.
8. Don't ship the declared dark set as a finished dark mode.
9. Don't expect filled icon buttons.
10. Don't compress type the way dense apps do.

Each rule links the screenshot or crop that shows it, under [Do and don't](#do-and-dont).

## How the values were read

Every value came off the running signed-out site in headless Chromium:

- **Tokens.** [tools/capture/vars.mjs](tools/capture/vars.mjs) walked `document.styleSheets` in every page's context at 1440 and wrote every custom property to [raw/css-vars.json](raw/css-vars.json), tagged with the declaring rule's selector (`:root`, the `.c12bynq4` always-dark class, the `.c1r7ywgw` prefers-dark block, the RTL `[dir=rtl]` block) and which set it lands in. [tools/build_tokens.py](tools/build_tokens.py) sorts those into `core.palette`, the semantic `color.*` names, the `radius`/`space`/`motion`/`elevation`/`material`/`type`/`gradient` scales, and the `measured` group the component readings add, then writes light and dark sets that are structurally the same names with each theme's declared value.
- **Components.** [tools/capture/public/measure.mjs](tools/capture/public/measure.mjs) opens each route in a fresh context, hides the load-time coachmarks and dimmers without clicking them, then reads `getComputedStyle`, painted layers and boxes per element in the default, hover, focus-visible and a CDP-forced pressed state, and screenshots the element for [components/crops/](components/crops). The "Where" search segment is clicked open and measured before Escape — the only interaction that toggles local UI without submitting. Results live in [raw/components-computed.json](raw/components-computed.json) and [raw/measurements.md](raw/measurements.md).
- **Screenshots.** [tools/capture/public/public.mjs](tools/capture/public/public.mjs) takes viewport and full-page shots per route, then [tools/capture/quantize.py](tools/capture/quantize.py) posterises them to 256 colours for the repo (the full-colour originals stay out of the tree).
- **Fonts.** The family list came from the same stylesheet walk plus `document.fonts` on the pages; only Airbnb Cereal VF is loaded, as variable faces.

Nothing was signed into, searched, booked, messaged, created or uploaded. The public surface was enough: the capture reads what a signed-out visitor sees, which on this network is the airbnb.com.sg mirror.

## What to distrust

- **Dark is declared, never applied.** The site pins `data-color-scheme="light"` on every root; the `dark` set holds the values the stylesheets declare for the always-dark class and the prefers-dark rebinds, not anything a visitor sees. Do not treat the dark theme as evidence of a shipped dark mode.
- **The SG mirror.** Readings came from www.airbnb.com.sg after geo-redirect: the design system is identical (same stylesheets, same tokens), but the content is Singapore-market — currencies show SGD, the Tokyo search was picked because it is a stable public query, and a different network may see different rails and coachmarks.
- **The wishlist heart is not white.** It paints as a black-at-50% glyph with a white stroke over the photo (`measured.heart-idle`, `measured.heart-stroke`); a real tap opens a sign-up sheet, so its pressed state was CDP-forced, never clicked.
- **Coachmarks are hidden, not dismissed.** The `home-*-default` and search/room default shots have first-load dialogs and dimmers hidden by CSS so the page underneath is measurable; `*-modal` shots keep them. Nothing was clicked away.
- **Some readings are ancestors.** Where a component's root paints transparent, the entry names the nearest painted ancestor (several cards read `#dddddd` from the photo holder behind them — that is the element that paints, not the card's own fill).
- **Rounded corners on photos.** The listing-photo rounding is a measured 20px at desktop width — that is the scale's `xlarge` step (`core.radius.xlarge`), so take the token rather than an off-scale literal.
- **Three components are missing on the current pages.** The header has no language-globe control (an earlier run's `header-globe` readings were the Search submit, since removed), and the promo strip with its Claim button is a per-listing feature the captured room does not show; `promo-strip` and `promo-claim` are flagged `missing`, not re-published as fresh. `rail-arrow`'s keyboard focus could not be driven, so its focus-visible state is an error entry, not a measurement.
- **No icons.** Airbnb's glyph set is its artwork; this package keeps the text components that show the glyphs in context but no standalone SVG files (declared under `layoutGaps` in catalog.json).
- **Readings past a masked bot signal.** Every committed screenshot and reading was taken with `navigator.webdriver` masked, which airbnb.com reads to wall automated sessions on some routes. The capture script no longer masks it (not run since); a recapture may record those routes as walled. Both scripts now check each page for a bot wall before any screenshot or reading, and record a walled route as failed with its earlier evidence left in place.
- **No layout.json.** Page geometry comes from the measured component boxes in `raw/components-computed.json` and the screenshots; there is no separate layout dump.

## Fonts

**Airbnb Cereal VF** is the only family: a commercial variable face Airbnb self-hosts, loaded weight 300–800 as four `font-face` files (regular/bold, latin/CJK). Every style guide and token falls back to the system sans because Cereal is licensed to Airbnb — the style guide shows Inter as the nearest free stand-in. The `type.*` tokens record the real family string (`"Airbnb Cereal VF"` and its full fallback list), so designs that can load Cereal get it.

## Do and don't

1. **Do use the brand pink only for the actions that end a flow.** #FF385C (`color.bg.brand.*`/`palette.rausch`) marks Search submit, Reserve and save confirmations; everything else is black on white. See [search-submit-default](components/crops/search-submit-default.png) and [host-cta-default](components/crops/host-cta-default.png).
2. **Do make the search bar a 66px capsule.** The Where | When | Who pill (`radius` 100px measured, hairline dividers) is the site's signature. See [search-bar-default](components/crops/search-bar-default.png) and [home-light-default](screenshots/home-light-default.png).
3. **Do round listing photos ~20px and keep cards chrome-free.** The photo radius is the measured `core.radius.xlarge` 20px; the badge pill and heart float on the photo while title, price and rating sit on the page. See [listing-card-default](components/crops/listing-card-default.png).
4. **Do separate surfaces with hairlines and fills, not shadows.** `#ddd`/`#ebebeb` lines divide; real shadows are reserved for floating layers (`elevation.high`, the `elevationN` steps). See [reserve-card-default](components/crops/reserve-card-default.png) and [home-light-default](screenshots/home-light-default.png).
5. **Do use medium 500 weight for nearly all UI text.** Semibold is kept for the largest titles only. See [section-title-default](components/crops/section-title-default.png) and [listing-card-default](components/crops/listing-card-default.png).
6. **Do draw focus as the white halo + #222 ring shadow on controls**, and the 2px outline 4px out on the category tabs. See [filter-chip-focus-visible](components/crops/filter-chip-focus-visible.png) and [tab-active-focus-visible](components/crops/tab-active-focus-visible.png).
7. **Don't add a second accent colour.** The support ramps are dataviz/status furniture, not UI colour. See [search-light-default](screenshots/search-light-default.png) and [host-light-default](screenshots/host-light-default.png).
8. **Don't ship the declared dark set as a finished dark mode.** It is an unapplied declaration; nothing paints it today — the evidence is `themeChecks` in [raw/css-vars.json](raw/css-vars.json) and the light-pinned surface in [home-light-default](screenshots/home-light-default.png).
9. **Don't expect filled icon buttons.** The heart and friends are bare glyphs; the heart is a black-at-50% glyph with a white stroke so it reads over photos. See [card-heart-default](components/crops/card-heart-default.png).
10. **Don't compress type the way dense apps do.** The body scale runs 14–18px with 18–28px line-heights. See [room-title-default](components/crops/room-title-default.png) and [listing-card-default](components/crops/listing-card-default.png).

## Rebuild

The kit under [tools/capture/](tools/capture) re-reads the live site; the builders re-derive the package from `raw/`:

```sh
cd systems/airbnb
PLAYWRIGHT=~/.design-systems/pw/node_modules/playwright/index.mjs \
  node tools/capture/public/public.mjs        # page screenshots into ~/.design-systems/airbnb/raw-shots (RAW)
PLAYWRIGHT=... node tools/capture/vars.mjs    # raw/css-vars.json
PLAYWRIGHT=... node tools/capture/public/measure.mjs   # raw/components-computed.json + crops
python3 tools/capture/quantize.py ~/.design-systems/airbnb/raw-shots   # screenshots/; originals stay out of the repo
node tools/capture/public/build-measurements.mjs       # raw/measurements.md
python3 tools/build_component_tokens.py       # raw/component-tokens.json from the readings
python3 tools/build_tokens.py                 # tokens.json from component-tokens.json + css-vars.json
python3 tools/build_components_md.public.py   # components.md
python3 tools/build_style_guide.py            # style-guide.html
```

Then `make design-md` at the repo root refreshes [DESIGN.md](DESIGN.md), and `make check` re-grades the package.

# Saint Laurent design reference

A token set for Saint Laurent's public signed-out storefront. Read from www.ysl.com on 2026-11-19, signed out. ysl.com redirects to www.ysl.com/en-sg/. That Singapore English storefront is what this package captures.

Surfaces: home, the Highlights menu, search, Women ready-to-wear, one product page, Stores, and Client service. The preview viewport measured 1169 by 731 CSS pixels at devicePixelRatio 2. One light theme. No screenshots: the preview browser stopped producing frames, and headless Chromium was denied.

The storefront paints with `--color-*`, `--sans`, and `--spacer-*`. The page token is white. Text is black. The buy button is a black rectangle with square corners. Type on the chrome is 12px Helvetica_Reg, uppercase.

## Do and don't

1. **Do keep the page white and the wordmark black on listing pages.** On the home hero the header type is white. See the header readings in [raw/components-computed.json](raw/components-computed.json).
2. **Do use a black square button for the buy action.** Add to Cart is `#000000`, white label, 36px tall, radius 0. See [style-guide.html](style-guide.html).
3. **Do set chrome type at 12px uppercase.** Nav, titles, prices, and buttons share that size in Helvetica_Reg. See [tokens.json](tokens.json).
4. **Do underline fields instead of boxing them.** Search, newsletter fields, and the country select use a 1px black bottom border and radius 0. See [components.md](components.md).
5. **Don't invent a dark theme.** `color-scheme` computed `normal`. No theme toggle was found.
6. **Don't press Add to Cart, Login, or Send.** Those controls were measured and never used to buy, sign in, or subscribe.
7. **Don't treat the error red as a button fill.** `--color-text-error` is `#b32519`. The measured buy button is black.

## How the values were read

Custom properties were read from computed style on `documentElement` at `https://www.ysl.com/en-sg` in the T3 preview browser, and confirmed on the client-service URL in the same tab. Colour, space, and easing tokens are those computed `--color-*`, `--spacer-*`, and `--ease*` values, converted to hex or px where the token format needs it. Component colours and sizes were read from computed style on the live DOM: header, nav hover, search, Add to Cart (including a synthetic hover and a real focus), size rows, filter Apply and Clear, newsletter fields, the civility radio, and the product title and price.

The region bar was dismissed with Continue to Singapore, which stays on /en-sg. The OneTrust preference centre was closed without Accept all. The newsletter panel was opened and not submitted. No name, email, card, or phone was entered.

The T3 preview browser returned "The browser is not producing screenshot frames". Headless Chromium then got HTTP 403 Access Denied on the same public URL. Screenshots were not invented.

## What to distrust

Nav hover colour (`#666666`) came from a synthetic mouseover. The 2px grey underline on `::after` was measured in that same state. Add to Cart hover did not change the fill.

The cookie Accept button is OneTrust (`Helvetica_Regular`, 2px radius). It is not the storefront button and is not a token.

`--swiper-theme-color` is `#007aff`. It is the carousel library default, not a Saint Laurent control colour, so it is not in the tokens.

Copperplate is declared in `--copperplate` and was not the computed font of any measured control.

`prefers-reduced-motion` turns off the Algolia panel transition. The reduce emulation was not run.

The phone number printed in the footer was not copied into this package.

## Fonts

Helvetica_Reg is the UI face, with weights 400 and 700 on the page. Copperplate is a declared token. Both are proprietary and are not in the package. The tokens name Helvetica_Reg, then Helvetica, Arial, sans-serif. The wordmark is the header SVG in [icons/wordmark.svg](icons/wordmark.svg).

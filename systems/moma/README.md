# MoMA design reference

A token set and component reference for the Museum of Modern Art's public site. Read from moma.org on 2026-11-19, signed out, in headed Chrome at 1440 x 900 and 390 x 844. Surfaces: home, visit, exhibitions, one exhibition, the calendar, the collection index, the membership marketing page at membership.moma.org, and the signed-out login card. No ticket was bought, no card was entered, no donation was completed.

MoMA ships a token layer in `sol.css`: `--color--brand--1` through `--color--brand--12`, a gray ramp `--color--gray--111` to `--color--gray--eee`, eighteen `--color--membership--*` colours, and motion durations. The public site paints one light theme. Type is MoMA Sans. The root font size is 10px, and type steps are unitless sizes times `0.1rem`. Tickets is brand blue `#00b7f2`. Actions are black on white, square corners.

### Principles

1. Do keep the page white and the wordmark black.
2. Do use brand blue only for Tickets.
3. Do set type in MoMA Sans at a 10px root.
4. Do keep corners square.
5. Do paint membership tiers from the membership ramp.
6. Don't invent a dark theme.
7. Don't follow Tickets, Donate, or Join.

## How the values were read

- **Declared, then resolved.** `sol.css` on www.moma.org declares the colour, type, spacing, focus, and motion custom properties. [raw/css-vars.json](raw/css-vars.json) lists the `:root` values. The same names were read with `getComputedStyle(documentElement)` in the T3 preview tab and again in headed Chrome: `--color--black` `#000`, `--color--brand--10` `#00b7f2`, `--page-spacing` `3.2rem` at 1440, `--header-height` `16.6rem`.
- **Computed components.** Headings, nav, Tickets, Donate, the search field, membership cards, and Join were read with `getComputedStyle` in headed Chrome at 1440 x 900, `devicePixelRatio` 1. Phone shots used 390 x 844 at 2x.
- **Headed Chrome.** The first launch loaded www.moma.org with no Cloudflare challenge. A later launch of `/auth/login` returned "Just a moment...". That launch stopped. No headless browser was started.
- **Cookie bar.** Left in place for [home-light-cookie](screenshots/home-light-cookie.png), then hidden with CSS. Accept was never clicked.
- **Motion.** `sol.css` declares `--motion--transition--duration` 100ms, colour and transform at 200ms, and `--motion--animation--duration` 4000ms. `prefers-reduced-motion` does not appear in `sol.css` or `main.css`.

## What to distrust

- Session colour is not one brand step. `html` carries `$color/session:N`, and `--color--session` aliases that step. One homepage read resolved `#ff8f1c` (brand 5). A later read resolved `#00b7f2` (brand 10). The Tickets fill is the class `$color/background:brand:10`, which is stable.
- Spacing in the first `:root` block is `2.4rem`. The live 1440px page overrides `--page-spacing` to `3.2rem` and `--page-spacing--fixed` to `4.8rem`. Tokens use the live values.
- Type roles are the computed sizes on the public pages, named after MoMA's `$typography/size:*` classes. They are not a separate declared type-token group.
- `core.radius.pill` is a stand-in for the Help chip's full pill, seen on the login screenshot, and is labelled Reconstruction. It is not a custom property. `light.color.border` is the login card's 1px black border as seen in that screenshot; no computed reading of it was saved, so it is labelled Observed.
- Screenshots are 256-colour PNGs. Read colours from tokens, not from the images.
- The street address on the visit page is published museum copy. It is not a private address.
- `/members/` is a 404 (Ruscha's *OOF*). The membership marketing page is `https://membership.moma.org/`.

## Fonts

MoMA Sans, and MoMA Sans Condensed, served as woff2 from `/dist/dist/moma-sans/`. Weights in the `@font-face` rules run from 100 to 900, with italics. The computed body stack is `"MoMA Sans", "MoMA Sans", Helvetica, sans-serif`. The font files are proprietary and are not in this package. Fall back to Helvetica, then sans-serif.

## Do and don't

1. **Do keep the page white and the wordmark black.** The header sits on white. The mark is black MoMA Sans, not the ticket blue. See [home-light-default](screenshots/home-light-default.png).
2. **Do use brand blue only for Tickets.** `#00b7f2` (`light.color.accent`) is the ticket control. Donate is `#eeeeee`. Actions such as Plan your visit and Join or renew are black. See [home-light-default](screenshots/home-light-default.png) and [join-default](components/crops/join-default.png).
3. **Do set type in MoMA Sans at a 10px root.** Display is 60px weight 900 with tracking `-0.02em`. Body is 18px weight 400. See [visit-light-default](screenshots/visit-light-default.png).
4. **Do keep corners square.** Cards, buttons, and the ticket control measure `border-radius: 0`. See [membership-card-access](components/crops/membership-card-access.png).
5. **Do paint membership tiers from the membership ramp.** Access is `#d5faea`. Explore is `#f6c1e6`. Those are `--color--membership--6` and `--color--membership--15`. See [membership-light-default](screenshots/membership-light-default.png).
6. **Don't invent a dark theme.** The public sheets have no `prefers-color-scheme` and no theme toggle. See [raw/css-vars.json](raw/css-vars.json).
7. **Don't follow Tickets, Donate, or Join.** Those leave the measured pages for a purchase or a payment. They were not pressed.

```bash
cd systems/moma
python3 tools/build_tokens.py
python3 tools/build_style_guide.py
```

Screenshots were taken by `tools/capture/public/moma-capture.mjs` in headed Chrome, then quantized with `tools/capture/quantize.py`.

Each raw file has one writer. `moma-capture.mjs` writes `capture-readings.json`, `moma-membership.mjs` writes `states.json` (the committed file is its output), and `moma-states.mjs` writes `login-states.json`. No script in `tools/` writes `membership-components.json`. Before, `moma-states.mjs` also wrote `states.json`, so whichever ran last replaced the other's readings. `moma-states.mjs` no longer presses Continue on the empty login form (that submits it), no longer clicks at a fixed point, and opens the Membership menu only through its menu button. The login validation state is not captured.

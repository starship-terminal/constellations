# GitHub Mobile design reference

A token set and component reference for GitHub Mobile, GitHub's iOS app for notifications, issues, pull requests, code and Copilot agent sessions. Use it to build a native iOS app (SwiftUI) for developer work that borrows its proportions and structure: grouped cards on a near-black or pale grey page, full-bleed lists on the card colour, a floating iOS 26 glass tab bar and nav buttons, grey neutral buttons, coloured icon tiles that mark each kind of object, filled state badges, and monospace diffs with GitHub's line and syntax colours. It was captured from the shipped app on iOS 26 on 2026-10-24, through iPhone Mirroring, signed in to the owner's account (Copilot Pro). The app version was not recorded. Dark is the phone's own appearance with the app's Settings > Appearance on Automatic; light was set with Settings > Appearance > Light and put back to Automatic afterwards. The device screen is 390 x 844 pt; the captures are 812 x 1780 px at 2 px per pt, with the screen at (16, 76) inside each PNG.

It holds 35 captures: 23 in dark (Home, Inbox and its Filters sheet, Explore, Copilot, search, repository results, a repository page and its menu, Issues and a pop-up filter, an issue, Pull Requests, a PR, Files Changed, an empty list, the profile, Settings, Code Options, Appearance) and 12 of the same screens in light. Repository, issue and PR screens use the public repository primer/design. Other GitHub users' handles and avatars are masked in the screenshots and the crops cut from them: the followed user on the Explore activity card, a person who owns a repository in the search results, the issue and pull request authors, and the reviewer avatars in the pull request list ([tools/redact-rules/github-ios.json](../../tools/redact-rules/github-ios.json)). The owner's own profile (name, handle, email, links), notifications and agent sessions stay, and so do organisations and the repository, issue and PR content. No credentials or other personally identifiable data appear.

This package contains no GitHub code, and none of its artwork has been redrawn. The screenshots and the visual system they show are GitHub's ([docs/RIGHTS.md](../../docs/RIGHTS.md)). Borrow structure and proportions, not the Octocat, the icons or the brand colours.

### Principles

1. Do put cards on the page and lists on the card colour.
2. Do keep everyday buttons grey and save colour for meaning.
3. Do give each kind of object one tile colour and keep it everywhere.
4. Do show an issue or PR's state as a filled capsule with an icon and a white label.
5. Do float navigation as glass over the content.
6. Don't outline cards.

Each rule links the screenshot or crop that shows it, under [Do and don't](#do-and-dont).

## How the values were read

GitHub Mobile is a native app, so there is no CSS. Each screen was captured as the iPhone Mirroring window alone (`tools/capture/native/shot.sh`: `screencapture -l` on the window, then converted from Display P3 to sRGB). `tools/measure.py` reads the full-colour captures, which stay outside the repo, and writes [raw/readings.json](raw/readings.json): 221 readings under 130 names, most in both themes. `tools/build_tokens.py` maps them to tokens. The committed screenshots are the same captures quantised to 256 colours, so a reading's box can be checked against them, but no value was read from the quantised copies.

| Method in readings.json | Label in tokens.json | What it gives |
|---|---|---|
| `fill`, the box's dominant colour covering 90% or more of it | Sampled | An exact flat surface |
| `fill` under 90% (glass, a tile behind its glyph, a one-pixel caret) | Derived | The dominant pixel; the description gives the share |
| `text`, the anti-aliased pixel furthest from the fill | Sampled (text) | A glyph colour; the true value is the same or slightly further from the fill |
| `bbox`, `extent`, `find` | Sampled | Sizes and positions exact to the pixel (half a point) |
| `diag`, the inset along a corner's diagonal | Derived | A corner radius, plus or minus 2 pt |
| `cap`, a capital's ink height less a pixel of anti-aliasing, at a 0.72 em cap height | Derived | A font size, plus or minus 1 pt |
| `lines`, the pitch of text bands | Derived | A line height |
| By eye | Derived | Font weights, the branch pill's 3 pt corner |
| Not determinable | Not captured | The font families |

Scale steps (spacing, the 26 pt card radius, the 14 pt button radius) are Derived from the readings named in each token's description. Where a role was read in dark only (menus, the search placeholder and caret, the Open badge), the light token is Derived and says what it was filled from.

## What to distrust

- **The fonts.** Not determinable from pixels. The text face is a neo-grotesque close to the iOS system face, and code, diffs, branch names and search qualifiers use a monospace face. `fontFamily.base` is `system` and `fontFamily.mono` is `system-mono`, both Not captured.
- **Glass.** The tab bar, nav buttons, search field, filter chips, menus and the dark New Session button are iOS 26 glass. Their tokens are readings over an empty page (`surface.glass`) or over the content behind (`surface.menu`, which picks up the page under the menu). Use the system material, not a flat fill.
- **Radii are estimates**, plus or minus 2 pt: cards 25.6, Add Favorites 13.7 to 15.4, Star 11.9 to 15.4, the status card 11.9, tiles 6.8. The branch pill's 1 px rim stops the diagonal reading, so its 3 pt corner is read by eye.
- **Type sizes are estimates**, plus or minus 1 pt, from cap heights at an assumed 0.72 em. Card row titles read 16 pt and Settings rows 17 pt; that one-point gap is inside the error. Weights are judged by eye. Only multi-line blocks have line heights.
- **Light covers 12 of 23 screens.** The menus, the Filters sheet, search focus, Issues, Pull Requests, the issue page and the empty list were captured in dark only; `surface.menu`, `text.placeholder`, `focus.caret` and `success.emphasis` are Derived in light from the role each description names.
- **Two background systems.** Code Options is a system grouped table: its page is the iOS grouped background (#000000 dark, #F2F2F6 light) and its section headers the system grey, not GitHub's page colour and greys. `bg.grouped` and `text.sectionHeader` keep it apart from `bg.page`.
- **Some state colours change between themes more than the rest.** The Merged badge is a light purple in dark (#AC7DF8) and a deeper one in light (#8251E0); the New Session button is grey glass in dark and near-black ink in light. Both are readings, not mistakes.
- **Tiles under glyphs.** Most icon-tile readings cover part of the white glyph, so tiles under 90% share are Derived. The colour is still the tile's.
- **Primer.** GitHub publishes its web colours as Primer. Nothing here was taken from it, and no value was checked against it.
- **No pressed states, no motion, no keyboard, no loading.** The captures are stills made with clicks; iPhone Mirroring hides the software keyboard; [09-repo-results-loading-spinner](screenshots/dark/09-repo-results-loading-spinner.png) is pixel-identical to [10-repo-results-list](screenshots/dark/10-repo-results-list.png), so the spinner had gone before the capture.
- **Screenshots are 256-colour PNGs.** Flat UI colours survive exactly; glass, photos and the diff tints band slightly. Read values from tokens.json.

## Do and don't

1. **Do put cards on the page and lists on the card colour.** Home, Explore, Copilot and Settings are grouped cards on `color.bg.page`; Inbox, Issues, Pull Requests and the repository, issue and PR pages are full-bleed rows on `color.bg.list`, which is the card colour. See [01-home](screenshots/dark/01-home-my-work-favorites-empty-shortcuts.png), [03-inbox](screenshots/dark/03-inbox-chips-banner-unread-rows.png) and [01-home light](screenshots/light/01-home-my-work-favorites-empty-shortcuts.png).
2. **Do keep everyday buttons grey and save colour for meaning.** Add Favorites, Get started, Star, fork and watch are `color.surface.button`; blue marks links, unread state, Configure and switches; purple marks Copilot and merged work. See [01-home](screenshots/dark/01-home-my-work-favorites-empty-shortcuts.png), [11-repo-page](screenshots/dark/11-repo-page-archived-banner-star-button-rows.png) and [06-copilot](screenshots/dark/06-copilot-promo-card-status-badges.png).
3. **Do give each kind of object one tile colour and keep it everywhere.** Issues are a green tile on Home and on a repository, Pull Requests blue, Discussions purple, Starred yellow, Organizations orange. See [01-home](screenshots/dark/01-home-my-work-favorites-empty-shortcuts.png), [11-repo-page](screenshots/dark/11-repo-page-archived-banner-star-button-rows.png) and [20-profile](screenshots/dark/20-profile-status-achievements-rows.png).
4. **Do show an issue or PR's state as a filled capsule with an icon and a white label.** Open is green, Draft grey and Merged purple; Locked sits beside them as a muted capsule, and branch names follow as monospace pills. See [15-issue-page](screenshots/dark/15-issue-page-open-locked-badges-comment.png), [17-pr-page](screenshots/dark/17-pr-page-draft-branch-pills-diffstat.png) and [05-explore](screenshots/dark/05-explore-activity-card-merged-badge-code.png).
5. **Do float navigation as glass over the content.** The tab bar, back and action buttons, the search field and the filter chips are glass; lists scroll under them. See [13-issues](screenshots/dark/13-issues-list-filter-chips-labels.png), [02-home-scrolled](screenshots/dark/02-home-scrolled-blur-header-fab.png) and [07-search-focused](screenshots/dark/07-search-focused-empty-qualifier-chips.png).
6. **Don't outline cards.** Cards separate from the page by fill alone; hairlines appear only between rows and between list sections. See [21-settings](screenshots/dark/21-settings-grouped-values-new-badge.png), [21-settings light](screenshots/light/21-settings-grouped-values-new-badge.png) and [08-search-typed](screenshots/dark/08-search-typed-scope-rows.png).

## Rebuild

From this folder. `measure.py` needs the full-colour captures, which live outside the repo in `~/.design-systems/github-ios/raw-shots/`; the other builders run from the committed files.

```bash
python3 tools/measure.py ~/.design-systems/github-ios/raw-shots
python3 tools/build_tokens.py
python3 tools/build_style_guide.py
python3 tools/build_components_md.py
python3 -m unittest discover -s tools
git status --short .
```

`tools/capture/quantize.py <raw-shots>` and `tools/crops.py` (both need Pillow) rewrite `screenshots/` and `components/crops/`. The raw shots are unmasked, so after `quantize.py` and before `crops.py`, mask the screenshots again from the repository root: `python3 tools/redact_images.py apply systems/github-ios --rules tools/redact-rules/github-ios.json --patterns ~/.design-systems/cleanup-redact.json --only 'screenshots/**'` (the patterns file's allow list keeps the owner's own email on the profile screen from being painted). `apply` keeps each image's palette, its transparency and every pixel outside the boxes. `crops.py` cuts the crops from the masked screenshots. A rebuild that changes nothing proves the outputs still match their inputs. From the repository root, `make design-md` regenerates DESIGN.md and the Brief.

## Use in SwiftUI and Figma

A colour asset per semantic key, with a light and a dark variant, maps one to one: the key names (`color.surface.card`) are the contract, and both sets have the same keys. Sizes and radii in `core` are points. Use the system components for the glass tab bar, nav buttons, menus, sheets, switches and pop-up selects rather than redrawing them; give the grouped cards the 26 pt continuous corner. In Figma, import tokens.json with Tokens Studio and pick the Light or Dark theme.

# Raster design reference

A token set for Raster's public signed-out surfaces, for building a dark marketing page in the style of the real thing. It was read from **raster.app** on **2026-11-19** and refreshed on **2026-11-21**, signed out. Desktop captures are 1440 x 900 at 1x. The phone pass is 390 x 844 at 2x. The control map is [site-tree.md](site-tree.md). Captured: `/`, `/product`, `/pricing`, `/blog`, `/design`, `/changelog`, `/changelog/2026-11-20`, `/docs` (dark, then the public theme toggle to light), `/privacy`, `/terms`, and the dead public share at `/s/q7Wm2xKp`.

Raster is a digital asset manager. The marketing site paints one dark theme: a black page, a zinc canvas (`#27272a`), and Raster Red (`#ff2f66`) on the actions. The hero's first line clips a cinema-lens gradient to the text. The wordmark is Raster Neue. Body and buttons are the system sans at a 14px root. Docs at `/docs` loads dark and can be switched to light with the public theme control. **Boundary:** the 2026-11-21 refresh is public only. `/sign-in` shows Continue with Google and Email link to sign in. Both were photographed and not used. The email field stayed hidden and empty. `/sign-up` redirects to the same wall. No card, phone, or checkout was entered. The signed-in library was not reached. `login-extracted` stays `not-started`.

### Principles

1. Do put Raster Red on the action.
2. Do clip the cinema gradient to one line.
3. Do keep the page black and the canvas zinc.
4. Do use 5.25px on controls.
5. Do keep Raster Neue on the wordmark.
6. Don't treat docs as a light marketing theme.
7. Don't invent a hover colour.
8. Don't follow sign-in into the library.

Each rule links the screenshot or crop that shows it, under [Do and don't](#do-and-dont).

## How the values were read

Computed styles were read in the T3 preview tab on `https://raster.app/` (innerWidth 1169, devicePixelRatio 2, `html.dark`, color-scheme dark) and again on 2026-11-21. The preview pane stopped painting frames, so the public pages were measured and shot in headless Chromium with `colorScheme: dark`. That pass applied `html.dark` on its own. `/docs` loaded dark and the public theme control switched it to `html.light`.

Custom properties came off the root. Control values came off the elements that were on screen: `.button-primary`, `.button-secondary`, `.input`, `.tag`, `.tabs`, the navbar, the hero spans, and the pricing titles. The design playground at `/design` publishes the gray ramp and the button, tag, field, and tab specimens. Raster Neue is one variable font, `/site-assets/fonts/raster-neue.woff2`, weight 100 to 900. It is not vendored.

## What to distrust

The focus ring on Get started is the browser default (`rgb(153, 200, 255) auto 1px`), not a product token. Hover on that button did not change the computed background. Disabled is opacity 0.5 on the same red. The oklab white tints (8%, 10%, 15%, 18%) are computed as written; they are not rounded to hex. The hero gradient is a background-clip on the first line, so a screenshot of that line is not a flat colour. Phone shots are 780 x 1688 because devicePixelRatio was 2. The hero video had not painted a frame when the 2026-11-21 shots were taken, so that frame is black. Docs light is a theme the docs shell can switch to. It is not a light mode of the marketing page. The 2026-11-19 crops were kept. They were not reshot.

## Fonts

Raster Neue is the product face (wordmark, nav, pricing titles, docs headings). It ships as a woff2 from the site. The licence was not published on the pages that were read, so the file is not in this package. Body, buttons, and fields compute to the system sans (`-apple-system, system-ui, Segoe UI, Roboto, Helvetica Neue, Noto Sans, Arial`). Docs body computes to `ui-sans-serif`. The mono stack is declared (`ui-monospace`) and was not used on the pages that were measured.

## Do and don't

1. **Do put Raster Red on the action.** `#ff2f66` is Start for free, Get started, and Contact Sales. See [home-dark-default](screenshots/home-dark-default.png).
2. **Do clip the cinema gradient to one line.** The first hero line is the only gradient text. The lines under it are near-white. See [hero-heading](components/crops/hero-heading-default.png).
3. **Do keep the page black and the canvas zinc.** Body is `#000`. The root is `#27272a`. See [home-dark-default](screenshots/home-dark-default.png).
4. **Do use 5.25px on controls.** Buttons, fields, and the sign-in email share that radius. Tags are pills. See [button-primary](components/crops/button-primary-default.png).
5. **Do keep Raster Neue on the wordmark.** Nav labels and plan titles use it. Body and buttons use the system sans. See [navbar](components/crops/navbar-default.png).
6. **Don't treat docs as a light marketing theme.** `/docs` loads dark and can be switched to light. See [docs-dark-default](screenshots/docs-dark-default.png) and [docs-light-default](screenshots/docs-light-default.png).
7. **Don't invent a hover colour.** The primary button's computed background did not change on hover. Disabled is the same red at 0.5 opacity. See [button-primary-disabled](components/crops/button-primary-disabled.png).
8. **Don't follow sign-in into the library.** Continue with Google and Email link to sign in were photographed and not used. See [auth-dark-default](screenshots/auth-dark-default.png).

## Rebuild

```bash
python3 tools/build_tokens.py
python3 tools/build_style_guide.py
python3 ../../tools/catalog.py design-md raster
```

Run the last command from the repository root, or the first two from `systems/raster`.

Both builders reproduce their committed files byte for byte; `tools/test_rebuild.py` checks it. The docs surface is the `docs` set (not `light`), the name the style guide and the catalog entry read.

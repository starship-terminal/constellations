# Asana design reference

A token set and component reference for Asana's public marketing site (https://asana.com), a Next.js site for a work/project-management product. Use it to build a marketing or product surface that borrows its look: a near-white page, near-black ink `#0d0d0d` on headings and `#3d3d3d` body text, TWK Lausanne (a webfont, Helvetica fallbacks) throughout, 3px control radii, near-black `#0d0d0d` primary buttons that lift to `#3d3d3d` on hover, `#f3f3f3` panels, `#cfcfcf` hairlines, and a full shipped design token layer — colour ramps (`--black-20..1100`, `--blue-0..980`, `--coral-*`, `--bright-*`), `--lightmode-*` semantic roles, a 16px-base `--spacing-*` scale, `--media-*` breakpoints, 12-column grid, `--shadow-10..40` and `--transition-*` durations. It was captured signed out, in headless Chromium at 1440 x 900 (mobile at 390 x 844) on 2026-11-21.

The site tree is [site-tree.md](site-tree.md): which header, menu and footer control opens which page. Screenshots cover that public tree at desktop, plus phone captures of home, pricing, product, sales, signup, resources, templates, enterprise and apps. Component crops are from the 2026-11-11 measure pass (32 of 33 entries measured). The product itself (app.asana.com) sits behind sign-in. On 2026-11-21 `https://app.asana.com/-/login` loaded a public login shell (Google, Microsoft, or email) and that branch stopped. No email was typed. No form was submitted. The site ships a full `--darkmode-*` role set in its CSS, but every captured route paints light. The dark set is declared evidence, not a painted page (see [components.md](components.md) > Gaps).

This package contains no Asana code, and none of its artwork has been redrawn. The screenshots, product imagery and visual system they show belong to Asana ([docs/RIGHTS.md](../../docs/RIGHTS.md)). Borrow structure and proportions, not the logo, artwork or brand assets.

## Brief

<!-- brief:start. Generated by tools/brief.py from catalog.json, the tokens file and this README; `make brief` rewrites it. Do not edit. -->

Read this before designing in this style. Take every value from [tokens.json](tokens.json), never from the screenshots; `python3 tools/catalog.py export asana` prints them all with aliases resolved.

### Principles

1. Do keep the page near-white and the ink near-black.
2. Do use near-black for primary actions.
3. Do pair TWK Lausanne display lines with its Helvetica fallbacks.
4. Do radius 3px on controls, 100px on CTA pills.
5. Do space on the 16px base.
6. Don't ship the marketing style as the app.

Each rule links the screenshot or crop that shows it, under [Do and don't](#do-and-dont).

### Using tokens

| Role | light | dark |
|---|---|---|
| page | #ffffff `light.page` | #1e1f21 `dark.page` |
| surface | #f3f3f3 `light.surface.default` | #252628 `dark.surface.default` |
| text | #3d3d3d `light.text.default` | rgba(255, 255, 255, 0.85) `dark.text.default` |
| muted | #6e6e6e `light.muted` | rgba(255, 255, 255, 0.55) `dark.muted` |
| accent | #0d0d0d `light.accent.default` | #f5f4f3 `dark.accent.default` |
| border | #cfcfcf `light.border.default` | rgba(217, 217, 217, 0.3) `dark.border.default` |

Fonts: `core.fontFamily.ui` is TWK Lausanne, then 3 fallbacks. Scales, counted as [DESIGN.md](DESIGN.md) holds them: 5 type styles (`core.typography`), no radius steps under `core.radius`, 13 spacing steps (`core.spacing`).

### Using components

Read [components.md](components.md) for the component inventory; [patterns.md](patterns.md) for how components combine into screens; 80 element crops in [components/crops/](components/crops); [style-guide.html](style-guide.html), which renders every token and the main components.

## How the values were read

- Every component was located on the live page by [tools/capture/public/measure.mjs](tools/capture/public/measure.mjs) in headless Chromium: asana.com is Next.js, so selectors key off landmarks (header/footer/accordion classes), roles and stable text, not generated class names alone. Computed styles were read per state — default, hover, focus-visible, pressed (forced via `CSS.forcePseudoState`), focused on the fields, opened on the flyout, FAQ and mobile menu — and one 2x crop saved per state.
- CSS custom properties were read from the live stylesheets by [tools/capture/vars.mjs](tools/capture/vars.mjs) into [raw/css-vars.json](raw/css-vars.json): the site ships Asana's token layer — ~382 rules covering the colour ramps, the `--lightmode-*`/`--darkmode-*` semantic sets, type, spacing, media, grid, zIndex, shadow and transition scales, and `[data-theme]` section schemes.
- Screenshots were taken on 2026-11-21 by [tools/capture/public/public.mjs](tools/capture/public/public.mjs) from the pages in [site-tree.md](site-tree.md), then quantised to 256 colours by [tools/capture/quantize.py](tools/capture/quantize.py). Desktop viewport shots measured `innerWidth` 1440 and `innerHeight` 900 at devicePixelRatio 1. Phone shots measured 390 by 844 at devicePixelRatio 2 (PNG 780 by 1688). `/apps` reports a growing height (109,623 px desktop, 224,060 px phone). The phone full page is truncated at 56,000 CSS px. Those two full-page files are not committed. The viewport shots are.
- The OneTrust consent banner was dismissed during capture and is not documented as a component; the Qualified chat widget's vars are binned as vendor in css-vars.json and nothing embedded was interacted with.

## What to distrust

- **The product is absent.** On 2026-11-21 `https://app.asana.com/-/login` returned a public login shell (Google, Microsoft, or email, plus reCAPTCHA). That branch stopped. No email was typed. Google and Microsoft were not clicked. No form was submitted. Nothing here describes a workspace.
- **The dark set is declared, not painted.** Every captured route paints light; `dark` is emitted from the `--darkmode-*` vars the stylesheet ships. Do not present it as a verified dark screen — it is real product evidence, unbound on these routes. Asana's own CSS is the source: it even ships the name `--darkmode-inline-inline-link-text` (the extra `inline` segment is theirs, kept verbatim).
- **Fields and buttons are the gate's, not the app's.** The 50px email field, continue button and SSO options belong to the sign-up gate; equivalent-looking controls inside the product were never seen.
- **`gate-title` is missing.** The create-account heading never resolved to a measurable element; the field, continue and SSO entries around it did measure.
- **Screenshots are 256-colour PNGs** — read exact colours from tokens.json or the raw JSON, never from a screenshot pixel.

## Fonts

- **TWK Lausanne** — the painted UI and display face, a commercial webfont the site loads via inline `@font-face`, falling back to Helvetica Neue/Helvetica. It is not loaded here: the style guide and exports name the stack, rendering falls back to system fonts.
- **Helvetica/Arial** — the secondary painted stack on elements outside Lausanne's coverage.
- **Consolas / Georgia** — the declared `--fontFamily-mono` and `--fontFamily-print` stacks for code and print contexts.

## Do and don't

- **Do keep the page near-white and the ink near-black.** Page `#ffffff`, panels `#f3f3f3`, body `#3d3d3d`, strong ink `#0d0d0d`. ([header](components/crops/header-default.png), [hero-title](components/crops/hero-title-default.png))
- **Do use near-black for primary actions.** CTAs are `#0d0d0d` pill blocks lifting to `#3d3d3d` on hover; secondary actions are outlined or ghost text. ([nav-cta](components/crops/nav-cta-hover.png), [plan-cta](components/crops/plan-cta-default.png))
- **Do pair TWK Lausanne display lines with its Helvetica fallbacks.** The hero is a large light-weight line; labels are 11px caps. Don't substitute a generic system face for the display measure. ([hero-title](components/crops/hero-title-default.png), [caps-label](components/crops/caps-label-default.png))
- **Do radius 3px on controls, 100px on CTA pills.** Sharp corners on fields and selects; full pills on the action buttons. ([gate-field](components/crops/gate-field-default.png), [hero-cta](components/crops/hero-cta-default.png))
- **Do space on the 16px base.** `--spacing-1` = 16px through `--spacing-10` = 160px; section rhythm follows it, don't hand-set gaps. ([pricing](screenshots/pricing-light-default.png))
- **Don't ship the marketing style as the app.** Nothing here was measured inside a workspace; a screen claiming Asana's product UI from these tokens would be invented. The honest gap is recorded in components.md.

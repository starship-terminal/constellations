# Alo Yoga design reference

A token set and component reference for Alo Yoga's public storefront — for building fashion-e-commerce surfaces in the style of the real thing. It was read from **aloyoga.com** (served at `/en-sg`) on **2026-11-21**, signed out, in headless Chromium at 1440 x 900 and 390 x 844. The map of which control opens which page is [site-tree.md](site-tree.md). Captured pages: home (consent, women mega-menu, search drawer), women's and men's shop grids, new arrivals, shoes, atelier, gift guide, a product page discovered at run time, New to Alo, the empty cart, help center, size guide, stores, We Are ALO, and the account URL as a stopped login wall. Phone captures cover home (drawer and search), the women grid (filter and sort), a product page, cart, gift guide and help.

Alo is worth a capture because it is a current reference for a monochrome storefront: black-on-white primary actions, uppercase small-cap nav on 84px chrome, colour-dot and square-tile swatch systems with an out-of-stock state, a member-price hook woven into every tile, and a monochrome-on-purpose surface: the shop's own tokens are a set of named neutrals plus a handful of accent/alert/highlight/success roles. (The `--color-*` ramp set in raw/css-vars.json is the embedded Sierra chat widget's palette, recorded as vendor evidence, never Alo's.)

## Brief

<!-- brief:start. Generated by tools/brief.py from catalog.json, the tokens file and this README; `make brief` rewrites it. Do not edit. -->

Read this before designing in this style. Take every value from [tokens.json](tokens.json), never from the screenshots; `python3 tools/catalog.py export aloyoga` prints them all with aliases resolved.

### Principles

1. Do keep the storefront achromatic.
2. Do run the two-button vocabulary.
3. Do keep controls square-edged.
4. Do use the square colour tile on PDPs, the dot on grids.
5. Don't reach for a second accent hue.
6. Don't ship a dark theme.
7. Don't treat vendor widget styles as Alo's.
8. Don't reach for rounded cards or shadows for tiles.

Each rule links the screenshot or crop that shows it, under [Do and don't](#do-and-dont).

## How the values were read

Every value came off the running signed-out shop in headless Chromium:

- **Tokens.** [tools/capture/vars.mjs](tools/capture/vars.mjs) captured every stylesheet body from the network responses (same-origin theme.css plus Builder.io and widget sheets), re-parsed them with `CSSStyleSheet`, and wrote every custom property to [raw/css-vars.json](raw/css-vars.json) binned `app`/`theme`/`vendor`/`utility`/`tailwind` — the embedded third-party app's `.s-mode-*`/`.s-theme-*` kit and Osano's own colours are binned `vendor`, never applied to the storefront and not tokenised. Each name is resolved in a probe carrying the real sheets (light; a `dark` probe lands identical values — nothing binds it). [tools/build_component_tokens.py](tools/build_component_tokens.py) writes the spec, [tools/build_tokens.py](tools/build_tokens.py) the sets.
- **Components.** [tools/capture/public/measure.mjs](tools/capture/public/measure.mjs) opens each public route in a fresh context, hides the Osano consent dialog (never answered), and reads `getComputedStyle`, painted layers and boxes per element in default, hover, focus-visible and a CDP-forced pressed state, plus `opened`/`picked` on the mega-menu, PDP colour tile and mobile drawer. The account login wall was not opened by this pass and nothing was typed into it. Results in [raw/components-computed.json](raw/components-computed.json) and [raw/measurements.md](raw/measurements.md).
- **Screenshots.** [tools/capture/public/public.mjs](tools/capture/public/public.mjs) takes viewport and full-page shots per route — the consent dialog is captured as it arrives first, then hidden — with `.capture.json` sidecars recording measured viewport/dpr; [tools/capture/quantize.py](tools/capture/quantize.py) posterises them to 256 colours.
- **The PDP is discovered.** `/collections/womens-shop-all`'s first product link is followed at run time and its URL recorded (`pdp_url`); a different run may land on a different product.

Nothing was bought, added to bag, joined, subscribed or signed into. No field was typed. The account URL is recorded as a stopped branch.

## What to distrust

- **One theme only.** The `dark` probe resolves to the same `:root` values — nothing paints dark. `tokens.json` ships no dark set.
- **Vendor vars are not the shop.** `.s-mode-*`/`.s-theme-*` (an embedded third-party app's theme kit, ~500 rules) and `--osano-*` are binned `vendor` in css-vars.json and excluded from tokens.
- **`component.*` tokens are measured**, not site variables.
- **`color-tile` and `to-top` missed their selectors** on this pass (lazy Builder.io blocks); recorded as missing, visible in screenshots.
- **Quantised screenshots.** `screenshots/` are 256-colour PNGs; read exact colours from tokens or `raw/full/`.
- **The PDP is a sample**, not a fixed product — see `pdp_url`.

## Fonts

**Proxima Nova** (`--primary-font`) is Alo's licensed face — every headline, nav item, button and price. It is not distributed; the style guide falls back to Helvetica/system. 276 `@font-face` rules were recorded across the sheets in [raw/css-vars.json](raw/css-vars.json) (many are icon/vendor faces); the storefront itself is sans-only.

## Do and don't

1. **Do keep the storefront achromatic.** White ground, black primary actions, grey secondary ink, hairline borders. Colour lives in product imagery, not chrome. See [home-light-default](screenshots/home-light-default.png).
2. **Do run the two-button vocabulary.** Filled black `--primary` uppercase for the action that ends a flow; hairline ghost for the sibling. See [add-to-bag-default](components/crops/add-to-bag-default.png) and [wishlist-button-default](components/crops/wishlist-button-default.png).
3. **Do keep controls square-edged.** The hero and buy buttons are sharp-cornered; size chips and colour tiles are square. See [size-button-default](components/crops/size-button-default.png).
4. **Do use the square colour tile on PDPs, the dot on grids.** PDP swatches are 46px labelled squares; grid swatches are 26px dots with an active ring. See [pdp-swatch-default](components/crops/pdp-swatch-default.png) and [swatch-selected-default](components/crops/swatch-selected-default.png).
5. **Don't reach for a second accent hue.** The named neutrals carry the whole surface; the accent/alert/highlight roles are the only colour, and they stay out of chrome. The `--color-*` ramps in [raw/css-vars.json](raw/css-vars.json) are the Sierra chat widget's palette (vendor bin), not Alo's.
6. **Don't ship a dark theme.** None is offered or declared for the storefront.
7. **Don't treat vendor widget styles as Alo's.** `.s-mode-*`/`.s-theme-*` and `--osano-*` belong to embedded apps. See the `vendor` bin in [raw/css-vars.json](raw/css-vars.json).
8. **Don't reach for rounded cards or shadows for tiles.** Product surfaces are square tiles separated by spacing, not bordered cards. See [product-tile-default](components/crops/product-tile-default.png).

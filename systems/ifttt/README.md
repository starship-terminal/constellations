# IFTTT design reference

A token set and component reference for IFTTT's signed-out surfaces — for building an automation platform, a SaaS marketing site or an app-integration gallery in the style of the real thing. It was read from **ifttt.com** and **ifttt.ai** on **2026-11-18**, signed out, in headless Chromium at 1440 x 900 and 390 x 844 (mobile at 2x). `https://ifttt.com/` 301s to `https://ifttt.ai/` — the marketing home lives there; the gallery, detail and legal surfaces stay on ifttt.com. Captured: every public route — the ifttt.ai home, /explore (+/explore/services, /explore/stories, /explore/applets), /plans, /twitter and /todoist (service pages), an applet page, /connect/discord/instagram, /solutions/productivity and /solutions/smart-home, /mcp, /about, /careers, /partners, /terms and a made-up-route 404 — in the **one theme the product paints**, plus the share modal, the plans Monthly/Yearly switch, a featured tab repaint, the focused prompt, "show more" text expanders and the mobile hamburger menu as transient states, and 390px passes on home (with the menu open), explore, plans, a service page and the applet page.

ifttt.com is worth a capture because it is a counter-example to token-first systems: a Sass-compiled Rails site where **the token layer is nearly absent**. The sheets declare a handful of custom properties — `--card-color`, `--hero-unit` and `--primary-text` on the home/plans heroes, the explore hero's `--cycle-*` cycler math — and everything else is literal hex/rgb() on class names. The harvest therefore records the literals as `core.palette.*` and the measured semantic roles — the white ground, the near-black ink, the **black action pill** (#0f0f0f-ish fills on "Get started"/"Start building"/"Connect"), the outlined secondary pills, the hairline borders, the pastel section tints and the **dark grounds** the explore hero and the service/applet/connect heroes paint — read off the painted page per component. **There is no theme control anywhere signed out**, so `light` is the only token set; the dark grounds are painted sections and land under `light.component.dark` as the measured values they are, never a fabricated dark theme. The brand face is **Museo Sans Rounded** (300/500/700/900 + italics, proprietary woff2 the site serves from web-assets.ifttt.com): names, weights and the fallback stack are evidence, the font files are not. **Boundaries:** sign-in, "Get started", /join and every account surface were never entered; the Applet **Connect** install toggle was measured, never pressed; the plan cards' CTAs were never followed to checkout; **help.ifttt.com answers HTTP 403 to automation** on every route — a documented blocked boundary, not a capture; platform.ifttt.com redirects to ifttt.ai — no separate public platform surface; the App Store/Play badges link off-site and were never followed; /pricing is not a live route (/plans is the pricing surface). Nothing was signed into, typed, searched, shared, bought or submitted — the only presses were local UI toggles the product's own chrome provides (the Share button's own modal, closed with its X; the billing switch; the category tabs; "show more"; the hamburger), and pressed states are DevTools-forced pseudo-classes, never real presses.

## How the values were read

- **Variables** come from the stylesheets themselves (`tools/capture/vars.mjs`): every same-origin CSS response plus the inline CSSOM is reparsed across nine surfaces (ifttt.ai/, /explore, /plans, /twitter, an applet, /connect/discord/instagram, /mcp, /about, /terms — the web-assets.ifttt.com/builds/assets/*.css bundles per section), every custom property resolved in a probe document carrying the real sheets, once — IFTTT paints a single theme. Literal colour declarations are harvested into `palette` with their selectors. `tokens.json` never publishes a raw `lab()`/`color-mix()` declaration — every colour is the painted value.
- **Geometry** is the live DOM (`tools/capture/public/measure.mjs`): bounding boxes and computed styles per component and state — hover by real mouse, focus-visible by keyboard, pressed by CDP `CSS.forcePseudoState` (no real press, so no button can fire), opened/toggled states via the component's own control (the share modal through `button.modal-open`, the plans switch through `button.switch-field`, the tabs through `.featured-tab`, "show more" through `.clamp-toggle`, the mobile menu through its `button.closed`).
- **Screenshots** (`tools/capture/public/public.mjs`) shoot at 1440 x 900 and 390 x 844 @2x. Full-page captures use bounded CSS-scale tiles — eight chunks maximum for the long galleries — with each `.plan.json` sidecar recording intended height, actual page height, chunk size, part count and scale; partial tiles are cleaned up on failure so an incomplete set never stitches as a complete page. Videos are paused, "show more" expanders opened, inner scrollers detected and the page state restored after.
- **The icon collection** (`tools/capture/icons.mjs`) hashes each inline svg's geometry, names it from its control's label or context, records where each was seen in `icons/INDEX.tsv`, and preserves `currentColor` where the original paints through computed text colour. Service-brand artwork inside image tiles is image content, not UI chrome, and is excluded.
- **The Share modal is the product's own** — opened with its Share button (`button.modal-open`), measured and captured, closed with its own X. The modal's **Copy** and the social share icons were measured inside the open modal, never pressed (a clipboard side effect / an external navigation).
- **Connect was never pressed.** The giant Applet toggle is the install action — an account feature. It is measured at rest and captured in the screenshots; pressing it would start an install flow.

## What to distrust

- **Sign-in and everything behind it**: Log in, Get started, /join, the account surfaces, Applet Connect/install — the product's own boundary, never entered. The controls are measured at rest, never activated.
- **The plan CTAs lead to checkout** — measured, never followed. The pricing surface itself (/plans, the Monthly/Yearly switch, the Free/Starter/Pro/Pro+ cards) is fully captured.
- **help.ifttt.com answers HTTP 403** to automation on every route — the help centre is a blocked boundary documented here, not a capture. No help content appears in this package.
- **platform.ifttt.com redirects to ifttt.ai** — no separate public platform surface exists to capture.
- **/pricing is not a live route**; /plans is the pricing surface and a made-up route was captured as the product's 404 (`notfound-*`).
- **The store badges link off-site** (apps.apple.com, play.google.com) — external surfaces, out of scope.
- **The search and prompt fields were clicked into for the focus look only** — never queried or submitted, so result surfaces are uncaptured.
- **The explore galleries and terms run 18k-46k px tall** — the full shots are tiled and bounded at eight 14k px chunks, the bound recorded in each sidecar.
- **Museo Sans Rounded renders from licensed woff2** loaded by the site; crops and screenshots show it, the style guide falls back to a rounded system face — the font files are not shipped.
- **Pressed states are DevTools-forced**; a script-applied mousedown style would not show.
- **IFTTT paints one theme** — the dark grounds on /explore and the detail heroes are painted sections measured in place, not a dark theme to tokenise.
- **The detail-page components are the /connect page's.** `back-button`, `share-button`, `share-modal-copy`, `share-url-field`, `service-hero`, `service-icon` and `get-started-today` were measured on the service, applet and connect pages under one key each, and the last page kept its reading; their tokens say "on connect". `tools/capture/public/measure.mjs` now gives a repeated key its page prefix (edited in the 2026-11 audit, not run); a recapture is needed for the service and applet versions.
- **The brand stack is the measured one.** `core.font.family.brand` is the computed stack verbatim (`"Museo Sans Rounded", "Museo Sans Rounded Fallback", "Avenir Next", helvetica, arial, sans-serif`); `font.family.fallback` is a hand-written stack, labelled Reconstruction.

## Fonts

- **Museo Sans Rounded** — the single brand face across every surface: weights 300 (light), 500 (medium, body), 700 (bold, headings) and 900 (black, the hero headlines) plus matching italics, served as woff2 from web-assets.ifttt.com. Licensed, not shipped; the token keeps the family name plus a rounded fallback chain (`ui-rounded, system-ui, sans-serif`).

## Coverage

- **Captured**: the ifttt.ai home, /explore (+services, +stories, +applets), /plans, /twitter and /todoist service pages, an applet page, /connect/discord/instagram, /solutions/productivity, /solutions/smart-home, /mcp, /about, /careers, /partners, /terms and a 404 at 1440 x 900; the share modal, the Monthly/Yearly switch (both ways), a featured tab repaint, the focused prompt, "show more", and the mobile hamburger menu as transient states; 390 x 844 passes on home (default + menu-open), explore, plans, a service page and the applet page; component states (hover/focus/pressed/opened) per components.md.

## Do and don't

1. **Do paint the ground white and the ink near-black.** The system is a white page with ~#0f0f0f text, hairline borders and the black pill as the action — restraint is the brand ([home](screenshots/home-light-default.png)).
2. **Do spend black on the action pill.** "Get started", "Start building" and the Connect toggle are solid near-black pills with white text; secondary actions are the same pill outlined, never filled grey ([hero](components/crops/hero-submit-default.png), [plans](screenshots/plans-light-default.png)).
3. **Do use pill shapes everywhere.** Buttons, inputs, tabs, the billing switch and the Connect toggle are all `border-radius: 9999px`-class shapes — radii are big and consistent, not a scale ([prompt](components/crops/hero-prompt-focused.png)).
4. **Do let brand colour come from the services.** The page itself is monochrome; the blues/oranges/greens arrive through service icons and the detail pages' brand heroes (iRobot green, X black) — the site does not paint a brand accent ([applet](screenshots/applet-light-default.png)).
5. **Do paint dark as a section, not a theme.** The explore hero and detail heroes paint near-black grounds with white ink inside the light page; there is no theme switch — `light.component.dark` holds those measured grounds ([explore](screenshots/explore-light-default.png)).
6. **Do compose the prompt hero as field + pill.** Home and explore lead with "Describe what you'd like to build" — a rounded input card with the black submit pill inside or below ([home](screenshots/home-light-default.png), [explore](screenshots/explore-light-default.png)).
7. **Do price with the switch + four cards.** /plans pairs the Monthly/Yearly toggle (the "SAVE 30%" badge) with Free/Starter/Pro/Pro+ cards, the recommended card carrying the dark header band ([plans](screenshots/plans-light-default.png)).
8. **Don't style the signed-in product from this package.** Log in, Get started, /join, account surfaces and the Connect install flow are boundaries — measured, never entered ([connect toggle](screenshots/applet-light-default.png)).
9. **Don't invent a dark theme or a spacing/radius scale.** IFTTT ships neither: dark grounds are sections ([explore dark hero](screenshots/explore-light-default.png)), geometry is per-component measurements in raw/layout.json, and there is no token ladder to fabricate.
10. **Don't copy the brand or ship the font.** The pill wordmark, the service icons and the Museo Sans Rounded woff2 files are IFTTT's and its licensors' — the tokens describe the system, not its artwork ([wordmark](screenshots/home-light-default.png)).

### Principles

1. Do paint the ground white and the ink near-black.
2. Do spend black on the action pill.
3. Do use pill shapes everywhere.
4. Do let brand colour come from the services.
5. Do paint dark as a section, not a theme.
6. Do compose the prompt hero as field + pill.
7. Do price with the switch + four cards.
8. Don't style the signed-in product from this package.
9. Don't invent a dark theme or a spacing/radius scale.
10. Don't copy the brand or ship the font.

Each rule links the screenshot or crop that shows it, under [Do and don't](#do-and-dont).

### Using tokens

| Role | light |
|---|---|
| page | #ffffff `light.color.bg.page` |
| surface | #ffffff `light.component.planCard.recommendedBg` |
| text | #111111 `light.color.text.body` |
| muted | rgba(17, 17, 17, 0.7) `light.color.text.muted` |
| accent | #111111 `light.color.action.fill` |
| border | #111111 `light.color.action.outline` |

Fonts: `core.font.family.brand` is Museo Sans Rounded, then 5 fallbacks. Scales, counted as [DESIGN.md](DESIGN.md) holds them: 14 type styles (`core.typography`), no radius steps under `core.radius`, no spacing steps under `core.spacing`.

### Using components

Read [components.md](components.md) for the component inventory; [patterns.md](patterns.md) for how components combine into screens; 91 element crops in [components/crops/](components/crops); [style-guide.html](style-guide.html), which renders every token and the main components.

### Accessibility

| Theme | text on page | text on surface | muted on page | muted on surface |
|---|---|---|---|---|
| light | 18.88:1 pass | 18.88:1 pass | 7.07:1 pass | 7.07:1 pass |

4 of 4 pairs pass 4.5:1 (WCAG AA for body text), the pairs the scorecard's F15 check grades. Focus: no focus tokens (no token path contains "focus").

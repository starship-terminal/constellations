# Codex desktop design reference

A token set and component reference for OpenAI's Codex desktop app for macOS, version 26.1013.40934 (build 20770), captured on 2026-10-25 from the owner's second, signed-in account. The installed bundle is `~/Applications/Codex 2.app` (bundle id `local.codex.acc2`): the owner's own copy of `/Applications/ChatGPT.app`, made by a launcher script so a second account can run beside the first, with its own data folder (`~/.codex-acc2`). It is Electron with the framework renamed `Codex Framework.framework` (`com.openai.codex.framework`, Chromium 155.0.8059.80), and every window is titled ChatGPT. The app has two modes, Codex and ChatGPT; this package is the Codex mode: the navigation rail and sidebar, the new-chat composer, a chat with an agent run, the right panel's tabs, menus, dialogs, the search palette, the rail's pages and every Settings pane. Both of the owner's themes were captured, Absolutely in dark and Catppuccin in light, at the window size the app was in: 1512 x 949 pt.

Everything was read live from the running app over Chromium's remote-debugging port with the Electron route that [cursor-desktop](../cursor-desktop/README.md) piloted ([issue 107](https://github.com/c-wenlong/designs/issues/107)): full-window screenshots of every screen and state, the theme's custom properties as they compute and paint, and the computed style of every captured part in every state. [Compared with Cursor and Devin](#compared-with-cursor-and-devin) says what differed. Use it to build a dense desktop agent tool whose whole palette comes from four inputs (a window colour, an ink colour, an accent and a contrast number): a rail and a slightly darker sidebar, raised surfaces only for the composer, menus and cards, every neutral the ink at a fixed alpha, an ink pill for the one primary action, and the accent kept for switches, focus and links. ChatGPT's web and iPhone apps are in [chatgpt](../chatgpt/README.md) and [chatgpt-ios](../chatgpt-ios/README.md); they share the kit's names but no value here was taken from them.

This package contains no OpenAI code, icons or artwork; the screenshots and the visual system they show are OpenAI's ([docs/RIGHTS.md](../../docs/RIGHTS.md)). Borrow structure and proportions, not the brand.

## Brief

Read this before designing in this style. Take every value from [tokens.json](tokens.json), never from the screenshots; `python3 tools/catalog.py export codex-desktop` prints them all with aliases resolved.

### Principles

1. Do derive every colour from four seeds.
2. Do make the primary action an ink pill, not an accent button.
3. Do raise only what floats.
4. Do give the prompt the only bubble and fold the agent's work.
5. Don't dim the window behind a dialog.
6. Don't colour the permission chip unless it matters.

Each rule links the screenshot or crop that shows it, under [Do and don't](#do-and-dont).

## How the values were read

Codex is an Electron app with a renamed framework (`Contents/Frameworks/Codex Framework.framework` beside `Resources/app.asar` and `default_app`), so its interface is HTML and CSS. `Codex 2.app` was not running, but `/Applications/ChatGPT.app`, the same app on the owner's first account, was, and was left alone. The bundle's executable is a launcher script that, before it starts the app, copies a newer ChatGPT.app over the bundle (ChatGPT.app had moved on to 26.1021), so `open -a "Codex 2.app"` would have replaced the version this capture was asked for. The capture ran the launcher's last line itself instead: `codex-bin --user-data-dir=~/.codex-acc2/user-data --remote-debugging-port=9408` with `CODEX_HOME=~/.codex-acc2`, the same process and data the launcher starts, without the copy. The switch was accepted on the first launch, the account was already signed in, and Playwright attached with `chromium.connectOverCDP`. Three CDP pages share the title ChatGPT (the main window, the floating pet overlay and a detached window), so the scripts pick the main window by its URL, `app://-/index.html` ([cdp.mjs](tools/capture/electron/cdp.mjs) gained that option). The scripts are in [tools/capture/electron/](tools/capture/electron): [shots.mjs](tools/capture/electron/shots.mjs) drives the shot list in [product.mjs](tools/capture/electron/product.mjs), [vars.mjs](tools/capture/electron/vars.mjs) reads the custom properties and [run.mjs](tools/capture/electron/run.mjs) captures an agent run. Screenshots are CDP's `Page.captureScreenshot`, the window's own backing store.

**The theme engine.** A Codex theme is four seeds that a `<style data-codex-app-themes>` element writes per `[data-theme]` from Settings > Appearance: `--codex-base-surface` (the window), `--codex-base-ink` (the text), `--codex-base-accent` and `--codex-base-contrast`, a number from 0 to 100. Everything else is a formula over the seeds and two grey ramps. Neutrals are the ink at fixed alphas (`--alpha-01` to `--alpha-*`, `text.secondary` the ink at 65%, `misc.border` at 7.5%), surfaces are `color-mix()` of the ink into the surface, and Lightning CSS's light-dark polyfill (`var(--lightningcss-light, A)var(--lightningcss-dark, B)`) picks one of two primitives per theme. The kit's semantic names (`--color-background-primary-soft`, `--color-text-tertiary`, `--color-ring-info`, ...) and the app's own (`--app-color-*`, `--color-codex-*`, `--color-token-*`) sit on top. Tailwind CSS 4 declares the scales as custom properties too (`--radius-*`, `--spacing`, `--text-*`, `--font-text-*-size`, `--control-size-*`), so no utility-class reading was needed. [vars.mjs](tools/capture/electron/vars.mjs) lists every declaration and paints each name through a probe element, so `color-mix()`, oklab and the polyfill come back as colours; [build_tokens.py](tools/build_tokens.py) keeps a name as an alias when its formula is a plain `var()` of a token that paints the same, and otherwise keeps the painted colour with the formula beside it.

**The owner's themes, not Codex's default.** Dark is the Absolutely preset (surface #2d2d2b, ink #f9f9f7, accent #cc7d5e, contrast 50) and light the Catppuccin preset (surface #eff1f5, ink #4c4f69, accent #8839ef, contrast 40), and the owner set the UI font to Garamond. Codex's own default (dark surface #181818, ink #ffffff, contrast 60; light surface #ffffff, ink #1a1c1f, contrast 45; accent #339cff in both) was read from the app bundle into [raw/theme-defaults.json](raw/theme-defaults.json) and `core.seed.$extensions.codexDefault`; no screen shows it. Changing the theme to capture it would have changed the owner's settings.

**Themes.** Codex's Mode setting was System, and System follows Electron's native theme, not an emulated `prefers-color-scheme` (CDP `Emulation.setEmulatedMedia` left `data-theme="dark"` in place). The dark pass ran as it was (macOS is dark). For the light pass Settings > Appearance > Mode was switched to Light, and back to System at the end; `config.toml` shows `appearanceTheme = "system"` again.

**Components and states.** Each shot resets the window to the new-chat page, reveals one state with Codex's own selectors (its data attributes such as `data-sidebar-destination`, `data-settings-panel-slug` and `data-composer-*`, roles and aria-labels, never account text), takes the screenshot and reads the computed style of every listed part, recording its box for [crops.py](tools/crops.py). Hover is a real pointer over the part; focus-visible is real keyboard focus (a key press, then `focus()`), and Codex draws its own ring (a 2px box-shadow ring in `token.focus-border`), so nothing was switched on; pressed is `:active` forced through CDP's `CSS.forcePseudoState` with the pointer over the part. Before and after every shot the script compares the theme, the composer's model, effort, permission mode and Work in target, the activity and tab toggles, the sidebar's projects, the pinned chats and the composer's draft, and stops if any changed.

**Sizes.** The window is 1512 x 949 CSS px at a device pixel ratio of 2, unzoomed (`--codex-window-zoom` 1, UI font size 14px). Every px value is a CSS px.

**The agent run.** The owner approved test prompts on 2026-10-25 in a fresh chat on the capture's own empty folder. The capture added `~/.design-systems/harness-scratch/codex` as a project named design-capture (Create project; the folder was picked in the macOS open panel through System Events, and Codex asked once whether to trust it, which the capture answered for that folder only: [trust-dialog](screenshots/dark/trust-dialog.png)). [run.mjs](tools/capture/electron/run.mjs) then sent "List the files in this folder." and "Create hello.txt here with one line: hello from the design capture" from the new-chat composer on that project, on This computer, with the owner's model (GPT-6 Astra, Light effort) and permission mode (Full access), screenshotting and measuring every 1.5 s until each finished. One chat was run in each theme; Codex titled both List folder files. The agent listed the folder and wrote `hello.txt` there with `printf`, nothing else. No approval prompt appeared: Full access runs commands without asking, and nothing was changed to force one.

**What the capture changed, and what was put back.** Created and then cleaned up: the design-capture project (removed from the sidebar with Remove project; the folder and `hello.txt` stay on disk), the folder's trust entry (removed from `~/.codex-acc2/config.toml` after Codex was quit, which leaves the file byte-identical to its copy from before the launch), the two test chats (archived; Codex keeps their history in the shared `~/.codex` store that both accounts read), and a terminal tab opened once per theme in the right panel and closed. The selected project was set back to downloads. Two toggles flipped by an early probe click (the activity view and the tab strip) were turned back off at once, and the guard watched them afterwards. Left in place: opening the Space page for its screenshot made Codex create its welcome page in the account's Space (a "Your guide to ..." page, by Codex's own first-visit routine), and Codex's bookkeeping in `~/.codex-acc2/.codex-global-state.json` (seen flags, caches, the window's maximised flag). Menus, dialogs and the palette were opened and closed with Escape or Cancel; text typed into the composer and the search fields was cleared without sending. No owner chat, project or cloud environment was opened. Codex was quit at the end and not reopened; port 9408 is closed, and the Codex Computer Use helper it had started quit with it.

## What to distrust

- **These are the owner's themes.** Absolutely and Catppuccin are presets the owner picked, with a custom accent in dark; Codex out of the box is the neutral grey and blue theme in `core.seed.$extensions.codexDefault`. Every colour token is the owner's theme run through Codex's formulas.
- **The UI font is not Garamond.** The owner's Font setting puts Garamond first in `--font-sans`, but Garamond is not installed on this Mac, so every screen renders in the system font (`-apple-system`, SF Pro). `core.fontFamily.sans` keeps the stack as declared; build with `core.fontFamily.sans-default`.
- **The two themes' sidebars differ.** The light screens were taken after the second run, so the design-capture project shows two chats there and one in dark, and a Recents row from another app's Codex session (a Conductor workspace, sharing the same history store) appears at the top of Recents in light.
- **The folder trust dialog is dark only.** Codex asks once, when a folder is first added.
- **Menu and dialog fills are not tokens.** Their computed fill is the elevated colour at 90% (`component.menu.bg`, `component.dialog.bg`), which no declared token paints exactly.
- **`role.overlay` is a tint in dark.** It maps to `app.background-elevated-secondary`, which is a near-opaque fill in light but the ink at 2.7% in dark.
- **Component values are one element each.** `component.*` and components.md read the first element that matched each part (or the shot [prefer.py](tools/prefer.py) names), not counts across pages.
- **Run frames are timed, not chosen.** The `run-*` screenshots are frames 1.5 s apart; the states named (started, working, tool call, finished, command, file created) are what was on screen then. The dark run's frames measured only the composer; the light run's measured the conversation parts.
- **The owner's email shows.** The [settings-account](screenshots/dark/settings-account.png) screens show the account's email, which is the owner's own address; it is left unmasked in both themes (the owner approved this on 2026-10-25).
- Screenshots are 256-colour PNGs. Flat UI colours are exact; read values from tokens.json.

## Do and don't

1. **Do derive every colour from four seeds.** Pick a surface, an ink, an accent and a contrast; make text the ink at 100, 65 and 47%, fills and edges the ink at 5, 7 and 10%, and raised surfaces the ink mixed into the surface. See [settings-appearance](screenshots/dark/settings-appearance.png) and [settings-appearance light](screenshots/light/settings-appearance.png).
2. **Do make the primary action an ink pill, not an accent button.** Create project and Trust folder are the ink colour with the surface as text; the accent fills only the on switch, the focus ring, links and file mentions. See [create-project-dialog](screenshots/dark/create-project-dialog.png) and [settings-general](screenshots/light/settings-general.png).
3. **Do raise only what floats.** The page and the sidebar are flat; the composer, menus, cards and dialogs sit on the elevated fill with a hairline and a soft shadow, at 20 to 25px squircle radii. See [home-default](screenshots/light/home-default.png) and [profile-menu](screenshots/dark/profile-menu.png).
4. **Do give the prompt the only bubble and fold the agent's work.** The user's message is a right-aligned soft bubble; each turn's steps fold into one muted Worked for row above a plain reply. See [conversation](screenshots/dark/conversation.png) and [conversation-expanded](screenshots/light/conversation-expanded.png).
5. **Don't dim the window behind a dialog.** Codex blurs the backdrop by a pixel and relies on the dialog's shadow; confirmations stay small, with the action in red on a red tint beside a ghost Cancel. See [remove-project-dialog](screenshots/dark/remove-project-dialog.png) and [delete-archived-dialog](screenshots/light/delete-archived-dialog.png).
6. **Don't colour the permission chip unless it matters.** Composer chips are muted text; Full access alone turns the warning colour. See [home-default](screenshots/dark/home-default.png).

## Rebuild

From the package folder:

```bash
python3 tools/build_tokens.py && python3 tools/build_style_guide.py && python3 tools/build_components_md.py
```

`build_tokens.py` reads `raw/css-vars.*.json`, `raw/components.*.json` and `raw/theme-defaults.json` and writes `tokens.json`; it refuses a token without a source, an alias that points at nothing, a dimension that is not one px length and a colour that is not hex or rgba, and moves a name present in only one theme to `$extensions.notTokenised`. `build_style_guide.py` renders `style-guide.html` from `tokens.json`; `build_components_md.py` writes `components.md` from the readings, `tokens.json` and the crops. All three are deterministic, standard library only. `python3 tools/crops.py` (needs Pillow) cuts `components/crops/` from the screenshots.

To capture again (Codex 2 must not be running; Playwright from `~/.design-systems/pw`; `PORT=9408` on every command):

```bash
CODEX_HOME=~/.codex-acc2 "$HOME/Applications/Codex 2.app/Contents/MacOS/codex-bin" --user-data-dir="$HOME/.codex-acc2/user-data" --remote-debugging-port=9408 &
node tools/capture/electron/run.mjs dark
node tools/capture/electron/shots.mjs dark
KEEP='^--(?!tw-)' node tools/capture/electron/vars.mjs ~/.design-systems/codex-desktop/raw-shots/dark/css-vars.json 'url:^app://-/index\.html$' html
node tools/capture/electron/shots.mjs --set-theme=Light
```

Then the same three lines with `light`, and `shots.mjs --set-theme=System` to put Mode back. The project must exist first: add `~/.design-systems/harness-scratch/codex` as a project named design-capture (Create project; the folder comes from the macOS open panel, which CDP cannot drive) and trust it when asked. `shots.mjs --from=<name>` resumes a pass that stopped. At the end remove the project, archive the test chats, quit Codex (`osascript -e 'tell application id "local.codex.acc2" to quit'`) and remove the folder's `[projects."..."]` trust entry from `~/.codex-acc2/config.toml`. Then `python3 tools/capture/quantize.py ~/.design-systems/codex-desktop/raw-shots`, which also copies the readings into `raw/`, `crops.py` and the builders, then the image check (`python3 tools/redact_images.py check systems/codex-desktop --patterns ~/.design-systems/cleanup-redact.json`, from the repository root). The capture scripts exit non-zero when a required part, a shot, a screen or a run step fails.

**What was reused from the earlier desktop packages.** `shots.mjs`, `run.mjs`, `vars.mjs` and `utilities.mjs` are Devin's with generic fixes: [cdp.mjs](tools/capture/electron/cdp.mjs) picks a window by URL when windows share a title (`{ url: RegExp }`, or `url:<regex>` as the title argument of vars.mjs and utilities.mjs), `shots.mjs --set-theme` and `utilities.mjs` use the product's first window instead of Devin's `agents`, and `shots.mjs` takes `--from=<name>` and deletes the image of a shot that failed. `utilities.mjs` was not run: Tailwind 4 declares its scales as custom properties. The builders are Orca's (the other Tailwind 4 package), with `prefer.py`. Everything marked `PRODUCT (adapt)` is Codex's: `product.mjs` whole, the run frames in `quantize.py`, the mapping block of `build_tokens.py`, `DEFAULT_SHOT` in `prefer.py`, `INVENTORY` and `GAPS` in `build_components_md.py`, and `NAME`, `LEDE`, `GROUP_ORDER` and `specimens()` in `build_style_guide.py`.

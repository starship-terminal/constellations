# Weekrise design reference

A token set and component reference for Weekrise's public site. It was read from weekrise.com on 2026-11-19, signed out. Computed styles came from the T3 preview browser at 1440 x 900 and 390 x 844. Public screenshots came from headless Chromium at the same CSS sizes after the preview browser returned "The browser is not producing screenshot frames". Login and signup were measured and not submitted.

Weekrise is a weekly task planner. The marketing site is a light page on `--vapor-background` (#ffffff), with Inter for UI and Playfair Display for a few display words. The action colour is `--vapor-primary` (#2481ff). A vapor accent ramp runs from #fcfcfc to #111111. Pricing paints Pro in that blue and Team in #a55eea.

### Principles

1. Do use one blue for the marketing action.
2. Do keep the page white and the type black.
3. Do set display words in Playfair Display and everything else in Inter.
4. Do paint Pro as the blue card and Team as the purple card.
5. Don't invent a dark theme.
6. Don't treat the auth blue as the brand blue.

Each rule links the screenshot or crop that shows it, under [Do and don't](#do-and-dont).

## How the values were read

Computed styles and custom properties were read in the T3 preview browser on the live page, with `getComputedStyle` and by walking readable `cssRules`. The viewport was 1440 x 900, then 390 x 844. `devicePixelRatio` was 2 and `visualViewport.scale` was 1.

Public screenshots were taken in headless Chromium after the preview browser could not produce frames. The homepage, academy, privacy and terms pages returned 200 with no Cloudflare challenge. Login and signup were not opened in that headless session.

The vapor custom properties are declared on `html`. Component sizes, colours and radii were read from the elements named in each token's source. Nothing was typed into a field except a focus call on the login email input, which was not submitted.

## What to distrust

- **Preview frames failed.** The T3 preview snapshot returned "The browser is not producing screenshot frames". Screenshots are from headless Chromium. The 2026-11-21 refresh photographed the empty login and signup walls and did not type into them.
- **One theme.** No `prefers-color-scheme` rule and no dark custom properties were in the readable sheets. The OS dark preference was on and the page stayed light.
- **Quantised screenshots.** `screenshots/` and `components/crops/` are 256-colour. Crops were scaled 2x with nearest-neighbour from 1x captures. Read colours from [tokens.json](tokens.json).
- **Auth link blue is a second blue.** Login and signup links paint #417ff7. Marketing links and the hero button paint `--vapor-primary` (#2481ff). The Continue button on the auth form also paints #417ff7, not `--vapor-primary`.
- **Team purple and the inverse band are not custom properties.** #a55eea and #1a1a1a were computed fills.
- **Focus did not change the field.** Focusing the login email input left the wrapper at 1px solid #e8e8e8 and `outline: none`. `--vapor-border-primary` exists and was not applied.
- **Paddle stylesheets were cross-origin** and were not read. They are payment chrome, not the marketing system.
- **The mobile nav overlay did not open.** The button is labelled "Open Navigation". After a click the overlay kept class `hidden` and opacity 0, and showed an empty progress spinner.

## Fonts

**Inter** is the UI face. The computed body stack is Inter, -apple-system, system-ui, Segoe UI, Roboto, Oxygen, Ubuntu, Cantarell, Open Sans, Helvetica Neue, sans-serif. Weights 400, 500, 600, 700 and 800 were loaded. Inter is licensed under the SIL Open Font License.

**Playfair Display** is used for a few display words (productivity, Pomodoro, differently), weight 700. It is also SIL Open Font License. The guide loads both from Google Fonts as stand-ins for the files the site already loaded.

## Do and don't

- **Do use one blue for the marketing action.** The hero "Get Started" and the Signup chip paint `--vapor-primary` (#2481ff). See [screenshots/home-light-default.png](screenshots/home-light-default.png).
- **Do keep the page white and the type black.** Body text is `--vapor-foreground` (#000000) on `--vapor-background` (#ffffff). See [screenshots/privacy-light-default.png](screenshots/privacy-light-default.png).
- **Do set display words in Playfair Display and everything else in Inter.** The word "productivity" in the command-palette headline is Playfair Display 86.4px / 700. The rest of that headline is Inter.
- **Do paint Pro as the blue card and Team as the purple card.** Pro is #2481ff. Team is #a55eea, which is not a vapor token. See [screenshots/home-light-pricing.png](screenshots/home-light-pricing.png).
- **Don't invent a dark theme.** No dark rule was declared, and the page stayed light while the OS preference was dark.
- **Don't treat the auth blue as the brand blue.** Continue, "Sign up instead" and the legal links on `/auth/login` paint #417ff7. The marketing primary is #2481ff.

## Rebuild

```bash
python3 tools/catalog.py design-md weekrise
python3 systems/weekrise/tools/build_tokens.py
python3 tools/package_tests.py weekrise
```

`build_tokens.py` checks that every `--vapor-*` colour and radius in [raw/css-vars.json](raw/css-vars.json) is present in [tokens.json](tokens.json). It does not regenerate the file. The style guide is hand-authored from those tokens because the kit template expects Claude's token names.

## Surfaces

Public pages captured: `/`, `/academy`, `/academy/pomodoro`, `/privacy`, `/terms`, `/payments`. The 2026-11-21 map is [site-tree.md](site-tree.md). Auth walls photographed empty and not submitted: `/auth/login`, `/auth/signup`. Login asks for an email, then Continue, and offers Sign in with Google. Signup asks for a name and an email, then the same two buttons. No account was created. Google sign-in was not used. No card, phone number or calendar OAuth was entered. The signed-in planner was not entered. `login-extracted` is not-started.

# fal.ai design reference

A token set and component reference for fal.ai's public signed-out website — for building generative-media marketing pages, dark model-catalog shells, playground forms and docs in the style of the real thing. It was read from **fal.ai** on **2026-11-14**, signed out, in headless Chromium at 1440 x 900 and 390 x 844. Captured: the home page, /pricing, /serverless, /contact-sales and a 404 page on the Webflow marketing surface; /explore, /models/krea/v3/text-to-image and its /api tab and /login on the Next.js app surface (dark, plus explore/model/login light passes); the fumadocs /docs/documentation entry in light and dark; and 390px passes on the marketing home and the explore catalog including the open nav drawer.

fal.ai is worth a capture because it ships three distinct token layers to the browser: the app's Tailwind v4-style layer (763 resolved names per pass — `--color-*` scales, `--primary-*/--secondary-*/--error-*/--info-*/--success-*/--warning-*/--neutral-*/--lightblue-*` ramps held as `H S% L%` triplets, the semantic `--surface-*/--content-*/--stroke-*/--overlay-*/--shadow-*/--badge-*/--accent-*` roles that switch per `html.light`/`html.dark`, `--product-banner-*`, `--chart-*`, `--composer-prompt-*`, the `--text-*/--tracking-*/--leading-*` type layer, `--radius-*`, `--ease-*`, `--animate-*`, `--breakpoint-*/--container-*`), the Webflow marketing layer (`--brand-colors--*`, `--base-color-*/--background-color--*/--border-color--*/--text-color--*` aliases, `--size-*`), and the docs' own fumadocs layer (`--primary`, `--gray-*`, `--twoslash-*`). Three surfaces paint signed out: the single-theme **light marketing pages** (a dark bronze `#403700` hero field with a cyan `#99edff` Focal Web display and a neon-lime `#adff00` CTA), the **dark app** (`#121216` canvas, white pill primary, the violet `#783afb` accent and Sign-in-to-run, translucent-white ghost controls) and the **light docs** (Focal Medium hero, Public Sans body, `#5718c0` focus). **Boundary:** everything past login — the dashboard, API keys, billing, deployments, the sandbox and real inference — was never reached; the OAuth buttons, Sign-in-to-run, Open-in-Sandbox, Download, Contact-Sales and Get-Started actions were measured, never followed; the prompt field was filled and cleared without running a model; the consent card was hidden, never answered.

## Brief

<!-- brief:start. Generated by tools/brief.py from catalog.json, the tokens file and this README; `make brief` rewrites it. Do not edit. -->

Read this before designing in this style. Take every value from [tokens.json](tokens.json), never from the screenshots; `python3 tools/catalog.py export fal` prints them all with aliases resolved.

### Principles

1. Do let the declared layers carry the design.
2. Do match the app chrome.
3. Do invert the primary button per surface.
4. Do spend the violet on the run action.
5. Do set display type in Focal at weight 500.
6. Do use ghost washes on the dark surface.
7. Do draw focus as a real ring.
8. Don't style the signed-in product from this package.
9. Don't fabricate inference or downloads.

Each rule links the screenshot or crop that shows it, under [Do and don't](#do-and-dont).

## What to distrust

- **Two values were resolved on the wrong viewport.** `tools/capture/vars.mjs` resolved viewport-relative declarations on a default 1280 x 720 probe page while its note says 1440 x 900, so `core.marketing.size.container.default` (`clamp(992px, 100vw, 1920px)`, committed 1280px) and `core.marketing.size.font` are the 1280-wide readings; their sources say a recapture is needed. The script now opens the probe at 1440 x 900 (not run). The same capture wrote hex as `#9b,9b,9b` in [raw/css-vars.json](raw/css-vars.json); `build_tokens.py` still reads that form until a recapture.
- **Hidden DOM twins ship beside real elements.** The app renders duplicate copies of the sandbox link, nav items, docs headings and card anchors inside `display:none` ancestors; `a` children of the docs cards are `display:contents` and measure 0 x 0. The kit resolves the first candidate with a real bounding box — the painted copy only.
- **The Products menu panel is `div.top-center`, not the trigger's wrapper.** Earlier reads of `app-nav-menu` through `ancestor::div[2]` land on the 91 x 48 trigger; the painted panel is `ancestor::div[1]` at 322 x 201.
- **`pager-next` pressed is a real 0 x 0.** The carousel arrow collapses mid-press; the state is measured, not missed.
- **Quantised screenshots band gradients.** Screenshots are 256-colour PNGs; read exact colours from tokens.json or the raw JSON, and pixel-perfect gradients from the full-colour originals.
- **The 404 page's `--error-page-*` variables are not tokens.** They ship in a route stylesheet the model page never applies, and the stylesheet harvest keeps only the sheets a document applies, so they are absent from `raw/css-vars.json` and `tokens.json`; the 404 itself is captured in `notfound-light-default.png`.
- **The model-light pass hit an edge security check.** `model-light-light-default.png` is real but the light model-page measurements come from the dark pass; the light set's declared values resolve both ways regardless.
- **App font stacks are classes, not variables.** The app declares only `--font-weight-*`; every `core.font.family.*` token is a measured computed `fontFamily` (publicSansRounded, focal, chivoMono, Focal Web/Text, Public Sans, Focal Medium) — the family names are the next/font class names.

## Do and don't

1. **Do let the declared layers carry the design.** The app ships its token system: use the semantic `surface.*`/`content.*`/`stroke.*`/`overlay.*`/`badge.*`/`accent.*` roles and the palette ramps rather than restating hex. See [tokens.json](tokens.json) and the rendered [style guide](style-guide.html); the dark semantic layer is what paints [explore-dark-default](screenshots/explore-dark-default.png).
2. **Do match the app chrome.** The dark shell is a 48px header over `#121216` with a cyan-on-navy announcement strip above it and a Products disclosure in the nav. See [app-header](components/crops/app-header-default.png) and [app-announce](components/crops/app-announce-default.png).
3. **Do invert the primary button per surface.** Black pill on the light marketing pages, white pill on the dark app — never a coloured primary except the violet run action. See [mkt-btn-start](components/crops/mkt-btn-start-default.png) and [app-btn-signup](components/crops/app-btn-signup-default.png).
4. **Do spend the violet on the run action.** `#783afb` (`accent.violet.solid`) paints Sign-in-to-run and the model badge's alpha tint; chrome stays neutral. See [mp-run](components/crops/mp-run-default.png) and [mp-badge](components/crops/mp-badge-default.png).
5. **Do set display type in Focal at weight 500.** The 96px marketing hero (cyan on the dark bronze `#403700` field), the docs' 56px "Build with fal" and the model page's focal heading share the voice; controls and body stay in publicSansRounded/Public Sans. See [mkt-hero-h1](components/crops/mkt-hero-h1-default.png) and [docs-h1](components/crops/docs-h1-default.png).
6. **Do use ghost washes on the dark surface.** Hover lays `surface.alpha.light` translucency; menus, chips and controls read through rgba whites, not solid greys. See [app-nav-menu](components/crops/app-nav-menu-default.png).
7. **Do draw focus as a real ring.** 1px `#101010` auto on marketing; on the dark app the buttons paint a 3px `#a284ff` box-shadow ring (`dark.border.focus`, `color.stroke.focus.brand`; their outline is none) and the nav links a 2px `overlay.primary.stroke` outline; 1px `#5718c0` on the docs. See [app-btn-signup focus-visible](components/crops/app-btn-signup-focus-visible.png) and [app-nav-docs focus-visible](components/crops/app-nav-docs-focus-visible.png).
8. **Don't style the signed-in product from this package.** The dashboard, API keys, billing and deployments were never reached; the signed-out surfaces are the only evidence — the login card is where the capture stops. See [li-card](components/crops/li-card-default.png).
9. **Don't fabricate inference or downloads.** Sign-in-to-run, Open-in-Sandbox, Download and the model playground were measured at rest; what they do signed out is unverified. See [mp-sandbox-link](components/crops/mp-sandbox-link-default.png) and [mp-download](components/crops/mp-download-default.png).

## Rebuild

```bash
cd systems/fal
python3 tools/build_component_tokens.py   # raw/component-tokens.json from the raw readings
python3 tools/build_tokens.py             # tokens.json
node tools/capture/public/build-measurements.mjs   # raw/measurements.md
python3 tools/build_components_md.py      # components.md
python3 tools/build_style_guide.py        # style-guide.html
python3 tools/token_checks.py             # structural token checks
```

Screenshots: set one scratch directory and use it for both steps, `export RAW=~/.design-systems/fal/raw-shots`, then `node tools/capture/public/public.mjs` (raw shots land in `$RAW`; the script's own default is `raw/full/` inside the package, so a bare run writes somewhere else) and `python3 tools/capture/quantize.py "$RAW"` (writes `screenshots/` with `.capture.json` sidecars; it quantizes every PNG in `$RAW`, so start from an empty directory or capture only the pages you mean to replace, `node tools/capture/public/public.mjs docs-dark`). `docs-dark` selects the docs dark theme with the page's own switcher and fails when `<html>` does not become dark. The stylesheet harvest is `node tools/capture/vars.mjs` (raw/css-vars.json). Measurements and crops: `node tools/capture/public/measure.mjs` (optionally page names: `home pricing explore model api login docs mobile`, or `motion` for the reduced-motion check alone). All capture scripts take `PLAYWRIGHT=<path to playwright/index.mjs>` and run signed out only.

- The capture scripts no longer hide automation: the `navigator.webdriver` mask is removed. The committed captures were taken with it.

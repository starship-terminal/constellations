# Bezi design reference

A token set and component reference for Bezi's public site — for building dark, game-tools marketing and pricing surfaces in the style of the real thing. It was read from **www.bezi.com** on **2026-11-11**, signed out, in headless Chromium at 1440 x 900 and 390 x 844: the home page (with the mobile menu opened), pricing and about, plus the mobile captures of home and pricing.

Bezi is worth a capture because it is a current reference for the dark AI-dev-tools surface: a `#0d0d0d` starfield ground, a floating translucent pill header (`rgba(31,31,31,0.84)`, 144px radius), one orange CTA recipe (`#f84503`, pill) repeated from the nav to the pricing page, an orange "NEW" chip in the announcement strip, corner-tick index chips instead of boxed cards for the feature sections, a pastel sky Free band on the pricing page, and the Framer `--token-*` palette declared on `body` — the product's own orange, ink, alpha and pastel values.

## Brief

Read this before designing in this style. Take every value from [tokens.json](tokens.json), never from the screenshots; `python3 tools/catalog.py export bezi` prints them all with aliases resolved.

### Principles

1. Do ground on the starfield.
2. Do use one CTA recipe.
3. Do box sections with corner ticks, not cards.
4. Do set display type in The Future Medium.
5. Don't spread the orange.
6. Don't invent a light theme.
7. Don't read link colour off the anchor.
8. Don't flatten the header.

Each rule links the screenshot or crop that shows it, under [Do and don't](#do-and-dont).

## How the values were read

Every value came off the running signed-out site in headless Chromium:

- **Tokens.** [tools/capture/vars.mjs](tools/capture/vars.mjs) captured every stylesheet body — the Framer bundle ships most of its CSS inline — re-parsed them, and wrote every custom property to [raw/css-vars.json](raw/css-vars.json) binned `token`/`app`/`framer`. The 47 `--token-<uuid>` declarations on `body` are the site's palette (36 unique values; several uuids repeat black, white and the common white alphas): an orange ramp around the `#f84503` CTA (`color.orange.*`), a dark neutral ramp (`color.ink.*`), translucent whites and blacks (`color.white-alpha.*`, `color.black-alpha.*`) and the pastel accents of the engine chips and the Free band (`color.pastel.*`). Each name is resolved in a probe carrying the real sheets. [tools/build_component_tokens.py](tools/build_component_tokens.py) writes the spec [raw/component-tokens.json](raw/component-tokens.json) that [tools/build_tokens.py](tools/build_tokens.py) renders.
- **Components.** [tools/capture/public/measure.mjs](tools/capture/public/measure.mjs) opens each route in a fresh context and reads `getComputedStyle`, painted layers and boxes per element in default, hover, focus-visible and a CDP-forced pressed state, plus `opened` on the mobile menu. Framer paints a button's fill on a sibling layer rather than the anchor, so the CTA and plan CTA are measured at the ancestor holding both the text and the fill, and the announcement strip at the anchor that paints it. Sections mount only while their band is near the viewport, so the section title is hunted by a scroll sweep that marks it in place. Results in [raw/components-computed.json](raw/components-computed.json) and [raw/measurements.md](raw/measurements.md); each entry also carries the painted text child's style, because the anchors themselves inherit the browser's unvisited-link colour.
- **Screenshots.** [tools/capture/public/public.mjs](tools/capture/public/public.mjs) takes viewport and full-page shots per route, including the opened mobile menu, with `.capture.json` sidecars; [tools/capture/quantize.py](tools/capture/quantize.py) posterises them to 256 colours for the repo.
- **Fonts.** 314 @font-face declarations sit in the bundle ([raw/css-vars.json](raw/css-vars.json) `fonts`): **The Future Medium** for the display headlines, **Inter** for the UI, **Inter Display** for the pricing title, **Space Mono** for the CTA labels, **IBM Plex Mono** and **Fragment Mono** for mono details, and single faces (P-DOT Regular, Sharp Grotesk Book/Medium 20, FT88, Family Regular, The Future Regular/Mono) mostly inside artwork. The webfonts themselves are not committed.

Nothing was sent, downloaded, signed into or trialled. The only press was a local UI toggle: the mobile menu trigger. "TRY FOR FREE", the plan CTAs, the Individual/Studio billing toggle and every outbound link (Docs, Discord, the footer socials) were measured, never followed.

## What to distrust

- **Readings past a masked bot signal.** The committed screenshots and readings were taken with `navigator.webdriver` masked, the flag bot checks read to spot automation. The capture scripts no longer mask it (not run since), so a recapture may record a walled route as a boundary instead of a reading.
- **One painted theme.** Every captured route paints dark; the bundle declares no light variant, so the semantic set is emitted under `dark` (the spotify convention for a single painted dark surface).
- **Framer uuid token names.** `--token-<uuid>` names are unstable build artefacts; tokens.json emits them under readable orange/ink/alpha/pastel names while each leaf keeps the real variable in `$extensions.source`.
- **Anchor `color` reads `#0000ee` or transparent fills.** Framer paints link/button text on inner spans and button fills on sibling layers; the anchor's own computed colour is the UA default and its background is transparent. `dark.accent`/`accentText`/`link` read the painted layers and text child (`paint`/`textStyle` in the raw file), never the anchor alone.
- **`component.*` tokens are measured**, not site variables.
- **The browser's focus ring.** Keyboard focus draws Chromium's default `auto` outline (`rgb(0,95,204)`), not a designed ring — `dark.focus` records it as measured.
- **Quantised screenshots.** `screenshots/` are 256-colour PNGs; read exact colours from tokens or the raw JSON.

## Do and don't

1. **Do ground on the starfield.** `#0d0d0d` page with the translucent pill floating over it. See [home-dark-default](screenshots/home-dark-default.png).
2. **Do use one CTA recipe.** The `#f84503` orange pill, 39px, white text — nav, hero and pricing all use it. See [cta-default](components/crops/cta-default.png) and [plan-cta-default](components/crops/plan-cta-default.png).
3. **Do box sections with corner ticks, not cards.** The "02. CONNECTED TOOLS" chips draw four 19px corner borders in `rgba(242,241,236,0.32)` — a bracket, not a filled box. See [tools-button-default](components/crops/tools-button-default.png).
4. **Do set display type in The Future Medium.** 53px/500 hero over the starfield; Inter Display carries the pricing title. See [hero-title-default](components/crops/hero-title-default.png).
5. **Don't spread the orange.** `#f84503` marks the CTA, the NEW chip, the pixel arrow and the RECOMMENDED tag — accents only, never a large fill. See [announcement-default](components/crops/announcement-default.png).
6. **Don't invent a light theme.** The bundle declares none; every route paints dark.
7. **Don't read link colour off the anchor.** Framer anchors keep the UA `#0000ee` and transparent fills; the painted text and fills live on inner spans and sibling layers (`textStyle`/`paint` in the raw JSON).
8. **Don't flatten the header.** The pill is `rgba(31,31,31,0.84)` over the starfield with a 144px corner — translucency, not a solid bar. See [header-default](components/crops/header-default.png).

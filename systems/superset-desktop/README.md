# Superset desktop design reference

A token set and component reference for Superset's desktop app for macOS, version 1.39.0 (Electron, bundle id `com.superset.desktop`), captured on 2026-10-25 from the owner's signed-in account (the organisation on its free plan). Superset runs coding agents in parallel workspaces: a sidebar of projects and their workspaces, a New Workspace page with one composer, workspaces made of tabs where each agent's CLI runs in a terminal, a right panel of changed files and diffs, a Workspaces board, Pull requests, Pages, Plugins, and 22 Settings panes. All of it was captured in Superset's built-in Light and Dark themes, at the window size the app was in: 1512 x 950 pt, maximised on the built-in display.

Everything was read live from the running app over Chromium's remote-debugging port, with Playwright connected over CDP, using the capture scripts of [cursor-desktop](../cursor-desktop/README.md) (the pilot of [issue 107](https://github.com/c-wenlong/designs/issues/107)) with Superset's own shot list: full-window screenshots of every screen and state, the custom properties as they compute and paint, the colours Superset's theme engine writes, and the computed style of every captured part in every state. Use it to build a dense desktop tool for running agents: a warm near-black or near-white window, a slightly darker sidebar, ink primary buttons instead of a brand hue, shadcn/ui components on Tailwind's scale, and the work itself in terminal panes.

This package contains no Superset code or artwork beyond the app icon (`icon.png`); the screenshots and the visual system they show are Superset's ([docs/RIGHTS.md](../../docs/RIGHTS.md)). Borrow structure and proportions, not the brand.

### Principles

1. Do make the primary action ink, not a hue.
2. Do keep warm greys in dark and neutral greys in light.
3. Do show hover and selection with a foreground wash.
4. Do use one popover surface for every menu, select and picker.
5. Do colour destructive actions, and only those.
6. Don't redraw the agent's output; host it.

Each rule links the screenshot or crop that shows it, under [Do and don't](#do-and-dont).

## How the values were read

Superset is an Electron app (`Contents/Frameworks/Electron Framework.framework`), so its interface is HTML and CSS: React with shadcn/ui components on Tailwind CSS 4, one stylesheet (`index-OKFLt8Wb.css`), xterm.js for terminals. It was not running; it was opened with `open -a Superset --args --remote-debugging-port=9404`, which it accepted, and Playwright attached with `chromium.connectOverCDP`. The account was already signed in; nothing was typed into a sign-in screen. The scripts are in [tools/capture/electron/](tools/capture/electron): [cdp.mjs](tools/capture/electron/cdp.mjs), [shots.mjs](tools/capture/electron/shots.mjs), [vars.mjs](tools/capture/electron/vars.mjs) and [run.mjs](tools/capture/electron/run.mjs) are Cursor's unchanged; [product.mjs](tools/capture/electron/product.mjs) is Superset's shot list and [theme.mjs](tools/capture/electron/theme.mjs) reads what its theme engine writes. Screenshots are CDP's `Page.captureScreenshot`.

**The theme engine.** A Superset theme is a JSON object with `ui`, `terminal` and `editor` colours; the built-in Dark (the default) and Light ship in the renderer bundle beside Catppuccin, Monokai, Solarized Light and Vellum. `applyUIColors()` writes `ui` onto `<html>` as inline custom properties with shadcn's names (`--background`, `--card`, `--primary`, `--muted-foreground`, ...) and sets `html.dark` or `html.light`; the stylesheet's `:root` and `:root.light` values are only fallbacks and differ from the themes in places (dark `--success` is #5fb37f in the stylesheet and #00c950 in the theme). [theme.mjs](tools/capture/electron/theme.mjs) records the inline values; [vars.mjs](tools/capture/electron/vars.mjs) records every declaration and what each name paints, through a probe element's `color: var(--x)`, so `color-mix()` and `oklch()` come back as painted colours. Two fills are mixed in the stylesheet from the foreground: `--fill-hover` at 7% (dark) or 4% (light) and `--fill-selected` at 10% or 6%. The terminal palette never reaches CSS: xterm.js paints on a canvas, so `terminal.*` comes from the copy the renderer keeps in `localStorage['theme-terminal']`.

**Themes.** Superset's theme does not follow an emulated `prefers-color-scheme` when it is set to Dark, as the owner's was (CDP `Emulation.setEmulatedMedia` left `html.dark` in place; only the System theme listens), so the owner's own setting was switched: Settings > Appearance > Theme from Dark to Light for the light pass and back to Dark at the end. `~/.superset/app-state.json` is byte-identical to its copy from before the capture. One slip, undone: the first switch picked Solarized Light (the option text matched on its last word); it was set to Light before anything was captured.

**Components and states.** Each shot resets the window to the New Workspace page, reveals one state with Superset's own selectors (shadcn's `data-slot` names, roles, aria-labels and fixed labels, never account text, apart from the capture's own project and workspace), takes the screenshot and reads the computed style of every listed part, recording its box for [crops.py](tools/crops.py). Hover is a real pointer over the part; pressed is `:active` forced through CDP's `CSS.forcePseudoState` with the pointer over it; focus-visible is real keyboard focus. Superset draws its focus ring without help (shadcn's 3px ring in `--ring` at 50% plus a `--ring` border), so unlike Cursor nothing was switched on for it; sidebar rows and workspace tabs take focus without a visible ring. Before and after every shot the script compares the composer's selections and the sidebar's rows and stops if either changed; the renderer refills both a moment after navigation, so the guard reads until two readings agree.

**Sizes.** The window is not zoomed: 1512 x 950 CSS px at a device pixel ratio of 2, so every px in tokens.json and components.md is what the stylesheet declares and what the screenshot shows at half size.

**The workspace and the agent run.** Superset had no projects. The capture created one with Add project > Create new project, named `superset`, in `~/.design-systems/harness-scratch` (Superset created the folder and its first commit), and one workspace on it in Local checkout mode (no worktree), by sending the test prompt "List the files in this folder." from the New Workspace page; Superset named the workspace after it. Superset's Claude preset runs `claude --dangerously-skip-permissions` in a terminal tab (Settings > Agent commands; not changed), so Claude Code asks for no tool approvals. The only prompt was Claude Code's own question whether to trust the folder, on that first start; it named the scratch folder, was answered Yes, and its window is kept as `run-approval` (dark only, outside run.mjs). For each theme [run.mjs](tools/capture/electron/run.mjs) then opened a fresh Claude tab in the workspace from the preset bar and sent "List the files in this folder." and "Create hello-&lt;theme&gt;.txt here with one line: hello from the design capture", screenshotting and measuring every 1.2 s; a run counts as working while its tab shows the amber dot. A probe run between them created `hello.txt` the same way. The agent wrote `hello.txt`, `hello-dark.txt` and `hello-light.txt` in the scratch folder and ran `ls` and `git remote -v` there.

**What else changed, and what was put back.** Opening and closing menus, dialogs and the palette changed nothing; typed text was cleared without sending. Picking Local for the workspace set the composer's checkout to Local; it was set back to Worktree. The sidebar collapse shot unfolds the sidebar again and reopens the project's group. The delete confirmation was opened on the capture's own workspace and cancelled. Superset was quit at the end (it asks to confirm) and not reopened; quitting let it install the update it had downloaded, so it is now 1.40.0. Its terminal daemon keeps terminals alive after the app quits, so the four Claude processes the capture had started (the first workspace, the probe tab and one per theme) and the daemon were stopped by hand.

## What to distrust

- **The New Workspace page shows the capture's project.** The composer's project select reads `superset` and the sidebar lists the scratch project and its workspace in every shot, because the account had no project of its own on this Mac.
- **The tab strip grows between themes.** Each run opened one more Claude tab, so the light workspace screenshots show one more tab than the dark ones.
- **Two sets of colours exist and only one is live.** The stylesheet's `:root` and `:root.light` are fallbacks; the theme engine's inline values win. tokens.json holds the painted, inline values; `raw/css-vars.*.json` holds both.
- **The terminal content is not Superset's design.** What streams in a pane is Claude Code's own interface in Superset's terminal palette; Superset's design is the chrome around it.
- **Component values are one element each.** `component.*` and components.md read the first element that matched each part; they are not counts across pages.
- **Run frames are timed, not chosen.** The `run-*` screenshots are frames 1.2 s apart; the states named (thinking, tool call, editing) are what was on screen at that moment.
- **The owner's addresses show.** Settings > Usage lists the agent accounts signed in on this Mac, including the owner's two own email addresses; they are left unmasked in both themes (the owner approved this on 2026-10-25). The two other users' names beside the owner's rank on the public leaderboard on that page are painted out in both themes (owner's decision, 2026-11-21, for the public repository) with [tools/redact_images.py](../../tools/redact_images.py) and [its rules](../../tools/redact-rules/superset-desktop.json).
- Screenshots are 256-colour PNGs. Flat UI colours are exact; read values from tokens.json.

## Do and don't

1. **Do make the primary action ink, not a hue.** Superset's primary button, switch-on and PRO pill are `ui.primary`, the foreground colour (#eae8e6 in dark, #171717 in light), with the page colour as text; hover and pressed are the same fill at 90%. See [create-project-filled](screenshots/dark/create-project-filled.png) and [button-primary-hover](components/crops/button-primary-hover.png).
2. **Do keep warm greys in dark and neutral greys in light.** Dark is a warm near-black (`ui.background` #151110, sidebar #1a1716, card #201e1c); light is near-neutral (#f9f9fa, #ececec, #f5f5f5). See [home-default](screenshots/dark/home-default.png) and [home-default light](screenshots/light/home-default.png).
3. **Do show hover and selection with a foreground wash.** Rows take `ui.fill-hover` (7% in dark, 4% in light) under the pointer and `ui.fill-selected` (10% or 6%) when selected, with the text going from `ui.muted-foreground` to `ui.foreground`. See [workspace-row-hover](components/crops/workspace-row-hover.png) and [settings-nav-selected](components/crops/settings-nav-selected-default.png).
4. **Do use one popover surface for every menu, select and picker.** `ui.popover`, a 1px `ui.border`, 10px radius, shadow-md, 32px rows with a 6px radius. See [model-menu](screenshots/light/model-menu.png) and [workspace-context-menu](screenshots/dark/workspace-context-menu.png).
5. **Do colour destructive actions, and only those.** Delete is the one red button (`ui.destructive`), in the confirmation and in account and organisation settings; everything else is ink, outline or ghost. See [delete-confirmation](screenshots/dark/delete-confirmation.png) and [settings-account](screenshots/light/settings-account.png).
6. **Don't redraw the agent's output; host it.** Each agent is its own CLI in a terminal pane; Superset adds only a tab, a pane header, a running dot and the diff count around it. See [run-tool-call](screenshots/dark/run-tool-call.png) and [run-file-changed](screenshots/light/run-file-changed.png).

## Rebuild

From the package folder:

```bash
python3 tools/build_tokens.py && python3 tools/build_style_guide.py && python3 tools/build_components_md.py
```

`build_tokens.py` reads `raw/css-vars.*.json`, `raw/theme.*.json` and `raw/components.*.json` and writes `tokens.json`; it refuses a token without a source, an alias that points at nothing, a dimension that is not one px length and a colour that is not hex or rgba, and moves a name present in only one theme to `$extensions.notTokenised`. `build_style_guide.py` renders `style-guide.html` from `tokens.json`; `build_components_md.py` writes `components.md` from the readings, `tokens.json` and the crops. All three are deterministic, standard library only. `python3 tools/crops.py` (needs Pillow) cuts `components/crops/` from the screenshots.

To capture again (Superset must not be running; Playwright from `~/.design-systems/pw`; the scratch project and workspace must exist, see above):

```bash
open -a Superset --args --remote-debugging-port=9404
export SLUG=superset-desktop PORT=9404
node tools/capture/electron/run.mjs dark
node tools/capture/electron/shots.mjs dark
```

## The Electron route, as it went

How Superset compared with the Cursor pilot, step by step.

| Step | Cursor | Superset |
|---|---|---|
| Port | Accepted the switch on the first launch | The same; one window, titled with the organisation's name |
| Values | Seeds in a style element, the rest color-mix formulas | Inline custom properties on `<html>` written from a theme object; the stylesheet holds stale fallbacks; the terminal palette lives only in JS and localStorage |
| Hover | Needed a real pointer | A real pointer was used; not tested whether forced `:hover` would do |
| Focus | Needed `[data-focus-ring]` set on the root | Drawn by default (shadcn's 3px ring) |
| Theme | Did not follow emulated media | Did not either (the theme was Dark, not System); the setting was switched and restored |
| Zoom | 0.84 window zoom from the UI font size | None; CSS px are screen points |
| Agent run | Agent chat in the window's own DOM | The agent is a CLI in an xterm.js canvas; run state read from the tab's running dot, not from the transcript |
| Approval | None (auto-run in the owner's settings) | None from tools (`--dangerously-skip-permissions` in Superset's preset); Claude Code's folder-trust prompt once |
| Side effects | A draft agent, a model change, an automation | A project and workspace created on purpose; the checkout default set back; quitting leaves a terminal daemon with the agents running |
| Generic scripts | Written for this route | Used unchanged; Superset's window key is aliased to `agents` in product.mjs so `--set-theme` works without editing shots.mjs |

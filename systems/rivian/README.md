# Rivian design reference

A token set and component reference for Rivian's public signed-out marketing site. Read from rivian.com on 2026-11-19, signed out.

Surfaces: home, the Vehicles menu, R2, charging, support, General Terms, and the public sign-in form. Desktop 1440 x 900 and phone 390 x 844. One light theme.

Rivian paints the site from HSL custom properties (`--brand`, `--stone-*`, `--text-*`, `--surface-*`) and a second Adventure type stack on the R2 page (`adventureFont`). The page is white (`#ffffff`). Text is `#000000`. The header action is a yellow pill (`#ffaa00`). Primary actions on the product page and the sign-in form are black pills. Type is Adventure.

## Do and don't

1. **Do keep the page white and the wordmark black.** The header sits on `#ffffff`. The wordmark uses `currentColor`. See [home-light-default](screenshots/home-light-default.png) and [logo-default](components/crops/logo-default.png).
2. **Do use the yellow pill for Demo drive.** Fill `#ffaa00`, black label, 32px, full pill radius. See [button-demo-default](components/crops/button-demo-default.png).
3. **Do use a black pill for Reserve and Sign in.** Fill `#000000`, white label, 56px. See [button-reserve-default](components/crops/button-reserve-default.png).
4. **Do set display type in Adventure at 72px / 600.** Home h1 computed 72px / 72px, letter-spacing -3px. See [home-light-default](screenshots/home-light-default.png).
5. **Don't invent a dark theme.** The site computed `color-scheme: normal`. No theme toggle was found.
6. **Don't open Design yours, Reserve, or Sign in.** Those controls were measured and never used to configure a vehicle, reserve one, or create an account. See [r2-light-default](screenshots/r2-light-default.png) and [login-light-default](screenshots/login-light-default.png).
7. **Don't treat Rivian orange as the button fill.** `--rivian-orange` resolves to `#e84a26`. The measured header action is `--brand` `#ffaa00`.

## How the values were read

Custom properties were read from the stylesheets on `https://rivian.com/` in the T3 preview browser at 1440 x 900. HSL channel values were resolved by painting each one on a probe element and reading `backgroundColor`. Component colours and sizes were read from computed style on the live DOM: header, Vehicles (open), Demo drive (including focus), hero pills, R2 Reserve and Design yours, charging fields, support search, and the login email, password, and Sign in button. Nothing was typed into a field. Sign in, Reserve, Design yours, and Book a drive were not clicked.

The T3 preview browser returned "The browser is not producing screenshot frames" after the style readings. Screenshots were taken in headless Chromium only after the public homepage loaded there without a Cloudflare challenge. Desktop shots are 1440 x 900 at 1x. The phone shot is 390 x 844 CSS pixels at devicePixelRatio 2, so the PNG is 780 x 1688.

## What to distrust

Demo drive hover and pressed fills are class names (`hover:bg-brand-accent`, `active:bg-brand-accent/85`), which resolve to `#ffbd2e` and that colour at 85% alpha. A synthetic mouseover did not change the computed fill. Those two are declared, not a held state.

The charging loader's green was not read from an element's computed style. The screenshot shows it. It is not a token.

R2 reports pill radius as `16777200px` (the computed form of `rounded-full`). The token uses the 9999px reading from Demo drive and Vehicles, which is the same pill.

Adventure, Adventure Mono, Adventure Display, and adventureFont are proprietary and are not in the package. The style guide falls back to Helvetica. adventureFont 400 and 600 reported as loaded. The Adventure family names reported as unloaded.

`prefers-reduced-motion` rules exist (27 media rules, mostly `no-preference`). The reduce emulation was not run, so the page verdict is not recorded.

Body text on the home page computed 10px. That is the unstyled body, not the type scale. The scale in the tokens is the `--text-*` custom properties plus the computed headings and buttons.

## Fonts

Adventure is the UI face on the home header, the home headings, support, and the login form. adventureFont is the face on the R2 page headings and buttons. Adventure Mono is a declared token with no specimen. All are proprietary. The tokens name them, then Helvetica or system-ui. They are not committed. The wordmark is the header SVG in [icons/wordmark.svg](icons/wordmark.svg), not a text face.

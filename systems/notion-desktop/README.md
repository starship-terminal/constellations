# Notion desktop design reference

A token set and component reference for Notion's desktop app for macOS, version 7.40.0 (Electron 44.9.1, Chrome 152), captured on 2026-10-25 from the owner's signed-in account and workspace. The app is Electron: each tab is its own page loading app.notion.com, and a separate page draws the tab strip above it. This package covers the tab strip and sidebar, a page of blocks with its editing states (the slash menu, the block menu, the formatting toolbar, selection), a database as a table and a board with its cell editors and side peek, menus, the search palette, a destructive confirmation, a toast, the Notion AI panel and every Settings pane but People. Both of Notion's own themes, Light and Dark, were captured at the window size the app was in: 1466 x 955 CSS px (a 36px tab strip over a 919px page) at the owner's 90% zoom.

Everything was read live from the running app over Chromium's remote-debugging port with the Electron route that [cursor-desktop](../cursor-desktop/README.md) piloted ([issue 107](https://github.com/c-wenlong/designs/issues/107)): full-window screenshots of every screen and state, Notion's theme custom properties as they compute and paint, and the computed style of every captured part in every state. [Compared with the earlier desktop routes](#compared-with-the-earlier-desktop-routes) says what differed. Use it to build a calm document and database workspace: a warm secondary grey for the sidebar, a white or near-black page with a 720px column of blocks, ghost controls that only fill on hover, one raised menu surface, coloured pills from ten hue families, and a single blue accent. Notion's iPhone app is in [notion-ios](../notion-ios/README.md); [How desktop differs from iOS](#how-desktop-differs-from-ios) compares the two, and no value here was taken from it.

This package contains no Notion code or artwork beyond the app icon (`icon.png`); the screenshots and the visual system they show are Notion Labs' ([docs/RIGHTS.md](../../docs/RIGHTS.md)). Borrow structure and proportions, not the brand.

### Principles

1. Do put navigation on a warm grey and content on the page colour.
2. Do keep controls ghost until the pointer arrives.
3. Do spend the blue accent on one thing per view.
4. Do give every menu the same surface.
5. Don't colour data with the accent.
6. Do confirm destruction in a small dialog over a dark scrim.

Each rule links the screenshot or crop that shows it, under [Do and don't](#do-and-dont).

## How the values were read

Notion is Electron (`Contents/Frameworks/Electron Framework.framework`). It was not running, so the capture started it with `open -g -a Notion --args --remote-debugging-port=9409 --disable-backgrounding-occluded-windows --disable-renderer-backgrounding --disable-background-timer-throttling`: the extra Chromium switches keep a covered window painting, since other captures were driving other apps on the same screen. The switch was accepted, and the account was already signed in. Notion holds one page target that never answers the DevTools protocol (an empty, unloaded WebContents), and Playwright's `connectOverCDP` waits for every page, so it timed out; [cdp.mjs](tools/capture/electron/cdp.mjs) now pings each page first and, when one stays silent, connects Playwright through a local proxy that hides that target. The window is two pages: the tab strip (`renderer/tabs/index.html`, 36px tall) and one page per tab. The scripts pick the active tab as the one the strip highlights, and [cdp.mjs](tools/capture/electron/cdp.mjs) stacks the strip's screenshot over the tab's (`shootStacked`), so every image is the whole window and every recorded box is shifted to match. [shots.mjs](tools/capture/electron/shots.mjs) drives the shot list in [product.mjs](tools/capture/electron/product.mjs) and [vars.mjs](tools/capture/electron/vars.mjs) reads the custom properties.

**The theme.** Notion's web app declares its theme as about 760 custom properties: `:root, .notion-light-theme` holds the light values and `.notion-dark-theme` (on `<body>` and the app root) overrides them. The names are camelCase abbreviations behind a prefix for how the value is written: `--c-texPri` (primary text), `--ca-borPriTra` (the primary border, translucent), `--c-bluBacAccPri` (the blue accent background), `--c-shaOutMd` (a medium outlined shadow). [build_tokens.py](tools/build_tokens.py) expands each abbreviation into words and files the name into a group, keeping the original name on the token. Notion declares no type, spacing, radius or size scale as custom properties: its components set those inline, so those `core` groups are measured from computed styles of named parts and each token says which.

**Themes.** The owner's setting was Theme: Use system setting. CDP's emulated `prefers-color-scheme` did repaint a tab, but Notion's renderer reports the scheme it sees back to the app, which stored it in `state.json` and repainted every tab, so emulation was not a clean read-only switch. The capture used Notion's own setting instead: Settings > Preferences > Theme set to Dark for the dark pass and Light for the light pass, then back to Use system setting.

**Components and states.** Each shot resets the tab to the scratch page, reveals one state with Notion's own class names (`notion-*-block`, `notion-topbar`, `notion-sidebar`), roles and aria-labels, takes the screenshot and reads the computed style of every listed part. Hover is a real pointer over the part; focus-visible is real keyboard focus, and Notion draws its own blue ring; pressed is `:active` forced through CDP's `CSS.forcePseudoState` with the pointer over the part. Before and after every shot the script compares the theme, the tab strip's tabs, the sidebar's rows and the scratch page's blocks and checkboxes, and stops if any changed. Notion's editor reverts DOM changes inside a page, so parts in the page are found by index and selector, never tagged.

**Sizes.** The window is 1466 x 955 CSS px at a device pixel ratio of 1.8: the owner's View zoom is 90% (`appState.zoomFactor` 0.9) on a 2x display. Every px value is a CSS px; hairlines measure 0.56px (one device pixel).

**What the capture created, changed and put back.** Created and left for the owner to delete: a private page, Design capture (scratch), holding sample blocks written through the Notion API (headings, a paragraph with bold, italic, a link and inline code, lists, two to-dos, a toggle, a quote, a callout, a code block, a divider), and inside it a child database, Sample tasks (scratch), with five rows, a Default view (table), a Board view and an inline linked table view at the foot of the page. Notion placed the page at the top of Private: the section sorts automatically, and dragging it down asked to switch Private to manual sort, which was cancelled. Changed and put back: the sidebar was docked (the owner keeps it collapsed) and collapsed again; the theme went to Dark and Light and back to Use system setting; a new tab was opened for the capture and closed; a slip of a drag widened the sidebar to 570px, which was put back to 270px with the keyboard; a click on Add icon gave the scratch page a random icon, removed through the API. Editing states were typed into new blocks at the end of the scratch page and removed after each shot. Menus, the select and date editors, the side peek, Share and the delete-property confirmation were opened and closed or cancelled. No owner page was edited, moved, shared or commented on; their titles show in the sidebar, the tab strip, the search palette and settings. Notion AI: the owner allowed a harmless prompt in the scratch page, but the account had run out of free AI responses, so Submit stayed disabled and nothing was sent; the typed prompt was cleared. Notion's own bookkeeping changed (launch time, the restored tab order, prewarmed tabs; on next launch the strip opens on the tab beside the one that was active). Notion was quit at the end and not reopened; port 9409 is closed.

## What to distrust

- **Light shows under Use system setting.** macOS was in dark mode, but after the capture Notion's renderer reported a light `prefers-color-scheme`, so with the setting back on Use system setting the app rendered light when it was quit. The stored setting matches the owner's (`usingSystemTheme` true, mode dark); the next normal launch should follow the system again.
- **Names are expanded abbreviations.** `misc.popover-bg` is `--c-popBac`; the expansion table is `ABBR` in [build_tokens.py](tools/build_tokens.py), and a few words are guesses at Notion's shorthand (`wax`, `sus`). Read `$extensions.css` for the real name.
- **Type, radius, spacing and sizes are one element each.** Notion sets them inline, so `core.typography`, `core.radius`, `core.spacing` and `core.controlHeight` hold the value of one named part each, not a scale Notion declares. Fractional heights (27.99px) are the 90% zoom.
- **Component values are one element each.** `component.*` and components.md read the first element that matched each part (or the shot [prefer.py](tools/prefer.py) names). Some parts were read on a wrapper that paints nothing (the toast, the board card, the switch), so their fills are missing.
- **The palette differs by theme.** Notion's `palette` steps are partly declared for one theme only; 14 names present only in dark are under `dark.$extensions.notTokenised`.
- **No AI response.** The AI panel, suggestions, typed input and model menu are real; no streaming or finished response was captured.
- **Nothing is masked.** The screens show the owner's own addresses (on the shared allow list) and page titles, which the repository's rule allows. The image check's boosted OCR cuts one address in the light switcher menu short, so [tools/redact-rules/notion-desktop.json](../../tools/redact-rules/notion-desktop.json) allows that truncated read; check with `--rules` pointing at it.
- **The sample content is the capture's.** Page titles, blocks and database rows on the scratch page are test data.
- Screenshots are 256-colour PNGs. Flat UI colours are exact; read values from tokens.json.

## Do and don't

1. **Do put navigation on a warm grey and content on the page colour.** The sidebar and tab strip sit on `role.surface`; pages, menus and dialogs on `role.page` or `role.raised`. See [page-default](screenshots/light/page-default.png) and [page-default dark](screenshots/dark/page-default.png).
2. **Do keep controls ghost until the pointer arrives.** Share, icon buttons and sidebar rows have no fill at rest and take a translucent one on hover; the block handle and a row's buttons appear only on hover. See [page-button-share-hover](screenshots/dark/page-button-share-hover.png) and [block-hover](screenshots/light/block-hover.png).
3. **Do spend the blue accent on one thing per view.** The New button, checked boxes, switches and the focus ring are blue; everything else is grey. See [database-table](screenshots/light/database-table.png).
4. **Do give every menu the same surface.** The slash menu, the block menu, page actions and selects share one raised panel, row height and hover fill, with a search field when the list is long. See [slash-menu](screenshots/dark/slash-menu.png) and [page-actions-menu](screenshots/light/page-actions-menu.png).
5. **Don't colour data with the accent.** Select values are pills from the ten hue families, one family per option, tinted rather than solid. See [database-board](screenshots/dark/database-board.png).
6. **Do confirm destruction in a small dialog over a dark scrim.** One question, the red action and Cancel stacked full width. See [delete-property-dialog](screenshots/dark/delete-property-dialog.png).

## Rebuild

From the package folder:

```bash
python3 tools/build_tokens.py && python3 tools/build_style_guide.py && python3 tools/build_components_md.py
```

`build_tokens.py` reads `raw/css-vars.*.json` and `raw/components.*.json` and writes `tokens.json`; it refuses a token without a source, an alias that points at nothing, a dimension that is not one px length and a colour that is not hex or rgba, and moves a name present in only one theme to `$extensions.notTokenised`. `build_style_guide.py` renders `style-guide.html` from `tokens.json`; `build_components_md.py` writes `components.md` from the readings, `tokens.json` and the crops. All three are deterministic, standard library only. `python3 tools/crops.py` (needs Pillow) cuts `components/crops/` from the screenshots.

To capture again (Notion must not be running; Playwright from `~/.design-systems/pw`; `PORT=9409` on every command, and `PYTHON` naming a Python with Pillow, which stacks the tab strip onto each screenshot):

```bash
open -g -a Notion --args --remote-debugging-port=9409 --disable-backgrounding-occluded-windows --disable-renderer-backgrounding --disable-background-timer-throttling
node tools/capture/electron/shots.mjs --set-theme=Dark
node tools/capture/electron/shots.mjs dark
KEEP='^--(?!rc-|crop-|safe-|drag-|sidebar-skeleton)' node tools/capture/electron/vars.mjs ~/.design-systems/notion-desktop/raw-shots/dark/css-vars.json 'url:Design-capture-scratch' body .notion-app-inner
```

Then the same with `Light` and `light`, and `shots.mjs "--set-theme=Use system setting"` to put the theme back. The scratch page must be open in its own tab with the sidebar docked first (the shots check both and stop otherwise). `run.mjs dark` opens the AI panel and types a prompt; it sends only when the account has AI responses left. `shots.mjs --from=<name>` resumes a pass that stopped. At the end collapse the sidebar, close the capture's tab and quit Notion (`osascript -e 'tell application "Notion" to quit'`). Then `python3 tools/capture/quantize.py ~/.design-systems/notion-desktop/raw-shots`, which also copies the readings into `raw/`, `crops.py` and the builders. The capture scripts exit non-zero when a required part, a shot or a screen fails.

**What was reused from the earlier desktop packages.** `shots.mjs`, `run.mjs`, `vars.mjs`, `utilities.mjs`, `cdp.mjs`, `crops.py` and `colour.py` are Codex's with generic fixes: [cdp.mjs](tools/capture/electron/cdp.mjs) connects through a filtering proxy when a page target never answers, picks a window by a function as well as by title or URL, and stacks a second page's screenshot above the window's (`shootStacked`, with `box()` shifted to match); `shots.mjs` and `run.mjs` stack the page product.mjs names in `ABOVE` and pass the window to `reset` and `guard`. `utilities.mjs` was not run. Everything marked `PRODUCT (adapt)` is Notion's: `product.mjs` whole, the run frames in `quantize.py` (none), the mapping block of `build_tokens.py` (the abbreviation table, groups, roles, components), `DEFAULT_SHOT` in `prefer.py`, `INVENTORY` and `GAPS` in `build_components_md.py`, and `NAME`, `LEDE`, `GROUP_ORDER` and `specimens()` in `build_style_guide.py`.

## Compared with the earlier desktop routes

| | Cursor 3.27.6 ([cursor-desktop](../cursor-desktop/README.md)) | Codex 26.1013 ([codex-desktop](../codex-desktop/README.md)) | Notion 7.40.0 |

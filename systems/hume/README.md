# Hume AI design reference

A token set and component reference for hume.ai's signed-out surfaces — for building an empathic-AI product's marketing pages, docs and auth shells in the style of the real thing. It was read on **2026-11-17/18**, signed out, in headless Chromium at 1440 x 900 and 390 x 844 (mobile at 2x). Captured: four public origins — **www.hume.ai** (home, /emotion-science, the six /products/* pages, the two /solutions/* pages, /benchmark, /blog + a post, /publications, /about, /careers, /contact-form, /privacy-policy, /terms-of-use, the /explore speech-prosody explorer and the not-found page), **dev.hume.ai** (the Audio Decisions docs: overview, quickstart, API reference, changelog — the one surface with a real theme control, whose header Theme menu painted `html.dark` for the dark shots), **demo.hume.ai** (the Audio Decision Model playground's invitation gate) and **app.hume.ai/log-in** (the sign-in card, never submitted). Themes: light everywhere; dark on the docs only. Widths: 1440 and a 390 mobile pass on home, benchmark, blog, contact, docs, the demo gate and log-in.

hume.ai is worth a capture because the product line pivoted from EVI/Octave TTS to the **Audio Decision Model** — and the public site now shows a distinctive grammar few AI products have: dark-hero marketing over a warm off-white ground, a serif display face (Martina Plantijn) scaled by a `--k` viewport factor, and a **question/answer pattern** whose categorical answers are small pastel pills painted from an eleven-colour `--accent-*` ramp. The www layer is a Next.js + Tailwind v4 build whose `:root` declares the product tokens beside the Tailwind default theme; the docs are a Fern build on a `--gray-1..12`/`--accent-*` layer with the only real theme control on any surface; the demo gate and log-in are their own light layers.

**Boundaries:** the demo.hume.ai playground is gated on an invitation email link and was never entered; app.hume.ai past /log-in (the platform dashboard, API keys, projects) was never entered; EVI and Octave TTS have no public surface post-pivot (demo.hume.ai/evi answers 404); the docs' Search and "Ask AI" were opened for their UI but never queried; the API reference's Send, the contact form, the newsletter Subscribe and the log-in button were measured, never pressed. Nothing was signed into, typed, searched, sent, bought or submitted; the only presses were local UI toggles the product's own chrome provides — the docs Theme menu items, the home player's transport (a scripted sample-call player), the benchmark category tabs, the blog filters and the mobile drawer.

## How the values were read

- **Variables** come from the stylesheets themselves (`tools/capture/vars.mjs`): every same-origin CSS response plus the inline CSSOM is re-parsed, rules binned app/skins/vendor/utility/tailwind, every custom property resolved in a probe carrying the real sheets — the docs once under `<html class="light">` and once under `class="dark"` (the classes the header Theme menu paints), the three light-only surfaces at their painted default. Literal colour declarations are harvested into `palette` with their selectors. `tokens.json` never publishes a raw `oklch()`/`color-mix()`/`lab()` declaration — every colour is the painted value.
- **Geometry** is the live DOM (`tools/capture/public/measure.mjs`): bounding boxes and computed styles per component and state — hover by real mouse, focus-visible by keyboard, pressed by CDP `CSS.forcePseudoState` (no real press, so no button can fire), opened states via the component's own toggle. Layout geometry (`tools/capture/layout.mjs`) reads the shells, grids, sticky layers and inner scrollers at 1440/1920/1024/390.
- **Screenshots** (`tools/capture/public/public.mjs`) record the painted theme in every sidecar: HTML classes, computed `color-scheme` and the document size. Pages taller than one GPU texture are tiled `*.partN` and stitched by `tools/capture/quantize.py`; full-page shots bound at eight chunks with the boundary in the sidecar.
- **Dark states** are painted by the dev.hume.ai header's own Theme button — Light / Dark / System — verified by the painted surface (html class, color-scheme, computed background), never by the mechanism, and Light is restored after. www, demo and app have no theme control: a `.dark` class and a dark colour-scheme emulation leave them unchanged, verified, so no dark marketing evidence exists.
- **The icon collection** (`tools/capture/icons.mjs`) hashes each inline svg's geometry, names it from `tools/capture/icon-names.tsv` or its control's label, and records where each was seen in `icons/INDEX.tsv`.
- **Nothing that submits was ever pressed.** The contact form, newsletter Subscribe, log-in button, the docs API playground's Send, Search and "Ask AI": measured at rest, never used. The home player's Play drives a scripted sample call — a media control, not a submission — and was stopped after.

## What to distrust

- **Font stacks and palette literals were rebuilt in the 2026-11 audit.** The five `core.font.family.*` stacks were hand-written with extra fallbacks; they are now the computed stack of an element that paints each face, verbatim (`body` is `Inter, system-ui, sans-serif`). `font.family.japanese` is again the declared `--font-japanese` value (a hand-written stack had overwritten it). Nine lab()/oklch() palette literals that the builder dropped are now tokens, converted to sRGB.
- **The signed-in product and the demo playground** are the product's own boundaries: app.hume.ai past /log-in and the demo.hume.ai workspace were never entered. The gate and log-in cards are the honest signed-out evidence.
- **EVI and Octave TTS are gone from the public web**: the pivot to the Audio Decision Model / VoiceEQ line retired every public EVI surface — demo.hume.ai/evi answers 404. No EVI demo, waveform or mic-permission surface exists to capture; none is claimed.
- **The /explore explorer is a canvas**: its visualisation is captured as pixels but its internal structure is not DOM — no values are invented for it.
- **The docs Search and "Ask AI" were never queried** (the dialog was opened for its UI, closed with Escape) and the API reference's Send was never pressed — result lists and the used response surface are uncaptured.
- **The channel-triplet vars** on demo and app (`--hume-black`, `--text-primary`, `--background-button`, `--border-button`: declared `R G B` for `rgb(var(--x)/α)` composition) resolve through box-shadow in the harvest and are emitted as their honest `rgb()` colour, with the triplet in the source label.
- **Screenshots are 256-colour PNGs** — read exact colours from tokens.json or the raw files, never the images. The rendered brand strings, author names, headshots and company logos are the product's published content.
- **The brand faces render from licensed files** the site loads; crops show them, the style guide falls back to system fonts — the font files are never shipped.
- **Pressed states** are DevTools-forced; a script-applied mousedown style would not show.
- **Reduced motion is only partly honoured** — `raw/motion.json` records `honours` on the www pages (the authored `*, ::before, ::after { transition-duration: 0.001ms; animation-duration: 0.001ms }` reset stops every moving element), `partial` on the docs (14 of 88 moving elements stopped, 74 keep moving) and `ignores` on the demo and app surfaces (the `spin` loader still loops). The package records the product's behaviour, it does not tidy it.
- **Three components' focus-visible rings** are the only real keyboard focus captured; where a ring could not be held the entry says so instead of claiming one.
- **Readings after two toggles were taken in the toggled page.** `player-card` `playing` pressed Play and never stopped the call, so `player-transport`, `scenario-button`, `benchmark-tab`, the newsletter field and button, `section-heading` and `product-hero` on the home page were read while the sample call played. `blog-filter` `selected` left Research selected. `tools/capture/public/measure.mjs` now stops the player and reselects All after those readings (edited in the 2026-11 audit, not run); a recapture is needed.

## Do and don't

1. **Do open dark over light.** The www pages paint a near-black `#1e1e1d` hero band under the sticky dark nav, then open onto the warm off-white `bg.default` #fdfdfc below the fold ([home](screenshots/home-light-default.png)). Don't flatten it into a single light page or a dark site.
2. **Do set display type in the serif.** Hero and section headlines are Martina Plantijn at the `--k`-scaled `title.*` sizes — 58 px at 1440, 77 px at 1920, ~37 px at 390 — at weight 300 ([hero](screenshots/home-light-full.png)); Inter carries body and UI. Don't reach for a sans display.
3. **Do paint answers as pastel pills.** The question/answer grammar colours every categorical answer from the eleven-step `--accent-*` ramp (pink, magenta, purple, blue, sky, mint, green, lime, orange, coral, salmon) — small tinted chips, never saturated fills ([playing](screenshots/home-light-playing.png), [tokens](tokens.json)).
4. **Do compose questions as type label + answer row.** `Pick One` / `Yes/No` / `Scale` labels lead each rubric row (340 px question column + chip row, 12 px gaps) — the decision-model signature ([decision-model](screenshots/decision-model-light-default.png)).
5. **Do keep CTAs as quiet pills.** The actions are 9999px-radius pills: a white "See a Demo" on the dark nav, black fills (`Contact sales`, `LOG IN`) on the gate and log-in, transparent bordered buttons elsewhere ([CTA](components/crops/nav-cta-default.png), [gate](components/crops/demo-gate-cta-default.png), [login](components/crops/login-submit-default.png)).
6. **Do give the docs a shell, not a page.** The Fern docs are a fixed 93 px header + a 272 px left sidebar in its own scroller + a sticky right TOC; reference pages split prose | code into two 528 px columns ([docs](screenshots/docs-overview-light-default.png), [reference](screenshots/docs-reference-light-default.png)).
7. **Don't invent a dark marketing theme.** www, demo and app have no dark paint — the only dark is the docs' `html.dark`, repainted by its own Theme menu ([docs dark](screenshots/docs-overview-dark-default.png)). Dark tokens outside `dark.docs.*` do not exist.
8. **Don't style the gated product from this package.** The demo playground and everything past /log-in are boundaries ([gate](screenshots/demo-gate-light-default.png), [login](screenshots/login-light-default.png)); EVI and Octave have no public surface left.
9. **Don't copy the brand or the faces.** The wordmark, icon set, Martina Plantijn, PP Fraktion Mono, Fellix and Fraktion are Hume's and its licensors' ([wordmark](screenshots/home-light-default.png)); the tokens describe the system, not its artwork.
10. **Don't ship reduced-motion users the full motion.** The product itself only partly honours `prefers-reduced-motion` (verdict `partial`; the `spin` loader loops). Anything built from this package should do better ([raw/motion.json](raw/motion.json)).

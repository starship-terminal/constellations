# Devin desktop design reference

A token set and component reference for the Devin desktop app for macOS (Cognition), version 3.11.216 (Electron 42.11.16, Chrome 148; the bundle id is `com.exafunction.windsurf` and the app is VS Code 1.126.0 with Windsurf's workbench), captured on 2026-10-25 from the owner's signed-in account in the cortexairobot organisation. A Devin window is one workbench with two views. The Agents view is the Devin web app mounted in the window: a sidebar of sessions, one composer that starts a cloud or local session, the session transcript with its Changes and PR panes, Automations, Wiki, Review, Customize, the command palette, the inbox and Settings. The IDE view is the VS Code workbench under Devin's theme, with a Devin session in its right-hand pane. Both were captured, in Devin Light and Devin Dark, at the window size the app was in: 1440 x 900 pt.

Everything was read live from the running app over Chromium's remote-debugging port with the Electron route that [cursor-desktop](../cursor-desktop/README.md) piloted ([issue 107](https://github.com/c-wenlong/designs/issues/107)): full-window screenshots of every screen and state, the theme's custom properties as they compute and paint, the Tailwind utility classes the screens use, and the computed style of every captured part in every state. [Compared with Cursor](#compared-with-cursor) says what differed. Use it to build a dense desktop agent tool: a near-black or near-white page, a quiet sidebar on the same page colour, raised surfaces only for the composer, cards and popups, every neutral one colour at fixed alphas, an ink button for page actions and blue only for focus, links and the selected switch.

This package contains no Devin code or artwork beyond the app icon (`icon.png`); the screenshots and the visual system they show are Cognition's ([docs/RIGHTS.md](../../docs/RIGHTS.md)). Borrow structure and proportions, not the brand.

## Brief

<!-- brief:start. Generated by tools/brief.py from catalog.json, the tokens file and this README; `make brief` rewrites it. Do not edit. -->

Read this before designing in this style. Take every value from [tokens.json](tokens.json), never from the screenshots; `python3 tools/catalog.py export devin-desktop` prints them all with aliases resolved.

### Principles

1. Do build every neutral from one colour at fixed alphas.
2. Do put the sidebar on the page colour and raise only the composer, cards and popups.
3. Do make page actions ink buttons, not blue ones.
4. Do use one segmented control for every either-or.
5. Do give the prompt the only bubble and fold the agent's work into muted rows.
6. Don't colour a warning box; tint it.

Each rule links the screenshot or crop that shows it, under [Do and don't](#do-and-dont).

## How the values were read

Devin is an Electron app (`Contents/Frameworks/Electron Framework.framework`), so its interface is HTML and CSS. It was not running; it was opened with `open -a Devin --args --remote-debugging-port=9402`, which it accepted, and Playwright attached with `chromium.connectOverCDP`. The account was already signed in; nothing was typed into a sign-in screen. Devin reopened the owner's last window (the quiver workspace). The capture did not work in it: it opened a window of its own on an empty scratch folder, `devin-desktop --new-window ~/.design-systems/harness-scratch/devin`, and every shot ran there (its title ends in the folder name, `devin`). The scripts are in [tools/capture/electron/](tools/capture/electron): [cdp.mjs](tools/capture/electron/cdp.mjs) connects and picks a window by its title, [shots.mjs](tools/capture/electron/shots.mjs) drives the shot list in [product.mjs](tools/capture/electron/product.mjs), [vars.mjs](tools/capture/electron/vars.mjs) reads the custom properties, [utilities.mjs](tools/capture/electron/utilities.mjs) reads the utility classes and [run.mjs](tools/capture/electron/run.mjs) captures an agent run. Screenshots are CDP's `Page.captureScreenshot`, the window's own backing store.

**The theme engine.** The Agents view is a Tailwind v3 app. Its theme is about 70 colour channels declared per theme on `.devin-app-root.dark` and `.devin-app-root.light` in `index.css`, such as `--text-secondary: 255 255 255 / 0.52`, and painted as `rgb(var(--text-secondary))` through a `devin-host-base` layer. So every neutral is one colour at a fixed alpha: white in dark (text at 90, 52 and 40%, fills at 8, 5 and 3%, edges at 8 and 4%) and near-black (13, 13, 13) in light (text at 90, 56 and 40%, fills at 8, 6 and 4%, edges at 10 and 8%), plus a page, a wash and an elevated fill, and six flat hues. A bare triplet is not a colour, so [vars.mjs](tools/capture/electron/vars.mjs) paints each one a second way, `rgb(var(--x))` on a probe element, and lists those names under `channels`. The workbench's `windsurfDesignTokens` style element maps the VS Code colour ids onto the same values, so the IDE view's editor is `bg.page`, its bars `bg.wash` and its button `bg.accent-primary`. Tailwind's scales (type, radius, spacing, durations) are not custom properties: [utilities.mjs](tools/capture/electron/utilities.mjs) walked 24 screens (25 in light) and recorded every single-class rule on screen (`.devin-app-root .text-13 { font-size: calc(.8125rem * var(--text-scale,1)); ... }`) with how many elements used it, and [build_tokens.py](tools/build_tokens.py) turns those into the core scales.

**Themes.** Devin's theme does not follow an emulated `prefers-color-scheme` (CDP `Emulation.setEmulatedMedia` left `.devin-app-root.dark` in place), so the owner's own setting was switched: Settings > Preferences > Theme was Dark, set to Light for the light pass and back to Dark at the end. Choosing a theme also wrote `"window.autoDetectColorScheme": false` to the user settings file; the file was restored from a copy taken before launch after Devin was quit, and only that line had changed. High contrast mode (System) was not touched.

**Components and states.** Each shot resets the window to the New session page, reveals one state with Devin's own selectors (its `data-slot` names, roles, aria-labels and fixed UI labels, never account text), takes the screenshot and reads the computed style of every listed part, recording its box for [crops.py](tools/crops.py). Hover is a real pointer over the part. Focus-visible is real keyboard focus (a key press, then `focus()`); Devin draws its own ring (`.focus-ring`: a 1px outline in `border.accent-primary`), so nothing was added. Pressed is `:active` forced through CDP's `CSS.forcePseudoState` with Base UI's `data-pressed` attribute set on the part, because Devin's controls style the press through that attribute (`data-[pressed]:bg-tint-secondary`); segments got no pressed shot, since `data-pressed` is their selected state. Before and after every shot the script compares the composer's mode and capability, any unsent draft and the sidebar's session titles, and stops if one changed.

**Sizes.** The window is 1440 x 900 CSS px at a device pixel ratio of 2, unzoomed: Settings > Preferences > Interface font size is 13 and `--text-scale` is 1. Every px value is a CSS px.

**The agent run.** The owner approved test prompts on 2026-10-25 in a fresh session on an empty folder. Local agents are off in an untrusted folder (Devin shows a warning banner and the workbench's trust dialog), so the capture trusted its own scratch folder, `~/.design-systems/harness-scratch/devin`, and nothing else. [run.mjs](tools/capture/electron/run.mjs) chose Local in the composer (Devin Local, the devin-cli agent, SWE-2 Max, in the owner's Bypass Permissions mode), sent "List the files in this folder." and "Create hello.txt here with one line: hello from the design capture", screenshotting and measuring every 1.2 to 1.5 s until each finished, then chose Cloud again. One session was run in each theme; Devin titled both List Files in the Current Folder. The agent wrote `hello.txt` in the scratch folder (the light session read it and left it). No approval prompt appeared: Bypass Permissions runs commands without asking, and nothing was changed to force one. Every turn also printed Hook failed: ... vibe-island-bridge (exit 127), a hook from the owner's own setup.

**What else changed, and what was put back.** The theme and the settings line are above. The scratch folder's trust was removed afterwards (Workspace Trust > Delete Path; the six folders the owner had trusted before are untouched), its window was closed so it does not reopen, and Devin was quit and not reopened; port 9402 is closed. Left in place: the two local test sessions (in the sidebar's Recent group), `hello.txt`, eight new message stores under `User/acp-messages/` and two `workspaceStorage` entries that Devin wrote for them and for the scratch window. Menus, dialogs and the palette were opened and closed with Escape or Cancel; text typed into the composer and the settings search was cleared without sending; the composer stayed on Cloud, Agent and Normal. One slip that could not be undone: opening the owner's cloud session Change Scene Limit Bar to 10 Hours, which was asleep, woke it; Devin worked for 8 seconds, posted a short closing message and went back to awaiting instructions, and the session moved to the top of the list. It is the session the [conversation](screenshots/dark/conversation.png) screens show; the other cloud session opened, Check MiniPCs Online, was already awake and did not change. The dark retake on 2026-10-25 opened no session, sent no prompt and left the folder untrusted and the theme on Dark; it expanded the sidebar's Participated group, which the owner had collapsed, and collapsed it again afterwards, closed its scratch window and quit Devin. Devin left two more `workspaceStorage` entries, one per launch, for an untitled workspace it opened and removed itself.

## What to distrust

- **Two dark screenshots still carry a stray toast.** The workbench's error toast (The terminal process failed to launch: Cannot launch a terminal process in an untrusted workspace) was raised by a trial terminal shot before the first dark pass and stayed in the bottom-right corner until the light pass dismissed it, so 90 dark screenshots showed it (a template match for its icon and first line; an earlier scan for its red icon alone counted 51). 88 were retaken on 2026-10-25 with the toast closed, all but [conversation](screenshots/dark/conversation.png) and [conversation-code-hover](screenshots/dark/conversation-code-hover.png): those show the owner's cloud session, and the capture no longer opens a session it did not create, so they are kept from the first pass with the toast in place (it covers no measured part). The [toast](screenshots/dark/toast.png) screens show it on purpose. Light screenshots are clean. The capture now closes any toast before each shot and fails a shot that has one on screen.
- **The light and dark home screens differ in the sidebar.** After the folder was trusted, the sidebar gained a Recent group of local sessions, so light screens taken after the run (and the `home-local-trusted` screens) show it. The dark Agents-view screens were retaken later, so their session times are a few hours later than in light; their sidebar also holds a Recent group below the visible list.
- **The accent has no hover tier of its own.** `role.accent.hover` and `role.accent.pressed` are the workbench's `button.hoverBackground`; Devin's own controls never fill with the accent except the switch, the checkbox and focus rings.
- **Row focus crops show no ring.** For sidebar, session and settings-navigation rows the capture focused the row element; the focusable element is the link inside it (`.focus-ring-inset`), so those `-focus-visible` crops look like the default. Controls show the ring.
- **Component values are one element each.** `component.*` and components.md read the first element that matched each part; they are not counts across pages.
- **Run frames are timed, not chosen.** The `run-*` screenshots are frames 1.2 to 1.5 s apart; the states named (started, working, editing) are what was on screen then. The two themes' runs differ in content: the light session found `hello.txt` already there.
- **The IDE editor's font is the workbench's.** The editor draws in Menlo (VS Code's default stack), not Devin Mono, which only the Agents view uses.
- **Redacted:** the linked Slack account's address on the [settings-connections](screenshots/dark/settings-connections.png) screens is painted out (an OCR check read it as a non-allowed address), and so are the requesters' usernames and initial avatars in the two access-request rows of the [notifications](screenshots/dark/notifications.png) screens (other people, masked since the repository went public), with the `notification-row` crops cut again from the masked screens by `crops.py`; [tools/redact-rules/devin-desktop.json](../../tools/redact-rules/devin-desktop.json) holds the rectangles. Re-running `quantize.py` brings it back; run the redaction again after it.
- Screenshots are 256-colour PNGs. Flat UI colours are exact; read values from tokens.json.

## Do and don't

1. **Do build every neutral from one colour at fixed alphas.** Text is white at 90, 52 and 40% in dark and near-black at 90, 56 and 40% in light; fills are the same colour at 8, 5 and 3% (8, 6 and 4% in light), edges at 8 and 4% (10 and 8%). See [settings-preferences](screenshots/dark/settings-preferences.png) and [settings-preferences light](screenshots/light/settings-preferences.png).
2. **Do put the sidebar on the page colour and raise only the composer, cards and popups.** The sidebar and the page are both `bg.page`; the composer, settings cards and automation cards sit on `bg.elevated` with a hairline, and menus on the elevated fill at 94% with the large shadow. See [home-default](screenshots/light/home-default.png) and [attach-menu](screenshots/dark/attach-menu.png).
3. **Do make page actions ink buttons, not blue ones.** Create automation, Add wiki and Generate are `bg.accent-neutral` (white in dark, near-black in light) with inverse text; blue is kept for focus, links, the on switch and the checkbox. See [automations](screenshots/light/automations.png) and [wiki](screenshots/dark/wiki.png).
4. **Do use one segmented control for every either-or.** Cloud / Local, the automation categories and the inbox's All / Unread are the same track with a raised selected segment. See [home-local-trusted](screenshots/dark/home-local-trusted.png) and [notifications](screenshots/dark/notifications.png).
5. **Do give the prompt the only bubble and fold the agent's work into muted rows.** The user's message is a right-aligned tinted bubble; Worked for, Thoughts and Read are single muted lines; the reply is plain text. See [conversation-local](screenshots/dark/conversation-local.png) and [run-editing](screenshots/light/run-editing.png).
6. **Don't colour a warning box; tint it.** The Restricted Mode banner is the orange hue at 8 to 12% with orange text, and the danger button is red text on the neutral hairline. See [home-local](screenshots/dark/home-local.png) and [settings-connections](screenshots/light/settings-connections.png).

## Rebuild

From the package folder:

```bash
python3 tools/build_tokens.py && python3 tools/build_style_guide.py && python3 tools/build_components_md.py
```

`build_tokens.py` reads `raw/css-vars.*.json`, `raw/utilities.*.json` and `raw/components.*.json` and writes `tokens.json`; it refuses a token without a source, an alias that points at nothing, a dimension that is not one px length and a colour that is not hex or rgba, and moves a name present in only one theme to `$extensions.notTokenised`. `build_style_guide.py` renders `style-guide.html` from `tokens.json`; `build_components_md.py` writes `components.md` from the readings, `tokens.json` and the crops. All three are deterministic, standard library only. `python3 tools/crops.py` (needs Pillow) cuts `components/crops/` from the screenshots.

To capture again (Devin must not be running; Playwright from `~/.design-systems/pw`; `SLUG=devin-desktop PORT=9402` on every command):

```bash
open -a Devin --args --remote-debugging-port=9402
/Applications/Devin.app/Contents/Resources/app/bin/devin-desktop --new-window ~/.design-systems/harness-scratch/devin
node tools/capture/electron/shots.mjs dark $(node -e "import('./tools/capture/electron/product.mjs').then(P=>console.log(P.SHOTS.map(s=>s.name).filter(n=>!P.AFTER_RUN.includes(n)).join(' ')))")
node tools/capture/electron/utilities.mjs ~/.design-systems/devin-desktop/raw-shots/dark/utilities.json '(^|\s)devin$' .desktop-shell-root --shots=home-default,settings-preferences,...
KEEP='^--(bg|text|border|tint|shadow|diff|word-diff|d2h|chart|sidebar|font|window-header|pending|red|orange|yellow|green|blue|purple)(?!-\d)(-|$)' node tools/capture/electron/vars.mjs ~/.design-systems/devin-desktop/raw-shots/dark/css-vars.json "Sessions devin" .devin-app-root
KEEP='^--vscode-(?!icon-)' node tools/capture/electron/vars.mjs ~/.design-systems/devin-desktop/raw-shots/dark/css-vars.ide.json devin .monaco-workbench
```

Repeat in light (`shots.mjs --set-theme=Light`). The last vars.mjs line needs the window in the IDE view. Before each shot `reset` closes any workbench toast, and `beforeShoot` fails a shot that has one on screen (except `toast`); `conversation` and `conversation-code-hover` are not in the list, because they opened an owner's session, and `quantize.py` keeps their screenshots and readings (its `KEPT`) when a capture does not have them. Then trust the scratch folder (choose Local, Trust Workspace & Continue), run `node tools/capture/electron/run.mjs <theme>` and `shots.mjs <theme>` with the names in `AFTER_RUN`, in each theme; set the theme back with `--set-theme=Dark`; remove the folder's trust (Workspaces: Manage Workspace Trust > Delete Path); close the scratch window; quit Devin (`osascript -e 'tell application "Devin" to quit'`); restore the settings file if the theme switch wrote `window.autoDetectColorScheme`. Then `python3 tools/capture/quantize.py ~/.design-systems/devin-desktop/raw-shots`, which also copies the readings into `raw/`, the redaction (`python3 tools/redact_images.py apply systems/devin-desktop --rules tools/redact-rules/devin-desktop.json --patterns ~/.design-systems/cleanup-redact.json`, from the repository root), `crops.py` and the builders. The capture scripts exit non-zero when a required part, a shot, a screen or a run step fails.

**What was reused from the Cursor pilot.** `cdp.mjs` is Cursor's, unchanged. `shots.mjs` and `run.mjs` are Cursor's except their default output folder, which now comes from the package the script sits in (the pilot's copies default to `cursor-desktop`, so run unchanged from another package they would write into Cursor's folder), and `shots.mjs` calls an optional `beforeShoot` from `product.mjs` right before each screenshot. `vars.mjs` gained two generic fixes: it skips the empty property names Chromium's style iteration returned on some of Devin's rules (the pilot's copy threw on them), and it paints bare channel triplets as `rgb(var(--x))`. `utilities.mjs` is new and generic: any app styled with utility classes needs it to see its scales; it writes nothing and exits non-zero when a screen fails. [rename_parts.py](tools/capture/rename_parts.py) records one part renamed after review (the search field's input). `quantize.py` also copies the vars and utilities readings into `raw/`. Everything marked `PRODUCT (adapt)` is Devin's: `product.mjs` whole, the run frames and `KEPT` in `quantize.py`, the mapping block of `build_tokens.py`, `INVENTORY` and `GAPS` in `build_components_md.py`, and `NAME`, `LEDE` and `specimens()` in `build_style_guide.py`.

## Compared with Cursor

Both apps are VS Code-based Electron apps with an agent-first view beside the editor; they get there differently.

| | Cursor 3.27.6 ([cursor-desktop](../cursor-desktop/README.md)) | Devin 3.11.216 |
|---|---|---|
| Windows | Two windows: the Agents window and the IDE window | One window per folder with two views (Agents view, IDE view) switched in place |
| Agent surface | Cursor's own React app (`anysphere-ui`) | The Devin web app (`app.devin.ai`, React, Tailwind v3, Base UI) mounted in the workbench |
| Theme engine | About 135 seed colours, the rest `color-mix()` formulas in oklch | About 70 channel triplets per theme, painted as `rgb(var(--x))`; scales are Tailwind classes, not variables |
| Neutrals | One base colour at fixed alphas | The same idea: white or near-black at fixed alphas |
| Primary action | Accent blue | Ink (white or near-black); blue only in the workbench's dialogs |
| Theme switch | Settings > Appearance > Theme; did not follow emulated media | Settings > Preferences > Theme; did not follow emulated media; wrote one settings line |
| Hover | Needed a real pointer | Needed a real pointer |
| Focus | No ring without `[data-focus-ring]` on the root | Draws its own 1px accent ring |
| Pressed | `:active` | Base UI's `data-pressed` |
| Zoom | 0.84 (UI font size 11) | None |
| Test run | A chat with the scratch folder as its environment | A local session (devin-cli) after trusting the scratch folder |
| Approval prompt | Not seen (auto-run) | Not seen (Bypass Permissions) |

## The Electron route, as it went

| Step | What happened |
|---|---|
| Port | Devin accepted `--remote-debugging-port` on the first launch and reopened the owner's last window; the capture opened a second window on the scratch folder with the app's own CLI and worked only there |

| Values | Colours are channel triplets, so vars.mjs paints them through `rgb(var())`; the scales come from the utility classes (utilities.mjs) |

| Pressed | Base UI's `data-pressed` set by the capture while `:active` is forced |

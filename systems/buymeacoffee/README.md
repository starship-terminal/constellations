# Buy Me a Coffee design reference

A token set and component reference for Buy Me a Coffee's public surface — for
building marketing pages and creator-facing widgets in the style of the real
thing. It was read from **buymeacoffee.com** on **2026-11-11**, signed out, in
headless Chromium at 1440 x 900 and 390 x 844. Captured: the home, FAQ, Wall of
Love, blog, brand-kit, about, stream-alerts and terms pages (the Nuxt marketing
surface), the public creator page /cara.app (the Vite-built product surface —
support widget, tabs, tiers), the login and signup cards, and a 390px mobile
pass.

Buy Me a Coffee is worth a capture because its friendly "fund your creative
work" positioning paints two related systems: a marketing site of Circular Bold
type (a 96px display at -2.4px tracking) on a warm `#faf8f0` cream field with
`#222` ink and the `#ffdd00` yellow pill CTAs — links and triggers grow a 5%-black
`::before` pill at a 40px radius on hover — and a public creator page on white
where the support widget, quantity pills, fields and checkboxes repaint per
creator through inline `--theme-color*` custom properties (`#ff813f` on
/cara.app, `#ff6b1c` on hover), with Tailwind's `#2563eb` focus ring on the
fields. **Boundary:** the creator dashboard lives behind /login — the page
editor, membership/shop/extras managers, payouts, analytics and settings were
never reached; the Stripe checkout behind the Support and Join buttons was never
opened; the login card's password step sits behind the un-submitted
Continue-with-email action.

## Brief

<!-- brief:start. Generated by tools/brief.py from catalog.json, the tokens file and this README; `make brief` rewrites it. Do not edit. -->

Read this before designing in this style. Take every value from [tokens.json](tokens.json), never from the screenshots; `python3 tools/catalog.py export buymeacoffee` prints them all with aliases resolved.

### Principles

1. Do set everything on the cream field.
2. Do spend the yellow on the pills.
3. Do grow the hover pill.
4. Do run the display type huge and tight.
5. Do theme the widget per creator.
6. Do keep the widget white, soft and round.
7. Don't style the dashboard or checkout from this package.
8. Don't invent a dark theme.

Each rule links the screenshot or crop that shows it, under [Do and don't](#do-and-dont).

| accent | #ffdd00 `core.color.brand.yellow` |
| border | #e5e5e5 `core.color.neutral.divider` |

Fonts: `core.font.family.bold` is Circular Bold, with no fallback; `core.font.family.regular` is Circular Regular, with no fallback; `core.font.family.medium` is Circular Medium, with no fallback; `core.font.family.book` is Circular Book, then 1 fallback; `core.font.family.borel` is Borel Regular, with no fallback; `core.font.family.app` is ui-sans-serif, then 6 fallbacks. Scales, counted as [DESIGN.md](DESIGN.md) holds them: no type styles under `core.typography`, 9 radius steps (`core.radius`), no spacing steps under `core.spacing`.

## How the values were read

Every value came off the running signed-out site in headless Chromium:

- **Tokens.** [tools/capture/vars.mjs](tools/capture/vars.mjs) captures every
  stylesheet body — the 35 marketing `_nuxt` stylesheets plus the 20
  cross-origin creator-app stylesheets served from cdn.buymeacoffee.com (the
  creator page is a separate Vite build) — and writes every custom property to
  [raw/css-vars.json](raw/css-vars.json) (580 rules, 17 font faces). The site
  declares no design-token layer beyond three `:root` layout vars, so nearly
  every value is a measured computed style; the exception is the creator
  page's inline `--theme-color*` accent set (`#ff813f` and its alpha and hover
  variants), read off the DOM verbatim. [tools/build_component_tokens.py](tools/build_component_tokens.py)
  writes the spec, [tools/build_tokens.py](tools/build_tokens.py) the sets.
- **Components.** [tools/capture/public/measure.mjs](tools/capture/public/measure.mjs)
  opens each route in a fresh context and reads `getComputedStyle`, painted
  layers and boxes per element in default, hover, focus-visible and a
  CDP-forced pressed state — 62 components, 151 states. Results in
  [raw/components-computed.json](raw/components-computed.json) and
  [raw/measurements.md](raw/measurements.md). The marketing links' hover pill
  is a `::before` layer, so the readings record painted layers rather than
  trusting the wrapper.
- **Screenshots.** [tools/capture/public/public.mjs](tools/capture/public/public.mjs)
  takes viewport and full-page shots per route (full pages in bounded chunks,
  8 max) with `.capture.json` sidecars, including the local UI toggles: the
  `Apps` nav dropdown, the search-creators overlay, the creator widget's
  three-coffee quantity and monthly checkbox, the more-options menu and the
  mobile menu. [tools/capture/quantize.py](tools/capture/quantize.py)
  posterises them to 256 colours.

Nothing was signed into, bought, supported or submitted: the login card's Email
field was focused and filled once with a throwaway address, then cleared; the
Support and Join actions and every Sign-up / Start-my-page link were measured,
never pressed or followed; the Report item in the more-options menu was never
followed. The CookieYes consent overlay was hidden before every shot and
measurement, never answered — no consent button was ever clicked.

## What to distrust

- **Readings past a masked bot signal.** The committed screenshots and readings were taken with `navigator.webdriver` masked, the flag bot checks read to spot automation. The capture scripts no longer mask it (not run since), so a recapture may record a walled route as a boundary instead of a reading.
- **This is the public shell, not the product.** The dashboard, membership,
  shop and extras managers, payouts, analytics and settings sit behind /login
  and are uncaptured. The public creator page *is* a real product surface —
  the support widget and tier cards are the shipped components — but the
  payment checkout behind it is Stripe's and was never opened.
- **Two frontends, one light theme.** The marketing pages are a Nuxt/Vue app
  on a cream field; the creator page, login and signup are a separate Vite
  build on white, styled through Tailwind utilities plus inline
  `--theme-color*` vars. Nothing dark paints anywhere; `dark` in tokens.json
  is an empty set.
- **The accent is per-creator, not global.** `#ff813f` comes from /cara.app's
  inline `--theme-color`. Other creators paint other accents; the marketing
  site itself never uses the orange — its accent is the `#ffdd00` yellow.
- **The yellow pill never repaints.** `nav-cta`, `hero-cta` and `l-cta` keep
  `#ffdd00` across default/hover/pressed in most readings; on the marketing
  links the visible hover fill is a `::before` layer that grows a dark-5%
  pill. `l-cta` does go `#ffc800` on hover. Copy the layers, not just the
  computed fill.
- **Quantised screenshots.** `screenshots/` are 256-colour PNGs; read exact
  colours from tokens or the raw files.
- **The creator names, avatars and tweets are published content.** The
  screenshots show real creators' public pages and testimonials — layout and
  proportion evidence only.

## Fonts

Two served families do everything. **Circular** — Regular, Book, Medium, Bold
and Black — runs both frontends: the 96px display is Circular Bold, body and
nav copy are Regular and Medium, the creator widget mixes Regular and Medium.
**Borel Regular** is the single display accent — the Wall-of-Love script
lettering. Both are served from buymeacoffee.com/_nuxt and
cdn.buymeacoffee.com; none is distributed with the package — the style guide
falls back to system sans. The `interface`, `nexablack`, `SSStandard` and
`SSSocial` faces in the CSS are vendor/icon fonts, not product type.

## Do and don't

1. **Do set everything on the cream field.** The marketing pages paint on
   `#faf8f0` with `#222` ink — the warmth, plus Circular Bold, is the whole
   look. See [home-light-default](screenshots/home-light-default.png).
2. **Do spend the yellow on the pills.** `#ffdd00` is the CTA colour only —
   nav Sign-up, hero Start-my-page, login Continue — never a background or a
   link. See [hero-cta](components/crops/hero-cta-default.png).
3. **Do grow the hover pill.** Marketing links and triggers keep their paint;
   a `::before` layer expands to a dark-5% pill at a 40px radius on hover.
   See [nav-link](components/crops/nav-link-hover.png).
4. **Do run the display type huge and tight.** The hero is Circular Bold 96px
   at -2.4px tracking on a 95px line; section heads run 64px at -2px. See
   [hero-title](components/crops/hero-title-default.png).
5. **Do theme the widget per creator.** On the creator page the accent is the
   page's `--theme-color`: quantity pills, field focus borders, checkboxes
   and the Support/Join buttons repaint to match — copy the mechanism, not
   just the orange. See [c-qty-on](components/crops/c-qty-on-default.png) and
   [c-support](components/crops/c-support-default.png).
6. **Do keep the widget white, soft and round.** 24px-radius white cards, 12px
   fields on `#f0f0f0` that turn white with a 2px border on focus, 9999px
   pills and checkboxes at 6px. See [c-widget](components/crops/c-widget-default.png)
   and [c-name](components/crops/c-name-focused.png).
7. **Don't style the dashboard or checkout from this package.** Every value is
   the public surface's; the signed-in product and the Stripe flow are
   uncaptured.
8. **Don't invent a dark theme.** Nothing dark paints on the public surface;
   the `dark` token set is intentionally empty.

## Rebuild

Everything derived regenerates offline from the raw readings (run from
`systems/buymeacoffee/`):

```sh
python3 tools/build_component_tokens.py        # raw/components-computed.json -> raw/component-tokens.json
python3 tools/build_tokens.py                  # -> tokens.json
python3 tools/build_style_guide.py             # -> style-guide.html
python3 tools/build_components_md.py           # -> components.md
node tools/capture/public/build-measurements.mjs  # -> raw/measurements.md
python3 tools/capture/quantize.py <raw-dir>    # full-colour PNGs -> screenshots/
```

Then `make brief && make design-md && make grade && make check` from the repo
root refreshes the generated sections and validates the catalog.

Live recapture (needs the site; Playwright at
`PLAYWRIGHT=~/.design-systems/pw/node_modules/playwright/index.mjs`):

```sh
node tools/capture/vars.mjs                    # stylesheet harvest -> raw/css-vars.json
node tools/capture/public/measure.mjs          # computed styles + crops -> raw/components-computed.json
RAW=<scratch> node tools/capture/public/public.mjs   # screenshots -> <scratch> (incl. the menu/search/widget toggles)
```

buymeacoffee.com loads headless from this client; the creator page's
stylesheet harvest needs its cross-origin CDN responses captured on the
creator route itself (public.mjs's vars step does this). The dashboard stays
behind /login.

# Leonardo.Ai design reference

A token set and component reference for Leonardo.Ai's public signed-out website, for building creator-first generative-media marketing pages and a dark prompt shell in the style of the real thing. It was read from **leonardo.ai**, **app.leonardo.ai** and **docs.leonardo.ai** on **2026-11-18**, signed out, in headless Chromium at 1440 x 900 and 390 x 844. Captured: the home page, pricing, API, Learn, contact, the image-generator marketing page and a 404 on the marketing surface; the signed-out app shell and public Blueprints; the login card; the docs getting-started page; and 390px passes on the marketing home (including the nav drawer), the app shell and the login card.

Leonardo.Ai is worth a capture because the public product is one dark paint across three hosts. Marketing is a black canvas with a violet `#6e60ee` wordmark and a white Start now pill. The signed-out app is `#0a0a0a` with a white display heading, a prompt bar and a muted Generate. The docs are ReadMe, painted dark, with a declared `data-color-mode` light alternate that the public page does not paint. **Boundary:** Library, account, generation, checkout, API keys and OAuth were never entered. Start now, Subscribe, Log in, Generate and the provider buttons were measured where they painted, never followed. The prompt was filled and cleared. The consent overlay was hidden, never answered.

### Principles

1. Do paint the canvas black and spend violet on the wordmark.
2. Do keep Start now white.
3. Do set the app heading in a heavy display face.
4. Do mute Generate until an account exists.
5. Do use ghost pills for OAuth.
6. Do keep the rail narrow.
7. Don't invent a light marketing theme.
8. Don't follow Log in, Start now, Subscribe, Generate or an OAuth provider from this package.
9. Don't treat the wordmark field as type.

Each rule links the screenshot or crop that shows it, under [Do and don't](#do-and-dont).

## What to distrust

- **The home measurement pass missed the nav.** Cloudflare blocked the retry. Header, Pricing, Log in, Create and Start now are in the screenshots and were not boxed. Do not invent their pixel sizes.
- **Generate looks disabled.** Its fill is `#262626` and its text is `#737373`. That is the signed-out paint. Submitting it was out of scope, so the enabled state is unknown.
- **The light set is the docs color mode only.** `--background` and the other product roles sit on `:root` and do not switch with the docs color mode, and the product never paints light, so they are in `dark` only. There is no `light.color.page`: a light design uses `light.color.docs.*`.
- **`--accent` is neon green, not the brand.** The violet is `--accent-brand` / `--color-purple` (`#6e60ee`). The token path is `core.color.accent.brand` and `dark.color.accent`. `core.color.neon` is the green.
- **Quantised screenshots band gradients.** Read exact colours from tokens.json. The wordmark field is a graphic, not a type style.
- **Docs search paints black text on a dark field.** That computed colour is the reading. Do not "fix" it.
- **App font stacks are measured, not variables.** canvaSans, ufficioDisplay, leoSans and leoRenaisans come from computed `fontFamily` and `@font-face`. `--font-sans` is the Tailwind system stack. The display tokens drop next/font's `"… Fallback"` placeholder face; where the measured stack has no generic family (`app-display`, `marketing`), the trailing `sans-serif` is a hand-written fallback and its source says so.
- **Captured past automation masking.** Every committed reading and screenshot was taken with `navigator.webdriver` masked, and the screenshots with a saved challenge-clearance `storageState` replayed across runs. Both were removed from the capture scripts (bot checks are now recorded as a boundary, not bypassed); the readings were kept and were not retaken.
- **`app-generate` focus-visible was not captured.** Keyboard focus never landed (`via: focus failed` in raw); components.md lists it as not capturable, and `components/crops/app-generate-focus-visible.png` is the element at rest, not a focus look.

## Do and don't

1. **Do paint the canvas black and spend violet on the wordmark.** Marketing is `#000` / `#0a0a0a` with `#6e60ee` as the graphic, not as every button. See [home-dark-default](screenshots/home-dark-default.png).
2. **Do keep Start now white.** The marketing primary is a white pill on the black field. The outline pill is the secondary. See [home-dark-default](screenshots/home-dark-default.png).
3. **Do set the app heading in a heavy display face.** "YOURS TO CREATE" is leoRenaisans at about 73px / 700, white on the image. Body and the prompt stay canvaSans at 13px. See [app-h1](components/crops/app-h1-default.png).
4. **Do mute Generate until an account exists.** Signed out it is a `#262626` pill with `#737373` text. Do not paint it violet. See [app-generate](components/crops/app-generate-default.png).
5. **Do use ghost pills for OAuth.** Equal-width rows, about 32.5px tall, 9.75px radius, white at low opacity. See [li-canva](components/crops/li-canva-default.png).
6. **Do keep the rail narrow.** The signed-out shell is an icon rail, about 77px, not a labelled sidebar. See [app-dark-default](screenshots/app-dark-default.png).
7. **Don't invent a light marketing theme.** The docs light roles are a declared alternate. Marketing and the app do not paint them. See [tokens.json](tokens.json).
8. **Don't follow Log in, Start now, Subscribe, Generate or an OAuth provider from this package.** Those are the boundary. See [login-dark-default](screenshots/login-dark-default.png).
9. **Don't treat the wordmark field as type.** The home hero is artwork. Set real UI type in canvaSans and the display faces named above. See [home-dark-full](screenshots/home-dark-full.png).

# Telegram design reference

A token set and component reference for Telegram for iOS, the messaging app. Use it to build a native iOS messaging or list-heavy app (SwiftUI) that borrows its proportions and structure: a black or white chat list with a grey band behind pinned chats, dense 76 pt chat rows, grouped settings cards led by gradient icon tiles, iOS 26 glass nav buttons, folder chips and a floating tab bar, one blue accent, and outgoing bubbles in the theme's colour over a chat wallpaper. It was captured from the shipped app on iOS 26 through iPhone Mirroring, signed in to the owner's account: dark on 2026-10-23 (the phone in dark mode, Auto-Night Mode on System, so the Night theme) and light on 2026-10-24 (Settings > Appearance > Auto-Night Mode > Disabled, put back to System afterwards). The device screen is 390 x 844 pt; the captures are 812 x 1780 px at 2 px per pt, with the screen at (16, 76) inside each PNG.

It holds 39 captures: 24 in dark (chat list, a forum thread, composer, menus, in-chat and global search, settings pages, calls, contacts, sheets, edit mode, Appearance) and 15 of the same screens in light. Following the repository's rule ([AGENTS.md](../../AGENTS.md)), two spans are masked: the owner's phone number on `09-settings-root-profile` in both themes, and the Mac's hostname in one recent-photo thumbnail on `22-attachment-sheet-tab-bar`. The owner reviewed the rest on 2026-10-24: the other thumbnails (food, a public poster, a song, the owner's own notes) hold no personal data. On 2026-11-21, for the public repository, other people's names, usernames and profile photos were painted out of 13 captures (chat list rows, calls, contacts, the new-message sheet, global search, a folder's chat list and one story) with [tools/redact_images.py](../../tools/redact_images.py) and [its rules](../../tools/redact-rules/telegram.json), and the crops re-cut from them. Initials avatars, the owner's own profile and chats, and the bots, channels and groups in the lists stay. Every value was read before masking (see [How the values were read](README.md#how-the-values-were-read)).

This package contains no Telegram code, and none of its artwork has been redrawn. The screenshots and the visual system they show are Telegram's ([docs/RIGHTS.md](../../docs/RIGHTS.md)). Borrow structure and proportions, not the stickers, icons, wallpapers or the paper-plane mark.

## Brief

Read this before designing in this style. Take every value from [tokens.json](tokens.json), never from the screenshots; `python3 tools/catalog.py export telegram` prints them all with aliases resolved.

### Principles

1. Do keep one blue accent for everything you can act on.
2. Do write secondary actions as accent text in a card row, not as outlined buttons.
3. Do lead each settings row with a gradient icon tile in its own colour.
4. Do float navigation as glass over the content.
5. Don't fill destructive actions red.
6. Do keep chat rows dense and scannable.
7. Don't use bubble or wallpaper colours outside the thread.
8. Do show focus with the caret alone.

Each rule links the screenshot or crop that shows it, under [Do and don't](#do-and-dont).

## How the values were read

Telegram is a native app, so there is no CSS. Each screen was captured as the iPhone Mirroring window alone (`tools/capture/native/shot.sh`: `screencapture -l` on the window, then converted from Display P3 to sRGB with `sips`). `tools/measure.py` reads the full-colour captures, which stay outside the repo, and writes [raw/readings.json](raw/readings.json): 205 readings of 132 ids, most in both themes. `tools/build_tokens.py` maps them to tokens. The committed screenshots are the same captures quantised to 256 colours, so a reading's box can be checked against them, but no value was read from the quantised copies.

Two captures were masked after capture (`09`, `22`). For those, `measure.py` reads the unmasked Display P3 original (`<name>.raw.png`) through the same `sips` conversion, so every reading sees the pixels the sRGB capture held before masking; the reading says so in `readFrom`.

| Method in readings.json | Label in tokens.json | What it gives |
|---|---|---|
| `fill`, the box's dominant colour covering 90% or more of it | Sampled | An exact flat surface |
| `fill` under 90% (glass, a gradient, a wallpaper behind a translucent surface) | Derived | The dominant pixel; the description gives the share |
| `text`, the anti-aliased pixel furthest from the fill | Sampled (text) | A glyph colour; the true value is the same or slightly further from the fill |
| `bbox`, `extent`, `find` | Sampled | Sizes, positions and row pitches exact to the pixel (half a point) |
| `diag`, the inset along a corner's diagonal | Derived | A corner radius, plus or minus 2 pt |
| `cap`, a capital's ink height less a pixel of anti-aliasing, at a 0.72 em cap height | Derived | A font size, plus or minus 1 pt |
| `lines`, the pitch of text bands | Derived | A line height |
| By eye | Derived | Font weights |
| Not determinable | Not captured | The font family |

Scale steps (spacing, radii, the 30 pt icon tile) are Derived from the readings named in each token's description. Roles read in dark only (the attachment sheet, the Sort menu, usernames, disabled text and switches) get a light token Derived from the closest light role, and the description says which.

## What to distrust

- **The font.** Not determinable from pixels. The shapes match the iOS system face and the sizes land on 17, 16, 15, 14, 12 and 10 pt, but `fontFamily.base` is `system` and marked Not captured.
- **Glass and wallpaper.** The nav buttons, chip bar, tab bar, segmented control, menus and composer are iOS 26 glass, and the composer, service pills and incoming bubble sit over the chat wallpaper. Their tokens are one reading of a material that takes colour from what is behind it: the dark context menu reads olive (`#413C22`) because the owner's photo wallpaper shows through, the dark composer reads orange. Use the system material, not those fills.
- **Gradients.** Dark's outgoing bubble runs from `#944AF2` at the top to `#525FFF` at the bottom; both ends are tokens, Derived. The icon tiles and initials avatars are gradients too, and each core colour is one 10 x 3 px band.
- **The wallpaper is the owner's.** The dark threads show a personal photo as wallpaper; light shows Telegram's default pattern. Neither is a token.
- **Radii are estimates**, plus or minus 2 pt: cards 25.6, bubbles 15.4 to 17.1, menus 29 to 30.7, the sheet 35.8, icon tiles 8.5.
- **Type sizes are estimates**, plus or minus 1 pt, from cap heights at an assumed 0.72 em. Weights are judged by eye. The profile name was read from the ascender of a lowercase k, which runs a little above cap height, so 27 pt may be 26.
- **Light covers 15 of 39 screens.** Search, sheets, edit mode and the Sort menu are dark only; their light tokens are Derived.
- **The light off switch is almost white** (`#F9F9FB` track on a white card). That is what the capture shows; it is not a reading error.
- **Avatar and row sizes include anti-aliasing.** The calls avatar reads 41 pt and the contacts avatar 38 pt; both are probably 40 pt.
- **No pressed states, no motion, no keyboard, no dialogs.** The captures are stills made with clicks; iPhone Mirroring hides the software keyboard; no destructive action was tapped.
- **Screenshots are 256-colour PNGs.** Flat UI colours survive exactly; glass, photos and gradients band slightly. Read values from tokens.json.

## Do and don't

1. **Do keep one blue accent for everything you can act on.** Filled buttons, the ADD pill, text actions, the selected tab, checkmarks, presence, the caret and the send button all use `color.accent.default`; nothing else is blue. See [24](screenshots/dark/24-devices-primary-button-destructive-row.png), [09](screenshots/dark/09-settings-root-profile.png) and [12](screenshots/dark/12-checklist-with-sticker-header.png).
2. **Do write secondary actions as accent text in a card row, not as outlined buttons.** Change Profile Photo, Create a Folder, Start New Call and Invite Friends are rows with an accent glyph and label. See [09](screenshots/dark/09-settings-root-profile.png), [13](screenshots/dark/13-chat-folders-add-pill-buttons.png) and [14](screenshots/dark/14-calls-segmented-all.png).
3. **Do lead each settings row with a gradient icon tile in its own colour.** The tile colour names the area (blue for chats, green for groups, red for blocking) and the row ends in a grey value and a chevron. See [10](screenshots/dark/10-settings-notifications-switches-on-off.png) and [11](screenshots/dark/11-settings-privacy-grouped-values.png).
4. **Do float navigation as glass over the content.** Back, Edit, the folder chips, the segmented control, the composer and the tab bar are glass with no bar behind them, and lists and threads scroll under all of them. See [02](screenshots/dark/02-chat-list-folders-tabbar.png), [03](screenshots/dark/03-chat-topics-pinned-link-preview.png) and [14](screenshots/dark/14-calls-segmented-all.png).
5. **Don't fill destructive actions red.** Delete and Terminate all other sessions are red text, with a red glyph, in an ordinary menu or card. See [05](screenshots/dark/05-message-context-menu-reactions.png), [19](screenshots/dark/19-chat-longpress-preview-menu.png) and [24](screenshots/dark/24-devices-primary-button-destructive-row.png).
6. **Do keep chat rows dense and scannable.** A 76 pt row holds a 60 pt avatar, a semibold title, two preview lines in grey and the time with read ticks; pinned chats share a grey band at the top. See [02](screenshots/dark/02-chat-list-folders-tabbar.png) and [02 light](screenshots/light/02-chat-list-stories-archive-folders-tabbar.png).
7. **Don't use bubble or wallpaper colours outside the thread.** The violet gradient and the pale green belong to message bubbles over a wallpaper; lists and settings stay neutral. See [03](screenshots/dark/03-chat-topics-pinned-link-preview.png) and [03 light](screenshots/light/03-chat-topics-pinned-link-preview.png).
8. **Do show focus with the caret alone.** A focused search field moves its placeholder left and gains a blue caret; there is no ring or border change. See [07](screenshots/dark/07-chat-search-focused-file-bubble.png) and [18](screenshots/dark/18-search-typed-global-results.png).

## Rebuild

From this folder. `measure.py` needs the full-colour captures, which live outside the repo in `~/.design-systems/telegram/raw-shots/`, and `sips` (macOS) for the masked ones; the other builders run from the committed files.

```bash
python3 tools/measure.py ~/.design-systems/telegram/raw-shots
python3 tools/build_tokens.py
python3 tools/build_style_guide.py
python3 tools/build_components_md.py
python3 -m unittest discover -s tools
git status --short .
```

`tools/capture/quantize.py <raw-shots>` and `tools/crops.py` (both need Pillow) rewrite `screenshots/` and `components/crops/`. Quantise from the masked `.png` captures only, never the `.raw.png` originals, then run `python3 tools/redact_images.py apply systems/telegram --rules tools/redact-rules/telegram.json` from the repository root before `tools/crops.py`, so the names stay masked. `apply` keeps each image's palette, its transparent screen corners and every pixel outside the boxes. A rebuild that changes nothing proves the outputs still match their inputs. From the repository root, `make design-md` regenerates DESIGN.md and the Brief.

## Use in SwiftUI and Figma

A colour asset per semantic key, with a light and a dark variant, maps one to one: the key names (`color.surface.card`) are the contract, and both sets have the same keys. Sizes and radii in `core` are points. Use the system components for the glass nav buttons, the tab bar, menus, sheets, switches and the segmented control rather than redrawing them, and the system grouped list for settings. In Figma, import tokens.json with Tokens Studio and pick the Light or Dark theme.

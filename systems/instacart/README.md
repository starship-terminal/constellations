# Instacart design reference

A token set and component reference for Instacart's public signed-out surface, for building grocery marketplace screens in the style of the real thing. It was read from **instacart.com**, signed out, in Chromium at 1440 x 900 and 390 x 844: the homepage, grocery delivery, deals, a food category, search for milk, help, Instacart Business, login, signup, and terms.

Instacart is worth a capture because the consumer site ships a small named token layer, IDS. `:root` declares `--ids-color-*` (primary green #108910, forest #003D29, warm wash #F7F5F0, grayscale 00 to 99, Plus pinks, Max yellow, feedback), `--ids-system-space-*` (4 to 48), `--ids-system-radius-*` (0 to 24), four opacities, and three `linear()` easing springs. Type is Instacart Sans. Emotion class names are hashes, so components are selected by role and text.

An email account was created in the attached T3 preview browser and the storefront loaded with ZIP 94105. Preview screenshots of that session failed because the host was not producing frames, so this package ships the public capture. Checkout, payment, a saved street address, and the phone path were not used.

## Do and don't

1. **Do keep marketing chrome white and put the forest green on the hero.** The header, cards and page are white. The homepage hero band is #003D29 (`color.hero`). See [home-light-default](screenshots/home-light-default.png).
2. **Do fill primary actions with #108910 and white type.** Sign up, Continue, Log in on the storefront, and Add are full pills. See [button-primary](components/crops/button-primary-default.png) and [button-continue](components/crops/button-continue-default.png).
3. **Do use the yellow chip for deals, not for actions.** #FFDC23 (`color.deal`) marks "No markups" and sale callouts. It is not a button fill. See [deals-light-default](screenshots/deals-light-default.png).
4. **Do round controls fully and cards at 12px.** Buttons, search and chips are pills (half their height: 20px on the 40px header buttons, 28px on the 56px search and Continue, 999px on chips). Cards use the declared 12px radius step. Fields use 8px. See [store-card](components/crops/store-card-default.png) and [text-field](components/crops/text-field-default.png).
5. **Don't invent a dark theme.** The consumer site paints one light theme. `colorScheme` is `normal` and there is no `data-theme`. See [login-light-default](screenshots/login-light-default.png).
6. **Don't treat Instacart Business as the consumer palette.** `/business` uses a purple header and a periwinkle pill. Those values are measured on that page, not aliased into the consumer green. See [business-light-default](screenshots/business-light-default.png).
7. **Don't press checkout.** Add, Continue, Shop and the Plus trial were not used to place an order, save a street address, or start a paid trial. See [search-light-default](screenshots/search-light-default.png).

## How the values were read

CSS custom properties were harvested from the live homepage stylesheets with [tools/capture/vars.mjs](tools/capture/vars.mjs) and written to [raw/css-vars.json](raw/css-vars.json). 62 names, 17 font faces, 0 blocked sheets. Component crops and computed styles came from [tools/capture/public/measure.mjs](tools/capture/public/measure.mjs) on the homepage, login, search, help and business pages. Screenshots came from [tools/capture/public/public.mjs](tools/capture/public/public.mjs) in headless Chromium, then [tools/capture/quantize.py](tools/capture/quantize.py).

Consent, location and promo dialogs were hidden in CSS. No consent control was clicked. Login Continue was not clicked in the headless capture, because an empty submit opened a visual reCAPTCHA. ZIP 94105 appears in the header of search and deals because the public storefront renders it. It was not submitted as a street address.

## What to distrust

- **Readings taken with automation hidden.** The committed screenshots and readings were taken by scripts that launched Chromium with the `AutomationControlled` flag off and masked `navigator.webdriver`. That code was removed on 2026-11-20 (capture conduct); a recapture runs undisguised and records any page that blocks it as a boundary.
- **Some type and weights were typed.** The heading (32/40) and display (48/56) styles, and the 500 and 700 weights, have no reading behind them; their sources say Reconstruction. Body, label and button type are read from the login card, the EBT chip and the Continue button (the element's own style: Continue computes weight 400; no text-node reading was recorded). The card radius is the declared `--ids-system-radius-12`; the captured store-card and login-card elements paint 0px.
- The signed-in storefront was reached in the T3 preview browser, then screenshot capture failed because the host was not producing frames. Those screens are not in this package. Do not treat the public search page as the logged-in home.
- Hover crops of green pills often match the rest state. Instacart's primary fill does not always shift on hover in headless Chromium. Do not invent a hover green.
- `login-card-default` is the form only, not the whole card with the social row.
- The ZIP field and Shop button on `/grocery-delivery` were not found in the measure pass (the hero image loaded first). They are visible in [grocery-delivery-light-default](screenshots/grocery-delivery-light-default.png).
- Add buttons on search were not cropped. The page uses an icon plus, not a text button named Add, in the measure pass. The search screenshot shows the green plus.
- Mobile grocery-delivery was dropped because a Google one-tap sheet covered the page.
- The phone menu is [mobile-home-light-menu](screenshots/mobile-home-light-menu.png). Departments, More ways to shop, and Help are collapsed. The desktop departments drawer is [home-light-departments](screenshots/home-light-departments.png).
- The phone homepage viewport is covered on the lower half by the app sheet. Continue in browser was not a clickable control in the headless pass. See [mobile-home-light-default](screenshots/mobile-home-light-default.png).
- The control map is [site-tree.md](site-tree.md). The stop at the empty login and signup cards is [login-review.json](login-review.json). Google, Facebook, and Phone were not clicked. Continue was not clicked.
- Icon.png is a cropped wordmark, not a fetched apple-touch icon. Icon SVGs were not extracted.
- Easings are the resolved `linear()` springs. The cubic-bezier fallback in the stylesheet is not what the page computed.
- `--ids-typography-name` is a per-class name, empty or a style id on `:root`. It is not a size scale. Type sizes in `core.typography` are measured roles, not a published ramp.
- Quantized screenshots band photographs. Read colours from tokens.json.

## Fonts

Instacart Sans is the body face, a self-hosted variable woff2 (400 to 800, roman and italic) from Instacart's CloudFront assets, with Instacart Sans Fallback (local Arial, size-adjusted). Instacart Contrast is declared the same way and is not the body default. Tokens fall back to Arial, then sans-serif. The font files are not committed.

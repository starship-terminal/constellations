# Officevibe

Officevibe is Workleap's employee engagement product. This package measures the public marketing site and the signed-out login, on 2026-11-19, from a signed-out preview tab. https://officevibe.com/ redirects to https://workleap.com/officevibe. No company workspace and no employee survey were entered. The login field is labelled "Email or mobile number", so it was not submitted. The demo form asks for a phone number, so it was not submitted either.

The only theme on these pages is light. The measured viewport was 1169 by 731 CSS pixels at device pixel ratio 2, not 1440 or 390. The preview browser returned "The browser is not producing screenshot frames", so this package has no screenshots.

## How the values were read

Custom properties were read from `getComputedStyle(document.documentElement)` on the live page. Component values were read from `getComputedStyle` on the elements named in each token's `$extensions.source`. Marketing tokens come from https://workleap.com/officevibe, https://workleap.com/pricing and https://workleap.com/demo. Login tokens come from https://login.workleap.com/. The dumps are [raw/marketing-root-vars.json](raw/marketing-root-vars.json) (415 properties) and [raw/login-hop-vars.json](raw/login-hop-vars.json) (547 `--hop-*` and `--o-ui-*` properties).

The marketing page set the root font size to 15.436px at 1169px width, so 1rem there is not 16px. Login used 16px. Tokens keep the declared rem or hex. A computed pixel check is in the token note when one was read.

No stylesheet was rewritten and no theme class was injected. The Osano cookie dialog was hidden with an inline `display: none` after its computed styles were read, so later readings are of the page underneath.

## What to distrust

The painted login primary button is `#2545ff`. The Hop token `--hop-primary-surface-strong` is `#4767fe`. Both are recorded. Use the component token for the button that was on screen.

`.button:hover` in the stylesheet sets `border-radius: 0.5rem`. The resting button is `100px`. A synthetic mouseover did not change the filled button's computed background, so the hover fill is a gap.

The login label computed colour was `rgb(108, 108, 107)`. `--hop-neutral-text-weak` is `#777775`. The token records the custom property. The computed label colour is in the note.

Screenshots are absent. Do not treat [style-guide.html](style-guide.html) as a capture of the page.

`raw/computed.json` holds the capture's metadata, not the element styles. Every token whose source is an element's computed style (the page, card and field fills, the nav colour, component heights and paddings, the pricing-card shadow, the 0.4s footer transition, the button easing) is labelled Reconstruction: typed in by hand at capture time. The custom properties from the two `:root` dumps are Measured. The heading styles (`display`, `h1` to `h5`) and the `.button` fill, text and radius come from stylesheet rules raw/ does not keep, and a token that aliases a hand-entered value is labelled the same way.

Two marketing custom properties in the dump have a `<deleted|...>` suffix in the name (`--_typography---paragraph-lg--bottom-margin` and `--_typography---paragraph-xl--bottom-margin`). They were not used as tokens.

## Do and don't

**Use leapin blue for the filled action.** The marketing primary button and the login Next button both paint `#2545ff`.

**Keep the marketing button a pill.** Resting radius is `100px`, from `--_components---button--border-radius`.

**Set marketing body in Inter and headings in ABC Favorit, weight 400.** Display headings use a tight negative letter-spacing (`-0.05em` on h0 and h1).

**Put the marketing footer on boardroom navy.** `footer.footer_main` is `#0c1754` with `#f9f8f6` text.

**Treat the login page as its own system.** Its page is `#f8f6f3`, its text is `#3c3c3c`, and its controls are 24px pills. It is not the marketing scale.

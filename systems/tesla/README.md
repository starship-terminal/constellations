# Tesla

Tesla's public marketing site, tesla.com, captured signed out on 19 November 2026. The pages opened were the homepage, Model Y, Solar Panels, Support, and About. The vehicle configurator, the shop, and account sign-in were not entered.

The site is built on the Tesla Design System (`--tds-*` custom properties, `tds-btn`, `tds-site-header`). One theme is live: light. A dark scheme was resolved by reading `.tds-colorscheme--dark` in the same page. The marketing theme overrides primary from blue to near-black.

The attached preview measured 1169 by 731 CSS pixels at device pixel ratio 2. Screenshot frames were not available, and headless Playwright received HTTP 403, so this package has no screenshots.

### Principles

1. Use the 4px radius on buttons, fields, and cards.
2. Set display headings in Universal Sans Display at weight 500.
3. Pair a blue Order Now with a white Learn More on a photograph.
4. Keep the header at 56px.
5. Leave the configurator, the shop, and account sign-in out of a marketing recreation.

## How the values were read

Custom properties were read with `getComputedStyle` on the live homepage. A hidden `.tds-colorscheme--light` node and a hidden `.tds-colorscheme--dark` node were inserted so both schemes resolved in one page. `.tds-theme--marketing` was read the same way. Component chrome (buttons, header, search field, menu rows, banners) was read from the elements on the page.

The stylesheet names that carry the system are the Tesla frontend CSS bundles and `tcl-react` 1.43.8 (`assets-tcl.tesla.com/tcl-react/1.43.8/tcl-react.umd.css`). Cross-origin sheets could not be enumerated rule by rule. The computed custom properties were readable.

Headless Playwright was tried once against the public homepage. It returned HTTP 403 Access Denied. Those captures were discarded. No colour was sampled from a screenshot.

## What to distrust

The dark palette is a probe, not a theme the marketing site offered. The site has no theme toggle, and `prefers-color-scheme: dark` was true in the browser while the page still painted light.

Marketing primary (#171a20 in light, #ffffff in dark) is an override on four tokens. The base TDS primary stays #3e6ae1. Order Now on the homepage computed as #3e6ae1, so both values are real and they disagree by context. The override is on `$extensions.marketing`.

One dark surface, `--tds-theme-background-container-alt`, computed as `hsla(0, 0%, 100%, .135)`. The builder stores that as #ffffff22. Other `hsla()` values were not parsed.

The viewport is 1169 CSS pixels, the preview window. It is not a 1440 or 390 capture.

[raw/token-board.png](raw/token-board.png) is a board drawn from the measured tokens so the catalog has a cover image. It is not a screenshot of tesla.com.

Universal Sans is named in the font stacks and is not shipped here. A browser without the face falls back to the system sans.

## Do and don't

- **Use the 4px radius on buttons, fields, and cards.** Every measured control used 4px. The location card and the cookie banner used 8px.
- **Set display headings in Universal Sans Display at weight 500.** The homepage h2 is 40px / 48px. The solar title is 56px / 64px. Body stays in Universal Sans Text at 14px / 20px.
- **Pair a blue Order Now with a white Learn More on a photograph.** Primary computed as #3e6ae1 with white text. The second button computed as white with #393c41 text.
- **Keep the header at 56px.** It is transparent over a hero and white on a light page.
- **Leave the configurator, the shop, and account sign-in out of a marketing recreation.** Those flows were not measured.

## Rebuild

```bash
cd systems/tesla && python3 tools/build/build_tokens.py
python3 tools/catalog.py design-md tesla
```

`build_tokens.py` reads [raw/tds-extracted.json](raw/tds-extracted.json) and writes [tokens.json](tokens.json). DESIGN.md is generated from the tokens. The style guide is hand-rendered from the same values because the kit template expects Claude's token paths.

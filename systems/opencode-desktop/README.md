# OpenCode desktop design reference

A token set and component reference for OpenCode's desktop app for macOS (Anomaly Innovations; bundle id `ai.opencode.desktop`), version 2.1.4 (Electron 44), captured on 2026-10-25 from the owner's own install, with model providers already connected. OpenCode is a coding agent: one window with a title bar of session tabs, a Home page that lists projects and their sessions, the session itself (a transcript column, a composer, review, context and terminal panes) and Settings as a page of twelve panes. Every screen was captured in the app's own theme, OpenCode, in light and dark, at the size the window was in: 1280 x 800 pt.

Everything was read live from the running app over Chromium's remote-debugging port, with the capture scripts [cursor-desktop](../cursor-desktop/README.md) piloted for this route: full-window screenshots of every screen and state, the custom properties of the theme engine as they compute and paint, and the computed style of every captured part in every state. Use it to build a quiet desktop coding agent: a rounded panel under a strip of tabs, no sidebar, a single centred transcript with the prompt as the only bubble, tool calls folded into one muted line, a raised composer with an ink Send button, Inter at a 440 weight with IBM Plex Mono for code, and every colour role pointing at a step of one grey ramp or eight hue ramps.

This package contains no OpenCode code, icons, wordmark or artwork; the screenshots and the visual system they show are Anomaly's ([docs/RIGHTS.md](../../docs/RIGHTS.md)). OpenCode itself is MIT-licensed open source, but the brand is a registered trademark. Borrow structure and proportions, not the brand.

## Brief

Read this before designing in this style. Take every value from [tokens.json](tokens.json), never from the screenshots; `python3 tools/catalog.py export opencode-desktop` prints them all with aliases resolved.

### Principles

1. Do build every surface from one grey ramp.
2. Do give the prompt the only bubble; let the reply sit on the page.
3. Do fold the agent's work into one muted line.
4. Do make the primary action an ink fill and keep blue for links, focus and the prompt.
5. Don't fill destructive actions with red.
6. Do separate surfaces with a 0.5px ring and a soft shadow, not a border.

Each rule links the screenshot or crop that shows it, under [Do and don't](#do-and-dont).

## How the values were read

OpenCode is an Electron app (`Contents/Frameworks/Electron Framework.framework`, Electron 44.9.1). It was not running; it was opened with `open -a OpenCode --args --remote-debugging-port=9406`, which it accepted on the first launch, and Playwright attached with `chromium.connectOverCDP`. The window is one CDP page, titled OpenCode, at `oc://renderer/index.html`. No sign-in or provider setup was shown: first-launch onboarding was already complete and the owner's providers were connected. The scripts in [tools/capture/electron/](tools/capture/electron) are the cursor-desktop set: [vars.mjs](tools/capture/electron/vars.mjs) is unchanged; [cdp.mjs](tools/capture/electron/cdp.mjs) gained a colour-scheme switch (below) and now derives the raw-shots folder from the package it sits in, which [shots.mjs](tools/capture/electron/shots.mjs) and [run.mjs](tools/capture/electron/run.mjs) import instead of defaulting to cursor-desktop's (otherwise unchanged); and [product.mjs](tools/capture/electron/product.mjs) is OpenCode's. Screenshots are CDP's `Page.captureScreenshot`, the window's own backing store.

**Two colour layers and ramps.** The theme engine writes one style element, `oc-theme`, on `:root` from the chosen theme (Settings > Appearance > Theme, here OpenCode, `data-theme="oc-2"`) and scheme (`data-color-scheme`). Its newer layer, v2, is a set of ramps (`--v2-grey-50` to `--v2-grey-1200`, and red, orange, yellow, green, cyan, blue, purple and pink from 100 to 1200) that are identical in light and dark, plus translucent white and black steps from the main stylesheet (`--v2-alpha-light-*`, `--v2-alpha-dark-*`). Every v2 role is a `var()` of one step, and the scheme only changes which step: `--v2-background-bg-base` is `var(--v2-grey-1100)` in dark and `var(--v2-grey-50)` in light. So the ramps are core tokens and each role is an alias of one (`bg.base` is `{color.grey.1100}` in dark). The older layer (`--background-*`, `--surface-*`, `--text-*`, `--border-*`, `--icon-*`, `--syntax-*`, `--markdown-*`) is written as literal colours beside it; the newer components use v2 classes (Tailwind's `bg-v2-background-bg-layer-03`), while code highlighting and markdown still take the older names, which is why `syntax.*` and `markdown.*` are kept at the top level and the rest under `legacy.*`. [vars.mjs](tools/capture/electron/vars.mjs) lists every declaration and reads each name three ways (computed, painted through a probe element, and as a painted box-shadow); [build_tokens.py](tools/build_tokens.py) keeps a literal as its value and makes a token an alias when its winning declaration is a plain `var()` of a token that paints the same.

**Themes.** OpenCode's Color scheme setting was System, and its theme follows `prefers-color-scheme`, so CDP's `Emulation.setEmulatedMedia` switches it and no setting was touched. One trap: Playwright's `connectOverCDP` itself emulates `prefers-color-scheme: light` for as long as it stays attached, so the first look showed a light window on a Mac in dark mode. [cdp.mjs](tools/capture/electron/cdp.mjs) now takes `COLOR_SCHEME=dark|light` and sets that scheme on the connection it opens; every script was run with it. Nothing about the scheme persists: when the connection closes the app follows macOS again. The other bundled themes were not captured.

**Components and states.** Every part carries a `data-component` (and `data-slot`) attribute, so [product.mjs](tools/capture/electron/product.mjs) finds parts by those, roles and aria-labels, never by account text. Each shot starts on Home with the capture's project selected and nothing focused, reveals one state, takes the screenshot and reads the computed style of every listed part. Hover is a real pointer over the part. Pressed is `:active` forced through CDP's `CSS.forcePseudoState`; nothing is clicked. Focus-visible is a key press and then `focus()`; OpenCode draws its ring without help (a 2px `border.focus` outline at 2.5px on buttons; rows draw a wash and a 0.5px inset ring instead). Before and after every shot the script compares the open session tabs and stops if they changed.

**Sizes.** The window is not zoomed: 1280 x 800 pt is a 1280 x 800 CSS px viewport at a device pixel ratio of 2, so every px value in tokens.json and components.md is what the stylesheets declare and what the screen shows. Most edges are drawn as a 0.5px box-shadow ring rather than a border (`borderWidth.hairline`); the radii the parts use (2, 4, 6, 8 and 10px) are Tailwind arbitrary values rather than the `--radius-*` scale, so both are kept (`radius.measured-*` and `radius.xs` to `xl`).

**The agent run.** The owner approved test prompts on 2026-10-25 in a fresh session on the capture's own folder only, `~/.design-systems/harness-scratch/opencode`. OpenCode needs a project for a session, so the folder was added through Home's Add project, a native folder panel driven with System Events; it is now the project `opencode`. [run.mjs](tools/capture/electron/run.mjs) opened a new session there with the model the new session offered (MiniMax-M3, the project's default; never changed) and sent, in dark, "List the files in this folder.", "Create hello.txt here with one line: hello from the design capture" and "Run ls -la in this folder and show me the output.", then in the same session (`dark-more`) "Run \`sleep 5; ls\` in this folder and tell me what it printed." and a short question about design tokens with a code block; in light, a second fresh session got "Show me what hello.txt in this folder says.", "Create notes.txt here with one line: second file from the design capture", the same slow command and the same question. Frames were taken every 1.2 s (dark) and 0.5 s (later steps and light) until each step finished. The agent wrote `hello.txt` and `notes.txt` in the scratch folder and ran `ls` and `sleep` there, nothing else. No approval prompt appeared: Auto-accept permissions is off, but OpenCode's default permissions let the agent work inside its project without asking, and nothing was changed to force one. OpenCode titled the sessions List folder files and Contents of hello.txt; the session shots use the first.

**Nothing else was changed.** Menus, dialogs, selects and the palette were opened and closed with Escape; the delete confirmation was opened on the capture's own session and cancelled; text typed into the composer, the palette and the search fields was cleared without sending. Opening the terminal started a shell in the scratch folder, which the capture closed again with Close terminal. At the end the capture closed its tabs (its two sessions and an empty draft tab its exploration had opened), deselected its project on Home and wrote back the window's last-open session, so the app reopens on the session that was open before. A read-back of Preferences, Appearance, Notifications, Server and Extensions after the capture matched what they showed before, and the app's settings files and `~/.config/opencode` were byte-identical before and after. OpenCode was quit at the end and not reopened.

## What to distrust

- **The project and the two sessions are the capture's.** Home lists a project named `opencode` (the scratch folder) with the sessions List folder files and Contents of hello.txt; the owner had neither before. `home-all-projects` shows the owner's other sessions as they were.
- **The empty project screen is from before the runs.** `home-project-empty` was taken right after the folder was added; a fresh capture (`EMPTY=1`, see Rebuild) only reproduces it on a project with no sessions.
- **Two runs, two sessions.** Dark frames come from List folder files and light frames from Contents of hello.txt, which asked different things, so dark has the streaming answer and light has the file being written. The session screenshots use List folder files in both themes. Run frames are timed, not chosen.
- **Some container colours are inherited.** A part that is a container (the composer, a dialog, a tab) reports the text colour it inherits; those are left out of `component.*`, and some containers report a transparent fill because the colour sits on an inner element (the selected project row, the prompt's bubble).
- **A name collision in the stylesheets.** Tailwind's `--text-base` (a font size) and the older layer's `--text-base` (a colour) share a name, and the colour wins on `:root`; the type scale is taken from `--font-size-*` instead.
- **The letter spacing tokens are unitless in the CSS** (`--letter-spacing-tight: -.16`); they are written here as px, which is a reading, not a declaration.
- **Component values are one element each.** `component.*` and components.md read the first element that matched each part, and a part name can cover different elements in different shots (the `button-neutral` measured first is New session).
- Screenshots are 256-colour PNGs. Flat UI colours are exact; read values from tokens.json.

## Do and don't

1. **Do build every surface from one grey ramp.** The page, the window behind it, the raised layers and the text are all steps of `color.grey` (`bg.base` is grey-1100 in dark and grey-50 in light, `bg.layer-01` to `-04` climb from there), and the scheme only changes which step a role points at. See [settings-preferences](screenshots/dark/settings-preferences.png) and [settings-preferences light](screenshots/light/settings-preferences.png).
2. **Do give the prompt the only bubble; let the reply sit on the page.** The owner's message is a right-aligned bubble in `text.accent`; the agent's answer is plain 14px text in the column, with code in bordered blocks. See [conversation](screenshots/dark/conversation.png) and [run-finished](screenshots/light/run-finished.png).
3. **Do fold the agent's work into one muted line.** Every tool call is a summary such as Used 1 Shell that expands on click, so the transcript reads as prompt and answer. See [conversation-top](screenshots/dark/conversation-top.png) and [tool-expanded](screenshots/dark/tool-expanded.png).
4. **Do make the primary action an ink fill and keep blue for links, focus and the prompt.** Send is a `role.contrast` square with its own shadow; the accent blue never fills a button. See [send-button-default](components/crops/send-button-default.png), [composer-typed](screenshots/light/composer-typed.png) and [button-neutral-focus-visible](components/crops/button-neutral-focus-visible.png).
5. **Don't fill destructive actions with red.** Delete session is a neutral button whose text is `state.danger.fg`; the warning is the colour of the words. See [delete-confirmation](screenshots/dark/delete-confirmation.png) and [button-danger-default](components/crops/button-danger-default.png).
6. **Do separate surfaces with a 0.5px ring and a soft shadow, not a border.** Settings groups carry an inset ring of `border.muted`, and the composer and menus float on `shadow.raised` and `shadow.floating`. See [settings-appearance](screenshots/dark/settings-appearance.png), [model-menu](screenshots/dark/model-menu.png) and [new-session](screenshots/light/new-session.png).

## Rebuild

From the package folder:

```bash
python3 tools/build_tokens.py && python3 tools/build_style_guide.py && python3 tools/build_components_md.py
```

`build_tokens.py` reads `raw/css-vars.*.json` and `raw/components.*.json` and writes `tokens.json`; it refuses a token without a source, an alias that points at nothing, a dimension that is not one px length and a colour that is not hex or rgba, and moves a name present in only one theme to `$extensions.notTokenised`. `build_style_guide.py` renders `style-guide.html` from `tokens.json`; `build_components_md.py` writes `components.md` from the readings, `tokens.json` and the crops. All three are deterministic, standard library only. `python3 tools/crops.py` (needs Pillow) cuts `components/crops/` from the screenshots.

To capture again (OpenCode must not be running; Playwright from `~/.design-systems/pw`):

```bash
open -a OpenCode --args --remote-debugging-port=9406
export PORT=9406 SLUG=opencode-desktop
COLOR_SCHEME=dark node tools/capture/electron/run.mjs dark
COLOR_SCHEME=dark node tools/capture/electron/shots.mjs dark
COLOR_SCHEME=dark KEEP='^--(?!tw-)' node tools/capture/electron/vars.mjs raw/css-vars.dark.json OpenCode ':root'
```

Repeat with `light`, quit OpenCode (`osascript -e 'tell application "OpenCode" to quit'`), then `python3 tools/capture/quantize.py ~/.design-systems/opencode-desktop/raw-shots`, which also copies the readings into `raw/`, and the builders. The `opencode` project (the scratch folder) must exist; `run.mjs` opens a new session in it, and the session shots open the session titled List folder files (`SESSION` in product.mjs). On 2026-10-25 the dark run had a second pass in the same session, `RAW=~/.design-systems/opencode-desktop/raw-more node tools/capture/electron/run.mjs dark-more`, whose frames were merged into the dark run's; `home-project-empty` was taken with `EMPTY=1` before any session existed. Both scripts exit non-zero when a required part or shot fails.

**Reusing this for another Electron app.** As in [cursor-desktop](../cursor-desktop/README.md#rebuild): copy `tools/capture/electron/` and `tools/capture/quantize.py`, then the builders, and rewrite everything marked `PRODUCT (adapt)`. If the app's theme follows `prefers-color-scheme`, set `COLOR_SCHEME` on every script, since Playwright's connection otherwise emulates light.

## The Electron route, as it went

| Step | What happened |
|---|---|
| Port | OpenCode accepted `--remote-debugging-port=9406` on the first launch; one page, titled OpenCode, at `oc://renderer/index.html`, signed in with providers connected |
| Screenshots | `Page.captureScreenshot` gives the exact window at its 2x pixel ratio; the window is not zoomed, so CSS px are screen points |
| Values | Every colour is a custom property in the `oc-theme` element; roles are `var()`s of ramp steps, so nearly all tokens are aliases. The probe element still resolved the older layer's `light-dark()` shadows |
| Hover | A real pointer, as for Cursor; Tailwind `hover:` rules would also take a forced `:hover` |
| Focus | Drawn without help after a key press: a 2px outline on buttons, a wash and inset ring on rows |
| Theme | Followed emulated media, the first app on this route to do so; no setting was switched. Playwright's own light emulation had to be overridden (`COLOR_SCHEME` in cdp.mjs) |
| Run | A session needs a project, so the scratch folder was added as one through the native Add project panel (System Events, not CDP). The model was fast: tool calls lasted under a frame at 1.2 s, so later steps were sampled at 0.5 s and a `sleep 5` command held a tool call on screen |
| Side effects | Home's button is a toggle (pressed on Home it returns to the last session); typed `/` and `@` stay in the composer until cleared; Escape typed while the terminal has focus goes to the shell. At launch the app replaced the background `opencode serve --service` it talks to (Homebrew's 2.1.3) with its own bundled 2.1.4 CLI on the same port, which keeps running after the app quits |
| Generic scripts | `cdp.mjs` gained `COLOR_SCHEME` and a `SLUG`/`RAW` default taken from the package folder (a copied script used to default to cursor-desktop's folder, and `run.mjs` empties its run folder first); `shots.mjs --set-theme` was not needed. product.mjs lists the window under `agents` too, as Grok Bot's does |

# Orca desktop design reference

A token set and component reference for Orca's desktop app for macOS (stablyai, bundle id `com.stablyai.orca`), version 1.4.237 (Electron), captured on 2026-10-25. Orca is a coding-agent harness: projects and their git worktrees in a sidebar, each workspace a strip of tabs (terminals running agent CLIs, Orca's own structured chat, browser tabs, files), an inspector on the right (Explorer, agent sessions, Source Control, Checks), a status bar of per-provider usage, and about thirty Settings panes. The workspace, the chat, Tasks, Automations, Orca Mobile, the search palette, menus, dialogs, the update card and Settings were captured in Orca's light and dark themes, at the window size the app was in: 1512 x 949 pt. Orca was not signed in to an Orca account (it does not need one), and the capture did not sign in.

Everything was read live from the running app over Chromium's remote-debugging port, with Playwright connected over CDP, using the route the [cursor-desktop](../cursor-desktop/README.md) pilot built for the Electron coding harnesses in [issue 107](https://github.com/c-wenlong/designs/issues/107): full-window screenshots of every screen and state, every custom property the stylesheets declare as it computes and paints, and the computed style of every captured part in every state. Use it to build a calm, neutral desktop tool on shadcn/ui: white or near-black panes, a grey sidebar, ink (not a hue) as the primary colour, 8px controls and 14px cards in Geist, red kept for removal only.

This package contains no Orca code, icons or artwork; the screenshots and the visual system they show are stablyai's ([docs/RIGHTS.md](../../docs/RIGHTS.md)). Borrow structure and proportions, not the brand.

## Brief

Read this before designing in this style. Take every value from [tokens.json](tokens.json), never from the screenshots; `python3 tools/catalog.py export orca-desktop` prints them all with aliases resolved.

### Principles

1. Do use ink, not a hue, for the primary action.
2. Do keep red for removal only.
3. Do draw the same focus ring on every form control.
4. Do give the prompt the only bubble; let the agent's work fold into one line.
5. Do set the sidebar one step off the page and keep panes flat.
6. Don't colour selection.

Each rule links the screenshot or crop that shows it, under [Do and don't](#do-and-dont).

## How the values were read

Orca is an Electron app (`Contents/Frameworks/Electron Framework.framework`), so its interface is HTML and CSS. It was not running; it was opened with `open -a Orca --args --remote-debugging-port=9405`, which it accepted on the first launch, and Playwright attached with `chromium.connectOverCDP`. The one window is a CDP page titled Orca. The capture scripts are the pilot's, in [tools/capture/electron/](tools/capture/electron): [cdp.mjs](tools/capture/electron/cdp.mjs) connects, [shots.mjs](tools/capture/electron/shots.mjs) drives the shot list in [product.mjs](tools/capture/electron/product.mjs), [vars.mjs](tools/capture/electron/vars.mjs) reads the custom properties and [run.mjs](tools/capture/electron/run.mjs) captures an agent run. Screenshots are CDP's `Page.captureScreenshot`.

**The theme.** Orca is built with Tailwind CSS 4 and shadcn/ui on its neutral base. The theme is shadcn's: about thirty hex values on `:root` and on `.dark` (`--background`, `--foreground`, `--card`, `--popover`, `--primary`, `--secondary`, `--muted`, `--accent`, `--destructive`, `--border`, `--input`, `--ring`, the sidebar sets), and Orca adds its own groups: the chat (`--chat-*`, each a `color-mix()` of the foreground into the canvas at a per-theme percentage), status, agent, callouts, git decorations and the git graph, diff and terminal pane titles. Many names are a `var()` of a Tailwind palette step (`--agent-working: var(--color-yellow-500)`); Tailwind's palette is declared as hex with display-p3 and lab copies under `@supports`, and is the same in both themes. [build_tokens.py](tools/build_tokens.py) keeps a declared hex as its value, makes a name an alias when its declaration is a plain `var()` of a name that paints the same, and otherwise keeps the painted colour with the formula beside it.

**Themes.** Orca's Theme setting is System, and its System theme follows `prefers-color-scheme`. CDP's `Emulation.setEmulatedMedia` switched `<html>` between `.light` and `.dark` at once, so each pass ran with the scheme emulated (`SCHEME=light` or `SCHEME=dark`, which [cdp.mjs](tools/capture/electron/cdp.mjs) applies to the session it opens) and Orca's own setting was never touched. The terminal pane is drawn by xterm with the owner's terminal themes (Ghostty Default Style Dark, Builtin Tango Light), so it follows the theme too.

**Getting a workspace.** The owner's Orca had no projects. A project must be a git repository, so the capture made an empty one, `~/.design-systems/harness-scratch/orca` (`git init`), and added it with Orca's own CLI (`orca repo add --path`). Its main worktree opened as a workspace with a shell terminal; everything in the workspace screenshots is that folder.

**Components and states.** Each shot resets the window to that workspace on its empty chat tab, reveals one state with Orca's own hooks (shadcn's `data-slot` names, roles, aria-labels and data attributes such as `data-worktree-card-surface`, never account text), takes the screenshot and reads the computed style of every listed part, recording its box for [crops.py](tools/crops.py). Hover is a real pointer over the part, focus-visible real keyboard focus (a key press, then `focus()`): Orca draws shadcn's focus ring itself (`focus-visible:ring-[3px]` in `--ring` at 50%, the border turning `--ring`), so nothing was switched on. Pressed is `:active` forced through CDP's `CSS.forcePseudoState` with the pointer over the part. Two cards Orca keeps on screen, the update notice (bottom right) and the Add a setup script callout (bottom of the sidebar), were hidden with a style the capture injected, not dismissed, except in the shots about them. Before and after every shot the script compares the projects, the workspaces, the open tabs and the empty chat's permission mode and model, and stops if any changed.

**The agent run.** The owner approved test prompts on 2026-10-25 in a fresh agent on the scratch folder. Orca's Chat UI setting (Settings > Experimental) is off, so new agents open as CLIs in a terminal; [run.mjs](tools/capture/electron/run.mjs) instead started each run with `orca agent launch --agent claude --surface chat`, which opens Orca's structured chat for that one launch and leaves the setting off. It sent "List the files in this folder.", "Create hello.txt here with one line: hello from the design capture" and "Run ls -la in this folder and show me the output.", screenshotting and measuring every 1.5 s until each finished. One chat was run in each theme. Claude wrote `hello.txt` in the dark run (the light run found it there) and ran `ls -la` in the folder. No approval prompt appeared: Settings > Agents > Agent Permissions is Yolo and the chat's permission mode is Full access, the owner's settings, and nothing was changed to force one.

**What the capture changed, and put back.** Orca's settings document in its profile was the same after the capture as before (compared byte for byte). The capture added the scratch project and, inside it, one empty Claude chat, two run chats and a shell terminal (where it typed `clear; ls -la` once per theme); at the end it removed the project from Orca with Remove Project, which closes its tabs, and left the folder on disk. Other traces are Orca's own bookkeeping: feature-use counters and the contextual tour marked seen, the New badge on Orca Mobile cleared by visiting it, the sidebar's open flag written, and an SSH target re-sync from `~/.ssh/config` when Settings > SSH Hosts opened. The activity view was turned on for one shot and off again. Orca was quit at the end and not reopened.

## What to distrust

- **Two owner choices shape the type.** The interface font is Geist because the owner's Settings > Appearance > IDE Font is Geist (`--app-font-family` on the root); the terminal is 14px SF Mono at weight 500 from the owner's terminal settings.
- **The empty chat's model label changed by itself.** It read `claude-opus-5-5[1m] High` for the first dark pass and `Opus` later; nothing the capture did selected a model, and the profile's settings are unchanged. The light screenshots show the later label.
- **The chat is opt-in.** Orca's structured chat is behind an experimental setting that is off here; the run chats were opened per launch. Its appearance settings (shown only with the setting on) were not captured.
- **Component values are one element each.** `component.*` and components.md read the first element that matched each part; they are not counts across pages.
- **Run frames are timed, not chosen.** The `run-*` screenshots are frames 1.5 s apart; the states named (thinking, tool call, editing) are what was on screen at that moment.
- **Two screenshots are painted.** Settings > SSH Hosts lists the owner's `~/.ssh/config` (users, hosts, addresses), painted out row by row; the Orca Mobile promo's two sample account addresses are painted too. The rules are in [tools/redact-rules/orca-desktop.json](../../tools/redact-rules/orca-desktop.json).
- **Muted text on the light sidebar is under AA.** `base.muted-foreground` #737373 on `worktreeSidebar.default` #f5f5f5 is 4.34:1, as Orca ships it; the other seven pairs pass. Darken the muted text a step if you reuse this pairing for body text.
- Screenshots are 256-colour PNGs. Flat UI colours are exact; read values from tokens.json.

## Do and don't

1. **Do use ink, not a hue, for the primary action.** The default button, the switch when on, the send button, the tooltip and the New pill are `base.primary`: near-black on white in light, near-white on black in dark. See [settings-orca-account](screenshots/light/settings-orca-account.png) and [toast](screenshots/dark/toast.png).
2. **Do keep red for removal only.** The destructive button appears once, as the confirm of Remove Project, with an outline Cancel beside it; the menu item that leads there is the only red text. See [remove-confirmation](screenshots/dark/remove-confirmation.png) and [project-menu](screenshots/light/project-menu.png).
3. **Do draw the same focus ring on every form control.** shadcn's 3px ring in `base.ring` at 50% with the border turning `base.ring`, on buttons, selects, switches, inputs, segments and sidebar rows alike (the workspace card and the tabs show little or none). See [button-outline-focus-visible](components/crops/button-outline-focus-visible.png) and [switch-on-focus-visible light](components/crops/switch-on-focus-visible-light.png).
4. **Do give the prompt the only bubble; let the agent's work fold into one line.** The user's message is a right-aligned `chat.user-surface` bubble; the reply is plain text, its tool calls collapsed under Worked for 11s. See [conversation](screenshots/dark/conversation.png) and [conversation-expanded](screenshots/light/conversation-expanded.png).
5. **Do set the sidebar one step off the page and keep panes flat.** The sidebar is `worktreeSidebar.default` (#f5f5f5 or #2a2a2a) against `base.background`; cards are bordered, not lifted; only menus, dialogs, the palette and the update card cast a shadow. See [workspace-terminal](screenshots/light/workspace-terminal.png) and [settings-general](screenshots/dark/settings-general.png).
6. **Don't colour selection.** A selected row or segment gets a grey wash (`worktreeSidebar.accent`, `base.accent`) and medium weight, never a hue. See [settings-nav-selected](components/crops/settings-nav-selected-default.png) and [radio-on light](components/crops/radio-on-default-light.png).

From the package folder:

```bash
python3 tools/build_tokens.py && python3 tools/build_style_guide.py && python3 tools/build_components_md.py
```

`build_tokens.py` reads `raw/css-vars.*.json` and `raw/components.*.json` and writes `tokens.json`; it refuses a token without a source, an alias that points at nothing, a dimension that is not one length and a colour that is not hex or rgba, and moves a name present in only one theme to `$extensions.notTokenised`. `build_style_guide.py` renders `style-guide.html` from `tokens.json`; `build_components_md.py` writes `components.md` from the readings, `tokens.json` and the crops. All three are deterministic, standard library only. `python3 tools/crops.py` (needs Pillow) cuts `components/crops/` from the screenshots.

To capture again (Orca must not be running; Playwright from `~/.design-systems/pw`). Once Orca is open, the scratch folder must be a git repository added with `orca repo add --path ~/.design-systems/harness-scratch/orca`, it must be the only project Orca lists (`home()` refuses otherwise), and its workspace needs one empty chat for the composer shots (`orca agent launch --agent claude --surface chat --worktree path:<scratch folder>`, no prompt):

```bash
open -a Orca --args --remote-debugging-port=9405
export PORT=9405   # SLUG defaults to this package's folder name
SCHEME=dark  KEEP='^--(?!tw-)' node tools/capture/electron/vars.mjs raw/css-vars.dark.json Orca body
SCHEME=light KEEP='^--(?!tw-)' node tools/capture/electron/vars.mjs raw/css-vars.light.json Orca body
SCHEME=dark  node tools/capture/electron/run.mjs dark
SCHEME=dark  node tools/capture/electron/shots.mjs dark
SCHEME=light node tools/capture/electron/run.mjs light
SCHEME=light node tools/capture/electron/shots.mjs light
```

Then quit Orca (`osascript -e 'tell application "Orca" to quit'`), run `python3 tools/capture/quantize.py ~/.design-systems/orca-desktop/raw-shots`, which also copies the readings into `raw/`, apply [the redaction rules](../../tools/redact-rules/orca-desktop.json) with `tools/redact_images.py apply`, and run the builders. `run.mjs` goes before `shots.mjs` in each theme: the conversation shots open the last chat tab, the one the run created. The run frames kept are listed in [quantize.py](tools/capture/quantize.py); pick them again after a new run.

## The Electron route, compared with Cursor's

| Step | Cursor (pilot) | Orca |
|---|---|---|
| Port | Accepted on the first launch | Accepted on the first launch; one window, titled Orca |
| Theme | Ignored emulated media; the owner's setting was switched and restored | Followed emulated `prefers-color-scheme`; no setting touched. `cdp.mjs` gained `SCHEME` for this |
| Hover | Needed a real pointer | Plain CSS `:hover`; the real pointer was kept anyway |
| Focus | Needed `[data-focus-ring]` set on the root | Drawn by default (shadcn's ring) |
| Values | Seed colours and color-mix formulas on Cursor's own names | shadcn's theme plus Tailwind's palette; chat colours are color-mix formulas |
| A place to run | An empty folder chosen as the composer's environment | A git repository added with Orca's CLI; the structured chat opened per launch with `orca agent launch --surface chat` |
| Overlays | Closed with Escape | The update card and the setup callout hidden by an injected style, never dismissed |
| Side effects | A draft agent, a model change, an empty automation, a settings line, all undone | Orca's own bookkeeping only (counters, a tour marked seen, a cleared New badge); the scratch project was removed at the end |

# Zendesk design reference

A token set and component reference for Zendesk's public signed-out surfaces. It was read from **www.zendesk.com** (geo-redirected to **/sg/**), **support.zendesk.com/hc/en-us**, and the first step of **/demo/** on **2026-11-19**, then refreshed on **2026-11-21** with a public site tree. Desktop is 1440×900. Phone is 390×844.

The marketing site is a styled-components build. Colour is not a custom-property ramp. Spacing, radius and content width are `:root` variables that change by breakpoint. The brand face is Vanilla Sans, with Arial as the declared fallback. The primary control is a lime pill, rgb(209, 244, 112), on ink text rgb(17, 17, 13). The hero is a dark panel, rgb(17, 17, 13), with cream display type rgb(245, 245, 242).

The site paints one light theme. No dark class and no `prefers-color-scheme` repaint was found. Garden (garden.zendesk.com) is a separate site and is not in the tokens.

The agent workspace, checkout, and any step that asks for a card, a phone, or company SSO were not entered. The contact form and the demo step were not submitted. The hero email and the login subdomain were not typed. The 2026-11-21 pass stopped at the empty login wall. `login-extracted` stays not-started.

## Brief

Read this before designing in this style. Take every value from [tokens.json](tokens.json), never from the screenshots; `python3 tools/catalog.py export zendesk` prints them all with aliases resolved.

### Principles

1. Do paint primary actions lime, with ink text on white pages.
2. Do paint the hero submit white on the same lime.
3. Do keep the hero panel dark and the page white.
4. Don't invent a dark theme.
5. Don't treat the 404 page as the current system.
6. Don't copy the wordmark into something that ships.

Each rule links the screenshot or crop that shows it, under [Do and don't](#do-and-dont).

## How the values were read

Custom properties were read from the live stylesheets on the homepage. The sheet exposes spacing, radius and content width, not a colour ramp. Computed control styles come from `getComputedStyle` on the live pages: default, and hover, focus-visible and active forced with CSS `forcePseudoState` so no submit fires. A real focus click was used on the hero email and the subdomain field.

Screenshots were taken at a measured 1440×900 (1x) and 390×844 (2x), then quantized to 256-colour sRGB PNGs. Read colours from the tokens, not the PNGs.

The 2026-11-19 readings come from headless Chromium on public pages that loaded without a Cloudflare challenge. The 2026-11-21 refresh used the same path: the T3 preview tab loaded the homepage, and a cookie dialog blocked pointer hovers, so the site tree and the new screenshots were taken in headless Chromium.

## What to distrust

The hero submit paints white text on lime. The nav primary paints ink on the same lime. They are two buttons, not one token with two colours. `light.component.button-primary` is the nav and login button. `light.component.button-on-hero` is the white-on-lime submit.

Forced hover and active often keep the lime fill and only change text opacity. A fill change that lives on a child overlay would not show up on the measured node.

The register email field was already invalid when the page loaded. The danger ring is real. The error message colour was not isolated from a script JSON text node, so it is not a token.

The 404 page is an older Zendesk template (teal rgb(23, 73, 77), square fields). It is not part of the current marketing tokens.

`--radius` at the 1150px breakpoint is 20px. Measured controls use 12px and 16px. The token `core.radius.root-desktop` records the variable. Do not use it as the button radius.

Garden's homepage declared no custom properties. Its type is system-ui at 48px/700. Those values are not in `tokens.json`.

Vanilla Sans is proprietary. The tokens name it and fall back to Arial, which is the site's own fallback. The font files are not in the repo.

## Do and don't

- **Do paint primary actions lime, with ink text on white pages.** The nav "Try it for free", the login "Sign in", and "Buy now" are rgb(209, 244, 112) with rgb(17, 17, 13) text. See [button-primary-default.png](components/crops/button-primary-default.png).
- **Do paint the hero submit white on the same lime.** The hero button is the exception. See [button-primary-on-hero-default.png](components/crops/button-primary-on-hero-default.png).
- **Do keep the hero panel dark and the page white.** The hero is rgb(17, 17, 13) with cream display type. The rest of the marketing page is white. See [home-light-default.png](screenshots/home-light-default.png).
- **Don't invent a dark theme.** No dark class or scheme repaint was found.
- **Don't treat the 404 page as the current system.** It is an older template. See [notfound-light-default.png](screenshots/notfound-light-default.png).
- **Don't copy the wordmark into something that ships.** The icon set keeps three UI glyphs. The wordmark stays in the screenshots.

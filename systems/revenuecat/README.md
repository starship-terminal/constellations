# RevenueCat

A measured reference for RevenueCat's public marketing site and public docs, captured on 2026-11-21, signed out, in headless Chromium. Desktop shots are 1440×900 at 1x. Phone shots are 390×844 at 2x. The marketing site is light only. Docs at `/docs` have a live light and dark toggle, and that dark state was captured. The signed-in product at `app.revenuecat.com` stops at a login wall. No email was typed. No form was submitted. The cookie banner was hidden, not accepted or rejected.

The control map is [site-tree.md](site-tree.md).

## How the values were read

Marketing pages declare a token layer on `:root`: `--rc-blue-primary` and the other `--rc-*` ramps, `--radius-*`, `--font-object-sans`, `--font-helvetica-neue`, `--spacing`, and a gray ramp as HSL triplets. [tools/capture/vars.mjs](tools/capture/vars.mjs) read those from the live CSSOM into [raw/css-vars.json](raw/css-vars.json). Docs add an Infima (`--ifm-*`) set. Tailwind internals (`--tw-*`) were left out of the tokens.

Component colours are computed styles from [tools/capture/public/measure.mjs](tools/capture/public/measure.mjs), written to [raw/components-computed.json](raw/components-computed.json). Hover used the pointer. Focus used `focus()`. Pressed was attempted with `CSS.forcePseudoState` and failed, so there is no pressed reading. Layout at 1440, 1024 and 390 is [raw/layout.json](raw/layout.json). The header is 64px at all three widths.

`prefers-color-scheme: dark` did not change the marketing page (`themeChecks` in css-vars.json). Docs dark was switched with the page's own theme button.

## What to distrust

- Screenshots are 256-colour PNGs. Read colours from tokens.json.
- `core.radius.pill` is derived. The browser reported a huge computed radius on the pills. The token records 9999px, the authored full-round length.
- Gray ramp steps are HSL triplets (`225 40% 94%`), type `other`. They were not converted to hex.
- Outline button borders came back as `lab()` and `oklab()` strings. Those stay as computed strings, not hex.
- Docs `dark.page` is not a token. The page fill was not read after the toggle. `dark.accent` is the declared `--rc-blue-primary`, not a second computed reading. `dark.on-accent` is observed from the screenshot.
- The FAQ "open" crop is the nav trigger, not an expanded answer. The selector matched the header button of the same name.
- Login and signup screenshots show the product's own email placeholder. No address was typed.

## Do and don't

1. **Do use the blue pill for the one primary action.** Sign up and Start for free are `#576cdb`, full round, white label. See [nav-signup-default](components/crops/nav-signup-default.png).
2. **Do keep Contact sales as an outline.** It is a pill with a blue label and a hairline border, not a second fill. See [nav-contact-default](components/crops/nav-contact-default.png).
3. **Do use the red only as a hover on nav labels and the wordmark.** The wordmark and the open menu label are `#f2545b`. Body text stays `#1f1f47`. See [nav-trigger-hover](components/crops/nav-trigger-hover.png).
4. **Do set display in Object Sans at weight 500.** The home headline is 60px, pricing 64px, sales 48px. Body is Helvetica Neue 16/24. See [home-title-default](components/crops/home-title-default.png).
5. **Don't invent a marketing dark theme.** `prefers-color-scheme` did not change the marketing page. Dark exists on docs only. See [docs-light-dark](screenshots/docs-light-dark.png).
6. **Don't fill the hero email or the sales form when reproducing a public page.** Those fields are empty in every capture. See [hero-email-default](components/crops/hero-email-default.png).

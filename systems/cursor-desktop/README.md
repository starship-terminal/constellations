# Cursor desktop design reference

A token set and component reference for Cursor's desktop app for macOS (Anysphere), version 3.27.6 (Electron 42.11.16, Chrome 148), captured on 2026-10-25 from the owner's signed-in account on the Team plan. Cursor 3 opens on its Agents window: a sidebar of projects, pinned agents and repositories, one composer that starts an agent, the agent conversation, Automations, Customize (plugins, MCP servers, skills) and Settings. The IDE window (the VS Code workbench Cursor is built on) opens beside it from the IDE button. Both were captured, the Agents window in full and the IDE window on an empty scratch folder, in Cursor Light and Cursor Dark, at the window size the app was in: 1280 x 800 pt.

Everything was read live from the running app over Chromium's remote-debugging port, with Playwright connected over CDP: full-window screenshots of every screen and state, the custom properties of the theme engine as they compute and paint, and the computed style of every captured part in every state. It is the first package captured this way and the pilot for the other Electron coding harnesses tracked in [issue 107](https://github.com/c-wenlong/designs/issues/107); [Rebuild](#rebuild) says what another app copies. Use it to build a dense desktop agent or developer tool: a near-black or off-white window, a quiet sidebar, raised surfaces only where something floats, text and fills made from one base colour at fixed alphas, and a single blue accent. For Cursor's iOS app see [cursor-ios](../cursor-ios/README.md); no value here was taken from it.

This package contains no Cursor code, icons or artwork; the screenshots and the visual system they show are Anysphere's ([docs/RIGHTS.md](../../docs/RIGHTS.md)). Borrow structure and proportions, not the brand.

## Brief

<!-- brief:start. Generated by tools/brief.py from catalog.json, the tokens file and this README; `make brief` rewrites it. Do not edit. -->

Read this before designing in this style. Take every value from [tokens.json](tokens.json), never from the screenshots; `python3 tools/catalog.py export cursor-desktop` prints them all with aliases resolved.

### Principles

1. Do build every neutral from one base colour at fixed alphas.
2. Do keep the window flat and raise only what floats.
3. Do give the prompt the only bubble; let the agent's reply sit on the page.
4. Do keep the accent for the one action that commits, and use ink pills for page actions.
5. Don't colour destructive actions.
6. Do show selection and hover with text contrast and a faint wash, not a coloured fill.

Each rule links the screenshot or crop that shows it, under [Do and don't](#do-and-dont).

## How the values were read

Cursor is an Electron app (`Contents/Frameworks/Electron Framework.framework`), so its interface is HTML and CSS. It was not running; it was opened with `open -a Cursor --args --remote-debugging-port=9401`, which it accepted, and Playwright attached with `chromium.connectOverCDP`. The account was already signed in inside the app; nothing was typed into a sign-in screen. The capture scripts are in [tools/capture/electron/](tools/capture/electron): [cdp.mjs](tools/capture/electron/cdp.mjs) connects and picks a window by its title, [shots.mjs](tools/capture/electron/shots.mjs) drives the shot list in [product.mjs](tools/capture/electron/product.mjs), [vars.mjs](tools/capture/electron/vars.mjs) reads the custom properties and [run.mjs](tools/capture/electron/run.mjs) captures an agent run. Screenshots are CDP's `Page.captureScreenshot`, the window's own backing store; Playwright's `page.screenshot` pads the image when the pixel ratio is not a whole number, as it is here.

**The theme engine.** A theme is about 135 seed colours written as hex on `body[data-cursor-glass-mode="true"]` by a `glass-cursor-theme-variables` style element (with an oklch copy under `@supports`): `base` (the ink: #141414 in light, #f0f0f0 in dark), `chrome`, `pane`, `sidebar`, `elevated`, `accent`, `brand`, nine hues, the status and git colours, the diff and terminal colours. About 460 more `--cursor-*` names are formulas over the seeds, and most of them are the base colour at a fixed alpha: `text.secondary` is `color-mix(in srgb, var(--cursor-base) 74%, transparent)`, `bg.tertiary` the base at 8%, `stroke.secondary` at 12%. [vars.mjs](tools/capture/electron/vars.mjs) lists every declaration with its sheet, selector and condition, then reads each name on `[data-component="root"]` three ways: the computed token stream, the colour it paints (a probe element's `color: var(--x)`, which Chromium returns as `color(srgb ...)` or `oklch(...)`) and, for shadows, the painted `box-shadow`. [build_tokens.py](tools/build_tokens.py) turns the painted colours into sRGB hex or rgba ([colour.py](tools/colour.py) converts oklch, lab and lch), keeps a seed as its value, makes a token an alias when its formula is a plain `var()` of another token that paints the same, and otherwise keeps the painted value with the formula beside it.

**Themes.** Cursor's theme does not follow an emulated `prefers-color-scheme` (CDP `Emulation.setEmulatedMedia` left `body.cursor-dark` in place), so the owner's own setting was switched, as approved on 2026-10-24: Settings > Appearance > Theme was System (macOS was dark), set to Cursor Dark for the dark pass, Cursor Light for the light pass, and back to System at the end. Choosing a theme also wrote `"workbench.colorTheme": "Cursor Light"` to the user settings file; that line was removed after Cursor was quit, leaving the file as it was. The other two themes, Cursor Light Colorblind and Cursor Dark High Contrast, were not captured.

**Components and states.** Each shot resets the window to the New Chat page, reveals one state with Cursor's own selectors (its `data-component` names, roles, aria-labels and class names, never account text), takes the screenshot and reads the computed style of every listed part, recording its box for [crops.py](tools/crops.py). Hover is a real pointer over the part: Cursor's controls only take their hover fill when its script has set `[data-pointer-hover-intent]` on pointer movement, so a hover forced through CDP shows nothing. Pressed is `:active` forced through CDP's `CSS.forcePseudoState` with the pointer over the part. Focus-visible is real keyboard focus (a key press, then `focus()`), with one change made by the capture: the Agents window draws its focus ring only when its root carries `[data-focus-ring]` (`--cursor-focus-ring-width` is 0px otherwise, and a Tab press did not set it), so the focus shots set that attribute on the root and the ring they show is Cursor's own rule, `1px solid` accent at `-1px` offset. Before and after every shot the script compares the composer's model and the sidebar's rows and stops if either changed.

**Sizes.** The owner's Settings > Appearance > UI Font Size is 11, which Cursor applies as a window zoom of 0.84 (`--zoom-factor` on the root), so the Agents window's 1280 x 800 pt is a 1524 x 952 CSS px viewport at a device pixel ratio of 1.68. Every px value in tokens.json and components.md is a CSS px before that zoom, the value Cursor's stylesheets declare (`--cursor-font-size-base` is 13px; on screen it is 11 pt). A 1px border computes as 0.595px, one device pixel. The IDE window is not zoomed: 1280 x 800 CSS px at 2x.

**The agent run.** The owner approved test prompts on 2026-10-25 in a fresh chat on an empty folder, `~/.design-systems/harness-scratch`. [run.mjs](tools/capture/electron/run.mjs) chose that folder as the composer's environment, sent "List the files in this folder.", "Create hello.txt here containing one line: hello from the design capture" and "Run ls -la in this folder in the terminal and show me the output.", screenshotting and measuring every 1.2 s until each finished, then set the environment back to Toolbox Fullstack Environment. One chat was run in each theme (both are titled Folder file listing). The agent wrote `hello.txt` and a `.cursor` folder in the scratch folder and ran `ls -la` there. No approval prompt appeared: the owner's agent settings auto-run such commands, and nothing was changed to force one.

**Nothing else was changed, with one slip, undone.** Menus, dialogs and the palette were opened and closed with Escape; text typed into the composer and the search fields was cleared without sending. Two things happened that were not meant to and were put back. Typing into the composer saves an unsent draft agent in the sidebar ("Draft text, never sent"); it disappeared when the text was cleared. In an early trial the composer's model changed from Grok 4.7 High to another model (the cause was not found); it was set back to Grok 4.7 High with Fast off, 256K context and High effort, and the guard above was added. Clicking New Automation while exploring created an empty, inactive automation named Untitled; it was used for the delete confirmation in both themes and then deleted. Cursor was quit at the end and not reopened; quitting let it install the update it was waiting on (it is now 3.27.12).

## What to distrust

- **Focus rings are shown with a switch the capture flipped.** Out of the box the Agents window draws no focus ring at all. The `-focus-visible` crops and screenshots show what Cursor draws when `[data-focus-ring]` is on its root; when Cursor sets it was not found.
- **The sizes are pre-zoom.** Cursor at its default UI font size draws them 1:1; this account draws them at 0.84. Screenshots show the zoomed result.
- **Two owner settings shape the surfaces.** Reduce Transparency is on and macOS vibrancy is off (`body.cursor-glass-reduce-transparency`, `cursor-glass-os-vibrancy-off`), so the glass surfaces are opaque here; `glass.vibrancy-on-*` tokens hold what they become otherwise. The UI font is the system font and the code font the system monospace by the owner's choice; the stylesheet defaults are recorded on `core.fontFamily.*` as `stylesheetDefault`.
- **The light and dark home screens differ in one label.** The composer's environment was harness-scratch while the light screens were taken (opening the test chat set it), Toolbox Fullstack Environment for the dark ones. Both are restored now.
- **Component values are one element each.** `component.*` and components.md read the first element that matched each part; they are not counts across pages.
- **Run frames are timed, not chosen.** The `run-*` screenshots are frames 1.2 s apart; the states named (thinking, exploring, editing) are what was on screen at that moment.
- **IDE window content is partly third-party.** Its first screen showed GitLens and MongoDB extension panels (closed again); the IDE values are VS Code workbench colours under Cursor's theme (`ide.*`), read once per theme.
- Screenshots are 256-colour PNGs. Flat UI colours are exact; read values from tokens.json.

## Do and don't

1. **Do build every neutral from one base colour at fixed alphas.** Text is the base at 100, 74, 60 and 36%, fills at 20, 14, 8, 6 and 4%, edges at 20, 12, 8 and 4%, in both themes; only the base changes (#141414 in light, #f0f0f0 in dark). See [settings-general](screenshots/dark/settings-general.png) and [settings-general light](screenshots/light/settings-general.png).
2. **Do keep the window flat and raise only what floats.** The page (`seed.chrome`) and sidebar (`seed.sidebar`) differ by one step; the composer, menus, dialogs, tables and cards sit on `seed.elevated` with a 12% hairline or a ring of 8%, and nothing else has a fill. See [home-default](screenshots/dark/home-default.png), [model-menu](screenshots/dark/model-menu.png) and [automations](screenshots/light/automations.png).
3. **Do give the prompt the only bubble; let the agent's reply sit on the page.** The user's message is a raised 12px card with a 10px blur; the reply is plain 13px text, its work folded into one muted line. See [conversation](screenshots/dark/conversation.png) and [run-finished](screenshots/light/run-finished.png).
4. **Do keep the accent for the one action that commits, and use ink pills for page actions.** Create Project, Invite and Update are accent blue with dark text; New Automation and Browse Marketplace are `text.primary`-filled pills. See [create-project-dialog](screenshots/dark/create-project-dialog.png) and [automations](screenshots/dark/automations.png).
5. **Don't colour destructive actions.** The delete confirmation's Delete is the same accent button as any other primary action; the warning is in the words. See [delete-confirmation](screenshots/dark/delete-confirmation.png).
6. **Do show selection and hover with text contrast and a faint wash, not a coloured fill.** A selected or hovered row goes from `text.secondary` to `text.primary` on a 6 to 8% wash, and its actions (archive, pin) appear only under the pointer. See [agent-row-default](components/crops/agent-row-default.png), [agent-row-hover](components/crops/agent-row-hover.png) and [tab-selected](components/crops/tab-selected-default.png).

## Rebuild

From the package folder:

```bash
python3 tools/build_tokens.py && python3 tools/build_style_guide.py && python3 tools/build_components_md.py
```

`build_tokens.py` reads `raw/css-vars.*.json` and `raw/components.*.json` and writes `tokens.json`; it refuses a token without a source, an alias that points at nothing, a dimension that is not one px length and a colour that is not hex or rgba, and moves a name present in only one theme to `$extensions.notTokenised`. `build_style_guide.py` renders `style-guide.html` from `tokens.json`; `build_components_md.py` writes `components.md` from the readings, `tokens.json` and the crops. All three are deterministic, standard library only. `python3 tools/crops.py` (needs Pillow) cuts `components/crops/` from the screenshots.

To capture again (Cursor must not be running; Playwright from `~/.design-systems/pw`):

```bash
open -a Cursor --args --remote-debugging-port=9401
PORT=9401 node tools/capture/electron/shots.mjs --set-theme="Cursor Dark"
PORT=9401 node tools/capture/electron/shots.mjs dark
PORT=9401 KEEP='^--(cursor|glass|ui|zoom)-' node tools/capture/electron/vars.mjs raw/css-vars.dark.json "Cursor Agents" '[data-component="root"]'
PORT=9401 KEEP='^--(cursor-|vscode-(?!icon-))' node tools/capture/electron/vars.mjs raw/css-vars.ide-dark.json '<IDE window title>' .monaco-workbench
PORT=9401 node tools/capture/electron/run.mjs dark
```

Repeat with `Cursor Light` and `light`, set the theme back with `--set-theme="System"`, quit Cursor (`osascript -e 'tell application "Cursor" to quit'`), then `python3 tools/capture/quantize.py ~/.design-systems/cursor-desktop/raw-shots`, which also copies the readings into `raw/`, and the builders. The IDE window must be open on the scratch folder (`cursor ~/.design-systems/harness-scratch`).

**Reusing this for another Electron app.** Copy `tools/capture/electron/` and `tools/capture/quantize.py`, then the builders (`build_tokens.py`, `build_style_guide.py`, `build_components_md.py`, `crops.py`, `colour.py`). `cdp.mjs`, `vars.mjs`, `shots.mjs`, `run.mjs`, `crops.py` and `colour.py` are generic. Everything marked `PRODUCT (adapt)` is Cursor's: rewrite `product.mjs` whole (window titles, `reset`, `setTheme`, the shot list and its selectors, `prepareState`, `guard`, `RUN`), the run frames kept in `quantize.py`, the mapping block at the top of `build_tokens.py` (prefix, seed sheet, groups, roles, components), `INVENTORY` and `GAPS` in `build_components_md.py`, and `NAME`, `LEDE` and `specimens()` in `build_style_guide.py`. Start by checking three things in the new app: whether its theme follows `Emulation.setEmulatedMedia` (Cursor's does not), whether its hover styles need a real pointer (Cursor's do), and whether it draws a focus ring without help (Cursor's does not).

## The Electron route, as it went

| Step | What happened |
|---|---|
| Port | Cursor accepted `--remote-debugging-port` on the first launch and kept the session; both windows (Agents and IDE) appear as CDP pages with the same URL, told apart by title |
| Screenshots | `Page.captureScreenshot` gives the exact window; Playwright's own screenshot padded the image at the 1.68 pixel ratio |
| Values | Every colour, size and duration is a custom property; reading the painted colour through a probe element resolves color-mix and oklch without re-implementing them |
| Hover | Needed a real pointer (`[data-pointer-hover-intent]` gate); forced `:hover` showed nothing |
| Focus | Needed `[data-focus-ring]` on the root; without it Cursor draws no ring |
| Theme | Did not follow emulated media; the app's own setting was switched and restored, and the settings file cleaned afterwards |
| Side effects | Typing in the composer saves a draft agent; New Automation creates a record at once; the guard on model and sidebar caught the rest |

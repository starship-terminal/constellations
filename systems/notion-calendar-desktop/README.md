# Notion Calendar desktop design reference

A token set and component reference for Notion Calendar 1.142.0 for macOS (formerly Cron; bundle id `com.cron.electron`, Electron 44.9.1 on Chromium 152), captured on 2026-10-25 from the owner's signed-in account. The app's one window loads the calendar web app from `https://calendar.notion.so/`, so everything here is that React app as the desktop frame shows it: the week, day and month views, the sidebar with the mini calendar and calendar lists, event chips, the event popover and the new-event editor, the scheduling pane, menus, the command menu, the keyboard shortcuts panel and every Settings pane. Both themes were captured, the owner's Dark mode and Light mode, at the window size the app was in: 1063 x 948 pt.

Everything was read live from the running app over Chromium's remote-debugging port with the Electron route that [cursor-desktop](../cursor-desktop/README.md) piloted ([issue 107](https://github.com/c-wenlong/designs/issues/107)): full-window screenshots of every screen and state, the custom properties as they compute and paint on `<html>`, and the computed style of every captured part in every state. Use it to build a calm, dense calendar or planner: a light wash sidebar beside a white (or near-black) grid, hairline edges drawn as 1px inset shadows instead of borders, 13px medium labels on 30px controls with 6px corners, the one blue accent kept for primary actions, switches and focus, red only for today, and menus and tooltips that stay dark in both themes. Notion's iPhone app is [notion-ios](../notion-ios/README.md); the Notion desktop app is being captured separately as `notion-desktop`. No value here was taken from either.

This package contains no Notion code or artwork beyond the app icon (`icon.png`); the screenshots and the visual system they show are Notion's ([docs/RIGHTS.md](../../docs/RIGHTS.md)). Borrow structure and proportions, not the brand.

### Principles

1. Do draw edges as hairline shadows, not borders.
2. Do keep one blue for action and focus.
3. Do mark today, and only today, in red.
4. Do keep menus and tooltips dark in both themes.
5. Do float event details in a translucent panel.
6. Don't hide an action without a key.

Each rule links the screenshot or crop that shows it, under [Do and don't](#do-and-dont).

## How the values were read

Notion Calendar is Electron (`Contents/Frameworks/Electron Framework.framework` beside `Resources/app.asar`), and its window is a page of `https://calendar.notion.so/`, the same web app the browser version serves, so its interface is HTML and CSS. The owner allowed a relaunch on 2026-10-25: the capture quit the running app, opened it with `--remote-debugging-port=9410`, found it still signed in (no sign-in screen showed) and attached Playwright with `chromium.connectOverCDP`. The window is the one CDP page whose URL is on `calendar.notion.so`; a service worker is the other target. The scripts are in [tools/capture/electron/](tools/capture/electron): [shots.mjs](tools/capture/electron/shots.mjs) drives the shot list in [product.mjs](tools/capture/electron/product.mjs) and [vars.mjs](tools/capture/electron/vars.mjs) reads the custom properties. Screenshots are CDP's `Page.captureScreenshot`, the window's own backing store.

**The token system.** One inline stylesheet declares about 730 custom properties on `:root` and redeclares 360 of them on `:root.dark`; the theme is the `dark` class on `<html>`. Notion's design system (`--nds-*`) names colours by role (`text`, `icon`, `surface`, `fill`, `tint`, `state`, `stroke`, `shadow`) with a `-contr-` twin of each that holds the dark value in both themes, which is how menus and tooltips stay dark in light mode; twelve hue ramps (`--nds-gray-*` to `--nds-yellow-*`) sit under them. The calendar's older Cron names (`--public-*`, `--object-*`, `--layout-*`, `--calendar-*`, `--kbs`, `--text-*`) are mostly `var()` of an `--nds-*` name. Scales are declared too: four radii, button, input and event-chip type, durations and easings, opacities, control sizes, layout widths and z-index layers. There is no numbered spacing scale. [vars.mjs](tools/capture/electron/vars.mjs) lists every declaration and paints each name through a probe element; [build_tokens.py](tools/build_tokens.py) keeps a name as an alias when its declaration is a plain `var()` of a kept name that paints the same, and otherwise keeps the painted colour with the declaration beside it.

**Themes.** The owner's Settings > General > Theme is Dark mode, not Auto, so an emulated `prefers-color-scheme` (CDP `Emulation.setEmulatedMedia`) changed nothing: `<html>` kept its `dark` class. The dark pass ran as it was. For the light pass the capture chose Light mode in Settings, then chose Dark mode again at the end; after a reload the stored setting read `dark` and the window was dark.

**Components and states.** Each shot starts from the same view: Week, today's week (19 to 25 October 2026), the grid scrolled to 07:30 and the sidebar to its top. It reveals one state with the app's own controls, mostly single-letter shortcuts, clicks on buttons and Escape; the selectors are styled-components classes (stable for this build), data attributes (`data-event-chip-key`, `data-calendar-id`, `data-grid-date`, `data-floating-context-panel`) and UI words. One owner event, Tech Sync on Tuesday, is named in [product.mjs](tools/capture/electron/product.mjs) because the popover shots open it. Hover is a real pointer over the part; focus-visible is real keyboard focus (a key press, then `focus()`), and Notion draws its own ring, a 1px accent box-shadow with a 4px tinted halo; pressed is `:active` forced through CDP's `CSS.forcePseudoState` with the pointer over the part, never a real press on an event. Before and after every shot the script compares the synced user settings (theme, time zones, time format), the view and visible range, every event chip on screen and which calendars are shown, and stops if any changed.

**Sizes.** The window is 1063 x 948 CSS px at a device pixel ratio of 2, unzoomed. Every px value is a CSS px.

**What the capture changed, and what was put back.** The owner's calendars are real and shared with other people, so the capture created, edited, moved, answered and shared nothing, and created no scheduling link. Two slips happened while the editor was being explored, before the shot list was written: Escape on the new-event editor saves a draft once anything has been typed into it, with no discard prompt, even after the text is cleared again. Two events were created that way on the owner's own primary calendar ("Draft title, never saved" and an untitled one, both on 25 October at 11:30, no participants, so no invitation went out). The capture deleted both in the app within minutes and then checked the owner's events from 18 October to 9 November through the Notion Calendar connector: 242 events, identical to the reading taken before the capture. The same check passed after each theme's pass and at the end. From then on the editor was only opened and closed untouched. Also changed and put back: the theme (Light mode for the light pass, Dark mode again), the sidebar's last-opened pane in `localStorage` (`ui.sidebarState`, rewritten when the scheduling pane opened and restored to its earlier value), the view (Day and Month for their shots, Week again) and the grid's scroll position. Menus, the command menu, the shortcuts panel, the event popover and Settings were opened and closed with Escape; text typed into the command menu and the shortcuts search was cleared by setting the field's value, never with Cmd+A and Backspace, which outside a field select every visible event and delete them. Notion Calendar was quit at the end and reopened normally; port 9410 is closed.

## What to distrust

- **Event chip colours are not tokens.** A chip's fill, text and ribbon are computed in script from its calendar's colour; `component.event-chip` holds the radius and padding only. The screenshots show the colours; never read a value off them.
- **Menus and tooltips are dark in light mode on purpose.** They use the `-contr-` tokens (`surface.contr-elevated`, `text.contr-primary`); `component.menu` and `component.tooltip` in the light set point at those.
- **`role.text.link` is Notion's link blue, which no captured screen shows.** Settings links are underlined secondary text.
- **The light dialog aliases the page.** The settings dialog paints white in light, which `surface.page` and `surface.elevated` both are, so `component.dialog.bg` names the page there and `surface.elevated` (#252525) in dark. Use `role.raised` for a dialog in either theme.
- **The accent's hover and pressed steps come from the switch.** `role.accent.hover` and `role.accent.pressed` are the on switch's fill under the pointer and while pressed; the primary button's own hover was not captured.
- **Type roles are one element each.** `core.typography.*` and `component.*` read the first element that matched each part (or the shot [prefer.py](tools/prefer.py) names), not counts across pages. Containers report the page's 16px; the roles are taken from the elements that hold the text.
- **These are the owner's calendars and settings.** The colours of the calendar list and the events, the two time-zone columns (SF and SG), 24-hour time, Monday as the first day and week numbers are the owner's choices; the tokens are the app's.
- **Redacted:** two participants' email addresses and the Google Meet code in the event popover, and in the month view one event title that names a hospital and a condition. [tools/redact-rules/notion-calendar-desktop.json](../../tools/redact-rules/notion-calendar-desktop.json) holds the rectangles. The account header crops show the owner's own work address and are kept; the file's `email_allow` covers the way OCR misreads it. Other people are masked too, since the repository went public (2026-11-21): event chip titles that name another person or their initials (two Wednesday chips and the first word of the Saturday chip in the week views, the same three events and ten more in the month view), the organizer's name and the other participants' avatar discs in the event popover (pixelated, so the discs still show), and the name of a workspace named after another person in the settings dialog's workspace list. The chips, times and the rest of each row stay. Re-running `quantize.py` brings the painted regions back; run the redaction again after it, then `crops.py`. The owner's name, avatar, addresses and own event titles stay.
- Screenshots are 256-colour PNGs. Flat UI colours are exact; read values from tokens.json.

## Do and don't

1. **Do draw edges as hairline shadows, not borders.** Buttons, fields, the sidebar and panels take a 1px inset shadow in `stroke.secondary` (`shadow.input-border`), so a control's size never changes when its edge does. See [week-default](screenshots/light/week-default.png) and [settings-general](screenshots/dark/settings-general.png).
2. **Do keep one blue for action and focus.** `fill.uiBlue` fills the primary button and the on switch; the same blue draws the 1px focus ring with its 4px halo. Everything else is grey text on a wash. See [scheduling](screenshots/light/scheduling.png) and [settings-select-focus-visible](screenshots/dark/settings-select-focus-visible.png).
3. **Do mark today, and only today, in red.** The date badge in the day header and the mini calendar and the now line share `app.secondary500`. See [week-default](screenshots/dark/week-default.png).
4. **Do keep menus and tooltips dark in both themes.** They use the `-contr-` tokens, so they read as a layer above the page whatever the theme. See [view-menu](screenshots/light/view-menu.png) and [event-context-menu](screenshots/light/event-context-menu.png).
5. **Do float event details in a translucent panel.** The popover and the command menu are `surface.elevated-wax` with a 12px blur and the high elevation, so the week stays visible behind them. See [event-popover](screenshots/dark/event-popover.png) and [command-menu](screenshots/light/command-menu.png).
6. **Don't hide an action without a key.** Every menu row and tooltip shows its shortcut in a key cap, and most views and actions are one letter. See [shortcuts](screenshots/dark/shortcuts.png) and [tooltip](screenshots/light/tooltip.png).

## Rebuild

From the package folder:

```bash
python3 tools/build_tokens.py && python3 tools/build_style_guide.py && python3 tools/build_components_md.py
```

`build_tokens.py` reads `raw/css-vars.*.json` and `raw/components.*.json` and writes `tokens.json`; it refuses a token without a source, an alias that points at nothing, a dimension that is not one px length and a colour that is not hex or rgba, and moves a name present in only one theme to `$extensions.notTokenised`. `build_style_guide.py` renders `style-guide.html` from `tokens.json`; `build_components_md.py` writes `components.md` from the readings, `tokens.json` and the crops. All three are deterministic, standard library only. `python3 tools/crops.py` (needs Pillow) cuts `components/crops/` from the screenshots.

Then the same two lines with `light`, and `shots.mjs --set-theme="Dark mode"` to put the theme back (use the label the first `--set-theme` printed). `shots.mjs --from=<name>` resumes a pass that stopped. Before and after, list the owner's events for the weeks around today (the Notion Calendar connector's list-events) and compare. Quit the app and reopen it normally (`open -a "Notion Calendar"`), then `python3 tools/capture/quantize.py ~/.design-systems/notion-calendar-desktop/raw-shots`, which also copies the readings into `raw/`, `python3 tools/capture/rename_parts.py`, the redaction (`python3 tools/redact_images.py apply systems/notion-calendar-desktop --rules tools/redact-rules/notion-calendar-desktop.json --patterns ~/.design-systems/cleanup-redact.json`, from the repository root), `crops.py`, the redaction once more (it deletes the account header crops) and the builders. The redaction paints out the private values and other people's names, initials and avatars (event guests, the organizer, a workspace named after another person); never skip it, or a rebuild brings them back. ## The Electron route, as it went

| Step | What happened |
|---|---|
| Launch | Quit, then `open -a` with `--remote-debugging-port=9410`; accepted at once, still signed in |
| Windows | One page on calendar.notion.so plus a service worker; picked by URL |
| Values | Every colour, shadow and scale is a custom property on `:root` / `:root.dark`; painted through a probe |
| Hover | Real pointer; Playwright's `hover()` also scrolls the near-million-pixel-wide week canvas, so every shot resets the view and grid parts are looked up inside one visible day column |
| Focus | Notion's own ring, no help needed |
| Theme | Did not follow emulated media; Settings > Theme was switched to Light mode and back to Dark mode |
| Side effects | Escape saves a typed event draft (two were created and deleted); menus with an open submenu ignore Escape and close on a backdrop click; letters on the page are shortcuts, so typing is allowed only when a field has focus |

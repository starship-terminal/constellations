# FeedHive design reference

A token set and component reference for FeedHive's public surfaces — for building SaaS marketing pages, pricing pages, feature pages, blog indexes, free-tool forms and the sign-in edge in the style of the real thing. It was read from **feedhive.com** on **2026-11-14**, signed out, in headless Chromium at 1440 x 900 and 390 x 844. Captured: the home page, /pricing, /features/scheduling, /features/ai, /blog plus one article, /integrations, /tools, /tools/bio-generator, /alternatives, /privacy, /terms, the app.feedhive.com/signin and /signup cards, and 390px passes on home, pricing and tools.

FeedHive is an AI social-media scheduling product, and its public surface is a light-only Next.js + Tailwind v4 marketing site. The declared custom-property layer is thin — Tailwind's theme defaults (`--spacing` 4px, `--radius-md/lg/xl`, `--text-sm`/`--text-lg`, `--font-weight-*`, `--leading-tight`, `--ease-out`, `--default-transition-*`, `--color-black`/`--color-white`) plus FeedHive's own `.cta-gradient-ring` signature (`--cta-border-angle` animating 0deg→1turn, `--cta-ring-*`, `--cta-glow-*`) and a themed vanilla-cookieconsent vendor layer whose `--cc-btn-primary-bg` confirms the brand indigo **#4457ff**. Nearly every real value rides arbitrary-value utilities, so the capture leans on computed styles: three next/font voices (**Inter** for everything, **Plus Jakarta Sans** for display, **Sometype Mono** for tracked caps eyebrows), a 55–68px display ramp (46px on the phone), the indigo action ramp (#4457ff → #3347fb hover, #eef2ff/#84a1ff/#5a84ff selected tint), warm inks #23252b/#20232b and subtle surfaces #f4f3f2/#f6f6f8/#fbfaf7, 9–20px radii against full pills, and the 150ms control transition. **Boundary:** app.feedhive.com sign-in/sign-up is a separate Chakra-UI app that shares no token layer (#3b82f6 submit blue, #5d60ec links, 9999px pills, 20px card) — measured as forms, never submitted; everything post-login (composer, scheduler, analytics) was never reached; docs.feedhive.com is a separate site; every CTA and link was measured, never followed; the dormant cookie-consent layer was never answered.

## Brief

### Principles

1. Do spend the indigo on action.
2. Do use the measured role names.
3. Do keep the two systems apart.
4. Do pair the three voices.
5. Do keep the radius ladder honest.
6. Don't style the signed-in product from this package.
7. Don't fabricate form outcomes.
8. Don't invent a dark mode.
9. Don't copy the brand.

Each rule links the screenshot or crop that shows it, under [Do and don't](#do-and-dont).

## How the values were read

| Step | What ran |
|---|---|
| Screenshots | `tools/capture/public/public.mjs` — 14 pages at 1440 x 900 (default + stitched `-full`, capped at 8 tiles) and 3 at 390 x 844, consent layer hidden, never answered |

| Measurements | `tools/capture/public/measure.mjs` — 55 components on public routes only; hover/focus-visible/pressed/opened/selected/focused/filled states; nothing signed into, submitted or followed |
| Tokens | `tools/build_component_tokens.py` → `raw/component-tokens.json` → `tools/build_tokens.py` → `tokens.json` |
| Docs | `tools/build_components_md.py`, `tools/build_style_guide.py`, `tools/capture/public/build-measurements.mjs` |

- **Provenance.** Every token leaf names its source in `$extensions.source`: `css-var --…` or "declared custom property in the site's css bundle" for the site's own variables, `computed …`/`measured …` for computed-style readings.

## What to distrust

- **The signed-in product.** Nothing behind app.feedhive.com was reached; the composer, scheduler, AI generation and analytics need an account this capture does not have. The product screenshots on the marketing pages are published images, not the product.
- **The Chakra values.** `component.login.*` is a different design system read at a different URL — never mix it with the marketing roles (its #3b82f6 blue is not the marketing #4457ff indigo).
- **The forms.** Bio-generator and sign-in/up fields were measured at rest and typed into then cleared — validation, error, loading and success states are unverified because nothing was submitted. The Generate button's pale #b9c0f5 is its resting style, not a measured disabled state.
- **The thin declared layer.** Most values are measured literals, not published variable names — `--color-primary` is compiled into utilities, not declared, so `light.action.*` names the brand ramp instead.
- **Quantised screenshots.** `screenshots/` are 256-colour PNGs; read exact colours from tokens or the raw values, never the pixels.

## Fonts

- **Inter** — the single UI voice (variable wght 100–900 via next/font, plus a local "Inter Fallback" metrics face), every control and body.
- **Plus Jakarta Sans** — display headings, section titles and the 31px plan names.
- **Sometype Mono** — the tracked caps eyebrows and card kicker labels.
- None is bundled here; the style guide falls back to system faces. Declared in the stylesheet's `@font-face` rules (harvested in `raw/css-vars.json`). The Chakra app uses a plain `Inter, sans-serif` stack.

## Coverage

- 14 desktop routes and 3 mobile routes captured signed out; both public surfaces covered (the light marketing site and the light Chakra sign-in/up cards).
- 55 components measured in 131 states, including opened nav dropdowns, the billing toggle, selected tab pills, the mobile drawer, forced-pressed controls and typed-then-cleared form fields.
- Missing surfaces (declared in the catalog's `capture.gaps`): every post-login app surface, docs.feedhive.com, all but one article and all but one tool generator.
- Icons: layout gap — no standalone SVG set lifted; product glyphs are visible in crops/screenshots.

## Do and don't

1. **Do spend the indigo on action.** `#4457ff` marks CTAs, the Business plan card, the selected billing toggle and the mono kickers; surfaces stay white or warm-subtle. See [nav-signup](components/crops/nav-signup-default.png) and [plan-card](components/crops/plan-card-default.png).
2. **Do use the measured role names.** The declared layer is thin — `light.action.*`/`light.text.*`/`light.background.*`/`light.border.*` carry the ramp; restating hex loses the aliases. See [tokens.json](tokens.json).
3. **Do keep the two systems apart.** Marketing Tailwind values and the Chakra `component.login.*` values come from different apps; the sign-in card is a documented boundary, not part of the marketing system. See [login-panel](components/crops/login-panel-default.png).
4. **Do pair the three voices.** Inter for UI, Plus Jakarta Sans for display, Sometype Mono only for the tracked caps labels. See [hero-h1](components/crops/hero-h1-default.png) and [feat-eyebrow](components/crops/feat-eyebrow-default.png).
5. **Do keep the radius ladder honest.** 9px chips, 11px header pills, 12px fields, 15px CTAs, 16px cards, 18px dropdown items — full pills only on tab/tone pills and the Chakra controls. See [hero-cta](components/crops/hero-cta-default.png).
6. **Don't style the signed-in product from this package.** Everything behind app.feedhive.com was never reached; the sign-in/up cards are the only app surfaces measured. See [login-light-default](screenshots/login-light-default.png).
7. **Don't fabricate form outcomes.** Generate, Sign in and Sign up were measured, never pressed; what a submission returns is unverified. See [bio-submit](components/crops/bio-submit-default.png).
8. **Don't invent a dark mode.** FeedHive ships light only — the `dark` token set is empty by design. See [home-light-full](screenshots/home-light-full.png).
9. **Don't copy the brand.** The bee mark, the indigo, the product screenshots and the brand logos are FeedHive's published artwork; borrow structure and proportion, not identity. See [mkt-logo](components/crops/mkt-logo-default.png).

# Coursera design reference

A token set and component reference for Coursera's web product, for rebuilding our course list and course detail pages in the style of a real course platform. It was read from coursera.org on 2026-09-29: the public catalogue pages headless (home, search, browse, course, specialization, certificate and the Explore topic page with its compact course cards, chip rows and scrolling card rows), and the signed-in learner pages from one learner's account (the course pages all from one enrolled course; My Learning also lists the learner's other courses, renamed), all at 1440 wide, with five public pages also at 390 wide. A refresh on 2026-10-17 added the log-in dialog and its validation error, the AI coach text area, the 404 page, the z-index layers and reduced-motion rules, and, signed in, the course overflow menu, the review and share dialogs, and Account settings (switches, the colour theme select, a warning notification) in light and in the dark theme learners can now choose. It also added written [patterns](patterns.md) and a coverage table.

A public-site refresh on 2026-11-22 mapped the signed-out marketing tree in [site-tree.md](site-tree.md) and added viewport shots under [screenshots/](screenshots) (`public-2026-11-22-*`) plus opened states in [screenshots/site-tree/](screenshots/site-tree). Desktop shots are 1440×900 CSS at 2x (2880×1800 PNG). Phone shots are 390×844 CSS at 2x (780×1688 PNG). Log In and Join for Free open one empty dialog (`?authMode=login` and `?authMode=signup`). The email field was left empty. Continue, Google, Facebook, and Apple were not clicked. Enroll was not clicked. The signed-in classroom was not opened. `login-extracted` stays not-started. [catalog.json](../../catalog.json) and [webapps-manifest.json](../../webapps-manifest.json) were left alone. DESIGN.md was not regenerated.


The earlier references (Duolingo, Brilliant, NotebookLM) are learning apps. Coursera is the one built around courses: a catalogue of product cards, a course landing page with modules and outcomes, and a course home where a learner works through modules, lessons and items with deadlines and grades. Those last screens map onto our `/courses` and course pages most directly.

### Principles

1. Do keep the filled blue button for the step that moves the learner on.
2. Do separate learner panels by fill and catalogue cards by a hairline.
3. Do put an item's facts on one grey line joined by dots.
4. Do mark the current item with a pale tint and a heavier label.
5. Do keep green for finished work.
6. Don't copy the mixed casing of button labels.

Each rule links the screenshot or crop that shows it, under [Do and don't](#do-and-dont).

## How the values were read

Coursera styles its product with CDS, the Coursera Design System, on Emotion. CDS writes its tokens onto `:root` as 386 custom properties (`--cds-color-interactive-primary`, `--cds-spacing-200`, `--cds-border-radius-100`, `--cds-typography-title-large`), and the signed-in course pages use exactly the same 386. So the palette, semantic colours, spacing, radii, type scale and elevation in the token file all trace to a named variable. The larger type styles shrink below 1024 and 600 wide through media-query overrides; each type token records its desktop size and those smaller sizes.

Every ramp colour is a `light-dark(<light>, <dark>)` pair and 86 of the other 87 colour variables alias a ramp step; the one exception, `--cds-color-callouts-tertiary-invert`, is a literal #b0e5fb that stays the same in both schemes. The ramps flip in the dark scheme: `blue.800` paints as `blue.300` does in light. `core.palette` holds each ramp's light values, and the light and dark sets alias the step each role paints in that scheme. The first capture thought dark was unshipped, because signed-out pages ignore `prefers-color-scheme`. Signed-in learners can choose it: Account settings > Appearance offers Light mode, Dark mode and System default, and Dark mode sets `data-color-theme="dark"` on `<html>`. On 2026-10-17, with Dark mode chosen for the capture (and set back to Light after), all 221 colour variables on a learner page equalled the dark side of their `light-dark()` pairs, so the dark set is the shipped theme; the build checks that match. The public dark screenshots still come from setting that attribute by hand.

Component values are computed styles read per state with Playwright. Hover used the pointer, focus-visible used a real keyboard Tab, and pressed was either held with the mouse (signed-in) or forced through DevTools (public), so no button was ever clicked for real. Where CDS draws its focus ring from a class its own script adds on keyboard focus, the measurement adds that class and labels the state `focus-visible-cds`.

The signed-in pages were captured without handing the account to a headless browser. In the signed-in tab, [snapshot.js](tools/capture/signed-in/snapshot.js) copied each page's DOM with every stylesheet inlined from the CSSOM (Emotion inserts rules with `insertRule`, so the `<style>` tags alone are empty), stripped the scripts, kept the current video frame, cut every presigned URL back to its path (a reading's narration audio is served from S3 with a credential in the query), and replaced the learner's name, avatar initials, institution and programme with "Learner", "L", "Example University" and "Example Program". A later pass (2026-10-11) scrubbed what that missed, in the snapshots and in every file measured from them: the career goal and weekly commitment, the other enrolled and completed courses (now "Example Course 1" to "9", "Another Course", "Completed Course A" to "C", with their partners and slugs), start, submission, due and completion dates, the time zone, certificate ids, signed thumbnail URLs and ad-tracking ids. The crops and screenshots were not retaken. On 2026-10-11 the career goal, weekly commitment, enrolled course titles, dates and due times were painted out of them with solid fills (`python3 tools/redact_images.py apply systems/coursera --rules tools/redact-rules/coursera.json --patterns ~/.design-systems/cleanup-redact.json`), and the 17 crops that showed only a goal, the calendar, a completed-course card or the enrolled course list were deleted. [components.md](components.md) says no crop was saved for the four entries that lost every crop (both career goal links, the calendar and the completed course card); the program card and the weekly goal card lost their own crop and show only a part (the programme header, a day circle). Grades-table due dates and the one enrolled public course title in the `learn-*` shots stay. The values to replace come from a redaction file kept outside the repository (`~/.self-learn/coursera-redact.json` by default, shaped like [redact.example.json](tools/capture/signed-in/redact.example.json)), since the file itself names the learner. [unsnap.py](tools/capture/signed-in/unsnap.py) refuses a snapshot in which any redacted string or signing parameter survived. The snapshots were then rendered and measured headless at 2x; CSS hover and focus rules still apply to a static copy, but anything that needs JavaScript (menus, the AI chat panel, toggling an accordion) could only be measured in the state it was captured in. The discussion forums, messages and notes pages were not captured, since they hold other people's posts or the learner's own notes.

The 2026-10-17 refresh read the public additions the same way ([measure.mjs](tools/capture/measure.mjs) pages `login`, `chat`, `notfound`, `motion`, `layers`, `darkparity`, `elevation`). The log-in error was reached by pressing Enter on "not-an-email" after every network request had been set to abort, so nothing was sent; the chat field was typed into and never sent. The signed-in additions came from the same snapshot script run in the built-in browser pane the learner signed in to: each element to measure was tagged before the copy, keyboard states were reached with real keys first (so CDS's own focus classes are in the copy, recorded as `focus-visible (as captured)`), private strings were replaced from `~/.design-systems/coursera-redact.json` after the copy left the browser, and [refresh.mjs](tools/capture/signed-in/refresh.mjs) measured them headless. Those copies hold the learner's current course list, so they stay outside the repository; the dark course home was copied but is not published for that reason. Nothing was rated, submitted, toggled or deleted, and the Appearance setting was restored to Light.

## What to distrust

- Screenshots are stored as 256-colour PNGs to keep the repo small. Flat UI colours are exact; read values from the tokens, not the images.
- States labelled `focus-visible-cds` are emulated: the measurement added the class CDS's script would add on keyboard focus. Only the 2026-10-17 states labelled `focus-visible (as captured)` carry classes CDS set itself.
- The learner pages were measured from static copies with scripts stripped, so menus, the AI chat panel, accordions and other scripted parts are only in the state they were copied in. The reading's subheadings, lists, code and tables come from a probe block the script inserted, not from course content.
- The learner crops and screenshots have solid fills painted over the career goal, weekly commitment, enrolled course titles, dates and due times, and 17 crops that showed only private content were deleted. Do not read layout or type from the filled areas.
- On the public course, specialization and certificate pages, Learner reviews have the reviewers' initials painted out (2026-11-21): the letter in each avatar circle, which keeps its fill, and the initials beside it, in the screenshots and the review-card crop. The recorded text in `raw/components-computed.json` says "Learner" in their place. Testimonials and instructors are Coursera's own published content and stay.
- The public dark screenshots were made by setting `data-color-theme="dark"` by hand; signed-out pages ignore `prefers-color-scheme` and stay light. Partner logos and some art keep their light look in them, the audience strip is black in both themes and the tab bar fade stays light.
- Some tokens are not readings. The four `role.status.*-border` colours are derived, because no CDS callout draws a border. `elevation.level3` is defined but nothing measured uses it. `callouts.tertiary-invert` is the same literal cyan in light and dark. In the dark set, `component.product-card.shadow-hover`, `component.hero.art-fill` and `component.hero.art-stroke` were measured in light only; the dark set reuses the same aliases.
- Everything the capture could not reach is listed under Gaps in [components.md](components.md#gaps).

## Do and don't

1. **Do keep the filled blue button for the step that moves the learner on.** Resume, Go to next item, Try again, Enroll for free and Add to LinkedIn are `blue.800` (#0056d2) fills; the actions beside them are an outlined button, a ghost button or bold blue text (View submission, Help me practice, Save note, View certificate). Apart from the search submit, there is one such action per screen or per row, even where the page repeats it (the reading page shows Go to next item twice). See [learn-assignment-light-submitted](screenshots/learn-assignment-light-submitted.png), [learn-reading-light-default](screenshots/learn-reading-light-default.png) and [my-learning-light-completed](screenshots/my-learning-light-completed.png).
2. **Do separate learner panels by fill and catalogue cards by a hairline.** Course home, grades and the item pages set white 16-radius cards on the `grey.25` (#f2f5fa) ground with no border or shadow. Product and compact cards on search and Explore carry a 1px `grey.200` (#c1cbdb) border and gain a shadow only on hover; the stats card over the course hero is the one card that rests on a shadow (`0 8px 16px` at 20%). See [learn-home-light-module-in-progress](screenshots/learn-home-light-module-in-progress.png), [search-light-card-hover](screenshots/search-light-card-hover.png) and [course-light-default](screenshots/course-light-default.png).
3. **Do put an item's facts on one grey line joined by dots.** Item rows read "Video • 5 min" in 14/20 `grey.750` (#48546e) under the title, product cards read "4.9 (39K) · Beginner · Specialization · 1 - 3 Months" in 12/18 of the same grey, and module headers read "Week 1 • 7 hours to complete". See [learn-home-light-module-not-started](screenshots/learn-home-light-module-not-started.png), [search-light-default](screenshots/search-light-default.png) and [course-light-tab-modules](screenshots/course-light-tab-modules.png).

## Rebuild

```bash
python3 tools/build_tokens.py
```

```bash
python3 tools/build_style_guide.py
```

```bash
python3 tools/build_components_md.py
```

`build_tokens.py` reads `raw/css-vars.json` and `raw/component-tokens.json`, checks `raw/css-vars-dark-shipped.json` against the forced dark readings in `raw/css-vars.json`, and writes `tokens.json`. `build_style_guide.py` renders `style-guide.html` from `tokens.json` and `tools/style-guide.template.html`, turning every token into a CSS variable so the page cannot drift from the file. `build_components_md.py` writes `components.md` from the measurement files and [icons/INDEX.tsv](icons/INDEX.tsv). All three are deterministic: re-running them on this commit reproduces their files byte for byte. Edit the raw inputs or the builders, never the generated files.

`tools/capture/` holds the kit the captures came from, written for one session. `measure.mjs` takes page names, so `node tools/capture/measure.mjs explore` re-reads only the Explore page (it merges into `raw/components-computed.json`, then run `node tools/capture/build-measurements.mjs`), and `public.mjs light explore,mobile-explore` re-takes its three screenshots. The Playwright scripts take `PLAYWRIGHT` as the path to a Playwright install when `playwright` is not resolvable from where they run: `explore.mjs` (the discovery pass that lists the `cds-*` classes on each page), `vars.mjs` (the variable dump), `public.mjs` and `layout.mjs` (public screenshots and grid measurements), `icons.mjs`, `measure.mjs` with `lib.mjs` and `build-measurements.mjs` (public components), and `quantize.py`. `tools/capture/signed-in/` holds the snapshot helper, `unsnap.py`, `render.mjs`, the signed-in `measure.mjs` (`--md-only` rebuilds [raw/measurements-signed-in.md](raw/measurements-signed-in.md) from the JSON) and `refresh.mjs`, which measures the 2026-10-17 copies from `SNAPS` (default `~/.design-systems/snaps/coursera`). `patterns.md` is written by hand.

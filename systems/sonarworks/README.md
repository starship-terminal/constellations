No account was created. No card was entered. The only theme on the pages was light. The CSS viewport was 1169 by 731, device pixel ratio 2.

## How the values were read

The T3 preview browser opened https://www.sonarworks.com/ in its own tab. `preview_evaluate` read `getComputedStyle` on the live DOM. The same tab then opened /account/login, /account/signup, /soundid-reference/pricing (which redirected to /black-friday) and /soundid-reference. A cookie bar was dismissed with its "Got it" control before the home tiles were measured. Colour utilities that were not painted (the highlight ramps, the error border, the success alert) were read from the page's own stylesheet rules and marked declared. The viewport was `innerWidth` 1169, `innerHeight` 731, `devicePixelRatio` 2, `visualViewport.scale` 1.

`preview_snapshot` failed with "The browser is not producing screenshot frames". No PNG was invented. Headless Playwright was not started.

## What to distrust

**Every value is a hand entry.** [raw/](raw) holds no value readings: [raw/readings.json](raw/readings.json) and [raw/viewport.json](raw/viewport.json) record the pages, the viewport and why the screenshot tool failed. The tokens were typed in at capture time from readings that were never saved. On 2026-11-21 the 58 tokens labelled Measured (47), Declared (9) or Derived (2) were relabelled Reconstruction ("entered by hand at capture time; no raw/ file holds this reading"), with the original wording kept after it; the 10 component tokens already carried that label. No value changed. A recapture that writes the readings into raw/ is needed before any of them can be called measured, and `tools/test_tokens.py` fails if a token claims a reading raw/ does not hold.

Secondary text `#96999c` on the white page is 2.86:1. On the black nav it is 7.33:1. Disabled text `#636669` on `#d8d9da` is 4.08:1. Those are the colours read at capture time. The icon is a redraw of the header mark on a black square, not a file the site served. Highlight colours other than trial blue and sale yellow were declared in CSS and not seen painted, except green as a class name on the product page. The error border was not shown. "Inter var" on the account pages and "Inter" on the marketing pages are both loaded as Inter. The 1169px width is the live viewport, not a requested 1440. Phone type (`.text-mobile-lg`, 32/40) was probed, not shown, because the viewport was wide. CookieScript uses Open Sans and is not a product font. No dark theme was measured.

## Do and don't

- **Keep the page black and white.** The nav, footer and primary pills are `#000000` and `#ffffff`. Colour is reserved for a trial pill, a sale badge and status. The home hero in [patterns.md](patterns.md) is the reference, and there is no screenshot.
- **Set display type in Inter 400 at 44/52 with -1.5px tracking.** Headings are not bold. The wordmark is the exception, at weight 600.
- **Use a full pill for every action.** Learn More, Buy now, social continue and the disabled submit all use `9999px` radius. Fields on the account form stay square.
- **Leave a disabled submit grey.** `#d8d9da` with `#636669` text, until the form is valid.
- **Do not invent a dark theme, a shadow, or a focus ring.** None of those were measured. A missing screenshot is a gap, not a prompt to draw stand-in UI.

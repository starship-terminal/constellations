### Principles

1. Keep project context in the top breadcrumb.
2. Use compact bordered controls for secondary actions.
3. Place filters beside search.
4. Give command search a centered dialog.
5. Adapt navigation at mobile width.

Each rule links the screenshot or crop that shows it, under [Do and don't](#do-and-dont).

## How the values were read

Read-only live computed styles and root custom properties were saved with each state. [Capture manifest](raw/capture-manifest.json) records actual viewport and PNG dimensions. Every retained screenshot was inspected, and crops were chosen against saved native pixels. Token values cite the exact raw file and component index. OKLCH colours are Derived 8-bit sRGB conversions for catalogue compatibility, with original measuredCss retained on each token; other values are Measured. Public landing readings are separate from app tokens. The 26 Derived colour tokens are listed individually in [derived-values.json](raw/derived-values.json); each is a colour-space conversion, never an inferred role or state. No Sampled or Reconstruction tokens are included.

[Usage counts](raw/usage-counts.json) records colour, size and radius occurrences in the dark organization DOM. Empty brand metadata is a missing measurement, not an inferred brand colour. Root variable exports are partial, not a complete token inventory. Re-capture uses the live procedure in [capture notes](tools/CAPTURE.md).

## What to distrust

This is limited coverage of the accessible shell. Database tables, schema navigation, row details and table filters were unavailable because both projects were paused. The empty SQL side panel and snippet picker are real app evidence, but do not prove a functioning SQL connection or results UI. Public dashboard illustrations are not interactive app evidence; none of the rejected demo screenshots enters this package.

The initial full-page attempts missed lazy-loaded content or misplaced the sticky header and were rejected. Viewport screenshots are retained instead. Browser screenshots arrived as JPEG bytes and were decoded, converted to PNG, then quantized; token colours come from CSS, never pixels. Screenshots are at native browser-output scale, not inferred from DPR. Mobile screenshots show a notice overlay as the product presented it. Captured means at least one documented example, not complete state parity.

## Fonts

The app reports Inter for body/control text and Manrope for headings, with system fallbacks retained verbatim. SQL raw variables include Source Code Pro, Office Code Pro and Menlo fallbacks; no code typography token is asserted from that declaration alone. No fonts are distributed; their licences were not reviewed.

## Do and don't

- **Keep project context in the top breadcrumb.** Organization, project and branch stay visible above the narrow icon rail ([paused project](screenshots/app-paused-project.png)); do not replace that hierarchy with an undifferentiated menu.
- **Use compact bordered controls for secondary actions.** Reserve the filled accent for primary actions ([projects](screenshots/app-projects-grid.png)); do not fill every toolbar action with accent.
- **Place filters beside search.** Show the checkbox popup anchored below Status ([filter](screenshots/app-status-filter.png)); do not detach it from the list toolbar.
- **Give command search a centered dialog.** Dim the app behind the dialog and keep query input above results ([command menu](screenshots/app-command-menu.png)); do not mix global commands into individual project cards.
- **Adapt navigation at mobile width.** Use the floating toolbar and organization menu ([mobile navigation](screenshots/app-mobile-navigation.png)); do not compress the desktop icon rail into the content column.

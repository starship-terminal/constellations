# Boords design reference

A token set and component reference for Boords' public surface — for building marketing, pricing and product pages in the style of the real thing. It was read from **boords.com** on **2026-11-11**, signed out, in headless Chromium at 1440 x 900 and 390 x 844: the home page, pricing (monthly + yearly), the AI storyboard generator, storyboard software, collaborate, customers, a customer story, docs, the free script timer, login, signup and the demo page.

Boords is worth a capture because its pre-production tooling marketing is a tight study in restraint: ink `#121212` on white, one cream `#f3f3e9` card field, an amber `#e8aa42` border on the hero CTA, everything pill-shaped (9999px) with a few 24px cards, and one typeface — matter — running from a 64px display headline down to 10.4px legal. **Boundary:** the product itself lives on app.boords.com behind login; /signup 404s on www and now points visitors at the app host. Everything behind the login is a recorded gap, never inferred.

## Brief

Read this before designing in this style. Take every value from [tokens.json](tokens.json), never from the screenshots; `python3 tools/catalog.py export boords` prints them all with aliases resolved.

### Principles

1. Do put ink on white.
2. Do pill every button.
3. Do round the cards at 24px.
4. Do reach for the cream sparingly.
5. Don't invent a second accent.
6. Don't add card chrome.
7. Don't style the app from this package.
8. Don't ship a dark theme.

Each rule links the screenshot or crop that shows it, under [Do and don't](#do-and-dont).

## How the values were read

Every value came off the running signed-out site in headless Chromium:

- **Tokens.** [tools/capture/vars.mjs](tools/capture/vars.mjs) captures every stylesheet body (Next.js chunks from network responses plus inline `<style>` blocks re-parsed with `CSSStyleSheet`) and writes every custom property to [raw/css-vars.json](raw/css-vars.json). boords.com declares almost no `:root` design vars — the names that exist are Tailwind internals — so **every design token is a measured computed value**. [tools/build_component_tokens.py](tools/build_component_tokens.py) writes the spec, [tools/build_tokens.py](tools/build_tokens.py) the sets.
- **Components.** [tools/capture/public/measure.mjs](tools/capture/public/measure.mjs) opens each route in a fresh context and reads `getComputedStyle`, painted layers and boxes per element in default, hover, focus-visible and a CDP-forced pressed state, plus `focused`/`filled` on the script textarea and `opened` on the nav flyout, pricing accordion and mobile menu. Results in [raw/components-computed.json](raw/components-computed.json) and [raw/measurements.md](raw/measurements.md).
- **Screenshots.** [tools/capture/public/public.mjs](tools/capture/public/public.mjs) takes viewport and full-page shots per route with `.capture.json` sidecars; [tools/capture/quantize.py](tools/capture/quantize.py) posterises them to 256 colours.

Nothing was signed into, bought or submitted: the timer textarea was filled with sample text and cleared; the signup/login forms were never used (signup 404s on www; no login fields mount); the billing tabs and accordions were toggled as local UI state; every CTA was measured, never followed. The cookie banner was hidden, never answered — its Accept & Close button was never clicked.

## What to distrust

- **Readings past a masked bot signal.** The committed screenshots and readings were taken with `navigator.webdriver` masked, the flag bot checks read to spot automation. The capture scripts no longer mask it (not run since), so a recapture may record a walled route as a boundary instead of a reading.
- **This is the marketing shell, not the app.** Storyboards, animatics, shot lists, the script editor and all project surfaces live on app.boords.com behind login and are uncaptured. Treat the app's own design system as unknown.
- **One theme only.** The site paints light everywhere; the dark footer is a section style. `tokens.json` ships no dark set.
- **The tokens are measured, not declared.** boords.com compiles Tailwind to classes; only a few component-scoped vars exist. Every token cites the measurement it came from — that is the honest provenance.
- **Quantised screenshots.** `screenshots/` are 256-colour PNGs; read exact colours from tokens or the raw files.
- **Some states were taken without their options.** The capture put `fillText` and `cropLoc` where they were ignored, so `timer-field` filled was typed with the default `name@example.com` rather than a script line, and the `nav-trigger-open` crop shows only the trigger, not the opened flyout. The script now passes them as options (not run since); the readings stand as labelled by their `via`.
- **`m-nav-item` was read from the wrong element.** The first link in any menu, nav or header caught "Try Boords Free" (y=88 at 390 wide), not a row inside the opened menu overlay. Needs a recapture.

## Do and don't

1. **Do put ink on white.** `#121212` on a white field is the whole base; nav and body text run at 60% ink, meta at #7b7b7b. See [home-light-default](screenshots/home-light-default.png).
2. **Do pill every button.** Actions are 9999px-radius pills — the ink-filled demo CTA, the amber-bordered hero action, the 3px-ink-outlined plan CTAs. See [plan-cta](components/crops/plan-cta-default.png).
3. **Do round the cards at 24px.** Feature and plan cards sit on a 24px radius (inner media at 16px), mostly borderless with a whisper of shadow. See [plan-card](components/crops/plan-card-default.png).
4. **Do reach for the cream sparingly.** `#f3f3e9` is the one soft fill for feature cards/sections; the page stays white. See [feature-card](components/crops/feature-card-default.png).
5. **Don't invent a second accent.** The only chromatic chrome is the amber `#e8aa42` CTA border; everything else is ink, white or cream.
6. **Don't add card chrome.** Cards have no visible border; a hairline `rgba(18,18,18,.15)` marks toggles and fields, not containers.
7. **Don't style the app from this package.** Every value is the marketing surface's; app.boords.com is uncaptured.
8. **Don't ship a dark theme.** None is offered; the footer is a section style, not a theme.

## Rebuild

Everything derived regenerates offline from the raw readings (run from `systems/boords/`):

```sh
python3 tools/build_component_tokens.py        # raw/components-computed.json -> raw/component-tokens.json
python3 tools/build_tokens.py                  # -> tokens.json
python3 tools/build_style_guide.py             # -> style-guide.html
python3 tools/build_components_md.py           # -> components.md
node tools/capture/public/build-measurements.mjs  # -> raw/measurements.md
python3 tools/capture/quantize.py <raw-dir>    # full-colour PNGs -> screenshots/
```

Then `make brief && make design-md && make grade && make check` from the repo root refreshes the generated sections and validates the catalog.

Live recapture (needs the site; Playwright at `PLAYWRIGHT=~/.design-systems/pw/node_modules/playwright/index.mjs`):

```sh
node tools/capture/vars.mjs                    # stylesheet harvest -> raw/css-vars.json
node tools/capture/public/measure.mjs          # computed styles + crops -> raw/components-computed.json
RAW=<scratch> node tools/capture/public/public.mjs   # screenshots -> <scratch>
```

boords.com loads fine headless from this client; the product host app.boords.com stays behind login.

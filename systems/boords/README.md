# Boords design reference

A token set and component reference for Boords' public surface, for building marketing, pricing and product pages in the style of the real thing. It was read from **boords.com** on **2026-11-21**, signed out, in headless Chromium at 1440 x 900 and 390 x 844. The site tree, including which control opens which page, menu or overlay, is [site-tree.md](site-tree.md).

Boords is worth a capture because its pre-production tooling marketing is a tight study in restraint: ink `#121212` on white, one cream `#f3f3e9` card field, an amber `#e8aa42` border on the hero CTA, everything pill-shaped (9999px) with a few 24px cards, and one typeface, matter, running from a 64px display headline down to 10.4px legal. The product itself lives on app.boords.com behind login. www `/login` and `/signup` are the public 404. The app login page asks for email and password, or Google. No email was typed. No password was typed. No form was submitted. Everything behind that wall is a recorded gap.

## Brief

<!-- brief:start. Generated by tools/brief.py from catalog.json, the tokens file and this README; `make brief` rewrites it. Do not edit. -->

Read this before designing in this style. Take every value from [tokens.json](tokens.json), never from the screenshots; `python3 tools/catalog.py export boords` prints them all with aliases resolved.

### Principles

1. Do put ink on white.
2. Do pill every button.
3. Do round the cards at 24px.
4. Do reach for the cream sparingly.
5. Don't invent a second accent.
6. Don't add card chrome.
7. Don't style the app from this package.
8. Don't ship a marketing dark theme.

Each rule links the screenshot or crop that shows it, under [Do and don't](#do-and-dont).

## How the values were read

Every value came off the running signed-out site in headless Chromium:

- **Tokens.** [tools/capture/vars.mjs](tools/capture/vars.mjs) captures every stylesheet body and writes every custom property to [raw/css-vars.json](raw/css-vars.json), re-read on 2026-11-21. Marketing colours are measured computed styles. Docs colours are declared as channel triples (`18 18 18`) on `:root` and `html.dark`. Those triples are recorded as raw and converted to `#rrggbb` in `docs-light` and `docs-dark`. The conversion is Derived from the declared channels. [tools/build_tokens.py](tools/build_tokens.py) writes the sets.
- **Components.** [tools/capture/public/measure.mjs](tools/capture/public/measure.mjs) reads `getComputedStyle` per element in default, hover, focus-visible and a CDP-forced pressed state. Results in [raw/components-computed.json](raw/components-computed.json).
- **Screenshots.** [tools/capture/public/tree.mjs](tools/capture/public/tree.mjs) photographs the public tree at 1440 x 900 and 390 x 844, including opened menus, the phone drawer, the docs search dialog and the home video overlay. [tools/capture/quantize.py](tools/capture/quantize.py) posterises them to 256 colours.

Nothing was signed into, bought or submitted. The timer textarea and the docs search field were filled with sample text and not submitted. Newsletter, enterprise and login fields were not typed into. Google was not clicked. The cookie card was hidden, never answered.

## What to distrust

- **This is the public site, not the app.** Storyboards, scripts and project surfaces on app.boords.com sit behind the login wall. The login page was photographed and not used. Treat the app's own design system as unknown.
- **Two themes, one of them docs-only.** Marketing paints light. The footer is a dark section, not a theme. Docs has a Light/Dark radio that sets `html.dark`. `docs-dark` is that theme, not a marketing dark theme.
- **Docs channel triples are Derived.** `--color-type-primary: 18 18 18` is a declared channel list. The `#121212` in `docs-light` is that list written as hex. It was not a `getComputedStyle` colour read.
- **Quantised screenshots.** `screenshots/` are 256-colour PNGs. Read exact colours from tokens or the raw files.
- **Sitemap children of the same template** (most `/blog/*`, `/how-to-storyboard/*`, `/docs/*`, printable PDF links) are mapped in [site-tree.md](site-tree.md) and not each photographed. One sample of each template is in `screenshots/`.

## Do and don't

1. **Do put ink on white.** `#121212` on a white field is the whole base; nav and body text run at 60% ink, meta at #7b7b7b. See [home-light-default](screenshots/home-light-default.png).
2. **Do pill every button.** Actions are 9999px-radius pills — the ink-filled demo CTA, the amber-bordered hero action, the 3px-ink-outlined plan CTAs. See [plan-cta](components/crops/plan-cta-default.png).
3. **Do round the cards at 24px.** Feature and plan cards sit on a 24px radius (inner media at 16px), mostly borderless with a whisper of shadow. See [plan-card](components/crops/plan-card-default.png).
4. **Do reach for the cream sparingly.** `#f3f3e9` is the one soft fill for feature cards/sections; the page stays white. See [feature-card](components/crops/feature-card-default.png).
5. **Don't invent a second accent.** The only chromatic chrome is the amber `#e8aa42` CTA border; everything else is ink, white or cream.
6. **Don't add card chrome.** Cards have no visible border; a hairline `rgba(18,18,18,.15)` marks toggles and fields, not containers.
7. **Don't style the app from this package.** Every value is the marketing surface's; app.boords.com is uncaptured.
8. **Don't ship a marketing dark theme.** Marketing offers none. The footer is a section. Docs dark is a docs-only theme, photographed at [docs-dark-default](screenshots/docs-dark-default.png).

## Rebuild

Everything derived regenerates offline from the raw readings (run from `systems/boords/`):

```sh
python3 tools/build_component_tokens.py        # raw/components-computed.json -> raw/component-tokens.json
python3 tools/build_tokens.py                  # -> tokens.json
python3 tools/build_style_guide.py             # -> style-guide.html
python3 tools/build_components_md.py           # -> components.md
node tools/capture/public/build-measurements.mjs  # -> raw/measurements.md
python3 tools/capture/quantize.py <raw-dir>    # full-colour PNGs -> screenshots/
```

Then `make brief && make design-md && make grade && make check` from the repo root refreshes the generated sections and validates the catalog.

Live recapture (needs the site; Playwright at `PLAYWRIGHT=~/.design-systems/pw/node_modules/playwright/index.mjs`):

```sh
node tools/capture/vars.mjs                    # stylesheet harvest -> raw/css-vars.json
node tools/capture/public/measure.mjs          # computed styles + crops -> raw/components-computed.json
RAW=<scratch> node tools/capture/public/tree.mjs      # public tree -> <scratch>
```

boords.com loads fine headless from this client; the product host app.boords.com stays behind login.

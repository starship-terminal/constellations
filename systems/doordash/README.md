# DoorDash design reference

A token set and component reference for DoorDash's public signed-out web surface — for building marketing pages, directory listings and storefronts in the style of the real thing. It was read on **2026-11-13** from **the product's own SSR pages rendered by the Internet Archive's Wayback Machine**, signed out, in headless Chromium at 1440 x 900 and 390 x 844: the home landing page, /food-delivery/ and /en-US/business/ directories, the DashPass student page, the restaurants-near-me listing, a real storefront (/en-US/store/the-sweet-tooth-north-miami-beach-33434247/), the HSA/FSA and seasonal catalog pages, /promos/, and careersatdoordash.com (a separate WordPress stack) — plus a mobile pass on the home, storefront and food-delivery pages.

**How this capture works:** every live *.doordash.com route this client tried (curl, headless Chromium, headed Chrome; home, /about/, /careers/, /merchant/, /dasher/, merchants/dasher/help subdomains, robots.txt, the favicon) answered a Cloudflare 403 "Performing security verification" challenge that never resolved. The package therefore captures the product's own output from Wayback snapshots — the real SSR HTML, the real prism stylesheet bundles proxied through web.archive.org, the real CDN imagery — labelled per route with its snapshot id in [raw/archive-urls.json](raw/archive-urls.json). Nothing here claims to be a current live capture; it is archival evidence of the product's own pages.

DoorDash is worth a capture because its consumer web declares a complete, legible token system. The consumer-web-next stack (Next.js SSR + styled-components) loads the **prism** design tokens on `:where(.prism-theme)`: `--base-*` primitives (the DoorDash red ramp `#eb1700` at doordash-60 feeding `action.primary`, the caviar and dashpass brand palettes, neutral and warm/cool greys, twelve hue ramps, a 32-step size scale, a 28-step DD Norms type scale), `--usage-*` semantic roles over them (stateful colour/type/space/size/radius/elevation/motion, default→hovered→pressed→disabled), and a `--comp-*` component layer over the roles — every name a `var()` alias down the chain, which this package preserves as DTCG aliases. The same sheet ships sibling brand themes (deliveroo, plus — light and dark) a doordash.com visitor never sees. **Boundary:** the signed-in product — the address gate, ordering, cart, checkout, DashPass, merchant and Dasher onboarding — was never crossed; on catalog pages whose bodies hydrate from live APIs, the shell renders and the body stays on the product's loading spinner (recorded as a gap, not hidden).

## Brief

### Principles

1. Do make the primary action DoorDash red.
2. Do pair the red field with white pills.
3. Do give controls full radii.
4. Do write display copy condensed and loud.
5. Do keep surfaces white and quiet.
6. Do mark the selected state in ink.
7. Do show ratings as compact inline text.
8. Don't put DoorDash red on large fills except the hero.
9. Don't style checkout or DashPass from this package.
10. Don't call the deliveroo/plus scopes "DoorDash dark mode".

Each rule links the screenshot or crop that shows it, under [Do and don't](#do-and-dont).

## How the values were read

Every value came off the running archived pages in headless Chromium — the product's own SSR HTML and stylesheets served through web.archive.org, Wayback's injected replay chrome hidden before any reading:

- **Tokens.** [tools/capture/vars.mjs](tools/capture/vars.mjs) captures every stylesheet body during archived renders of the marketing home, a storefront and the careers site (the web-assets.cdn4dd.com Next.js bundles plus inline `<style>` blocks, archive prefixes stripped), re-parses them with `CSSStyleSheet` and resolves every custom property in a probe document carrying the real sheets on a `body.prism-theme` scope at 1440 x 900 — colours come back sRGB hex, lengths px — into [raw/css-vars.json](raw/css-vars.json). The deliveroo/plus `[data-dt-theme][data-dt-mode]` sibling themes and the careers Tailwind layer are harvested but binned apart, not tokenised. [tools/build_component_tokens.py](tools/build_component_tokens.py) maps every resolved prism name to a set and path, preserves a plain `var()` declaration as a `{path}` alias (the comp → usage → base chain survives), folds the `--usage-type-*` slots into `core.typography` composites, and adds the measured component leaves; [tools/build_tokens.py](tools/build_tokens.py) emits the two sets and checks every alias resolves and every value is its declared DTCG type.
- **Components.** [tools/capture/public/measure.mjs](tools/capture/public/measure.mjs) opens each archived route in a fresh context, hides the Wayback chrome and DoorDash overlays, and reads `getComputedStyle`, painted layers and boxes per element in default, hover, focus-visible (a real keyboard focus), a CDP-forced pressed state and focused (fields) — no press that would submit anything was ever performed. Results in [raw/components-computed.json](raw/components-computed.json) and [raw/measurements.md](raw/measurements.md); crops in [components/crops/](components/crops).
- **Screenshots.** [tools/capture/public/public.mjs](tools/capture/public/public.mjs) takes viewport and bounded full-page shots per route at 1440 x 900 1x and 390 x 844 2x with `.capture.json` sidecars, plus the local UI toggles: the Top Cuisines directory tab, the storefront Pickup option and the (absent) mobile hamburger. A page taller than one GPU texture tiles into `*.partN.png` parts capped at 8 chunks — the 91,084px mobile food-delivery page hit the cap and the boundary is in the log. [tools/capture/quantize.py](tools/capture/quantize.py) stitches parts and posterises to 256 colours.

Nothing was signed into, ordered, address-entered or submitted: the Sign-in/Sign-up anchors to identity.doordash.com OAuth were measured, never followed; the address-search field was focused once for measurement and never filled or submitted; the quick-add, cart, group-order and every CTA was measured, never pressed; the cookie banner and dormant Turnstile nodes were hidden (the banner un-hidden once for a computed-style reading, then re-hidden) and never answered; the only toggles were local UI state (directory tab, fulfilment pill).

## What to distrust

- **This is archival evidence, not a live read.** Live *.doordash.com Cloudflare-blocks this client on every surface tried; the DOM, sheets and imagery are the product's own via Wayback snapshots dated 2026-09-30 → 2026-11-12. Colours, tokens and components are real; a value could have changed since the snapshot — trust it as "the product at that snapshot", not "the product today".
- **Hydration-dependent content is absent.** The archived pages serve SSR HTML; React hydration under Wayback does not complete, so anything mounted after hydration — lazy directory rows, the HSA/seasonal catalog bodies (a spinner, never loaded), some imagery — is missing from shots and measurements. What rendered is real; what did not is a recorded gap, never faked.
- **Ghost duplicate nodes.** The restaurants page carries `CompactCard*` testid nodes that paint 0x0 (SSR duplicates); the visible cards are `/store/` anchors and were measured as such. Selector names in components-computed.json say which shape was read.
- **The public shots are still archival.** Live *.doordash.com Cloudflare-blocked the 2026-11-13 capture client. Those screenshots, tokens, and crops stay Wayback evidence.
- **A signed-in walk was added on 2026-11-20.** The default preview profile was already signed in. Opened screens are named in [login-review.json](login-review.json): account menu, profile, change password (empty, not submitted), manage account (archive and delete not clicked), orders empty state (desktop and 390 x 844), rewards empty state, gift card buy/redeem (not submitted), and help. Cart stayed at 0. Credential fields on the profile shot are blurred. Home feed frames from this pass were compositor-blurred and were not committed. Checkout, DashPass purchase, address entry, group order, and business-profile create were not started.
- **Quantised screenshots.** `screenshots/` and `components/crops/` are 256-colour PNGs; photographs band. Read exact colours from tokens or the raw files.
- **Sibling brand themes in the sheet.** The prism bundle ships deliveroo/plus `[data-dt-theme]` scopes (light and dark). They are real declarations but not what doordash.com paints; only the unscoped doordash light set is tokenised — do not read them as "DoorDash dark mode".
- **Browser defaults under the replay.** Elements the site styles only through their text children kept the browser's inherited defaults in the replay (Times 16px, #000000, the #0000ee link blue on anchors and the icons inside them); 92 states carry them. The `light.component.*.text` tokens now read the first text node instead of the wrapper (12 of them changed, for example `offerBadge.text` #0000ee to #d91400 and `heroBand.text`/`footer.text` #000000 to #ffffff); `menuItem.text` and `hsaSearch.text`, which have no text node, say they are unconfirmed. components.md marks those values as browser defaults. The capture script now refuses a page on which the prism face did not apply (not re-run).
- **Fonts are proprietary.** DD Norms and TTNormsProCond are not distributed; the style guide falls back to the system sans, so its type samples approximate.
- **Automation was masked during capture.** Until 2026-11-20, `tools/capture/public/lib.mjs` hid `navigator.webdriver` in every page it opened, so every committed reading was taken with that mask. The mask is removed (a bot check is now recorded as a boundary, not bypassed); whether any page needed it to load is not known, and a recapture without it is the check.

## Fonts

Two served faces do the work. **DD Norms** (the prism `--base-font-family-default/brand`, plus a condensed variant) runs everything on the consumer surface at weights 300–800 over a 28-step px scale. **TTNormsProCond-Blk** at 900 is the campaign display face set inline on hero headlines ("$0 DELIVERY FEE ON FIRST ORDER"). Both are proprietary, served from web-assets.cdn4dd.com (100 `@font-face` rules harvested in css-vars.json), and not distributed with the package — the style guide and any consumer of `font.family.*` should expect the declared fallback stack (ui-sans-serif system faces). The careers site's WordPress theme loads its own faces.

## Do and don't

1. **Do make the primary action DoorDash red.** Buttons and links that commit are `#eb1700` (`color.action.primary.default`, hover `#d91400` `…-hovered`, pressed `#b71000` `…-pressed`) — solid pills at radius-full. See [cta-btn](components/crops/cta-btn-default.png).
2. **Do pair the red field with white pills.** On the campaign band the address gates invert to white-fill pills with ink text and the Sign In button stays the solid red pill — never a second hue. See [signin-btn](components/crops/signin-btn-default.png), [address-pill](components/crops/address-pill-default.png) and [hero-band](components/crops/hero-band-default.png).
3. **Do give controls full radii.** Pills and toggles paint `radius.full` (9999px measured on addressPill, fulfilToggle, offerBadge, popularButton); cards and menu tiles sit at 16px. See [fulfil-toggle](components/crops/fulfil-toggle-default.png) and [menu-item](components/crops/menu-item-default.png).
4. **Do write display copy condensed and loud.** Campaign headlines are TTNormsProCond-Blk 900 uppercase on tight leading; body is DD Norms 400–700 on the 28-step scale. See [hero-title](components/crops/hero-title-default.png).
5. **Do keep surfaces white and quiet.** The field is `color.background.default` white with `#fdf0ed`-family subdued tints for CTA bands; borders are `color.border.default` hairlines; depth is the `elevation-1–6` ladder, not heavy strokes. See [cta-band](components/crops/cta-band-default.png).
6. **Do mark the selected state in ink.** Selected tabs, chips and the toggle's on-pill take the near-black `border.selected`/`background.selected` (#191919 neutral-100 family), not the action red — red is reserved for actions and promos. See [tab-selected](components/crops/tab-selected-default.png).
7. **Do show ratings as compact inline text.** The `4.8 (6k+) • 0.7 mi • 21 min` row is one muted line with `•` separators under the name — badges (offer, leaderboard) chip beside it. See [rest-card](components/crops/rest-card-default.png).
8. **Don't put DoorDash red on large fills except the hero.** The full-bleed `#eb1700` band is the campaign hero signature; ordinary sections stay white/tint — a page of red reads wrong. See [home-light-full](screenshots/home-light-full.png).
9. **Don't style checkout or DashPass from this package.** The 2026-11-20 walk opened the signed-in shell, empty orders, rewards, profile, password, manage account, gift cards, and help ([login-review.json](login-review.json)). Checkout, cart add, DashPass purchase, and address entry were not started. The public DashPass shot is still the signed-out marketing page. See [signed-in-orders-desktop](screenshots/signed-in-orders-desktop.png).
10. **Don't call the deliveroo/plus scopes "DoorDash dark mode".** They are sibling brands in the same prism sheet; the doordash surface publishes light only. See [store-light-default](screenshots/store-light-default.png).

## Rebuild

Everything derived regenerates offline from the raw readings (run from `systems/doordash/`):

```sh
python3 tools/build_component_tokens.py        # raw/css-vars.json + components-computed.json -> raw/component-tokens.json
python3 tools/build_tokens.py                  # -> tokens.json
python3 tools/build_style_guide.py             # -> style-guide.html
python3 tools/build_components_md.py           # -> components.md
node tools/capture/public/build-measurements.mjs  # -> raw/measurements.md
python3 tools/capture/quantize.py <raw-dir>    # full-colour PNGs -> screenshots/
python3 ../../tools/redact_images.py apply ../doordash --rules ../../tools/redact-rules/doordash.json   # repaint the masks over the new screenshots
# The rules' boxes are pixel positions on the committed screenshots, size-gated, so a fresh capture of another
# size or layout is silently skipped: re-place the boxes for every new shot and open each image before committing.
```

The capture side needs Playwright (`PLAYWRIGHT=<playwright index.mjs>`) and Pillow for crop quantization (`PYTHON=<python with Pillow>`):

```sh
RAW=/path/to/scratch node tools/capture/public/public.mjs     # screenshots
node tools/capture/public/measure.mjs                         # computed styles + crops
node tools/capture/vars.mjs                                   # css-vars.json + archive-urls.json
```

# ElevenReader design reference

A token set and component reference for ElevenReader's public surface — for building marketing pages and auth-boundary cards in the style of the real thing. It was read from **elevenreader.io** on **2026-11-13**, signed out, in headless Chromium at 1440 x 900 and 390 x 844. Captured: the home, pricing, explore, collections, genres, free-audiobooks, iconic-voices, compare and blog marketing pages, one public audiobook detail page, the `/reader/sign-in` and `/reader/sign-up` cards (measured, never submitted — the email credential forms were revealed by their own '…with email' toggles and the fields were focused, never filled past deleted sample text), and a 390px mobile pass on home and explore.

ElevenReader is worth a capture because its public site is a disciplined near-monochrome Tailwind v4 system. The stylesheet declares a complete token layer — the `--themed-*` RGB triplets bound into `--color-*` roles (a neutral ramp that flips on `.dark`, named brand hues like forest-green and magenta-light, a blue accent `#4680fd` the marketing surface barely uses, the reader app's own `--reader-*` palette), the `--f-*` type scale (display/heading in **Waldenburg**, subhead/description/body/ui in **Inter**), the `--spacing`/`--container`/`--ease` scales and a themed `--focus-ring` — and paints one light theme over it: black ink on white with a `#F5F3F1` promo band, `#F2F2F2` sunken fills, and pill geometry everywhere (9999px on every button, chip, input and badge; 20px FAQ cards; 40px plan cards). Keyboard focus draws the same 2px solid black outline everywhere, at 2px offset on most controls and 0px on the header CTA, the SSO buttons and the sign-in submit. **Boundary:** the reader app — library, upload, the player, settings, billing — lives behind `/reader/sign-in` and was never reached; nothing was bought, subscribed to, signed into or submitted; the declared `.dark` scope inverts the palette but no public page paints it.

## Brief

<!-- brief:start. Generated by tools/brief.py from catalog.json, the tokens file and this README; `make brief` rewrites it. Do not edit. -->

Read this before designing in this style. Take every value from [tokens.json](tokens.json), never from the screenshots; `python3 tools/catalog.py export elevenreader` prints them all with aliases resolved.

### Principles

1. Do paint the page white with black ink.
2. Do make the primary action a black pill.
3. Do use the 9999px pill for every control.
4. Do ring focus in solid black.
5. Do set display type in Waldenburg, everything else in Inter.
6. Do keep the layered ring shadow on white pills.
7. Do run the section rhythm on gutters.
8. Don't paint the declared .dark scope as if captured.
9. Don't style the reader app from this package.
10. Don't submit from this package.

Each rule links the screenshot or crop that shows it, under [Do and don't](#do-and-dont).

## How the values were read

Every value came off the running signed-out site in headless Chromium:

- **Tokens.** [tools/capture/vars.mjs](tools/capture/vars.mjs) captures every stylesheet body (the Next.js `/_next/static/css/*.css` bundles fetched as network responses so cross-origin sheets can be re-parsed, plus inline `<style>` blocks) and writes every custom property to [raw/css-vars.json](raw/css-vars.json), resolved on a probe page once plain and once under `.dark`. The `--f-*` type scale resolves at 1440px; the media-query base steps are recorded on the leaves. [tools/build_component_tokens.py](tools/build_component_tokens.py) writes the spec, [tools/build_tokens.py](tools/build_tokens.py) the sets — one `{"var": ...}` leaf serves both themes because `.dark` re-binds the same names.
- **Components.** [tools/capture/public/measure.mjs](tools/capture/public/measure.mjs) opens each route in a fresh context and reads `getComputedStyle`, painted layers and boxes per element in default, hover, focus-visible, CDP-forced pressed, focused, open and filled states, across the marketing pages, the audiobook page, the auth cards and mobile. Results in [raw/components-computed.json](raw/components-computed.json) and [raw/measurements.md](raw/measurements.md). The sign-in/sign-up credential forms are `sr-only` until their '…with email' toggles are pressed — a local UI toggle that sends nothing — so the fields were measured revealed.
- **Screenshots.** [tools/capture/public/public.mjs](tools/capture/public/public.mjs) takes viewport and full-page shots per route with `.capture.json` sidecars, including the local UI toggles: the Discover mega-menu, the mobile menu and the Monthly/Annual billing segment. Full pages are bounded to 8 chunks (every captured page fits). [tools/capture/quantize.py](tools/capture/quantize.py) posterises them to 256 colours.

Nothing was signed into, bought or submitted: the sign-in and sign-up cards were captured as surfaces — the OAuth buttons were never pressed, the credential forms were revealed by their own toggles, fields were focused and sample text was typed and deleted; every Start-listening, Try-it-free, plan CTA and 'Get this offer' link was measured, never followed; the Discover menu, mobile menu, billing segment, FAQ items and footer accordions were toggled as local UI state. The Cookiebot consent banner was hidden, never answered — no consent button was ever clicked.

## What to distrust

- **This is the public shell, not the product.** The ElevenReader app — library, upload, the reader/player, settings, billing — sits behind /reader/sign-in and is uncaptured. Treat the product's own design system as unknown beyond its declared `--reader-*` palette.
- **Dark is declared, not painted.** The `.dark` scope inverts the `--themed-*` triplets (white→black, neutral ramp flipped, focus-ring to white), but no public page applies it. `dark.*` in tokens.json is a real token scope with real values; it is not a captured surface.
- **The f-* scale declares 700 where the paint reads 375-400.** The Waldenburg headings' computed weight is the book face (400, sometimes reported 375); the declared `--f-heading-*-font-weight` says 700. Copy the painted weight for a faithful look.
- **The accent blue is declared but barely painted.** `--color-accent` `#4680fd` exists in the token layer; the marketing surface is black/white/neutral — don't flood a mock with blue.
- **Two summaries were read with their `<details>` open.** `faq-summary` and `m-footer-summary` were measured right after `faq-item` and `m-footer-col` opened the same `<details>` for their `open` state and left it open, so their states are of an open item labelled default (and `m-footer-summary`'s keyboard focus failed). `measure.mjs` now closes the item after the `open` reading (edited, not run); both entries need a recapture.
- **Quantised screenshots.** `screenshots/` and `components/crops/` are 256-colour PNGs; read exact colours from tokens or the raw files.
- **No standalone icon set.** The wordmark, SSO glyphs, chevrons and footer arrows appear in crops and screenshots but were not lifted as an icon library; icon.png is the site favicon-derived mark.
- **Automation was masked during capture.** Until 2026-11-20, `tools/capture/public/lib.mjs` hid `navigator.webdriver` in every page it opened, so every committed reading was taken with that mask. The mask is removed (a bot check is now recorded as a boundary, not bypassed); whether any page needed it to load is not known, and a recapture without it is the check.

## Fonts

Two families do everything. **Inter** runs all UI, body and form text (served with an 'Inter Fallback' metrics clone; `--font-sans` is the system-ui fallback stack). **Waldenburg** runs the display face — h1s at 60px/40px (desktop/mobile) with -1.8px tracking, pricing and audiobook titles, section headings, plan names and FAQ questions; `WaldenburgHF` bold-semi-condensed is declared for hero use. All served from the product's own CDN; none is distributed with the package — the style guide falls back to system fonts.

## Do and don't

1. **Do paint the page white with black ink.** The field is `#FFFFFF`, text is `#000000`; the only tints are `#F5F3F1` (promo band), `#F6F6F6`/`#F2F2F2` (surface/sunken) and `#FAF8F8` (FAQ). See [home-light-default](screenshots/home-light-default.png).
2. **Do make the primary action a black pill.** Buttons are `bg-inverse` black pills with white text that lift to `#6E6E6E` on hover — never the declared accent blue on marketing chrome. See [hero-cta](components/crops/hero-cta-default.png) and [nav-cta](components/crops/nav-cta-default.png).
3. **Do use the 9999px pill for every control.** Buttons, chips, inputs, badges and the billing segment all paint `rounded-full`; square corners on a control are wrong. Cards step up — 20px FAQ, 40px plan cards, 16px covers. See [genre-chip](components/crops/genre-chip-default.png) and [plan-card](components/crops/plan-card-default.png).
4. **Do ring focus in solid black.** The keyboard focus indicator is a 2px solid `#000` outline on every interactive element that rings, at 2px offset on 19 of the 24 and 0px on `nav-cta`, `sso-google`, `sso-apple`, `signin-submit` and `signup-google`. See [nav-link](components/crops/nav-link-focus-visible.png).
5. **Do set display type in Waldenburg, everything else in Inter.** Headings run 36-60px with negative tracking at the book weight; UI/body run Inter 12-18px. See [hero-h1](components/crops/hero-h1-default.png) and [book-meta](components/crops/book-meta-default.png).
6. **Do keep the layered ring shadow on white pills.** Secondary buttons, chips and the selected billing segment carry `0 0 0 1px 6% + 0 1px 2px + 0 2px 4px` at 4% black — a ring, not a border. See [hero-cta-2](components/crops/hero-cta-2-default.png).
7. **Do run the section rhythm on gutters.** Content sits in a ~1304px column inside 1440px (64px outer gutters); sections separate with 100-200px spacing and 120px footer padding. See [home-light-full](screenshots/home-light-full.png).
8. **Don't paint the declared .dark scope as if captured.** It is a token inversion, not a painted surface — don't present a dark ElevenReader page as evidence. See [DESIGN.md](DESIGN.md).
9. **Don't style the reader app from this package.** Library, player and upload are behind sign-in and uncaptured; the `--reader-*` palette is declared evidence, not a measured UI. See [sign-in-light-default](screenshots/sign-in-light-default.png).
10. **Don't submit from this package.** The auth forms were revealed and focused only; error and success states are uncaptured by design. See [email-field](components/crops/email-field-default.png).

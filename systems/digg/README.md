# Digg design reference

A token set and component reference for Digg's public product surface — for building news-feed apps, story cards, vote controls, right-rail panels and auth flows in the style of the real thing. It was read from **digg.com** (the 2025 reboot — "News, before it trends") on **2026-11-14**, signed out, in headless Chromium at 1440 x 900 and 390 x 844. Captured: the home feed in light **and** dark, the /tech category feed, a story page in both themes, the /u/wired source profile, the Clerk /login and /sign-up forms, and 390px passes on the feed and the story.

Digg is worth a capture because it ships a real declared token layer to the browser: a shadcn-style semantic set (`--background`/`--foreground`, `--card*`/`--popover*`, `--primary*`/`--secondary*`/`--muted*`/`--accent*`, `--destructive*`, `--border`/`--input`/`--ring`), the `--sidebar-*` rail set, `--chart-1..5`, app roles (`--rank-one`, `--success`, `--media-overlay-*`, `--typeset-*`, `--site-*`, `--scroll-fade-*`, `--item-*`, `--thumb-*`, `--topic-*`), the full Tailwind hue scales (`--red-50..950`, `--featured-image-gray-*`, `--color-gray-*`) and the theme-invariant Tailwind layer (`--text-*`, `--leading-*`, `--tracking-*`, `--radius-*`, `--animate-*`, `--ease-*`). 353 variables resolve per theme — and unlike most products the dark theme is genuinely painted signed out: the sidebar theme pill cycles System -> Light -> Dark and the dark readings below are measured through it, not declared-only guesses. The surface is a `#fdfdff` field with `#161617` ink, ink@70% muted text, white cards on rgba(0,0,0,0.08) hairlines, `#f0f0f5` fills, a single `#1c66eb` primary blue on Sign up/Continue/links, and `#e37b4c` rank-one orange in the contributors rail. Three served voices: roobert on everything (UI and headings, 400-700), declared ibmPlexSans for typeset prose, and vt323 — the retro bitmap mono the vote odometer's digits are drawn in (`digg-score-*` animation classes, `linear()` spring easing). **Boundary:** everything interactive needs an account — digging, commenting, submitting, settings — and was never reached; the vote pills and comment links were measured, never pressed, and the Clerk fields were measured/filled, never submitted. A cookie banner painted on first load and was hidden for screenshots only — no consent choice was made.

### Principles

1. Do let the declared layer carry the design.
2. Do spend the blue on one action.
3. Do keep rows on fills, cards on hairlines.
4. Do pill the interactive edges.
5. Do count in the odometer mono.
6. Do theme for real.
7. Don't style the signed-in product from this package.
8. Don't invent a form flow.

Each rule links the screenshot or crop that shows it, under [Do and don't](#do-and-dont).

## Do and don't

- **Do let the declared layer carry the design.** The shadcn-style semantics and the Tailwind hue scales resolve per theme; measured roles alias them where they match. See [home](screenshots/home-light-default.png).
- **Do spend the blue on one action.** `#1c66eb` is reserved for Sign up, Continue, links and the vote pill's border-tint — everything else is ink, muted or gray fills. See [sb-signup](components/crops/sb-signup-default.png) and [st-vote](components/crops/st-vote-default.png).
- **Do keep rows on fills, cards on hairlines.** Sidebar rows and feed controls fill `#f0f0f5` (or the input wash); cards stay white on a `rgba(0,0,0,0.08)` hairline — no shadows except the auth field's 0 1px 2px. See [sb-home](components/crops/sb-home-default.png) and [post-card](components/crops/post-card-default.png).
- **Do pill the interactive edges.** Sidebar items, primary CTAs and vote pills are full pills (`calc(infinity * 1px)`, 999px on the story digg-it); controls are 26px, cards 18px, fields 8px. See [st-vote](components/crops/st-vote-default.png).
- **Do count in the odometer mono.** The vote counts render in vt323's retro digits with `digg-score-*` spring animations — the one playful voice against roobert's flat UI. See [post-vote](components/crops/post-vote-default.png).
- **Do theme for real.** The sidebar pill cycles System -> Light -> Dark and every surface repaints — dark is `#161617` field, `#1c1c1f` cards, `#fdfdff` ink, rgba(255,255,255,0.08) hairlines. See [home dark](screenshots/home-dark-default.png).
- **Don't style the signed-in product from this package.** Voting, commenting, submitting and settings were never reached — the vote and comment controls gate on sign-in and were never pressed.
- **Don't invent a form flow.** The Clerk fields were focused and filled but never submitted — no validation, error or success state exists in this capture.

## How the values were read

1. **Harvest.** `tools/capture/vars.mjs` reads every served stylesheet (digg.com serves CSS same-origin), classifies each custom property (theme / Tailwind utility / app / vendor), and resolves the `:root` and `.dark` declarations in [raw/css-vars.json](raw/css-vars.json) — colour functions (lab/oklab/oklch) normalise to hex.
2. **Measure.** `tools/capture/public/measure.mjs` opens each public route signed out at 1440 x 900 (390 x 844 for the mobile pass) and records computed styles plus a crop per state — default, hover, focus-visible, DevTools-forced pressed, plus the opened sort dropdown and focused/filled auth fields — into [raw/components-computed.json](raw/components-computed.json). The dark pass cycles the sidebar theme pill to dark first, so the `d-*` components are measured dark paint.
3. **Shoot.** `tools/capture/public/public.mjs` captures default viewport and `-full` shots per surface into [screenshots/](screenshots); the phone feed's long page is captured as bounded clip tiles and stitched.
4. **Build.** `tools/build_component_tokens.py` turns the harvest + measurements into [raw/component-tokens.json](raw/component-tokens.json); `tools/build_tokens.py` writes [tokens.json](tokens.json) with `core`/`light`/`dark` sets; `tools/build_components_md.py`, `tools/build_style_guide.py` and `capture/public/build-measurements.mjs` generate the docs. Re-running the builders is a no-op by design.

## Known gaps

- `feed-compact`, `post-headline`, `post-vote`, `post-comment`, `post-avatars`, `post-sources`: each `focus-visible` reading is `via: focus failed`. The capture opened the Trending sort dropdown (`feed-trending` opened) and never closed it, so the open menu held keyboard focus for every later home component. components.md lists them as focus not capturable; their focus look was never read, and they need a recapture. `tools/capture/public/measure.mjs` now closes an opened toggle before the next state (edited, not run).
- **Automation was masked during capture.** Until 2026-11-20, `tools/capture/public/lib.mjs` hid `navigator.webdriver` in every page it opened, so every committed reading was taken with that mask. The mask is removed (a bot check is now recorded as a boundary, not bypassed); whether any page needed it to load is not known, and a recapture without it is the check.

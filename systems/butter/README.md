# Butter design reference

A token set and component reference for Butter's public surface — for building marketing and gallery pages in the style of the real thing. It was read from **butter.video** on **2026-11-11**, signed out, in headless Chromium at 1440 x 900 and 390 x 844 — reached via **usebutter.com**, which redirects to www.butter.video. Captured: the home, product, pricing, blog, MCP, contact and terms pages (the light marketing surface), the explore, blocks and templates galleries (a dark app shell that is public signed-out), the login page and a 390px mobile pass.

Butter is worth a capture because its "the first video editor you can build on" positioning paints an unusually restrained system: a declared `--butter-*` token layer whose palette is almost pure greyscale — `#0f0f0f` ink on white, `#1e1e1e` buttons and nav text, `#ededed` fields for the floating header island, the footer and the pricing cards — with a single cyan `#4dc5e5` accent hidden inside every button (the layer that surfaces on interaction and draws the 3px focus outline) and four bright accents (green `#63ad45`, pink `#f9abff`, red `#ff3333`, yellow `#e9d352`) spent mostly on artwork. A 107px DieGrotesk display type, 16px button pills, 32px cards, then a second surface entirely: the dark MUI app shell on a `#0a0909` canvas with `#151515` cards on `#212121` hairlines and inverted `#f5f5f5` buttons. **Boundary:** the editor itself lives behind /login; the workspace, projects, exports, checkout and every signed-in surface were never reached. The dark galleries are public — they are captured — but the product past them is a recorded gap, never inferred.

## Brief

<!-- brief:start. Generated by tools/brief.py from catalog.json, the tokens file and this README; `make brief` rewrites it. Do not edit. -->

Read this before designing in this style. Take every value from [tokens.json](tokens.json), never from the screenshots; `python3 tools/catalog.py export butter` prints them all with aliases resolved.

### Principles

1. Do keep it greyscale.
2. Do hide the accent inside the button.
3. Do float the header as an island.
4. Do run the display type huge and tight.
5. Do give cards one fill and a big radius.
6. Do invert buttons in the dark shell.
7. Don't style the editor from this package.
8. Don't spread the bright accents.

Each rule links the screenshot or crop that shows it, under [Do and don't](#do-and-dont).

## How the values were read

Every value came off the running signed-out site in headless Chromium:

- **Tokens.** [tools/capture/vars.mjs](tools/capture/vars.mjs) captures every stylesheet body (the Next.js CSS bundles from network responses plus the styled-components inline `<style>` blocks re-parsed with `CSSStyleSheet`) and writes every custom property to [raw/css-vars.json](raw/css-vars.json). butter.video declares a real design-token layer — `--butter-black`, `--butter-true-black`, `--butter-blue`, `--butter-charcoal`, the greys, four accents, two font stacks and two easings — so most light-surface tokens are declared variables resolved the way the browser resolves them; the dark app shell declares nothing (MUI compiles its theme into the bundle), so its tokens are measured computed values. [tools/build_component_tokens.py](tools/build_component_tokens.py) writes the spec, [tools/build_tokens.py](tools/build_tokens.py) the sets.
- **Components.** [tools/capture/public/measure.mjs](tools/capture/public/measure.mjs) opens each route in a fresh context and reads `getComputedStyle`, painted layers and boxes per element in default, hover, focus-visible and a CDP-forced pressed state. Results in [raw/components-computed.json](raw/components-computed.json) and [raw/measurements.md](raw/measurements.md). Butter's buttons are transparent anchors whose inner layers paint the dark fill and the cyan accent, so the readings record painted layers rather than trusting the wrapper.
- **Screenshots.** [tools/capture/public/public.mjs](tools/capture/public/public.mjs) takes viewport and full-page shots per route with `.capture.json` sidecars, including the local UI toggles: the Monthly/Annually billing buttons on /pricing (it clicks `Monthly` and shoots `pricing-light-monthly`), the Claude agent tab on /mcp, the nav dropdown and the mobile menu. [tools/capture/quantize.py](tools/capture/quantize.py) posterises them to 256 colours.

Nothing was signed into, bought or submitted: the login page was captured as a surface, never filled or submitted; every Try-for-free, Get-Started and Choose-plan action was measured, never followed; the billing tabs, MCP agent tabs, nav dropdown and mobile menu were toggled as local UI state; the FAQ accordion was measured closed, never expanded. The iubenda consent banner was hidden, never answered — no consent button was ever clicked.

## What to distrust

- **Readings past a masked bot signal.** The committed screenshots and readings were taken with `navigator.webdriver` masked, the flag bot checks read to spot automation. The capture scripts no longer mask it (not run since), so a recapture may record a walled route as a boundary instead of a reading.
- **This is the public shell, not the editor.** The Butter workspace, projects, exports, billing and the API-key flows the /mcp page advertises sit behind /login and are uncaptured. Treat the editor's own design system as unknown.
- **Two surfaces, not a theme toggle.** The marketing pages are light-only and /explore, /blocks and /templates are dark-only; no switch is offered. `tokens.json` keeps the app-shell roles in the `dark` set — read them as the gallery shell, not a user-selectable dark mode.
- **The buttons are wrappers.** `hero-cta`, `nav-cta` and `plan-cta` compute `background transparent`: the visible dark `#1e1e1e` fill and the `#4dc5e5` accent live on painted inner layers (the Child-layers rows in components.md). Copy the layers, not the wrapper.
- **The shell looks like product but is public.** /explore, /blocks and /templates paint the dark sidebar and card grid signed out — they are marketing galleries of blocks and templates, and opening one inside the editor needs an account.
- **Quantised screenshots.** `screenshots/` are 256-colour PNGs; read exact colours from tokens or the raw files.
- **Missing components.** `d-search` is recorded missing — the signed-out /explore shell paints no search input — and the FAQ accordion's answers stay unexpanded.

## Fonts

Three served faces do everything. **DieGrotesk** runs the marketing pages: the 107px `Engineered for Creativity` display, section heads, nav, buttons and footer. **ABCDiatype** covers marketing meta text — plan-card copy, footer small print, menu labels (the `--butter-font-secondary` var). **dieGroteskA** runs the dark app shell's 24px section heads, 14px nav and 12px labels. All are served from the Butter CDN; none is distributed with the package — the style guide falls back to system sans.

## Do and don't

1. **Do keep it greyscale.** `#0f0f0f` ink on white fields with `#ededed` surfaces is the whole marketing palette; restraint is the look. See [home-light-default](screenshots/home-light-default.png).
2. **Do hide the accent inside the button.** The `#4dc5e5` cyan lives on a painted layer inside every dark button — it surfaces on hover and draws the 3px focus outline — not on backgrounds. See [hero-cta](components/crops/hero-cta-default.png).
3. **Do float the header as an island.** The nav is a light-grey `#ededed` pill inset from the viewport edges at a 16px radius, not a full-width bar. See [header](components/crops/header-default.png).
4. **Do run the display type huge and tight.** The hero display measures 107px at ~0.99 line-height in DieGrotesk with hairline letter-spacing; section heads run 60px. See [pricing-light-default](screenshots/pricing-light-default.png).
5. **Do give cards one fill and a big radius.** Pricing cards are `#ededed` at 32px with no border; dark cards are `#151515` at 32px on a 1px `#212121` hairline. No shadows anywhere. See [plan-card](components/crops/plan-card-default.png) and [d-card](components/crops/d-card-default.png).
6. **Do invert buttons in the dark shell.** The shell's actions are `#f5f5f5` fills with `#0a0909` labels at a 10px radius — the mirror of the marketing dark pill. See [d-signup](components/crops/d-signup-default.png).
7. **Don't style the editor from this package.** Every value is the public surface's; the workspace behind /login is uncaptured.
8. **Don't spread the bright accents.** Green, pink, red and yellow are declared tokens but appear in artwork, not chrome — UI stays monochrome with the cyan accent.

## Rebuild

Everything derived regenerates offline from the raw readings (run from `systems/butter/`):

```sh
python3 tools/build_component_tokens.py        # raw/components-computed.json -> raw/component-tokens.json
python3 tools/build_tokens.py                  # -> tokens.json
python3 tools/build_style_guide.py             # -> style-guide.html
python3 tools/build_components_md.py           # -> components.md
node tools/capture/public/build-measurements.mjs  # -> raw/measurements.md
python3 tools/capture/quantize.py <raw-dir>    # full-colour PNGs -> screenshots/
```

Then `make brief && make design-md && make grade && make check` from the repo root refreshes the generated sections and validates the catalog.

Live recapture (needs the site; Playwright at `PLAYWRIGHT=~/.design-systems/pw/node_modules/playwright/index.mjs`):

```sh
node tools/capture/vars.mjs                    # stylesheet harvest -> raw/css-vars.json
node tools/capture/public/measure.mjs          # computed styles + crops -> raw/components-computed.json
RAW=<scratch> node tools/capture/public/public.mjs   # screenshots -> <scratch> (incl. the billing/MCP/menu toggles)
```

butter.video loads headless from this client; Cloudflare can gate a fresh context on the first load — the scripts retry on a clean context. The editor stays behind /login.

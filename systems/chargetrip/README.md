# Chargetrip design reference

A token set and component reference for Chargetrip's public surface — for building warm-cream, editorial-serif B2B pages and EV-routing chrome in the style of the real thing. It was read from **www.chargetrip.com** on **2026-11-12**, signed out, in headless Chromium at 1440 x 900 and 390 x 844: the marketing routes (home, Routing, API, No-code, CPO, both pricing pages, About, Newsroom, Contact, Contact sales and Terms), the public sign-in card on **account.chargetrip.io**, and the documentation shell on **developers.chargetrip.com** plus the credential-gated **playground.chargetrip.com** as boundaries.

Chargetrip ("EV routing, solved") is worth a capture because it is a study in warm restraint: a `#efede5` cream page ground with near-white `#fffffb` cards, a warm ink ramp (`#262322` text and dark fills, `#877f78` muted) doing all the structural work, and a single high-chroma `#f94d00` orange reserved for CTAs, hovers and the press state of footer links — all set in Geist with Cirka, an editorial serif, at an 88px display size for the headlines. The dark hero band and the "Most popular" plan card are dark islands inside the one light theme, not a dark theme. **Boundary:** the routing engine, dashboard, API playground credentials and every account surface sit behind sign-in on account.chargetrip.io and were never crossed; the sign-in card itself was measured but nothing was ever submitted.

## Brief

<!-- brief:start. Generated by tools/brief.py from catalog.json, the tokens file and this README; `make brief` rewrites it. Do not edit. -->

Read this before designing in this style. Take every value from [tokens.json](tokens.json), never from the screenshots; `python3 tools/catalog.py export chargetrip` prints them all with aliases resolved.

### Principles

1. Do paint the page in warm cream (`paper.200` `#efede5`) and float near-white cards (`paper.0` `#fffffb`) on it.
2. Do keep one accent: `#f94d00` orange for CTAs, the nav hover wash (`rgba(221, 59, 0, 0.15)`) and the footer link press.
3. Do pair Geist for UI with Cirka for display type (88/64/48px headlines at weight 400).
4. Do build dark islands (`ink.800` `#262322`) inside the light surface — the hero band and the Popular card — with `paper.100` text and 52% white muting.
5. Do corner buttons at 8px, submits at 10px, cards at 12–24px.
6. Don't underline links — hovers repaint colour or wash only.
7. Don't add a second accent colour; the only other hue is the green status dot.
8. Don't ship a dark theme from these tokens; the dark islands are part of the light theme.
9. Don't treat the sign-in card's oklch/Tailwind values as the marketing palette — it is a different stack on a sibling origin.

Each rule links the screenshot or crop that shows it, under [Do and don't](#do-and-dont).

## How the values were read

Every value came off the running signed-out site in headless Chromium:

- **Tokens.** [tools/capture/vars.mjs](tools/capture/vars.mjs) reads every stylesheet through the CSSOM on the live home page (the Framer bundle's inline `<style>` blocks) and re-parses them in a probe document, writing every custom property plus its resolved value to [raw/css-vars.json](raw/css-vars.json). The bundle declares a named token layer — the `--token-<uuid>` palette on `body` — so palette tokens resolve through the real declarations (`var` leaves); semantic roles and component metrics are measured computed values. [tools/build_component_tokens.py](tools/build_component_tokens.py) writes the spec, [tools/build_tokens.py](tools/build_tokens.py) the sets.
- **Components.** [tools/capture/public/measure.mjs](tools/capture/public/measure.mjs) opens each route in a fresh context and reads `getComputedStyle`, painted layers and boxes per element in default, hover, focus-visible and a CDP-forced pressed state, plus `focused`/`filled` on the sales and sign-in fields, `opened` on the Products flyout, and the mobile group at 390 wide. Results in [raw/components-computed.json](raw/components-computed.json) and [raw/measurements.md](raw/measurements.md).
- **Screenshots.** [tools/capture/public/public.mjs](tools/capture/public/public.mjs) takes viewport and full-page shots per route with `.capture.json` sidecars; [tools/capture/quantize.py](tools/capture/quantize.py) posterises them to 256 colours and stitches the tiled mobile pages.

Nothing was signed into, booked, sent or consented to: the Products flyout and the mobile menu are local toggles, each opened once for the reading and closed again; the "Cookie Settings" card was hidden, never answered; the sales and sign-in fields were focused and the sign-in card was filled with the documented `name@example.com` test address, then cleared — no form was ever submitted, and every Book-a-demo / Plan-a-route / Contact-sales / Sign-in / Create-account / Send action was never followed.

## What to distrust

- **Captured with the automation flag masked.** The public capture (`tools/capture/public/`) hid `navigator.webdriver` from every page, so the committed readings and screenshots it took were taken past that mask. The scripts no longer hide it (edited, not run); a recapture that meets a bot check records it as a boundary.
- **The signed-in product is uncaptured.** The routing engine, dashboard, API keys and the working playground all sit behind account.chargetrip.io; the sign-in card and the developers/playground shells were captured as boundaries and nothing authenticated was inferred.
- **Two stacks on one domain group.** The marketing site is a Framer build (Geist + Cirka, `--token-*` palette); account.chargetrip.io's sign-in card is a different stack (Tailwind v4, oklch colours, Geist) — the sign-in measurements are real but belong to a different design layer, and are recorded as such.
- **One theme only.** Every captured route paints the same light surface; the dark hero band and the "Most popular" plan card are dark islands, not a dark theme — `tokens.json` ships a single `light` set.
- **The tokens mix declared and measured.** The palette resolves the bundle's own `--token-*` vars; roles and component metrics are computed-style readings. Each token's `$extensions.source` says which.
- **The status pill was read from the wrong element.** `status-pill` caught the outermost footer column whose text ends in "Stable" (208 x 171, the Resources column), not the status link, so its size, crop and type in [components.md](components.md) describe that column. Only its green dot (`light.status.online`, the column's one painted 8 x 8 child) is used; `light.text.muted` now reads the footer's own heading colour, the same value. It needs a recapture; the selector is fixed (edited, not rerun).
- **Quantised screenshots.** `screenshots/` are 256-colour PNGs; read exact colours from tokens or the raw files.
- **One focus could not be driven.** `nav-item` (the Products menu trigger) could not be given a real keyboard focus; its focus behaviour is unmeasured, not absent.
- **Two hovers are unmeasured.** `nav-cta` and `nav-signin` answered `default`/`focus-visible`/`pressed` but their hover reads timed out on this pass; `components.md` shows those slots as unmeasured rather than reusing the old rows.

## Fonts

The marketing bundle declares **83 @font-face faces** (`fonts` in [raw/css-vars.json](raw/css-vars.json)) across four families: **Geist** (Variable plus Regular/Medium/Bold and the monospace Fragment Mono and Geist Mono faces) for the UI, **Cirka** (Regular and Bold, with a PP Cirka Medium face) for the 88/64/48px display type, and **Inter** (50 faces) carried for Framer's preset styles. The measured components render Geist Variable for controls and body copy and Cirka Regular for headlines and plan prices; `core.font.family.ui` and `core.font.family.display` name the stacks, `core.font.size.*` the measured steps. The sign-in card's Tailwind sheet sets plain Geist. No font file is distributed with the package.

# Awwwards design reference

A token set and component reference for Awwwards' public directory — for building awards-gallery and curated-index surfaces in the style of the real thing. It was read from **awwwards.com** on **2026-11-21**, signed out, in **headless Chrome** at 1440 x 900 and 390 x 844. The site tree is [site-tree.md](site-tree.md). Screenshots cover every public section index reached from the header, the Explore dropdown, and the footer, plus one site-detail sample. Login, signup, votes, and form submits were not taken.

Awwwards is worth a capture because it is the reference for *the web-awards directory look*: a near-achromatic interface — ink #222 text on white, #f8f8f8 washes and #ededed hairlines — where colour is reserved for meaning (six category accent triads plus the orange/blue brand accents and the measured #e3c352 award gold), a single family does all the work (Inter Tight at declared weights 300–800, four named UI sizes, display titles past 120px), radius is the signature (8px buttons, 14px cards, 72px tag chips), and every declared value is a hand-named custom property on `:root`.

## Brief

<!-- brief:start. Generated by tools/brief.py from catalog.json, the tokens file and this README; `make brief` rewrites it. Do not edit. -->

Read this before designing in this style. Take every value from [tokens.json](tokens.json), never from the screenshots; `python3 tools/catalog.py export awwwards` prints them all with aliases resolved.

### Principles

1. Do keep the chrome achromatic.
2. Do radius by role.
3. Do reserve fills for actions.
4. Do let Inter Tight do the work.
5. Do answer hover with a fill swap.
6. Don't ship a dark theme.
7. Don't box the cards.
8. Don't invent chrome colour.

Each rule links the screenshot or crop that shows it, under [Do and don't](#do-and-dont).

## How the values were read

Every value came off the running signed-out site in headless Chrome on 2026-11-21 (`vars.mjs` re-read the sheets that day; component measurements are the 2026-11-11 readings, still the same class selectors):

- **Tokens.** [tools/capture/vars.mjs](tools/capture/vars.mjs) captured every stylesheet body from the network responses plus inline `<style>` blocks, re-parsed them with `CSSStyleSheet`, and wrote every custom property to [raw/css-vars.json](raw/css-vars.json) binned `generated`/`app`/`vendor`/`utility`/`tailwind` — the site's design tokens (`--color-*`, `--bg-*`, `--font-*`, `--text-size-*`, `--rounded-*`, `--button-*`, `--innerWidth`, `--gutter`) land in `app`. Each name is resolved in a probe carrying the real sheets (light; a `dark` probe lands identical values — nothing binds it). [tools/build_component_tokens.py](tools/build_component_tokens.py) writes the spec, [tools/build_tokens.py](tools/build_tokens.py) the sets.
- **Components.** [tools/capture/public/measure.mjs](tools/capture/public/measure.mjs) opens each route in a fresh context, hides any consent or promo layer (never answered), and reads `getComputedStyle`, painted layers and boxes per element in default, hover, focus-visible and a CDP-forced pressed state, plus `opened` on the winners-grid filter dropdown and the mobile menu. Selectors are the site's long-lived classes (`header-main__logo`, `nav-filters__item`, `figure-rollover__link`, `box-score`, `button--tag`). Results in [raw/components-computed.json](raw/components-computed.json) and [raw/measurements.md](raw/measurements.md).
- **Screenshots.** [tools/capture/public/public.mjs](tools/capture/public/public.mjs) takes viewport and full-page shots per route — the arrival view is captured first, before anything is hidden — with `.capture.json` sidecars recording measured viewport/dpr; [tools/capture/quantize.py](tools/capture/quantize.py) posterises them to 256 colours.
- **The site detail is discovered.** `/websites/` card links are walked at run time until one whose detail page still has a Vote button lands (Site of the Day winners have closed voting); the URL is recorded as `site_url`. A different run may land on a different entry.

Nothing was voted on, submitted, joined, searched or signed into. The public directory, the winners grid, a site detail and the submit gate was enough.

## What to distrust

- **One theme only.** A `dark` probe resolves to the same `:root` values — nothing paints dark. `tokens.json` ships no dark set.
- **Roles are verified, not declared.** Every `light` role pairs a var (or a measured colour) with the component that was measured wearing it; the site declares palette, category accents and control vars, no semantic roles.
- **The award gold is measured, not declared.** The Vote button's #e3c352 fill (`core.measured.action-award`) exists in no var; likewise the #383838 the outlined Submit Website fills on hover/pressed, and the #005fcc browser focus ring on nav/footer links.
- **`component.*` tokens are measured**, not site variables. The site declares control heights (`--button-height` 48px, `--sf-height` 42px, `--nf-height` 54px); the Vote CTA's 60px is a measured value.
- **The card hover layer stayed hidden under headless hover.** The Vote Now overlay on grid cards did not materialise for measurement (`card-cta`/`card-action` are recorded gaps); `home-light-card-hover` shows it in the screenshot.
- **Log in and Sign Up are visible in the header** on the 2026-11-21 shots ([home-light-default](screenshots/home-light-default.png)). They were not clicked. `https://www.awwwards.com/login` asks for email or username and a password. Those fields were not filled. `/register`, `/forgot-password`, and the Google, Twitter, and Facebook login links were not opened.
- **`submit-cta-2` is a recorded miss** — /submit/ showed no measurable CTA to headless; the plan card is the evidence.
- **Focus styles were not systematically captured** beyond focus-visible states on the measured components.

## Fonts

**Inter Tight** is the single family — every measured component resolves to it, at declared weights 300–800 (`--font-light` to `--font-black`) and four named UI sizes 11–22px (`--text-size-*`). Display sizes are measured on the components: the ~127px site-detail title (600), ~42px page headings, 18px tag chips. Only one `@font-face` rule was captured in the sheets, recorded in [raw/css-vars.json](raw/css-vars.json); the variable font is self-hosted.

## Do and don't

1. **Do keep the chrome achromatic.** Ink #222 on white, #f8f8f8 washes, #ededed hairlines — colour is for category accents and the award gold, not the frame. See [home-light-default](screenshots/home-light-default.png).
2. **Do radius by role.** 8px buttons and score boxes, 14px site cards, 72px fully-round tag chips — never a fourth step. See [tag-chip-default](components/crops/tag-chip-default.png).
3. **Do reserve fills for actions.** The ink #222 pill (Be Pro), the outlined pill that fills #383838 on hover (Submit Website) and the #e3c352 gold Vote CTA are the only filled controls. See [bepro-link-default](components/crops/bepro-link-default.png).
4. **Do let Inter Tight do the work.** One family, weights 300–800 — hierarchy comes from weight and the ~127px display sizes, not a second family. See [site-title-default](components/crops/site-title-default.png).
5. **Do answer hover with a fill swap.** Buttons pick up #383838, dropdown rows #ededed — never scale or shadow. See [filter-option-hover](components/crops/filter-option-hover.png).
6. **Don't ship a dark theme.** None is offered or declared; a `.dark` probe resolves every var identically.
7. **Don't box the cards.** Site cards are image+caption rows at 14px radius, not bordered tiles. See [grid-card-default](components/crops/grid-card-default.png).
8. **Don't invent chrome colour.** The category triads belong to category surfaces; the frame stays ink-on-white. See [websites-light-default](screenshots/websites-light-default.png).

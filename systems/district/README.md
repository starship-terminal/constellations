# District design reference

A token set and component reference for District's public surface — for building event-booking apps, venue cards, category tabs and listing grids in the style of the real thing. It was read from **district.in** on **2026-11-15**, signed out, in headless Chromium at 1440 x 900 and 390 x 844. Captured: the home feed (/), the listing pages (/movies/, /dining/, /events/, /events/comedy, /stores/, /play/), an artist page (/events/samay-raina/artist), a ticket page (/events/all-stars-live-apr12-2026-buy-tickets), forced `data-theme="dark"` passes on / and /movies/, and 390px passes on the home and movies pages.

District is worth a capture because the whole product runs on the District Design System — a declared token layer shipped to the browser, not a convention reverse-engineered from pixels. `:root`/`html[data-theme=light]` and `html[data-theme=dark]` blocks carry the `--color-<hue>-<step>` scales (grey, purple, pink, blue, red, yellow, green, ember, peach, black/white alphas) plus `--color-<role>` semantics (background, surface, border, icon, text, button, gradient, pastel, vivid, extended, overlay, switch, selection families), `--font-<weight>`, `--font-size-*`, `--line-height-*`, `--space-*`, `--typography-scale-*` and `--page-max-width` — 589 variables resolved per theme over the `dds-*` utility layer. The paint: a `#ffffff` field with `#131316` ink (`--color-text-primary`), `#545459` muted tabs (`--color-text-secondary`), a `#eae5ff` selected tab (`--color-purple-100`/`--color-gradient-purple`) with `#231268` deep-purple label (`--color-text-accent-purple`), black@8% nav hairline and black@24% filter-chip border (`--color-border-subtle`/`--color-border-intense`), a `#131316` Book-tickets CTA (`--color-button-primary-background`) with `#f7f7f7` label, a `#1e1e20` footer slab (`--color-grey-800`) and the `#6e52fa` theme purple / `#6444e4` brand purple. Dark is real too: flipping the product's own `html[data-theme=dark]` repaints the chrome to `#131316` with `#f7f7f7` ink and white@8% hairlines — though feed sections keep their baked gradient fills, so dark is measured partial paint on this surface, honestly recorded. **Boundary:** booking and payment gate on the Zomato account — Book/Proceed buttons and date pills were measured at every paintable state, never pressed; the signed-out pages hold no disabled, error or loading states.

## How the values were read

1. **Harvest.** `tools/capture/vars.mjs` reads every served stylesheet across / and /movies/ (district.in serves CSS same-origin), classifies each custom property (theme / app / skins / vendor), and resolves the `plain`, `data-theme="light"` and `data-theme="dark"` declarations in [raw/css-vars.json](raw/css-vars.json).
2. **Measure.** `tools/capture/public/measure.mjs` opens each public route signed out at 1440 x 900 (390 x 844 for the mobile pass) and records computed styles plus a crop per state — default, hover, focus-visible, DevTools-forced pressed — into [raw/components-computed.json](raw/components-computed.json). The dark group applies the product's own `html[data-theme=dark]` attribute before measuring. District shows a city it picked for the visitor in the top bar, and measures every venue's distance from it; in the recorded text the location line reads `[city]` `[state]` and each distance `[distance]`, so the committed text does not say where the capture ran. The screenshots and crops have the same city line and venue distances painted out (see What to distrust).
3. **Shoot.** `tools/capture/public/public.mjs` captures default viewport and `-full` shots per surface into [screenshots/](screenshots); `-dark-*` shots flip the attribute first.
4. **Build.** `tools/build_component_tokens.py` turns the harvest + measurements into [raw/component-tokens.json](raw/component-tokens.json); `tools/build_tokens.py` writes [tokens.json](tokens.json) with `core`/`light`/`dark` sets; `tools/build_components_md.py`, `tools/build_style_guide.py` and `capture/public/build-measurements.mjs` generate the docs. Re-running the builders is a no-op by design.

## Known gaps

These readings caught another element in the 2026-11 run. `tools/capture/public/measure.mjs` now targets the right one (edited, not run); each needs a recapture.

- `mv-h1`, `ev-h1`, `cm-h1`: the first visible `h1`/`h2` was an off-screen carousel slide title (x < 0), not the listing heading. `core.font.size.measured.display` cites `ev-h1` and says so; its 40px matches the declared `--font-size-4xl`.
- `cm-filter`: the loose text filter matched the 632x500 sort dropdown panel, not a filter control.
- `at-book`: the loose text filter matched the show card that `at-show` already reads (it carries the price), not a booking control.
- **The location is painted out of the images.** The top bar's location line (the city and state District detected for the visitor), the city or state named elsewhere on a page, and venue distances (measured from the visitor) are masked in every screenshot and crop by the boxes in [tools/redact-rules/district.json](../../tools/redact-rules/district.json), as raw/ already masks them in text. The "Under N km" filter chips are product labels and stay. Read layout around those boxes, not the boxes.
- **Automation was masked during capture.** Until 2026-11-20, `tools/capture/public/lib.mjs` hid `navigator.webdriver` in every page it opened, so every committed reading was taken with that mask. The mask is removed (a bot check is now recorded as a boundary, not bypassed); whether any page needed it to load is not known, and a recapture without it is the check.

# Cal.com design reference

A token set and component reference for Cal.com's public signed-out surface — for building marketing pages, booking flows and auth cards in the style of the real thing. It was read from **cal.com** on **2026-11-11**, signed out, in headless Chromium at 1440 x 900 and 390 x 844 across three public hosts: the marketing pages on **cal.com** (home, pricing, Cal Video, teams, enterprise, customers, blog, FAQ), the public booking page on **i.cal.com** (cal.com/peer — Peer Richelsen's `15 Minute Meeting`, light plus its supported `?theme=dark&embed=true` dark mode) and the auth cards on **app.cal.com** (`/auth/login` and `/signup`).

Cal.com is worth a capture because the public surface carries two real declared token layers that paint differently per host: the marketing pages run on a `--color-hp-*` homepage layer — `#242424` ink on white, `#6a6e78` muted, `#e5e7eb`/`#dee1e6` hairlines, a `#cc4510` orange accent, `#0f234b`-tinted shadows and a 72%-white glass header bar — over an 80px calSans display and dark `#242424` buttons on 10-18px radii. The booker and auth hosts run the `--cal-*` semantic layer — `#3c3e44` text on white with `#d1d5db` borders, Inter on the booking page, fontSans/fontHeading on the auth cards — and the booker is the only surface that paints dark signed out (`#0f0f0f` canvas, `#4d4d4d` borders, `#d4d4d4` text, `#f5f5f5` inverted buttons). This booking page's effective brand paint is `#292929` on today and Confirm; the declared `--cal-brand` is `#111827`, and other hosts' pages vary. **Boundary:** the whole product — scheduler, event-type editor, availability, bookings, workflows, insights, settings — sits behind app.cal.com login and was never reached; the auth cards were measured as forms, never filled, and no booking was ever created.

## Brief

<!-- brief:start. Generated by tools/brief.py from catalog.json, the tokens file and this README; `make brief` rewrites it. Do not edit. -->

### Principles

1. Do keep it ink-on-white.
2. Do float the header as a glass bar.
3. Do run the display type huge and tight.
4. Do give every dark button a white inset top line.
5. Do draw focus as a gap plus a ring.
6. Do let the booking page keep its brand.
7. Do invert buttons in the dark booker.
8. Don't style the product from this package.
9. Don't use the declared `--cal-*` primaries on marketing.

Each rule links the screenshot or crop that shows it, under [Do and don't](#do-and-dont).

## How the values were read

Every value came off the running signed-out site in headless Chromium:

- **Tokens.** [tools/capture/vars.mjs](tools/capture/vars.mjs) captures every stylesheet body from two surfaces — the marketing site and the booker — from network responses plus inline blocks, resolves each custom property once light and once dark, and writes [raw/css-vars.json](raw/css-vars.json) (`surfaces.site` / `surfaces.booker`). cal.com declares a real token layer: the `--color-hp-*` homepage set (ink/muted/subtle text, line/hairline/field/surface greys, the `#cc4510` accent, `--hp-shadow-*` elevation, `--ease-hp-*` curves, `--font-weight-*`) and the `--cal-*` semantic set the booker and auth hosts paint (bg/text/border/brand roles that resolve differently per theme), so most tokens are declared variables resolved the way the browser resolves them; the measured extras (the type ramp, radii, control heights, the `#292929` booker paint, the near-black footer and focus rings) come from computed styles. [tools/build_component_tokens.py](tools/build_component_tokens.py) writes the spec, [tools/build_tokens.py](tools/build_tokens.py) the sets; wide-gamut `lab()`/`oklab()`/`color()` readings are converted to sRGB.
- **Components.** [tools/capture/public/measure.mjs](tools/capture/public/measure.mjs) opens each route in a fresh context and reads `getComputedStyle`, painted layers and boxes per element in default, hover, focus-visible and a CDP-forced pressed state. Results in [raw/components-computed.json](raw/components-computed.json) and [raw/measurements.md](raw/measurements.md). The nav mega-menu is a body-level Base UI panel anchored to the sticky bar, so the crop pass keeps the bar painted while it shoots the menu items.
- **Screenshots.** [tools/capture/public/public.mjs](tools/capture/public/public.mjs) takes viewport and full-page shots per route with `.capture.json` sidecars, including the local UI toggles: the Teams plan tab and the YEARLY billing switch on /pricing, another day cell then a time slot on the booker (which opens the guest-details form), the Products mega-menu, the mobile drawer, and the booker's `?theme=dark&embed=true` mode. [tools/capture/quantize.py](tools/capture/quantize.py) posterises them to 256 colours.

Nothing was signed into, booked or submitted: the login and signup pages were captured as cards, never filled or followed; every Get-started, Sign-up-with and Continue action was measured only; the booker's day cells, slot list and details form were toggled as local UI state and the Confirm button was never pressed, so no booking exists; the FAQ accordion was measured closed, never expanded.

## What to distrust

- **Captured with the automation flag masked.** The public capture (`tools/capture/public/`) hid `navigator.webdriver` from every page, so the committed readings and screenshots it took were taken past that mask. The scripts no longer hide it (edited, not run); a recapture that meets a bot check records it as a boundary.
- **This is the public shell, not the product.** The scheduler, event-type editor, availability, bookings, workflows, insights and settings sit behind app.cal.com and are uncaptured. Treat the product's own design system as unknown — a signed-in pass would add real coverage.
- **Two token layers, three hosts.** Marketing values come from `--color-hp-*`; the booker/auth values from `--cal-*`. They disagree where they overlap (marketing ink `#242424` vs booker text `#3c3e44`), so the light set keeps them apart at `*` and `booker.*`.
- **One booking page, one brand.** The booker is cal.com/peer's event type; its `#292929` paint on today/Confirm is this host's effective brand — other users' pages recolour and reflow.
- **Dark is the booker's mode, not the marketing site.** The marketing pages declare `--color-hp-*` dark overrides but never paint them signed out; the exported dark set is the booker's `?theme=dark` surface only.
- **Quantised screenshots.** `screenshots/` are 256-colour PNGs; read exact colours from tokens or the raw files.
- **The details form was opened by clicking a live slot.** The committed `bk-form`, `bk-field` and `bk-confirm` readings were taken after the capture clicked an available time slot on a real booking page, which can hold the slot. The script no longer clicks it (edited, not run), so a recapture records those three missing until an owned demo page is used.
- **Auth values serialize wide-gamut.** The app.cal.com cards compute colours as `lab()`/`oklab()`; tokens carry the sRGB conversion (`#262626` dark fill, `#696969` muted), provenance notes say where.
- **The hero headline wraps its mock.** `hero-title`'s rect covers the embedded booking mock too; the text readings are the headline's own.

## Fonts

Four served faces do everything. **calSans** (a variable face with a metric-matched `calSans Fallback`) runs the marketing pages: the 80px display, nav, buttons and footer. **fontSans**/**fontHeading** run the app.cal.com auth cards — fontSans body and buttons, fontHeading the 56px `Claim cal.com/you` display. **Inter** runs the booking page. All are served from Cal.com's CDN; none is distributed with the package — the style guide falls back to system sans.

## Do and don't

1. **Do keep it ink-on-white.** `#242424` headlines, `#3c3e44` booker text, hairline greys and white fields are the whole palette; the single `#cc4510` orange is the accent, not a second ink. See [home-light-default](screenshots/home-light-default.png).
2. **Do float the header as a glass bar.** The nav is a 72%-white blurred pill inset from the viewport edges at an 18px radius — never a full-width opaque bar. See [header](components/crops/header-default.png).
3. **Do run the display type huge and tight.** 80px calSans at 1.08 line-height with -1% tracking on desktop, 42px at 390 — and let imagery sit inside the headline. See [hero-title](components/crops/hero-title-default.png).
4. **Do give every dark button a white inset top line.** The `#242424`/`#262626` fills draw a 16% white 1px inset on top plus a 5% drop — the raised look is the whole button recipe. See [hero-google](components/crops/hero-google-default.png).
5. **Do draw focus as a gap plus a ring.** Keyboard focus paints a 1px white gap then a 3px `#9ca3af` ring (the booker's is quieter: 1px 20%-white + 2px 10%-black). Never an outline colour alone. See [nav-cta focus-visible](components/crops/nav-cta-focus-visible.png).
6. **Do let the booking page keep its brand.** The host's `#292929` paint owns today, selected moments and Confirm — it is per-page brand, not the marketing ink. See [booking-light-default](screenshots/booking-light-default.png).
7. **Do invert buttons in the dark booker.** Its actions are `#f5f5f5` fills with black labels — the mirror of the light booker's dark Confirm. See [bkd-slot](components/crops/bkd-slot-default.png).
8. **Don't style the product from this package.** Every value is the signed-out surface's; app.cal.com behind login is uncaptured.
9. **Don't use the declared `--cal-*` primaries on marketing.** `--cal-bg-primary`/`--cal-brand` (#1d2735/#111827) are declared but the marketing buttons measure `#242424` — copy the painted value, not the unused variable.

## Rebuild

Everything derived regenerates offline from the raw readings (run from `systems/cal/`):

```sh
python3 tools/build_component_tokens.py        # raw/components-computed.json -> raw/component-tokens.json
python3 tools/build_tokens.py                  # -> tokens.json
python3 tools/build_style_guide.py             # -> style-guide.html
python3 tools/build_components_md.py           # -> components.md
node tools/capture/public/build-measurements.mjs  # -> raw/measurements.md
python3 tools/capture/quantize.py <raw-dir>    # full-colour PNGs -> screenshots/
```

Then `make brief && make design-md && make grade && make check` from the repo root refreshes the generated sections and validates the catalog.

Live recapture (needs the site; Playwright at `PLAYWRIGHT=~/.design-systems/pw/node_modules/playwright/index.mjs`):

```sh
node tools/capture/vars.mjs                    # stylesheet harvest -> raw/css-vars.json
node tools/capture/public/measure.mjs          # computed styles + crops -> raw/components-computed.json
RAW=<scratch> node tools/capture/public/public.mjs   # screenshots -> <scratch> (incl. the pricing/booker/menu toggles)
```

cal.com loads headless from this client; the edge can slow the first load of a fresh context — the scripts wait it out rather than retrying. The product stays behind app.cal.com login.

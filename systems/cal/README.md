# Cal.com design reference

A token set and component reference for Cal.com's public site, for building a scheduling-product marketing page or an account-entry screen in that style. It was read from https://cal.com/ on 2026-11-21, signed out, in headless Chromium at 1440x900 and 390x844. The site paints one light scheme. Cal Sans carries the marketing type. The primary action is an ink pill (#242424) on white. An orange accent (#cc4510) is reserved for status chips.

The scheduler itself (bookings, event types, availability, settings) sits behind https://app.cal.com/auth/login and was never entered. The login page asks for email and password, or Google, Microsoft, or SAML. Nothing was typed. Nothing was submitted. The site tree is [site-tree.md](site-tree.md).

## How the values were read

cal.com is a Next.js marketing site. [tools/capture/vars.mjs](tools/capture/vars.mjs) captured linked stylesheets from network responses and inline sheets from the CSSOM, then parsed them with a constructed CSSStyleSheet. 743 custom properties were declared. The product layer is `--cal-*` (booker colours: ink, status, borders) and `--color-hp-*` (homepage roles, including the orange accent). Tailwind's default hue ramps are in `core.color.ramp` as declared stops, not as semantic roles.

Component values are computed styles from [tools/capture/public/measure.mjs](tools/capture/public/measure.mjs). Hover used the pointer. Focus-visible and pressed were forced through the DevTools protocol, so no primary button was clicked for real. The login fields were focused and not typed into. Consent SDK hosts were aborted at the network layer, so no consent banner was answered.

Screenshots were taken by [tools/capture/public/public.mjs](tools/capture/public/public.mjs) and quantised to 256 colours. Sidecars with the measured viewport stay with the full-colour originals under `~/.design-systems/cal/raw-shots/`.

## What to distrust

- Screenshots are 256-colour PNGs. Read colours from tokens.json.
- Hover on the ink pill computed to an oklab colour with alpha, not a second declared hex. The token records the declared rest fill.
- Radius steps other than xs and the measured 10px and 12px are Derived from `--radius` 0.625rem and the calc() aliases. The source string says Derived.
- Spacing steps are Derived multiples of the declared `--spacing` 0.25rem. The site does not name `--spacing-4`.
- `light.disabled` is `--cal-text-muted`. No separate disabled token was declared.
- `light.link` is the same ink as text. Marketing links are not a second colour.
- The auth card uses `fontSans`, not the marketing `calSans` face. Both are recorded.
- No dark theme was painted. Do not invent one.
- The home hero includes a product demo (a fake desktop and a booking card). That is a public demo, not the signed-in app.

## Fonts

| Family | Used for |
|---|---|
| calSans | Marketing body, nav, headlines. Served as woff2 from the site. Weight axis 400 to 700. |
| calSans Fallback | Local Arial, declared as the fallback face. |
| fontSans | The auth card on app.cal.com. |
| Inter | Declared in a stylesheet font-face. Not the computed body face on the marketing home. |

Cal Sans is the product's own face (`/font` documents it). No font file is committed. The style guide falls back to system-ui when calSans is not installed.

## Do and don't

- **Do let one ink do the primary action.** Get started is #242424 on white. See [screenshots/home-light-default.png](screenshots/home-light-default.png).
- **Do keep Sign in quiet.** It is text, not a second pill. See [components/crops/nav-signin-default.png](components/crops/nav-signin-default.png).
- **Do set headlines in Cal Sans, tight.** The home h1 is 80px with -0.8px tracking. See [components/crops/display-default.png](components/crops/display-default.png).
- **Don't spend the orange on buttons.** `--color-hp-accent` #cc4510 is a status chip colour, not the CTA.
- **Don't style the scheduler from this package.** Bookings, event types and settings were not captured. The login wall is [screenshots/login-wall-light-auth-wall.png](screenshots/login-wall-light-auth-wall.png).
- **Don't invent a dark theme.** `color-scheme` computed to light and no theme toggle was on the public pages.

# Square design reference

A token set and component reference for Square's public marketing site (squareup.com), captured signed out on 2026-11-21. Headless Chromium, desktop 1440x900 at 1x and phone 390x844 at 2x. The US English homepage, header menus, cart popover, pricing, hardware, payments, point of sale, restaurants, banking, help, the empty hardware cart, the contact form (not submitted), about, software, the privacy notice, and the login wall (nothing typed). No account was created. No password, email, phone, or location was entered.

Square paints one live theme on the public site: light, white page, black ink. A dark token set exists as `data-color-mode=dark` custom properties. Those values are recorded. The homepage was not painted dark.

## How the values were read

`tools/capture/public/read-vars.mjs` opened https://squareup.com/us/en in headless Chromium, hid the OneTrust cookie dialog (it was not accepted), and walked every readable stylesheet. 656 rules declared custom properties. 681 names resolved on `documentElement`. Cross-origin sales-bridge CSS threw and was skipped.

Semantic light and dark roles come from the `--color-*-color-mode-light` and `--color-*-color-mode-dark` declarations. The dark rule `:where([data-color-mode="dark"])` aliases those names. Setting `data-color-mode=dark` on the live homepage did not change computed custom properties, because the dark values are already resolved on `:root` under the `color-mode-dark` names. The homepage class is `html-bg-white`.

Spacing and type sizes in px are derived: `--font-size-body` is `1.6rem` and the homepage body computed to 16px, so 1rem is 10px. That conversion is labelled Derived.

## What to distrust

- Dark colours are declared tokens, not a screenshot of a dark page. The public site did not offer a theme switch on the pages that were opened.
- Screenshots are 256-colour PNGs. Read colours from tokens.json.
- The contact form shows Square's own example placeholder. That string was not typed. No email, phone, or postal code was entered.
- Login screenshots show an empty email-or-phone field and a passkey button. Nothing was typed and Continue was not pressed.
- Hover, pressed, disabled and error colours were not measured on live elements. Those states are Not captured.
- The cookie dialog was removed from the DOM before shots. Its visual design is Not captured.

## Fonts

Square ships its own faces, read from `@font-face` on the homepage: Square Sans Text, Square Sans Text VF, Square Sans Display, Square Sans Display VF, Square Sans Mono, Cash Sans, Cash Sans Mono, Exact Block, Noto Sans JP. They are proprietary. The style guide falls back to Helvetica and Georgia. Font files are not in the package.

## Do and don't

1. **Do use black ink on white.** Page and accent are `#000000`. Primary pills are black with white type. See [login-light-default](screenshots/login-light-default.png).
2. **Do pill the primary action.** Get started, Continue, and Shop hardware are fully rounded. See [home-light-cart](screenshots/home-light-cart.png).
3. **Do set headlines in Square Sans Display or Exact Block.** The hero is Square Sans Display at 64px. Section lines use Exact Block. See [home-light-default](screenshots/home-light-default.png).
4. **Don't treat the dark tokens as a captured theme.** They are declared `data-color-mode=dark` values. The live public pages that were opened are light.
5. **Don't follow Sign up or Log in into the app.** Those controls open an auth wall. The capture stops there. See [site-tree.md](site-tree.md).
6. **Don't sample colours from the screenshots.** They are 256-colour PNGs. Use tokens.json.

```bash
python3 tools/build_design_md.py
python3 tools/build_components_md.py
python3 tools/capture/quantize.py ~/.design-systems/square/raw-shots
```

Run the commands from `systems/square`.

## Gaps

- catalog.json and webapps-manifest.json were not edited, by instruction. The package is not in the gallery index.
- Signed-in dashboard, POS, banking account, payroll, order history: auth wall. Not captured.
- 144 public URLs loaded during the site-tree probe. Screenshots cover the header destinations and the main product, pricing, hardware, help, cart, contact, and login surfaces, not every industry subpage.
- Mobile menu category expansion (Business types and Products inside the phone sheet) was not captured as a second state.
- Homepage disclosure summaries and the audience tabs were not recaptured after the first runner missed them.
- Hover, pressed, focus-visible, disabled, loading, and error crops: Not captured.
- Cookie dialog: hidden, not captured.
- Warning colour: no token found. Not captured.

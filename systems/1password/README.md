# 1Password

The public face of [1password.com](https://1password.com): the marketing home, pricing, product, download, developer and contact-sales pages, plus the edge of the sign-in surface, read as a design system. 44 components in 97 measured states, 97 crops, 19 screenshots, 113 tokens. The vault itself is credential-gated (account + secret key + master password) and was never reached — everything here is the public site, and the gaps below say exactly where the evidence stops.

## How values were read

- **CSS variables.** `tools/capture/vars.mjs` reads the live CSSOM on 1password.com and resolves each custom property at `:root` — 567 names in `raw/css-vars.json`. The design system here is **Knox**, shipped as `--knox-*` variables (background/text/border ramps, motion, radii, component roles) inside a Tailwind/Next.js build.
- **Computed styles.** `tools/capture/public/measure.mjs` measures real elements in each state: `hover` is a real hover, `focus-visible` a real keyboard focus, `pressed` is forced via CDP (`CSS.forcePseudoState :active:hover` — nothing was ever pressed), `open` is a resting state reached by a UI toggle (nav flyout, FAQ, mobile drawer).
- **Screenshots.** `tools/capture/public/public.mjs`, same routes, whole pages plus state shots; `tools/capture/quantize.py` turns them into the 256-colour PNGs in `screenshots/`.
- **Provenance.** A token leaf is either `var` (the CSS variable it came from) or `value` + `source` (the measurement anchor in `raw/measurements.md`). Nothing is inferred from pixels.

## What to distrust

- **The vault.** Nothing behind `my.1password.com`/`start.1password.com` was reached; the app needs credentials this capture does not have. The unsupported-browser page is the honest boundary. Do not read app functionality into this package — it is a marketing-site system.
- **Cross-origin embeds.** The Vimeo player (`video-embed`) and the Marketo sales form (`form-embed`) are measured as element boxes only; their contents are unreachable and nothing inside them is claimed.
- **The consent card.** The OneTrust "We use cookies" card renders in a closed shadow root; it was suppressed for the committed captures, so it has no measurements — it is chrome of the consent vendor, not of the design system. The committed screenshots (public.mjs) and component readings (measure.mjs) were taken past a consent choice: those scripts wrote OneTrust's consent cookie with all four groups opted in, and their dialog sweep clicked Accept All, Reject or Agree where a dialog offered one. The CSS variable readings (vars.mjs) were not: that script opens its own context and calls neither. The scripts now block the OneTrust SDK and remove the banner instead (not run since), so a recapture's pages may load fewer third-party scripts than these did.
- **`--knox-*` variables that resolve to nothing.** Some Knox names (e.g. button hover/pressed fills) are unset on this site; only resolved values made it into tokens.
- **Quantised screenshots.** `screenshots/` are 256-colour PNGs; read exact colours from the tokens.

## Fonts

- **Agile Sans Variable** — the site's single voice (display at 300, body/nav at the variable-font 350, CTAs at 400), served as woff/woff2 from `/_next/static/media/`.
- **Agile Mono Variable** — the code face.
- Neither is bundled here; the style guide falls back to system faces.

## Coverage

- Home, pricing, product, downloads/mac, developer-security, contact-sales, and the `start.1password.com` unsupported surface; mobile at 390x844 for home and pricing.
- 44/44 components measured (97 states); the two cross-origin embeds are measured as frames and documented.
- Missing surfaces (declared in the catalog's `layoutGaps`): `icons/` — no icon harvest was run; the icon set is documented by usage only.

## Do and don't

- **Do treat `tokens.json` as truth.** Knox roles (secure-blue #0364d3, midnight-navy #1a2860, ink #303136) and the 90px pill profile are the site's own tokens.
- **Do read interaction behaviour in `components.md`.** Every control lists its hover, focus-visible and pressed diffs there.
- **Don't infer vault UI, auth flows or app functionality from these pages.** They were never captured.
- **Don't read exact colours off the PNGs in `screenshots/`.** They are 256-colour quantised; use tokens.
- **Don't treat the Marketo or Vimeo iframe internals as measured.** They are documented boundaries.

## Rebuild

From the repo root, Playwright at `PLAYWRIGHT` (index.mjs) and Pillow at `PYTHON`:

```sh
cd systems/1password
PLAYWRIGHT=$PW node tools/capture/public/public.mjs        # screenshots -> ~/.design-systems/1password/raw-shots/ (outside the repo)
PYTHON=$PY python3 tools/capture/quantize.py ~/.design-systems/1password/raw-shots      # -> screenshots/
PLAYWRIGHT=$PW PYTHON=$PY node tools/capture/vars.mjs      # -> raw/css-vars.json
PLAYWRIGHT=$PW PYTHON=$PY node tools/capture/public/measure.mjs        # -> raw/components-computed.json + crops
node tools/capture/public/build-measurements.mjs           # -> raw/measurements.md
python3 tools/build_tokens.py                              # -> tokens.json (spec: raw/component-tokens.json)
python3 tools/build_style_guide.py                         # -> style-guide.html
python3 tools/build_components_md.py                       # -> components.md
make design-md grade check                                 # repo-level: DESIGN.md, health, validation
```

## The product beyond the marketing site

The measured surface stops where sign-in begins. `start.1password.com` serves an unsupported-browser page to headless clients, and the app requires an account, secret key and master password — authentication was out of scope and out of bounds for this capture. For the same reason there is no `icons/` set and no app screenshots; `layoutGaps` declares both.

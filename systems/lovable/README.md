# Lovable design reference

A token set and component reference for Lovable's public site. It was read from **lovable.dev** and **docs.lovable.dev** on **2026-11-18**, signed out, in headless Chromium at 1440 x 900 and 390 x 844: home, pricing, blog, security, templates, the enterprise landing, the dark enterprise form, log in, and the docs welcome and plans pages.

Lovable's marketing bundle names its own token layer (`--bg-*`, `--fg-*`, `--border-*`, `--text-*-lmk`, `--radius-*-lmk`) on a `#f5f5f5` page with Camera Plain Variable, a blue `#1f55f1` accent, inverse near-black pills, and a hero prompt composer. Dark is painted on `/enterprise-form`. The builder sits behind sign-in and was not captured.

## Brief

### Principles

1. Do ground on #f5f5f5.
2. Do use the inverse pill for the primary action.
3. Do keep blue for accent and focus.
4. Do set UI type in Camera Plain Variable.
5. Do treat the composer as the hero control.
6. Don't paint marketing pages dark.
7. Don't reuse the marketing tokens on docs.
8. Don't follow Get started.

Each rule links the screenshot or crop that shows it, under [Do and don't](#do-and-dont).

## How the values were read

Every value came off the running signed-out site in headless Chromium:

- **Tokens.** [tools/capture/vars.mjs](tools/capture/vars.mjs) read the stylesheet bodies and wrote every custom property to [raw/css-vars.json](raw/css-vars.json). Each name is resolved on `html.light` and `html.dark`. [tools/build_tokens.py](tools/build_tokens.py) maps the named roles into [tokens.json](tokens.json).
- **Components.** [tools/capture/public/measure.mjs](tools/capture/public/measure.mjs) reads `getComputedStyle` in default, hover, focus-visible and a CDP-forced pressed state. Fields were focused and filled, then cleared. Results are in [raw/components-computed.json](raw/components-computed.json).
- **Screenshots.** [tools/capture/public/public.mjs](tools/capture/public/public.mjs) takes viewport shots and desktop full-page shots. [tools/capture/quantize.py](tools/capture/quantize.py) posterises them to 256 colours.
- **Fonts.** The bundle declares **Camera Plain Variable** (100 to 900, plus a 400 italic) and **Roboto Mono Variable**. Docs uses Inter. The font files are not committed.

Nothing was sent, signed into, purchased or submitted. Consent overlays were hidden, never clicked. The only presses were local toggles: the Solutions menu, the Yearly segment, one FAQ row, the docs search dialog and the mobile menu.

## What to distrust

- **Two hosts.** Marketing tokens do not describe docs.lovable.dev. Docs measurements are in components.md and are not tokenised.
- **The home hero kicker is not the display style.** The measured h1 is 18px weight 480. `core.typography.display` is the bundle's `--text-heading-lg-lmk` (36px, weight 600), not that kicker.
- **Get started's fill is on a child.** The header anchor itself computes a transparent background. The inverse fill is `light.inverse`.
- **Phone full pages were dropped.** The screenshot height and the CSS page height disagreed by more than one pixel. Viewport phone shots remain.
- **Quantised screenshots.** `screenshots/` are 256-colour PNGs. Read exact colours from tokens or the raw JSON.
- **Medium is 480, not 500.** `--font-weight-medium` resolves to 480.
- **There is no accent hover fill.** `accentHoverGlow` and `accentPressedGlow` are `--glow-accent-hover` and `--glow-accent-pressed`: tints Lovable paints over a fill, not fills (8% and 16% in light, 16% and 24% in dark). Before the 2026-11 audit they were named `accentHover` and `accentPressed`.
- **Keyboard focus failed on two controls.** `prompt-build` and `icon-button` record `focus failed`: keyboard focus never landed, so their focus-visible readings are the element at rest. [components.md](components.md) leaves them out and lists them as not captured. They need a recapture (the pk-k recapture tracking issue, 2026-11 audit).
- **Automation was masked.** The committed readings and screenshots were taken with `navigator.webdriver` hidden by `tools/capture/public/lib.mjs`. The mask has been removed from the script (2026-11 audit); a bot check is now a boundary, not something to get past.

## Fonts

Declared in `raw/css-vars.json` (`fonts`): **Camera Plain Variable** for UI and headings, **Roboto Mono Variable** for code. `--font-serif` is a system stack. Docs uses Inter. The guide renders system fallbacks. The webfont files are not committed.

## Do and don't

1. **Do ground on #f5f5f5.** `light.page` is `#f5f5f5`. Text is `light.text` `#030303`. See [home-light-default](screenshots/home-light-default.png).
2. **Do use the inverse pill for the primary action.** Get started and Continue use `light.inverse` (`rgba(0, 0, 0, 0.88)`) with near-white text, pill radius. See [login-continue-default](components/crops/login-continue-default.png).
3. **Do keep blue for accent and focus.** `light.accent` and `light.focus` are `#1f55f1`. Links use `light.link` `#123ec5`. See [nav-link-focus-visible](components/crops/nav-link-focus-visible.png).
4. **Do set UI type in Camera Plain Variable.** Medium is 480, not 500. See [pricing-title-default](components/crops/pricing-title-default.png).
5. **Do treat the composer as the hero control.** A textbox, an icon button and a Build chip, not a marketing form. See [prompt-field-default](components/crops/prompt-field-default.png).
6. **Don't paint marketing pages dark.** Dark is the enterprise form. Marketing stays `html.light`. See [enterprise-form-dark-default](screenshots/enterprise-form-dark-default.png).
7. **Don't reuse the marketing tokens on docs.** Docs is Inter on its own blue. See [docs-light-default](screenshots/docs-light-default.png).
8. **Don't follow Get started.** It opens sign-up. It was measured, never followed.

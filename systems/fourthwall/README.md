# Fourthwall design reference

A token set and component reference for Fourthwall's signed-out public surfaces — for building creator-commerce marketing pages, product catalogues, developer docs and help centers in the style of the real thing. It was read from **fourthwall.com**, **products.fourthwall.com**, **docs.fourthwall.com**, **help.fourthwall.com** and the `/get-started` auth shell on **auth.fourthwall.com** on the capture date, signed out, in headless Chromium at 1440 x 900 and 390 x 844. Captured: the marketing home, /pricing, /blog, /compare plus the Fourthwall-vs-Shopify page, /shops, /get-inspired, /contact, /memberships, /faq, /features, the catalogue home plus /all and one product page, the docs home and quickstart in light and genuinely-toggled `html.dark`, the help home and a category in light and genuinely-toggled `data-theme="dark"`, the Keycloak signup surface at rest, and 390px passes on home, pricing, the catalogue and the help category.

Fourthwall is worth a capture because it is five surfaces on five hosts sharing one brand voice but no stylesheet, which the token sets keep honest: the Webflow marketing site layers `--_primitives---*` ink/paper ramps under a `--_surface---*` semantic layer (`bg.page` #ffffff, `text.body` #0a0a0a, `bg.action` #0a0a0a inverting to #ffffff on `.on-ink` dark bands) with flat `--gs*`/`--b*`/`--r*` legacy ramps; the styled-components catalogue carries the real product DS — `--bg-*`/`--text-*`/`--border-*`/`--input-*`/`--radius-*`/`--motion-*` where every colour is a declared `light-dark()` pair (#161712 ink, #f2f2f2 fills, #b5b3b0 hairlines); the Keycloak auth shell reuses that DS in light; Mintlify docs run on `--gray-*` + Inter/Paper Mono behind a real `html.dark` theme menu; Docusaurus help runs on `--ifm-*` with #161712 as ink-and-primary behind a real `data-theme` toggle. Suisse Int'l + Saans VF carry marketing, catalogue and help; PP Telegraf is the marketing display face; docs speak Inter. **Boundary:** everything post-login — the shop dashboard, the product designer, checkout and order flow, promotions, account — was never reached; the Google/Apple/email auth choices and the PDP "Sign in to design" were measured at rest, never pressed; fields were typed into then cleared, never submitted; the Osano consent layer was hidden, never answered.

## Brief

Read this before designing in this style. Take every value from [tokens.json](tokens.json), never from the screenshots; `python3 tools/catalog.py export fourthwall` prints them all with aliases resolved.

### Principles

1. Do keep the five surfaces apart.
2. Do treat the marketing dark bands as scopes, not a theme.
3. Do reach for the pill.
4. Do spend the blue sparingly.
5. Do take dark modes only from real toggles.
6. Don't style the signed-in product from this package.
7. Don't fabricate outcomes.
8. Don't copy the brand.

Each rule links the screenshot or crop that shows it, under [Do and don't](#do-and-dont).

## Do and don't

1. **Do keep the five surfaces apart.** Each host has its own variable vocabulary — `--_surface---*` on marketing, `--bg-*`/`--text-*` on the catalogue and auth shell, `--gray-*` + `--primary` on docs, `--ifm-*`/`--fw-*` on help. Take values from that surface's set in [tokens.json](tokens.json); never blend them. ([home-light-default](screenshots/home-light-default.png), [catalog-light-default](screenshots/catalog-light-default.png))
2. **Do treat the marketing dark bands as scopes, not a theme.** The marketing site is one light surface; its dark sections repaint the `--_surface---*` layer under `.on-ink` — that is the `ink` set. There is no user-facing marketing toggle. ([wordmark-section default](components/crops/wordmark-section-default.png))
3. **Do reach for the pill.** `a.btn-primary` — 12px radius, `#0a0a0a` ink on white (inverted on ink bands), `Start now` in the nav and hero — is the one repeated action shape; catalogue/auth buttons drop to 8px radius on `#f2f2f2` fills. ([nav-cta default](components/crops/nav-cta-default.png), [auth-google default](components/crops/auth-google-default.png))
4. **Do spend the blue sparingly.** Marketing is monochrome ink-on-white; the catalogue adds the `#0042ff` link blue and status hues inside an otherwise neutral `#161712`/`#f2f2f2`/`#b5b3b0` palette. ([catalog-light-default](screenshots/catalog-light-default.png))
5. **Do take dark modes only from real toggles.** `docsDark` was painted by the docs site's own theme menu (`html.dark`) and `helpDark` by the Docusaurus colour-mode button (`data-theme="dark"`); `catalogDark` is the declared `light-dark()` branch, resolved under a forced colour-scheme probe — declared-not-painted evidence. ([docs-dark-dark-default](screenshots/docs-dark-dark-default.png), [help-dark-dark-default](screenshots/help-dark-dark-default.png))
6. **Don't style the signed-in product from this package.** The dashboard, designer, checkout and order flows are authenticated and were never reached; the auth shell covers only the signed-out choices. ([signup-light-default](screenshots/signup-light-default.png))
7. **Don't fabricate outcomes.** The provider buttons, "Sign in to design" and every link were measured never pressed; search and quiz states are local interactions only — no validation, cart or checkout state exists here. ([pdp-design-cta default](components/crops/pdp-design-cta-default.png))
8. **Don't copy the brand.** The Fourthwall wordmark, product photography, creator shop examples, mega-menu artwork and Eli assistant marks are the product's — borrow structure and tokens, never the artwork. ([home-light-mega-menu](screenshots/home-light-mega-menu.png))

## What to distrust

- **Fills the element does not paint.** Ten measured surface roles read a transparent `backgroundColor` (the fill comes from an ancestor): catalog `background.page` (cat-nav), `surface.card` (prod-card), `surface.field-bg` (cat-search), signup `surface.card` (auth-card), docs `surface.sidebar-bg`, docsDark `background.page` and `surface.code-bg`, help `surface.card`, helpDark `background.page` and `surface.card`. They are not tokens. `catalog.background.page` and `help.background.page` still alias the declared page names (`--bg-primary`, `--ifm-background-color`). docs, docsDark and helpDark have no page token: the docs' declared `--background-light`/`--background-dark` sit in the capture's `app` bin, which the builder does not emit, and nothing measured paints a docs page field.
- **No catalogue field border.** cat-search paints no border (style none, 0px on every side), so there is no `catalog.border.field-border`.
- **The auth Log-in link** is `signup.text.login-link` (it computes the primary ink); `signup.text.link` holds the declared `--text-link` blues.
- **The capture scripts were edited after the capture** (2026-11 audit, not run since): every scripted click in `tools/capture/public/measure.mjs` now goes through `toggle()`, so its never-press list applies to the openers too. The committed readings were taken before that edit; nothing was pressed that the list names.

# Rive

Rive is an interactive graphics engine. This package covers the public marketing site at https://rive.app/ and https://rive.app/pricing, the signed-out login at https://rive.app/login/ and signup at https://rive.app/signup/, and the public docs introduction at https://rive.app/docs/getting-started/introduction. Captured on 2026-11-19 from a signed-out browser. No account was created. No form was submitted. No payment was entered. Google and SSO were not clicked.

The marketing pages paint a black page. Login and signup paint a white panel beside a purple canvas. Docs paint a near-black page. There is no theme switch on these pages. The viewport that was measured was 1169 x 731 CSS px at device pixel ratio 2. A 1440 and a 390 capture were not taken: the preview browser returned "The browser is not producing screenshot frames", so this package has no screenshots.

## Brief

<!-- brief:start. Generated by tools/brief.py from catalog.json, the tokens file and this README; `make brief` rewrites it. Do not edit. -->

Read this before designing in this style. Take every value from [tokens.json](tokens.json), never from the screenshots; `python3 tools/catalog.py export rive` prints them all with aliases resolved.

### Principles

1. Set the marketing page on black and the auth panel on white.
2. Use amber as the brand mark and blue as the auth action.
3. Set display type in Orbitron, uppercase, with tight tracking.
4. Keep controls nearly square.
5. Show auth focus with the amber ring, not a blue outline.

Each rule links the screenshot or crop that shows it, under [Do and don't](#do-and-dont).

## How the values were read

Custom properties and computed styles were read with `getComputedStyle` and the CSSOM in a live T3 preview tab on 2026-11-19. The marketing site is a Framer page. Its colour tokens are hashed `--token-*` names on `body`, and a `prefers-color-scheme: dark` query flips a few of them. The login shell publishes named tokens: `--s-*` on `.site-refresh`, overridden again on `.LoginPage_LoginInputContainer`, plus `:root` `--color-*`. Docs are a Mintlify site and publish `--primary`, `--background-dark`, and a `--gray-*` scale as space-separated RGB channels.

The readings are in [raw/css-vars.json](raw/css-vars.json) and [raw/components-computed.json](raw/components-computed.json). Hover and focus colours that the live element did not show were read from the matching stylesheet rule (`.rn-cta:hover`, `.LoginFormButton_LoginAction__VF8hR:hover`, `.LoginInput_Input__gxjE6:hover`).

## What to distrust

The preview browser did not produce screenshot frames. There are no page captures and no crops. Layout claims in this README come from `getBoundingClientRect`, not from a picture.

The viewport was 1169 CSS px, the fill size of the preview tab. It is not a 1440 capture. Phone width was not measured.

The plan buttons on pricing computed `color: rgb(0, 0, 0)` on a `#1d1d1d` face. The visible label is likely a child. That color is not a token.

The docs heading font computed as "Tomorrow Placeholder". The real Tomorrow file may not have loaded. The token records the family name Tomorrow.

`ease` on the home CTA was the keyword. The cubic-bezier token expands that keyword. The points were not in the computed style.

A few Framer tokens (`#f30058`, `#71ff19`, `#19f2ff`, `#ff483c`) are declared on `body` and were not seen on a measured control. They are in `core.color` with that limit in the source string.

## Fonts

Orbitron is the display face (`--s-font-display`). Inter is the body face (`--s-font-body`). PragmataPro VF is the marketing mono face on GET STARTED and COPY. JetBrains Mono is the auth mono face (`--s-font-mono`). Tomorrow is the docs heading face. The style guide loads Orbitron, Inter, and JetBrains Mono from a public font host. PragmataPro and Tomorrow are not bundled.

## Do and don't

- **Set the marketing page on black and the auth panel on white.** The home body is rgb(0, 0, 0). The login panel is rgb(255, 255, 255) beside a rgb(60, 43, 75) canvas. Readings: [raw/components-computed.json](raw/components-computed.json).
- **Use amber as the brand mark and blue as the auth action.** `--s-highlight` is #ffa41c. The LOG IN button is #1f6fe5. The marketing GET STARTED button is white on black, not blue.
- **Set display type in Orbitron, uppercase, with tight tracking.** The home h1 is 48px, weight 900, letter-spacing -1.44px. Nav labels are 12px Inter, weight 500, letter-spacing 0.96px, uppercase.
- **Keep controls nearly square.** Auth fields and the LOG IN button use 2px radius (`--s-radius`). The marketing CTA uses 4px. The docs search uses 12px.
- **Show auth focus with the amber ring, not a blue outline.** On the white panel, `--s-focus` is a 2px white ring plus a 4px #b86e00 ring. The email field's own `:focus` rule did not change its computed shadow.

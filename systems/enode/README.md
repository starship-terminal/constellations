# Enode design reference

A token set and component reference for Enode's public marketing site — for building energy-tech marketing pages, product-overview pages, mega-menu chrome, contact forms and the sign-in edge in the style of the real thing. It was read from **enode.com** on **2026-11-13**, signed out, in headless Chromium at 1440 x 900 and 390 x 844. Captured: the home page, /platform/overview, /platform/homes, /platform/flexibility, /platform/assets, /enterprise, /customers, /customers/vattenfall, /company, /careers, /partnerships, /newsroom plus one article, /updates plus one article, /contact, /contact/partnerships, /privacy-policy, the platform.enode.com/login form, and 390px passes on home, platform overview, contact and updates.

Enode is worth a capture because it ships a complete token layer to the browser: ~160KB of inline CSS declaring `--color-brand-*`, `--color-gray-*`, `--color-enode-green-*` and alpha palette scales, semantic `--color-background-*`/`--color-foreground-*`/`--color-card-*`/`--color-border-*`/`--color-line-*`/`--color-diagram-*` roles resolved under `data-mode="light"`/`"dark"`, a full `--text-*`/`--leading-*`/`--tracking-*` type ramp, `--radius-*` steps, `--container-*`/`--grid-*`/`--gutter-*` layout tokens, breakpoints, blurs and `--ease-*`/`--default-transition-*` motion. The mode is chosen per page, never by a user toggle: most marketing pages paint light on the pale-green `--color-brand-75` field, while /platform/overview and /platform/flexibility paint `data-mode="dark"` on `<html>` — and the light pages carry scoped `[data-mode="dark"]` showcase sections and a dark-glass mega-menu. Two self-hosted variable voices: **Enode Sans** (wght 375–635, everything from the 68px masthead to 13px labels) and **Enode Mono** (product demo and code frames). The signature `#b0f87c` green is spent on live metrics and focus rings, not fills. **Boundary:** everything behind platform.enode.com was never reached — the login and contact forms were measured as forms, never submitted; docs.enode.com redirects to sign-in; every CTA and link was measured, never followed; the dormant Cookiebot consent layer was never answered.

2. Do spend the green on signals.
3. Do keep the painted modes honest.

5. Do pair the two voices.
6. Don't style the signed-in product from this package.
7. Don't fabricate form outcomes.
8. Don't copy the brand.

## How the values were read

| Step | What ran |
|---|---|
| Screenshots | `tools/capture/public/public.mjs` — 19 pages at 1440 x 900 (default + stitched `-full`, capped at 8 tiles; no page hit the cap) and 4 at 390 x 844, consent layer hidden, never answered |
| CSS harvest | `tools/capture/vars.mjs` — every custom property in the site's stylesheets (network bodies + inline CSSOM), resolved in `data-mode="light"` and `data-mode="dark"` probes, 283 values each |
| Measurements | `tools/capture/public/measure.mjs` — 46 components on public routes only; hover/focus-visible/pressed/open/focused/filled states; nothing signed into, submitted or followed |
| Tokens | `tools/build_component_tokens.py` → `raw/component-tokens.json` → `tools/build_tokens.py` → `tokens.json` |
| Docs | `tools/build_components_md.py`, `tools/build_style_guide.py`, `tools/capture/public/build-measurements.mjs` |

- **Provenance.** Every token leaf names its source in `$extensions.source`: `css-var --…` for the site's own declared variables, `measured …` for computed-style readings.

## What to distrust

- **The signed-in product.** Nothing behind platform.enode.com was reached; the dashboard, docs portal and API surfaces need an account this capture does not have. The `.visual-frame` tiles on the marketing pages are product mocks, not the product.
- **Animated surfaces.** The hero showcase and mega-menu demo tiles hold live canvas/video content; a screenshot freezes one frame, so sparse-looking panels (the "BALANCING 9.24 MW" diagram mid-animation) are a capture artifact, not the design.
- **The forms.** Contact and login fields were measured at rest and typed into then cleared — validation, error, loading and success states are unverified because nothing was submitted.
- **`--leading-*` and tracking companions.** Plain-number line heights are DTCG `number` tokens; a few `--tracking-*` values that ship unitless/`em` sit as `other` rather than letter-spacing dimensions.
- **Quantised screenshots.** `screenshots/` are 256-colour PNGs; read exact colours from tokens or the raw values, never the pixels.
- **Automation was masked during capture.** Until 2026-11-20, `tools/capture/public/lib.mjs` hid `navigator.webdriver` in every page it opened, so every committed reading was taken with that mask. The mask is removed (a bot check is now recorded as a boundary, not bypassed); whether any page needed it to load is not known, and a recapture without it is the check.

## Fonts

- **Enode Sans VF** — the single voice (masthead at weight 475, body ~470, controls ~490), served as variable woff2 (wght 375–635, italic companion) from `/assets/EnodeSans-VF-*.woff2`.
- **Enode Mono VF** — the mono face for product demo and code frames, same weight range.
- Neither is bundled here; the style guide falls back to system faces. Declared in the stylesheet's `@font-face` rules (harvested in `raw/css-vars.json`).

## Coverage

- 19 desktop routes and 4 mobile routes captured signed out; both painted modes covered (light marketing pages, whole-dark /platform/overview + /platform/flexibility, scoped dark sections, the dark-framed login).
- 46 components measured in 105 states, including opened mega-menus, the mobile drawer, forced-pressed controls and typed-then-cleared form fields.
- Missing surfaces (declared in the catalog's `capture.gaps`): every post-login platform surface, docs.enode.com, the careers ATS board, and all but one article per index.
- Icons: layout gap — no standalone SVG set lifted; product glyphs are visible in crops/screenshots.

## Do and don't

1. **Do let the declared layer carry the design.** Enode ships its tokens: use the `color.brand.*`/`color.gray.*` scales and the per-mode `color.<role>` semantics rather than restating hex. See [tokens.json](tokens.json) and [updates-light-default](screenshots/updates-light-default.png).
2. **Do spend the green on signals.** `#b0f87c` marks live metrics ("BALANCING 9.24 MW"), diagram accents and the 2px focus ring; surfaces stay pale-green, paper or warm-black. See [dark-showcase](components/crops/dark-showcase-default.png).
3. **Do keep the painted modes honest.** The mode is per page, not a toggle: pale-green light marketing, whole-dark /platform pages, and scoped dark showcases inside light pages. See [home-light-default](screenshots/home-light-default.png) and [platform-overview-dark-default](screenshots/platform-overview-dark-default.png).
4. **Do use the full-pill CTA.** CTAs and the Send-message submit are `radius.full` pills at 32px tall; nav pills drop to 4px, cards to 6px, fields to 6px. See [hero-cta](components/crops/hero-cta-default.png).
5. **Do pair the two voices.** Enode Sans carries everything from the 68px masthead to labels; Enode Mono owns product demo and code frames. See [hero-h1](components/crops/hero-h1-default.png) and [code-frame](components/crops/code-frame-default.png).
6. **Don't style the signed-in product from this package.** Everything behind platform.enode.com was never reached; the login panel is the only app surface measured, and it does not share this token layer. See [login-dark-default](screenshots/login-dark-default.png).
7. **Don't fabricate form outcomes.** Send-message and Log-in were measured, never pressed; what a submission returns is unverified. See [send-btn](components/crops/send-btn-default.png).
8. **Don't copy the brand.** The wordmark, the green, the photography and the demo diagrams are Enode's published artwork; borrow structure and proportion, not identity. See [mkt-logo](components/crops/mkt-logo-default.png).

## Rebuild

From the repo root, Playwright at `PLAYWRIGHT` (index.mjs) and Pillow at `PYTHON`:

```sh
cd systems/enode
RAW=~/.design-systems/enode/raw-shots PLAYWRIGHT=$PW node tools/capture/public/public.mjs   # -> RAW full-colour shots
PYTHON=$PY python3 tools/capture/quantize.py ~/.design-systems/enode/raw-shots             # -> screenshots/
PLAYWRIGHT=$PW PYTHON=$PY node tools/capture/vars.mjs                                      # -> raw/css-vars.json
PLAYWRIGHT=$PW PYTHON=$PY node tools/capture/public/measure.mjs                            # -> raw/components-computed.json + crops

python3 tools/build_tokens.py                                                              # -> tokens.json

python3 tools/build_components_md.py                                                       # -> components.md
make -C ../.. design-md grade check                                                        # repo-level (the Makefile is at the root): DESIGN.md, health, validation
```

# ClassPass design reference

A token set and component reference for ClassPass's public surface — for building clean white fitness-marketplace pages and pill-shaped CTA chrome in the style of the real thing. It was read from **classpass.com** on **2026-11-16**, signed out, in headless Chromium at 1440 x 900 and 390 x 844: the marketing routes (home, search, plans, features, how ClassPass works, fitness, gifts, reviews, partners, corporate wellness, about, contact, blog and terms), plus the public sign-in card on **/login** and the onboarding carousel on **/walkthrough** as boundaries.

ClassPass ("One app for fitness, wellness, beauty…") is worth a capture because it is a study in disciplined restraint: a white `#fff` ground with white cards, a near-black `#000`/`#111` ink ramp doing all the structural work, and a single high-chroma `#0055ff` blue reserved for the CTA system — with a designed three-step press ramp (`#0055ff` default, `#004de6` hover, `#0044cc` pressed) and a `#1a5ee5` link/focused-field blue. The supporting cast is equally tight: a `#c0e0ff` light-blue plan pill, a `#fce172` promo yellow on mobile, `#f7f7f7`/`#e7e7e7`/`#d6d6d6` neutral washes and hairlines, and a brand-tinted `rgba(1, 85, 254, 0.1)` shadow under the plan cards — all set in TT Norms with Circuit, a condensed display face, for the rotating-word hero and the plan headings. The black footer is the site's only dark island inside the one light theme, not a dark theme. **Boundary:** booking, member search results, the plan purchase and every account surface sit behind sign-in or payment and were never crossed; the sign-in card and walkthrough carousel were measured but nothing was submitted or completed.

## Brief

<!-- brief:start. Generated by tools/brief.py from catalog.json, the tokens file and this README; `make brief` rewrites it. Do not edit. -->

Read this before designing in this style. Take every value from [tokens.json](tokens.json), never from the screenshots; `python3 tools/catalog.py export classpass` prints them all with aliases resolved.

### Principles

1. Do paint the page white (`paper.0` `#fff`) and keep cards the same white, separated by hairlines and the brand-tinted shadow.
2. Do keep one accent: `#0055ff` blue for CTAs, links, the star rating and the focus ring, stepping `#004de6` hover to `#0044cc` pressed.
3. Do pair TT Norms for UI with Circuit for display type (60px plan headings, 40px hero, 36px prices).
4. Do use fully-rounded pills for buttons (9999px) against small-radius fields (4px) and mid-radius cards/filters (5–20px).
5. Do reserve the dark fill (`#111`) for secondary buttons and `#000` for the footer island only.
6. Don't underline links — hovers repaint colour or a `#f7f7f7` wash only.
7. Don't add a second accent hue; the only other colours are the promo yellow and the plan-pill light blue.
8. Don't ship a dark theme from these tokens; the footer island is part of the light theme.
9. Don't treat SGD prices or Singapore studio content as universal — the site geo-localizes.
10. Don't reuse a `body` background as the page ground; the white lives on `documentElement`.

Each rule links the screenshot or crop that shows it, under [Do and don't](#do-and-dont).

## How the values were read

Every value came off the running signed-out site in headless Chromium:

- **Tokens.** [tools/capture/vars.mjs](tools/capture/vars.mjs) reads every stylesheet through the CSSOM on the live home page and re-parses them in a probe document, writing every custom property plus its resolved value to [raw/css-vars.json](raw/css-vars.json). The harvest is thin — four rules (two carousel-dot variables, two framework internals) and nine @font-face faces — because **ClassPass declares no design-token CSS layer**. Every token is therefore a measured computed-style reading, not a resolved declaration. [tools/build_component_tokens.py](tools/build_component_tokens.py) writes the spec, [tools/build_tokens.py](tools/build_tokens.py) the sets.
- **Components.** [tools/capture/public/measure.mjs](tools/capture/public/measure.mjs) opens each route in a fresh context and reads `getComputedStyle`, painted layers and boxes per element in default, hover, focus-visible and a CDP-forced pressed state, plus `focused`/`filled` on the sign-in fields, `opened` on the filter dropdown and the mobile menu, and the mobile group at 390 wide. Results in [raw/components-computed.json](raw/components-computed.json) and [raw/measurements.md](raw/measurements.md).
- **Screenshots.** [tools/capture/public/public.mjs](tools/capture/public/public.mjs) takes viewport and full-page shots per route with `.capture.json` sidecars; [tools/capture/quantize.py](tools/capture/quantize.py) posterises them to 256 colours and stitches the tiled mobile pages.

classpass.com sits behind Cloudflare and challenges sequential navigation, so every route and every measurement group runs in a fresh browser context with a long settle; the TrustArc consent overlay was hidden, never answered. Nothing was signed into, searched for, booked or submitted: the Products flyout, the activity filter dropdown and the mobile menu are local toggles, each opened once for the reading and closed again; the sign-in fields were focused and filled with placeholder text only — the Sign-in / Sign-up / Next / Book / Search actions were never followed.

## What to distrust

- **Captured with the automation flag masked.** The public capture (`tools/capture/public/`) hid `navigator.webdriver` from every page, so the committed readings and screenshots it took were taken past that mask. The scripts no longer hide it (edited, not run); a recapture that meets a bot check records it as a boundary.
- **The signed-in product is uncaptured.** Booking, member-only search results, plan checkout, credits and account pages all sit behind sign-in or payment; /login and /walkthrough were captured as boundaries and nothing authenticated was inferred.
- **No declared token layer.** Every token is a measured computed-style value, not a resolved `--token-*` variable — the palette is reconstructed evidence, not the site's own names. `raw/css-vars.json` records the thin harvest that proves it.
- **The page ground is painted by `html`, not `body`.** `document.body` computes `rgba(0,0,0,0)`; the white ground lives on `document.documentElement`. `page-ground` is measured there and the entry says so — don't reuse a `body` fill value from elsewhere.
- **Four entries are kept from an earlier run.** `menu-panel`, `menu-card`, `section-title` and `app-badge` were not found by the 2026-11-16 recapture, so their readings are an earlier run's (`app-badge` even came from an uncommitted script edit, a `span` inside the badge link). [components.md](components.md) marks them, and `core.font.size.h2`, the one token built from them, says stale in its source. They need a recapture.
- **Geo-localized content.** ClassPass localizes by request origin: this capture shows SGD prices and Singapore plan content. Layout, chrome and components are the invariant evidence; the copy and currency are region-dependent.
- **One theme only.** Every captured route paints the same light surface; the black footer is an island, not a dark theme — `tokens.json` ships a single `light` set.
- **Quantised screenshots.** `screenshots/` are 256-colour PNGs; read exact colours from tokens or the raw files.
- **Two focuses could not be driven.** `nav-login` and `nav-cta` (the header's Log-in link and CTA pill) could not be given a real keyboard focus on this pass; their focus behaviour is unmeasured, not absent.
- **Transient surfaces.** The venue map, the rotating hero word and the sticky trial CTA animate or render through third-party scripts; a capture's pixel state is a moment, not a spec.

## Fonts

The site declares **9 @font-face faces** (`fonts` in [raw/css-vars.json](raw/css-vars.json)) across three families: **TT Norms Pro** (`norms`, regular/500/700) for the UI, **Circuit** for the display type — the rotating-word hero and the plan headings — and **Hiragino** faces as system fallbacks. `core.font.family.ui` and `core.font.family.display` name the stacks, `core.font.size.*` the measured steps (60px plan/display heading, 40px hero, 24px section, 20px subtitles, 18px FAQ, 16px body, 14px nav, 36px prices). No font file is distributed with the package.

# Attio design reference

Captured on 31 October 2026 from [Attio](https://attio.com) and its signed-in web app using the visible Codex in-app browser. The owner completed sign-in and authorized onboarding. Attio automatically provisioned a 14-day Pro trial during basic setup; these captures do not establish free-tier availability. No purchase, invitation, mailbox connection or record creation was submitted.

The package separates public marketing illustrations from interactive application evidence. It contains 37 accepted screenshots, including onboarding, light/dark company tables, filter/sort/view dialogs, record overview/actions, empty Notes and an unsubmitted create form. The theme preference was restored to **System**, rendering dark; the temporary viewport override was reset.

## Brief

<!-- brief:start. Generated by tools/brief.py from catalog.json, the tokens file and this README; `make brief` rewrites it. Do not edit. -->

Read this before designing in this style. Take every value from [tokens.json](tokens.json), never from the screenshots; `python3 tools/catalog.py export attio` prints them all with aliases resolved.

### Principles

1. Do reserve the filled accent button for New Company; don't give every toolbar action equal emphasis.
2. Do separate navigation, view controls and data into stable horizontal bands; don't mix table controls into the sidebar.
3. Do place record attributes beside the overview and keep tabs above it; don't require leaving the record to inspect related material.
4. Do keep sort priority visible as separate rows; don't hide sort direction.

Each rule links the screenshot or crop that shows it, under [Do and don't](#do-and-dont).

## How the values were read

Computed styles came from rendered DOM elements. Theme variables must be read inside `main`: root variables remain light even when the app renders dark. Only the scoped measurements supply semantic tokens. Opaque custom-property names retain their original names with no inferred role. Frozen element indices identify the exact measured source for each component token.

Every exported value is **Measured**. No sampled or reconstructed token values, and no derived conversions. The original API screenshots have `.png` names but decode as JPEG; the package stores decoded, quantized PNG copies. The manifest preserves original format, dimensions, hash and timestamp where available. Never sample colours from these images. Usage counts count viewport-intersecting HTML elements, including inherited styles, not pixel area or visual prominence.

App desktop measurements are 1386 by 959 CSS pixels, DPR 2, with 1386 by 959 decoded images. Public desktop is 1440 by 1000; phone is 390 by 844. The 390px app retains a wide table and overflowing toolbar, so it is evidence of a layout limitation. The dark table crop includes the observed sidebar tooltip. The full-page marketing attempt was rejected for unloaded animation sections.

## Do and don't

- Do reserve the filled accent button for New Company; don't give every toolbar action equal emphasis. [Toolbar](components/crops/light-toolbar.png).
- Do separate navigation, view controls and data into stable horizontal bands; don't mix table controls into the sidebar. [Companies](screenshots/companies-light-scoped.png).
- Do place record attributes beside the overview and keep tabs above it; don't require leaving the record to inspect related material. [Record](screenshots/company-record-overview.png).
- Do keep sort priority visible as separate rows; don't hide sort direction. [Sorting](screenshots/companies-sort-light.png).

These are observations for this reference, not an official Attio design guide.

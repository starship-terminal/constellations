# Grammarly design reference

A token set and component reference for Grammarly's signed-out public site, captured from www.grammarly.com on 2026-11-16 in headless Chromium at 1440 x 900 (mobile pages at 390 x 844): the home page, /features, /plans, /business/enterprise, /business, /professionals, /students, /edu, /ai, /ai-agents, /grammar-check, /plagiarism-checker, /paraphrasing-tool, /ai-detector, /word-counter, /desktop, /browser, /trust, /contact/sales, /signin, /signup and /blog/, plus home, plans and the grammar checker again at 390. Everything captured is public marketing and free-tool surface; nothing was signed into, submitted or sent.

Grammarly's marketing site is a Next.js app on two layered token systems: the legacy GDS layer (`--green-60`-style ramps plus the `--color-*`, `--button-*`, `--tag-*`, `--space-*`, `--radius-*`, `--elevation-*`, `--z-index-*` semantics) and the newer Origin layer (`--origin-*` primitives and the `--origin-color-*` semantics shared with the sibling Superhuman and Coda themes). The public pages paint one light theme — there is no switch and `prefers-color-scheme` does not repaint — while the stylesheets declare a full dark theme under `[data-gds-theme="dark"]`/`[data-origin-mode="dark"]` that no public page mounts. Matter is the display face, Inter the text face; the free grammar checker at /grammar-check runs signed-out and was measured empty and with a sample sentence (typed, analysed, deleted).

### Principles

1. Do use `green.60` `#027e6f` as the brand action colour.
2. Do give controls the 6px GDS radius.
3. Do set display type in Matter, text in Inter.
4. Do make focus visible the site's way.
5. Do keep the header compact.
6. Do put featured plan content on the brand fill.
7. Don't paint dark chrome from the declared dark tokens.
8. Don't add a billing toggle the page doesn't have.
9. Don't invent suggestion UI.
10. Don't press, submit or follow the green CTAs.

Each rule links the screenshot or crop that shows it, under [Do and don't](#do-and-dont).

## How the values were read

Every value was read signed-out from grammarly.com in headless Chromium (Playwright), no account, no cookies carried in.

- **Declared tokens.** `tools/capture/vars.mjs` read every stylesheet the pages link (the Next.js bundles served from static-web.grammarly.com, cross-origin, read through the CSSOM) and kept each rule that declares a `--*` custom property, with its selector and media context. Each name was then resolved on a probe page carrying the real sheets at 390, 768, 1024 and 1440, into raw/css-vars.json. The dark set was resolved synthetically by mounting the theme attributes the stylesheets declare (`data-gds-theme`, `data-origin-theme="grammarly"`, `data-origin-mode="dark"`), then removed; those values are labelled declared evidence, never painted.
- **Painted values.** `tools/capture/public/measure.mjs` measured 57 components at DPR 2: geometry, computed styles, the painted layers inside, and element crops. `hover` is a real pointer hover, `focus-visible` a real keyboard focus, `focused`/`filled` a field clicked and typed into (then cleared; nothing sent), `selected`/`open` states reached through the pages' own toggles (a feature tab, the nav flyout, the mobile sheet). `pressed` is forced with DevTools `CSS.forcePseudoState` and says so in its `How` row.
- **Screenshots.** `tools/capture/public/public.mjs` shot every listed page at 1440x900 (mobile 390x844 at 2x), viewport and full-page, then `tools/capture/quantize.py` stored 256-colour PNGs here; the full-colour originals stay in `~/.design-systems/grammarly/raw-shots`, outside git. Every shot's `.capture.json` sidecar records the measured viewport, DPR and document size and its dimension check.
- **Theme.** There is nothing to switch: the public site ships light only. The dark set in tokens.json comes from the stylesheets' own `[data-gds-theme="dark"]`/`[data-origin-mode="dark"]` declarations, resolved synthetically — reconstruction, not painted evidence. The same sheets also carry Superhuman and Coda themes (sibling Grammarly Inc. products on the shared Origin layer); only the grammarly theme was resolved.
- **Icons.** `tools/capture/icons.mjs` lifted every distinct inline SVG from the public pages, named by role.
- **Motion.** `tools/capture/motion-probe.mjs` read computed transitions and animations on five pages, then again under `prefers-reduced-motion: reduce` (the site honours it partially).
- **The consent sheet** (Transcend airgap) and the live-chat launcher were hidden before every capture, never clicked — hiding accepts nothing — and are not treated as part of the design.

## What to distrust

- **Captured with the automation flag masked.** The public capture (`tools/capture/public/`) hid `navigator.webdriver` from every page, so the committed readings and screenshots it took were taken past that mask. The scripts no longer hide it (edited, not run); a recapture that meets a bot check records it as a boundary.
- **The dark set is declared, not painted.** Every `dark.*` value is a stylesheet declaration resolved with the theme attributes mounted by hand; no public page ever paints it, so a dark screenshot does not exist and none is implied.
- **`pressed` is forced**, not a real mousedown: a JS-only press state would be missed.
- **`copy-button` reads 0x0.** The button is in the DOM but collapsed whenever the editor's helper footer hides; its states record the declared style of a collapsed slot, not a painted button.
- **`nav-panel-item` focus-visible reads 0x0.** Keyboard focus left the hover-driven flyout closed; the other three states are painted.
- **The checker's live analysis is a product overlay.** Typed text underlines issues visibly (see [grammar-check-light-filled](screenshots/grammar-check-light-filled.png)) but the underlines and suggestion cards render outside the page's light DOM, so `suggestion-card` is recorded missing rather than measured on the rail's header.
- **Lazy-mounted sections.** The Compare Plans table, FAQ and promo banner mount on scroll; they were scrolled in before measuring, and a slower page could still miss them.
- **Marketing copy inside shots** (plan prices like $12 USD/month Pro, feature lists, testimonials) is Grammarly's content, kept as captured for layout reference; prices and offers change.
- **Screenshots are 256-colour** — never read a colour off them; use tokens.json or the raw files.
- **Two filled states sent text to the server.** The `checker-filled` reading and the [grammar-check-light-filled](screenshots/grammar-check-light-filled.png) and [paraphrasing-tool-light-filled](screenshots/paraphrasing-tool-light-filled.png) shots were taken after a sample sentence was typed into the free checker and paraphraser, which send it to Grammarly for analysis. The scripts no longer type there (edited, not run); a recapture reads those editors at rest only.
- **Dark provenance named the light rule until 2026-11-20.** Each `dark.*` token now cites its `[data-gds-theme="dark"]` or `[data-origin-mode="dark"]` declaration (and the var it aliases there); values were unchanged. Six variables whose names extend another token's (`--color-border-base-default-f3`) are siblings now (`default-f3`), not children of a token.

## Fonts

- **Matter** is Grammarly's self-hosted display face (heading roles, plan names, prices); it is served from Grammarly's CDN and is not vendored here — the style guide falls back to Inter, the same fallback the token stacks name.
- **Inter** covers every text role (12-18px) and the UI controls.
- **Super Sans Mono VF** and **Super Serif VF** are Superhuman's brand faces in the shared Origin stacks; they resolve to the platform fallbacks here.

## Coverage

Captured: every public route listed at the top at 1440, home/plans/grammar-check again at 390, plus the states under "How the values were read" — the Product flyout open, the Proofreading feature tab selected, the checker and paraphraser filled with sample text (deleted after), the sales form's field focused, the sign-in email filled (deleted after), the mobile nav sheet open.

Not captured: everything behind Log in / Sign up (app.grammarly.com — the editor, dashboard, documents, account, billing, admin), every form's submitted success or painted error state, checkout and trial flows, the tools' result views (plagiarism report, AI-detector verdict, paraphrase output — each needs a submit the kit never performs), live suggestion cards (product overlay, not light DOM), a billing-period switch (not painted on the captured /plans), the nav panel's keyboard-focus state, blog articles, and any painted dark theme (declared only — see What to distrust).

## Do and don't

- **Do use `green.60` `#027e6f` as the brand action colour.** Primary buttons, the focus ring and the Most-popular header all take it; hover deepens to `green.70` ([btn-hero](components/crops/btn-hero-default.png), [nav-menu-button focus](components/crops/nav-menu-button-focus-visible.png)).
- **Do give controls the 6px GDS radius.** Buttons, fields and the sign-in card's inputs all measure a 6px corner on the GDS-skinned controls (the Origin scale's radius-2 is 8px — check which layer you are matching) ([form-input](components/crops/form-input-default.png), [signin-continue](components/crops/signin-continue-default.png)).
- **Do set display type in Matter, text in Inter.** Headings (heading-xsmall through heading-xlarge) are Matter at weight 600 with flat tracking; everything else is Inter ([hero](components/crops/hero-default.png)).
- **Do make focus visible the site's way.** A 2px `green.60` ring with a 1-3px offset on nearly every control — 20 of 27 focused components draw it ([tab focus](components/crops/tab-focus-visible.png) is one of the quiet exceptions).
- **Do keep the header compact.** The sticky bar is 65px on white with the lockup left and the Request a demo / Log in / Sign Up cluster right; at 390 it collapses to lockup + menu sheet ([m-header](components/crops/m-header-default.png)).
- **Do put featured plan content on the brand fill.** The Pro column's "Most popular" strip is brand green with white ink above the quiet card ([plan-card](components/crops/plan-card-default.png)).
- **Don't paint dark chrome from the declared dark tokens.** The public product never does — dark surfaces exist only as in-page sections like the enterprise strip ([section-dark](components/crops/section-dark-default.png)), which is dark-on-light design, not a theme.
- **Don't add a billing toggle the page doesn't have.** The captured plans grid is three static columns; prices like `$12 USD / month` are copy, not a toggled state ([plans-light-full](screenshots/plans-light-full.png)).
- **Don't invent suggestion UI.** What a signed-out visitor sees in the rail is the Suggestions header and the get-started steps — the live cards belong to the signed-in product ([suggestions-panel](components/crops/suggestions-panel-default.png)).
- **Don't press, submit or follow the green CTAs.** Every "Try for $0.00", "Create account", "Continue" leads to an account surface; the kit measured them and never followed ([plan-cta-primary](components/crops/plan-cta-primary-default.png)).

# Grok / xAI docs design reference

A token set and component reference for the Grok product family's public documentation portal — for building developer-docs pages, API reference chrome, pricing tables and search/command surfaces in the style of the real thing. It was read from **docs.x.ai** on **2026-11-17**, signed out, in headless Chromium at 1440 x 900 and 390 x 844. Captured: every public route the portal serves — /overview, /developers/quickstart, /developers/models, /developers/pricing, /developers/rate-limits, /developers/faq/general, /developers/model-capabilities/text/generate-text, /developers/rest-api-reference/inference, /developers/release-notes, /cookbook, /grok/overview, /grok/faq, /grok/user-guide, /grok-bot/overview, /build/overview and /x-subscription/overview — in the painted light theme, with verified dark repaints on the overview, quickstart, pricing, generate-text, api-reference and the Grok help home; the Ctrl+K search dialog, the product switcher, an opened sidebar group, an SDK tab switch and the 390px nav sheet as transient states; plus 390px passes on the overview and its drawer.

docs.x.ai is worth a capture because it declares a complete token layer to the browser: a Tailwind v4 `@theme` of `--neutral2..98` (the near-achromatic ramp the whole palette mixes from), the `--solar`/`--darksolar` brand accents (the orange **#ff640a**), a hand-written semantic layer — `--bg-base/-inset/-l1..l4/-card/-codeblock`, `--fg/-muted/-tertiary/-quaternary`, `--primary/-secondary/-accent/-muted/-card/-popover/-destructive/-success/-warning` and their `-foreground` partners, `--border-bold/-muted/-subtle`, `--sidebar-*`, `--chart-1..5`, `--content-*` — plus the `--sh-*` shiki syntax set, the proprietary variable faces **xVf** and **xMono** (weight 200-800) scoped to next/font classes, the `--text-xs..5xl` ramp, `--radius-*`, `--spacing`, `--container-*`, `--breakpoint-*` and `--ease-*/--duration-*` motion. The architecture: every page boots **html.light** (next-themes, `localStorage.theme`) and the header carries a real "Switch to dark theme" button — `light` is the painted default, `dark` re-points the roles under `.dark`/`:root.dark`, and a handful of names (`--border`, `--input`, `--ring`, `--alert`, `--on-alert`, `--background-*`, `--content-*`, `--sb-*`) are declared under `.dark` only. **Boundary:** grok.com itself and the x.ai sibling surfaces — x.ai, console.x.ai, status.x.ai, accounts.x.ai — sit behind Cloudflare; the managed challenge never cleared and the siblings returned 403 from the capture host, so the chat product, console, auth and status surfaces are documented as blocked boundaries, never claimed as captures. Nothing was signed into, typed, searched, sent, bought or submitted; the only presses were local UI toggles the site's own chrome provides (theme button, Ctrl+K, sidebar chevrons, SDK tabs, the phone's nav button), and pressed states are DevTools-forced pseudo-classes, never real presses.

## How the values were read

- **Variables** come from the stylesheets themselves (`tools/capture/vars.mjs`): every same-origin CSS response plus the inline CSSOM is reparsed, rules are binned theme/skins/app/vendor/utility/tailwind, and every custom property is resolved in a probe document carrying the real sheets and the live page's own generated classes (the next/font classes that scope `--font-x-vf`/`--font-x-mono`), once under `<html class="light">` and once under `class="dark"`. `tokens.json` never publishes a raw channel triplet — every colour is the painted value.
- **Geometry** is the live DOM (`tools/capture/public/measure.mjs`): bounding boxes and computed styles per component and state — hover by real mouse, focus-visible by keyboard, pressed by CDP `CSS.forcePseudoState` (no real press, so no link can fire), opened/focused states via the component's own toggle.
- **Screenshots** (`tools/capture/public/public.mjs`) verify the painted theme before writing a sidecar: HTML class, computed `colorScheme` and sampled background luminance must all agree. The article scrolls inside its own pane, so `-full` captures scroll that pane for lazy content, temporarily expand it, shoot, and restore the shell — bounded at eight chunks.
- **Dark states** are painted by the header's own theme button (verified, then switched back); the search dialog's dark reading closes the dialog, repaints, and reopens it because the button sits under the open overlay.
- **The icon collection** (`tools/capture/icons.mjs`) hashes each inline svg's geometry, names it from its control's label, and records where each was seen in `icons/INDEX.tsv`.

## What to distrust

- **Captured with the automation flag masked.** The public capture (`tools/capture/public/`) hid `navigator.webdriver` from every page, so the committed readings and screenshots it took were taken past that mask. The scripts no longer hide it (edited, not run); a recapture that meets a bot check records it as a boundary.
- **grok.com, x.ai, console.x.ai, status.x.ai, accounts.x.ai**: blocked at the edge — the Cloudflare managed challenge on grok.com never cleared headless or headed, and the sibling domains returned 403. Nothing on those surfaces was captured; the blocked attempts are the evidence. Do not present this package's tokens as the Grok chat product's tokens — they are the documentation portal's.
- **Dark-only names**: `--border`, `--input`, `--ring`, `--alert`, `--on-alert`, `--background-level-*`, `--background-screen/-striped/-vignette`, `--content-*` and `--sb-*` are declared under `.dark` only; the light set has no values for them and none were inferred.
- **Search results**: the cmdk dialog was opened and its resting suggestions measured; no query was ever typed, so result rows and the "Ask Grok" answer path are uncaptured.
- **xVf/xMono rendering**: the faces are self-hosted and not shipped here; crops show them, the style guide falls back to system fonts.
- **Pressed states** are DevTools-forced; a script-applied mousedown style would not show.
- **`docs-cta` pressed equals its default.** The capture forced `:active` on the topmost node at the button's centre (a text span or svg), not the button, so the button's own `:active` rule never applied. The script now forces the component's own node (edited, not run); the committed pressed reading needs a recapture.
- **Reduced motion**: the probe saw prefers-reduced-motion ignored on most pages (two pages partially honour it) — see `raw/motion.json`.

## Do and don't

1. **Do paint the docs light, and let the switch carry dark.** Every page boots `html.light` — white `--bg-base`, near-black `--fg` ([home](screenshots/home-light-default.png)); dark is a real painted surface behind the header's own button, not a media-query guess ([dark](screenshots/home-dark-default.png)).
2. **Do spend the solar orange on small marks.** #ff640a tints inline code, link underlines and accent details ([inline code](components/crops/prose-inline-code-default.png), [text link](components/crops/docs-text-link-default.png)); surfaces stay neutral — restraint is the pattern.
3. **Do keep the code panel dark.** `--bg-codeblock` is #121212 in both themes, so a light page carries a dark sample with the shiki `color.shiki.*` palette and SDK tabs on top ([code block](components/crops/docs-code-block-default.png)).
4. **Do pair the two voices.** xVf carries every heading, control and body in variable weights 200–800 (the h1 paints at an intermediate 450); xMono draws all code ([h1](components/crops/prose-h1-default.png), [code](components/crops/docs-code-block-default.png)).
5. **Do let the shell scroll inside.** The document never scrolls — the article and the sidebar each own an `overflow-y-auto` pane under the fixed 80px bar ([quickstart](screenshots/quickstart-light-default.png)); layout work belongs inside those panes.
6. **Don't style the Grok app from this package.** grok.com, x.ai, console.x.ai, status.x.ai and accounts.x.ai are blocked boundaries (Cloudflare challenge and 403s, documented, never bypassed) — these tokens describe the docs portal only ([docs wordmark](components/crops/docs-logo-default.png)).
7. **Don't invent the dark-only names.** `--border`, `--input`, `--ring`, `--alert`, `--on-alert`, `--background-*`, `--content-*` and `--sb-*` exist under `.dark` alone; light has no values for them and none were inferred ([dark repaint](components/crops/docs-sidebar-dark.png)).
8. **Don't fabricate the search.** The cmdk dialog was opened and its resting suggestions measured ([dialog](components/crops/docs-search-dialog-default.png)); no query was ever typed, so results and the "Ask Grok" path are unverified.
9. **Don't copy the brand or the fonts.** The wordmark (aria-labeled "SpaceXSI Docs home"), the icons and the xVf/xMono files are xAI's ([wordmark](components/crops/docs-logo-default.png)); the tokens describe the system, not its artwork.

1. Do paint the docs light, and let the switch carry dark.
2. Do spend the solar orange on small marks.
3. Do keep the code panel dark.
4. Do pair the two voices.
5. Do let the shell scroll inside.
6. Don't style the Grok app from this package.
7. Don't invent the dark-only names.
8. Don't fabricate the search.

Each rule links the screenshot or crop that shows it, under [Do and don't](#do-and-dont).

### Using tokens

| Role | light | dark |
|---|---|---|
| page | #ffffff `light.bg.base` | #0a0a0a `dark.bg.base` |
| surface | #f9f8f6 `light.bg.card` | #1a1a1a `dark.bg.card` |
| text | #0a0a0a `light.fg.default` | #d5d9e2 `dark.fg.default` |
| muted | rgba(10, 10, 10, 0.6) `light.fg.muted` | rgba(255, 255, 255, 0.6) `dark.fg.muted` |
| accent | #ff640a `core.color.brand.solar` | #ff640a `core.color.brand.solar` |
| border | rgba(213, 217, 226, 0.55) `light.border.muted` | rgba(31, 34, 40, 0.6) `dark.border.muted` |

Fonts: `core.font.family.sans` is xVf, then 8 fallbacks; `core.font.family.mono` is xMono, then 8 fallbacks. Scales, counted as [DESIGN.md](DESIGN.md) holds them: 10 type styles (`core.typography`), 8 radius steps (`core.radius`), 1 spacing step (`core.space`).

# Instagram design reference

A token set and component reference for Instagram on the web, captured signed out from `https://www.instagram.com/` on 2026-11-21. Headless Chromium, desktop 1440x900 at 1x and phone 390x844 at 2x, light and dark. Dark is `color-scheme: dark`, which sets `html.__fb-dark-mode`. Light sets `html.__fb-light-mode`. There is no public theme switch.

The homepage is a login wall. Public pages that loaded are the locations directory, one country page, Popular, Instagram Lite, the official profile `instagram`, and the 404 page. Login, signup, password reset, Facebook, and Meta Verified were recorded and not entered. No form was submitted.

### Principles

1. Do keep the page white in light and near-black in dark.
2. Do use one blue for the enabled action.
3. Don't treat the empty-form login button as the brand blue.
4. Do keep fields as 12px pills with a 1px stroke.
5. Don't follow a control that asks for a password.
6. Don't copy the glyph logo or the phone mock.

Each rule links the screenshot or crop that shows it, under [Do and don't](#do-and-dont).

## How the values were read

`tools/capture/public/capture.mjs` opened each public URL in headless Chromium and read `getComputedStyle(document.documentElement)` for every `--ig-*`, `--igds-*`, `--fds-duration-*`, and `--font-*` custom property. Light and dark are the same names resolved under `color-scheme`. `tools/build_tokens.py` writes [tokens.json](tokens.json) from [raw/capture.json](raw/capture.json). RGB triplets such as `255, 255, 255` become `#ffffff`. A value that is not a colour, length, duration, or cubic bezier is listed under `$extensions.notTokenised`.

Login field type (size, weight, family) was read from computed style on the live form and is recorded in `raw/capture.json` under `loginMeasure`. Those numbers are not all tokenised: Instagram does not publish a type scale as custom properties. The families that are tokenised are `--font-family-system` and `--font-family-system-prism`.

## What to distrust

- The login "Log in" button in the screenshots is the disabled wash. Both fields were empty. The enabled blue is the token `light.color.button.primary.background` (`#4a5df9`), not the pixels of that crop.
- Screenshots are 256-colour PNGs. Read colours from tokens.json.
- The phone profile capture is the app-install sheet over a dimmed profile. Hiding that sheet left a blank page, so the sheet is the phone state.
- A bio links dialog was opened and then left out of the package. It contained private handles. It is not in `screenshots/`.
- Hover and pressed button fills are tokenised from CSS and were not photographed.

## Fonts

`--font-family-system-prism` is `"Instagram Sans UI", -apple-system, BlinkMacSystemFont, "Segoe UI", Roboto, Helvetica, Arial, sans-serif`. Instagram Sans UI is Instagram's face and is not committed. The hero on the login page computed as "Instagram Sans Regular" at 40.32px. Body labels on the form computed as Optimistic at 15px / 500. Optimistic is not in the custom properties that resolved, so it is not a token. Fall back to the system stack in `core.font.family.system`.

## Do and don't

- **Do** keep the page white in light and `#0c1014` in dark. The login split and the directory header both sit on `color.primary.background`.
- **Do** use one blue for the enabled action. The nav "Log In" pill and the enabled login button share `color.button.primary.background`.
- **Don't** treat the empty-form login button as the brand blue. That crop is the disabled wash.
- **Do** keep fields as 12px pills with a 1px stroke. The login form stacks two of them.
- **Don't** follow a control that asks for a password, a phone number, or Facebook. Those branches stop. See [site-tree.md](site-tree.md).
- **Don't** copy the glyph logo or the phone mock into something that ships. Borrow the split, the pill, and the type sizes.

## Rebuild

```bash
cd systems/instagram
PLAYWRIGHT=~/.design-systems/pw/node_modules/playwright/index.mjs node tools/capture/public/capture.mjs
python3 tools/build_tokens.py
python3 tools/build_style_guide.py
python3 tools/capture/quantize.py ~/.design-systems/instagram/raw-shots
```

`quantize.py` writes every PNG in the scratch folder into `screenshots/`. The committed set is the 2026-11-21 viewport captures listed above, not older files that may still sit in that scratch folder.

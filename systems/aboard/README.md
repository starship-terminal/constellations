# Aboard design reference

A token set and component reference for Aboard's public marketing site, for building a consultancy-style editorial marketing page in the style of a real AI product studio. It was read from aboard.com on 2026-11-09, signed out, in headless Chromium at 1440 wide and 390 wide: the home page, How We Work, the case-studies index and a case study, Foundry, the four content feeds (Perspectives, Newsletter, Podcast, Events), In Media, About, FAQ, Careers, Security, and the Meet Aboard Sign article page. The look is warm and editorial: a Tobias serif display on a cream `#fffefb` ground, Work Sans for the interface, every button and field a full pill, and one loud bright-citrus `#de4c00` accent that the buttons and the whole footer carry.

aboard.com is a WordPress site; the theme's own custom properties (`--wp--preset--*` presets and the `--rd-*` design tokens) carry most of the values, and the token file aliases them where they exist. There is no product app behind the marketing site to capture: Aboard's product surface (the dashboard demo inside the hero carousel) is a marketing animation, not a reachable app. Nothing was signed into, bought or submitted; the newsletter signup was measured at rest and focus only, and the CookieYes consent strip never rendered in the headless capture.

### Principles

1. Do set headlines in Tobias, UI in Work Sans.
2. Do pill every control.
3. Do let bright citrus carry the actions.
4. Don't add borders or shadows to text blocks.
5. Do keep the warm-dark bands inside the light scheme.
6. Do give focus two different rings.

Each rule links the screenshot or crop that shows it, under [Do and don't](#do-and-dont).

## How the values were read

aboard.com is WordPress (block theme markup, `wp-singular` body classes, Tailwind-style utilities plus `.rd-*` theme classes), so its stylesheets are same-origin and fully readable. [vars.mjs](tools/capture/vars.mjs) resolved 124 custom properties at `:root` (of 245 declared): the `--wp--preset--*` colour/spacing/type presets and the `--rd-*` design tokens (`--rd-ink`, `--rd-body`, `--rd-line`, the `--rd-ease*` easings and the reveal durations). Where a token's value is one of those variables, its leaf says `"var"` and the builder resolves it against [raw/css-vars.json](raw/css-vars.json); everything else is a literal measured off a computed style, and each leaf's `$extensions.source` names the component or variable it came from.

Component values are computed styles read per state with Playwright ([measure.mjs](tools/capture/public/measure.mjs)). Hover used the pointer, focus-visible a real keyboard Tab, and pressed was forced through DevTools (`CSS.forcePseudoState`), so no button was clicked for real. The only presses were local UI toggles: the FAQ accordion headings and the mobile menu trigger. The newsletter fields were clicked into for their focus style but nothing was typed or sent (the form posts to `/wp-json/aboard/v1/newsletter-signups`). The CookieYes consent strip is hidden by CSS for the clean captures ([lib.mjs](tools/capture/public/lib.mjs)), which is a hide, not a consent; it was re-shown for measurement but its `.cky-*` markup never rendered in headless Chromium, so the four `cookie-*` entries record `missing` rather than values.

Font sizes on this site are fluid (`clamp()` everywhere), so every size token is a px value resolved at 1440 wide; at 390 the same roles measure smaller (the mobile hero reads 44.8px where the desktop reads 77.76px). Screenshots were lazily scrolled to settle lazy-loaded media, then stored quantised to 256 colours; the unquantised originals and per-capture metadata stay outside the repo.

## What to distrust

- **Readings past a masked bot signal.** The committed screenshots and readings were taken with `navigator.webdriver` masked, the flag bot checks read to spot automation. The capture scripts no longer mask it (not run since), so a recapture may record a walled route as a boundary instead of a reading.
- **Screenshots are 256-colour PNGs.** Gradients, photography and the frosted nav pill band slightly; read exact colours from tokens.json or the raw files.
- **Font sizes are fluid.** The px values in `core.font.size` are resolved at 1440 wide; scale them or re-measure for another width (see `font.size.m-display` for the 390 hero step). The `--wp--preset--font-size--*` presets in css-vars.json are the theme's own steps and differ from what the `.rd-*` classes paint.
- **The four `cookie-*` components are recorded missing.** CookieYes never rendered headless, so `home-light-cookie-banner.png` shows the page without the strip; the consent mock in style-guide.html is a placeholder, not a measurement.
- **`palette.nav-pill` and `palette.submenu` are translucent fills.** The nav pill paints `#f0f1ef` at 84% and the dropdown `#faf5ef` at 97% over whatever scrolls beneath; the token is the declared fill, not the composited result.
- **The hero carousel's dashboard is a marketing animation.** Metrics inside it (revenue figures, the "57%" dial) are demo content, not a live product.
- **`layout.header-height` is 80px declared, 78px measured.** The `--header-height` variable and the rendered bar disagree by 2px.
- **`home-light-contact.png` is a scroll position, not a route.** The contact block is the home page's bottom section (a same-origin iframe form).
- **Mobile `-full` screenshots stitch viewport slices.** `mobile-*-light-full.png` are stitched from `*.partN.png` tiles in the scratch dir (`~/.design-systems/aboard/raw-shots`, outside the repo); the stitch seams can shift a pixel.

## Do and don't

1. **Do set headlines in Tobias, UI in Work Sans.** Every display headline and row title is Tobias serif (300 or 400, tracked about -2.5%); nav, body, buttons, fields and labels are Work Sans. Never mix them the other way. See [hero-title-default](components/crops/hero-title-default.png) and [nav-link-default](components/crops/nav-link-default.png).
2. **Do pill every control.** Buttons, nav links, email fields and icon buttons are all fully round (999px or 50%); the mobile menu sheet is the only soft panel at 28px, and media thumbnails sit at 10-12px. See [nl-field-default](components/crops/nl-field-default.png) and [nav-cta-default](components/crops/nav-cta-default.png).
3. **Do let bright citrus carry the actions.** `#de4c00` is the only accent: the nav CTA, the footer fill, every submit button and the how-we-work strikethrough. Its hover is either dark-citrus `#c44300` (forms) or near-black `#291503` (nav). See [nl-submit-hover](components/crops/nl-submit-hover.png) and [nav-cta-hover](components/crops/nav-cta-hover.png).
4. **Don't add borders or shadows to text blocks.** Copy sits on the cream or white ground with hairlines only where lists need them (`rgba(6,7,10,0.1)`); the deep `0 40px 80px -48px` lift belongs to case-figure hovers alone. See [case-card-hover](components/crops/case-card-hover.png) and [faq-panel-open-open](components/crops/faq-panel-open-open.png).
5. **Do keep the warm-dark bands inside the light scheme.** Dark sections (the newsletter hero, the podcast tile, the case figures) reuse the same palette: cream text on `#1a110a`/`#0b2050`, translucent cream fields at 8% fill. Don't invent a second theme. See [pod-play-default](components/crops/pod-play-default.png) and [nl-form-default](components/crops/nl-form-default.png).
6. **Do give focus two different rings.** On the cream ground keyboard focus is a 2px warm-black outline offset 2px; on dark bands and submits it's 2px orange-peel offset 3px, and fields swap their border to orange-peel plus a 3px halo. See [nav-link-focus-visible](components/crops/nav-link-focus-visible.png) and [nl-field-focused](components/crops/nl-field-focused.png).

## Rebuild

```bash
python3 tools/build_tokens.py
```

```bash
python3 tools/build_style_guide.py
```

```bash
python3 tools/build_components_md.py
```

`build_tokens.py` reads `raw/component-tokens.json` and writes `tokens.json`; it refuses a value that is not the DTCG type it claims and an alias that points at nothing. `build_style_guide.py` renders `style-guide.html` from `tokens.json` and `tools/style-guide.template.html`, turning every token into a CSS variable so the page cannot drift from the file. `build_components_md.py` writes `components.md` from `raw/components-computed.json`, `raw/layout.json`, `tokens.json`, the screenshots and `icons/INDEX.tsv`. All three are deterministic: re-running them on this commit reproduces their files byte for byte. Edit the raw inputs or the builders, never the generated files.

`tools/capture/` holds the kit the captures came from. The Playwright scripts take `PLAYWRIGHT` as the path to a Playwright install's `index.mjs` when `playwright` is not resolvable from where they run.

```bash
PLAYWRIGHT=/path/to/playwright/index.mjs node tools/capture/public/public.mjs
PLAYWRIGHT=/path/to/playwright/index.mjs node tools/capture/public/measure.mjs home newsletter mobile
```

`public.mjs` re-takes the screenshot set into `~/.design-systems/aboard/raw-shots` (outside the repo); `python3 tools/capture/quantize.py ~/.design-systems/aboard/raw-shots` stores the quantised copies in `screenshots/`. `measure.mjs` takes page names and merges into `raw/components-computed.json`; `node tools/capture/public/build-measurements.mjs` then rewrites `raw/measurements.md`. `vars.mjs`, `layout.mjs` and `icons.mjs` rewrite their raw or icon files whole. `lib.mjs` holds the shared helpers, including the consent-strip hide (it no longer masks `navigator.webdriver`).

## Use in Figma

Import `tokens.json` with Tokens Studio and choose the Light theme. Set display type in Tobias (or the closest light text serif where it is not installed), UI type in Work Sans, round every control to a full pill, and keep `bright-citrus` as the single accent.

## The screen to get right

The home page is the screen to get right. A frosted `#f0f1ef` pill floats the nav: the aboard wordmark, five Work Sans links, and the citrus "Get in Touch" pill. Below, a 77.76px Tobias headline ("Your partner for the big AI leap") sits on the cream ground over a full-width media carousel that slides case-study films under serif captions, with tick pagination and a pause control. Sections alternate warm and white grounds separated by hairlines; feed rows stack kind tag, Tobias row title and date; case cards lift a 12px-radius figure on a deep shadow at hover. The page closes on the bright-citrus footer: the "We Can Help" Tobias heading, the translucent newsletter signup, link columns in off-white, and a giant clipped wordmark. Everything the capture could not reach is listed under Gaps in [components.md](components.md#gaps).

# Luma design reference

A token set and component reference for Luma, the events app for finding, hosting and chatting about events. Use it to build a native iOS app (SwiftUI) for events or communities that borrows its proportions and structure: full-bleed lists on pure black or white, square cover thumbnails with small status pills, a floating iOS 26 glass tab bar and round glass nav buttons, grouped settings cards, one purple accent, and event pages that take their colour from the cover. It was captured from the shipped app on iOS 26 on 2026-10-24, through iPhone Mirroring, signed in to the owner's account. The app version was not recorded. Dark is Luma's Settings > Appearance > Colour Scheme on System with the phone in dark mode; light was set with Colour Scheme > Light and put back to System afterwards. The app icon stayed on Default. The device screen is 390 x 844 pt; the captures are 812 x 1780 px at 2 px per pt, with the screen at (16, 76) inside each PNG.

It holds 66 captures, the same 33 screens in dark and in light: Home and its scrolled header, Picked for You and its pop-up, an event page (top, location, hosts and About, the More menu), Discover (categories, cities, featured calendars), a category page, search (focused, typed, the Date Range sheet, the location pop-up), the Discover map, Notifications, Create Event (three states), a calendar page and its Following menu, Settings, Appearance, Notification settings, Account settings, Edit Profile, the chat list, a chat thread and its composer, and Your Events (Upcoming, Past, the filter menu). Light 02 to 04 sit at a different scroll position from dark. They show the owner's profile (name, handle, email, social handles), their events, chats and notifications. On 2026-11-21, for the public repository, other people's names and photos were painted out of 25 captures: individual event hosts on the event rows, the people who sent invites in Notifications, a person's chat and a name in a chat preview, and a message sender in the event chat, with [tools/redact_images.py](../../tools/redact_images.py) and [its rules](../../tools/redact-rules/luma-ios.json), and the crops re-cut from them. Organisations hosting public events, event covers and the owner's own profile stay. No credentials or other personally identifiable data appear; the one chat preview that leads to an elevator code is cut off before it.

Event pages and the Create Event sheet take their colours from the cover image in both themes. A light-theme event page with a dark cover is as dark as the dark one, and the Create Event sheet was orange in dark and purple in light only because its cover is random. Their tokens (`color.coverExample`) are one cover's readings, kept as evidence, not values to reuse.

This package contains no Luma code, and none of its artwork has been redrawn. The screenshots and the visual system they show are Luma's ([docs/RIGHTS.md](../../docs/RIGHTS.md)). Borrow structure and proportions, not the wordmark, the icons, the app icons or the brand colours.

## Brief

<!-- brief:start. Generated by tools/brief.py from catalog.json, the tokens file and this README; `make brief` rewrites it. Do not edit. -->

Read this before designing in this style. Take every value from [tokens.json](tokens.json), never from the screenshots; `python3 tools/catalog.py export luma-ios` prints them all with aliases resolved.

### Principles

1. Do put lists on the bare page and settings in cards.
2. Do lead every event with its cover.
3. Do let the cover colour the event page.
4. Do say an event's state in a small pill with a faint fill.
5. Do float controls as glass and mark the choice with a darker pill.
6. Don't use the accent for primary actions.

Each rule links the screenshot or crop that shows it, under [Do and don't](#do-and-dont).

## How the values were read

Luma is a native app, so there is no CSS. Each screen was captured as the iPhone Mirroring window alone (`tools/capture/native/shot.sh`: `screencapture -l` on the window, then converted from Display P3 to sRGB). `tools/measure.py` reads the full-colour captures, which stay outside the repo, and writes [raw/readings.json](raw/readings.json): 225 readings under 133 names, most in both themes. `tools/build_tokens.py` maps them to tokens. The committed screenshots are the same captures quantised to 256 colours, so a reading's box can be checked against them, but no value was read from the quantised copies.

| Method in readings.json | Label in tokens.json | What it gives |
|---|---|---|
| `fill`, the box's dominant colour covering 90% or more of it | Sampled | An exact flat surface |
| `fill` under 90% (glass, a two-pixel caret) | Derived | The dominant pixel; the description gives the share |
| `mean`, the average of a small box | Derived | Small tinted fills (badges, pills, the send button, cover tints), where the mirroring stream leaves a few levels of noise so no one pixel dominates; the description gives the channel spread |
| `text`, the anti-aliased pixel furthest from the fill | Sampled (text) | A glyph colour; the true value is the same or slightly further from the fill |
| `bbox`, `extent`, `find` | Sampled | Sizes and positions exact to the pixel (half a point) |
| `diag`, the inset along a corner's diagonal | Derived | A corner radius, plus or minus 2 pt |
| `cap`, a capital's ink height less a pixel of anti-aliasing, at a 0.72 em cap height | Derived | A font size, plus or minus 1 pt |
| `lines`, the pitch of text bands | Derived | A line height |
| By eye | Derived | Font weights, border widths |
| Not determinable | Not captured | The font family |

`mean` is new in this package's copy of the kit, and so is a reading table entry that takes a different box per theme (the selected Colour Scheme card is System in dark and Light in light). The scrim behind the Date Range sheet is Derived as black at an alpha from the search field's grey with and without the sheet: 0.66 in dark and 0.24 in light, from one sheet each. Scale steps (spacing, the 26 pt card radius, the 12 pt control radius) are Derived from the readings named in each token's description. Glass in light is almost the page colour, so control sizes (tab bar, nav buttons, search field, chips, segmented control, composer) were read in dark only.

## What to distrust

- **The cover tint.** Event pages and the Create Event sheet take their background, the Contact and More tiles, the fields and even the switch's off track from the cover image. `color.coverExample` and `color.switch.off` hold one cover's readings: the TEDxSingapore page (#45474A dark, #373B42 light) and a random orange (dark) and purple (light) Create Event cover. Do not reuse them as fixed colours. Register on the event page is white in both themes, not the theme's ink.
- **The font.** Not determinable from pixels. The face is a neo-grotesque close to the iOS system face. `fontFamily.base` is `system`, Not captured.
- **Glass.** The tab bar, nav buttons, search field, filter chips, segmented control, composer, menus and the Date Range sheet are iOS 26 glass. Their tokens are readings over an empty page (`surface.glass`) or over whatever is behind (`surface.menu`, `surface.sheet`). Use the system material, not a flat fill. In light the glass is within a few levels of white, so its edges barely show.
- **Small fills are averages.** Badge, pill and send-button fills are `mean` readings of a few dozen pixels; the stream noise is two to five levels per channel.
- **Radii are estimates**, plus or minus 2 pt: cards and the banner 25.6, the Bio area 23.9, the Register tile and the Create Event group 11.9 (the group over the cover tint), thumbnails and calendar tiles 8.5, Settings icon tiles 5.1 to 6.8.
- **Type sizes are estimates**, plus or minus 1 pt, from cap heights at an assumed 0.72 em. The host line reads 12 pt and could be 13; weights are judged by eye. Only multi-line blocks have line heights.
- **Several reds and blues.** Sold Out reads #FD766B in dark, Delete Account #FF786D and the Unfollow menu item #FF575B; the unread count and dot are #FA534F. The 'Open Settings' link (#0D90FE dark) is not the Waitlist blue (#78ACFF) or the send button (#0563F1). `color.danger.fg` and `color.text.link` name the others in their descriptions.
- **Grey text in light is light.** `color.text.tertiary` (#A09FA1) on white is about 2.6:1, below 4.5:1. It is the product's own value for weekdays, section headers and dates.
- **The caret.** It reads #5A5A5A in dark and #151515 in light over a two-pixel column, so the dark value is the white ink anti-aliased, not a grey.
- **No pressed states, no motion, no keyboard, no loading.** The captures are stills made with clicks; iPhone Mirroring hides the software keyboard; the chat list loaded before its capture.
- **Screenshots are 256-colour PNGs.** Flat UI colours survive exactly; glass, photos and the cover tints band slightly. Read values from tokens.json.

## Do and don't

1. **Do put lists on the bare page and settings in cards.** Home, Discover, search, Chat and Your Events are full-bleed rows on `color.bg.page`, pure black or white; Settings and its pages are rows in rounded cards on `color.bg.grouped`. See [01-home](screenshots/dark/01-home-your-events-calendars.png), [23-settings](screenshots/dark/23-settings-root-grouped-rows.png) and [23-settings light](screenshots/light/23-settings-root-grouped-rows.png).
2. **Do lead every event with its cover.** Rows open with an 80 pt square cover, calendars with a square tile and cities with a photo card; the text is grey meta around one white title. See [31-your-events](screenshots/dark/31-your-events-segmented-upcoming-soldout-badge.png), [10-discover](screenshots/dark/10-discover-cities-featured-calendars.png) and [01-home light](screenshots/light/01-home-your-events-calendars.png).
3. **Do let the cover colour the event page.** The event page and the Create Event sheet take their background, buttons and fields from the cover in both themes; the rest of the app stays neutral. See [05-event-page](screenshots/dark/05-event-page-cover-tinted-actions.png), [18-create-event](screenshots/dark/18-create-event-form-cover-tinted.png) and [18-create-event light](screenshots/light/18-create-event-form-cover-tinted.png).
4. **Do say an event's state in a small pill with a faint fill.** Prices are green, Sold Out red, Near Capacity amber and Waitlist Open blue, each label on a wash of its own colour; Invited is a purple badge on the cover. See [31-your-events](screenshots/dark/31-your-events-segmented-upcoming-soldout-badge.png), [11-category](screenshots/dark/11-category-page-subscribe-badges.png) and [13-search-typed light](screenshots/light/13-search-typed-results-waitlist-badge.png).
5. **Do float controls as glass and mark the choice with a darker pill.** The tab bar, nav buttons, chips, the segmented control and the composer are glass; the selected tab or segment sits in a darker pill with an ink label. See [28-chat-list](screenshots/dark/28-chat-list-unread-dot.png), [32-your-events-past](screenshots/dark/32-your-events-segmented-past.png) and [32-your-events-past light](screenshots/light/32-your-events-segmented-past.png).
6. **Don't use the accent for primary actions.** Confirm and the enabled Create Event check are the theme's ink; purple appears on Invited badges and Subscribe, and blue only on links and the send button. See [14-date-range](screenshots/dark/14-date-range-sheet-calendar-confirm.png), [14-date-range light](screenshots/light/14-date-range-sheet-calendar-confirm.png) and [20-create-event](screenshots/dark/20-create-event-name-typed-confirm-enabled.png).

## Rebuild

From this folder. `measure.py` needs the full-colour captures, which live outside the repo in `~/.design-systems/luma-ios/raw-shots/`; the other builders run from the committed files.

```bash
python3 tools/measure.py ~/.design-systems/luma-ios/raw-shots
python3 tools/build_tokens.py
python3 tools/build_style_guide.py
python3 tools/build_components_md.py
python3 -m unittest discover -s tools
git status --short .
```

`tools/capture/quantize.py <raw-shots>` and `tools/crops.py` (both need Pillow) rewrite `screenshots/` and `components/crops/`. After a re-quantise, run `python3 tools/redact_images.py apply systems/luma-ios --rules tools/redact-rules/luma-ios.json` from the repository root (it keeps each image's palette and transparency and every pixel outside the boxes) before `tools/crops.py`, so the names stay masked. A rebuild that changes nothing proves the outputs still match their inputs. From the repository root, `make design-md` regenerates DESIGN.md and the Brief.

## Use in SwiftUI and Figma

A colour asset per semantic key, with a light and a dark variant, maps one to one: the key names (`color.surface.card`) are the contract, and both sets have the same keys. Sizes and radii in `core` are points. Use the system components for the glass tab bar, nav buttons, menus, sheets, the segmented control, switches and pop-up selects rather than redrawing them; give grouped cards the 26 pt continuous corner. For event pages, derive the tint from the cover image (an average or dominant colour, darkened for white text) rather than reading `color.coverExample`. In Figma, import tokens.json with Tokens Studio and pick the Light or Dark theme.

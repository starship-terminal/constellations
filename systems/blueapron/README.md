# Blue Apron design reference

A token set and component reference for Blue Apron's public editorial surface — for building recipe/editorial pages in the style of the real thing. It was read from **blog.blueapron.com** ("Extra Helpings") on **2026-11-21**, signed out, in headless Chromium at 1440 x 900 and 390 x 844: the blog home, the Recipes category list, a guide article, the membership/Autoship FAQ and the empty cart. The same day, https://www.blueapron.com/ returned a Cloudflare block in the T3 preview and from curl, so the shop is still a recorded gap.

Blue Apron is worth a capture because its new (Wonder-era) editorial surface is a clean study in one blue on cream: a `#002856` navy promo strip over a `#f2f0e5` field, the navy wordmark, a `#2959e0` pill CTA that recurs as every button, blue Ovo serif headlines over Almarai body text, and a masonry guide grid with no card chrome. **Boundary:** www.blueapron.com itself (the shop, menu, sign-in and checkout) hard-blocks this client at the Cloudflare edge — 403 "Sorry, you have been blocked" on every route including robots.txt, reproduced with curl, headless Chromium, headed Chromium and real Chrome; the egress IP is non-US and the shop is US-only. The blog host (Squarespace) does not block, so it is the whole capturable surface; everything on www is a recorded gap, never inferred.

## Brief

<!-- brief:start. Generated by tools/brief.py from catalog.json, the tokens file and this README; `make brief` rewrites it. Do not edit. -->

Read this before designing in this style. Take every value from [tokens.json](tokens.json), never from the screenshots; `python3 tools/catalog.py export blueapron` prints them all with aliases resolved.

### Principles

1. Do put the blue on cream.
2. Do pill every button.
3. Do pair navy with cream.
4. Do set headlines in blue serif.
5. Don't invent a second accent.
6. Don't add card chrome.
7. Don't style the shop from this package.
8. Don't ship a dark theme.

Each rule links the screenshot or crop that shows it, under [Do and don't](#do-and-dont).

## How the values were read

Every value came off the running signed-out site in headless Chromium:

- **Tokens.** [tools/capture/vars.mjs](tools/capture/vars.mjs) captures every stylesheet body (linked Squarespace sheets from network responses plus inline `<style>` blocks re-parsed with `CSSStyleSheet`) and writes every custom property to [raw/css-vars.json](raw/css-vars.json), resolved in a probe document at 1440 x 900. blog.blueapron.com declares a real token layer — palette accents, the `--heading-*` ramp, the font vars — so palette and ramp tokens resolve declared names; everything else is a **measured computed value**. [tools/build_component_tokens.py](tools/build_component_tokens.py) writes the spec, [tools/build_tokens.py](tools/build_tokens.py) the sets.
- **Components.** [tools/capture/public/measure.mjs](tools/capture/public/measure.mjs) opens each route in a fresh context and reads `getComputedStyle`, painted layers and boxes per element in default, hover, focus-visible and a CDP-forced pressed state, plus `focused`/`filled` on the search field and `opened` on the comments toggle and the mobile menu. Results in [raw/components-computed.json](raw/components-computed.json) and [raw/measurements.md](raw/measurements.md).
- **Screenshots.** [tools/capture/public/public.mjs](tools/capture/public/public.mjs) takes viewport and full-page shots per route with `.capture.json` sidecars; [tools/capture/quantize.py](tools/capture/quantize.py) posterises them to 256 colours.

Nothing was signed into, bought or submitted: the search field was filled with sample text and deleted, never run; the cart was captured empty; every CTA was measured, never followed. The cookie banner is disabled sitewide, so there was no consent UI to handle; a promo popup would be hidden, never answered.

## What to distrust

- **Readings past a masked bot signal.** The committed screenshots and readings were taken with `navigator.webdriver` masked, the flag bot checks read to spot automation. The capture scripts no longer mask it (not run since), so a recapture may record a walled route as a boundary instead of a reading.
- **www.blueapron.com is not in this package.** The shop front end blocks this client at the edge; every value here is the blog's. The blog is genuinely Blue Apron-branded (same palette and logo, links to the shop) but its components are Squarespace's, not the shop's.
- **One theme only.** The site paints light everywhere; the navy footer is a section style. `tokens.json` ships no dark set. Ten section palettes are declared in raw/css-vars.json for the record.
- **Squarespace vars are scoped.** The resolved values in css-vars.json are the `:root` (light) readings; section-theme vars (`data-section-theme`) are harvested per selector but resolve in their own scopes — the footer's navy was measured, not resolved.
- **Quantised screenshots.** `screenshots/` are 256-colour PNGs; read exact colours from tokens or the raw files.
- **The opened menu crop is the toggle.** `m-menu-open` still frames the burger button, not the overlay. The overlay itself is [mobile-home-light-menu](screenshots/mobile-home-light-menu.png). `comments-open` was not mounted on the sampled article. The filled search field was typed with "dinner ideas" and deleted, never submitted.

## Fonts

**Ovo** is the display serif — headlines, card titles, article titles — configured in the site's heading vars. **Ivory** is a self-hosted serif that custom.css's `@font-face` puts on h1–h4 in body content. **Almarai** is the body/nav face. All are served from the Squarespace CDN; none is distributed with the package — the style guide falls back to Georgia/system.

## Do and don't

1. **Do put the blue on cream.** The page field is `#f2f0e5` cream, never white; the one action blue `#2959e0` carries CTAs, links and headline accents. See [home-light-default](screenshots/home-light-default.png).
2. **Do pill every button.** Every button is a 300px-radius pill ~65px tall; the same shape serves primary (blue fill), secondary (blue border, transparent fill) and the header CTA. See [button-secondary](components/crops/button-secondary-default.png).
3. **Do pair navy with cream.** The navy `#002856` lives only in the announcement strip and the footer section; everything between stays cream. See [footer](components/crops/footer-default.png).
4. **Do set headlines in blue serif.** Card and article titles paint the action blue in Ovo at 37–68px, centred, on cream. See [article-title](components/crops/article-title-default.png).
5. **Don't invent a second accent.** Links, the read-more, category links, card titles and buttons all share the one blue; there is no hover recolour — the secondary button just fills.
6. **Don't add card chrome.** Blog cards have no fill, border or shadow — the photo, blue title and meta row sit straight on cream.
7. **Don't style the shop from this package.** Every value is the Squarespace blog's; www.blueapron.com is edge-blocked and uncaptured — treat the shop's own design system as unknown.
8. **Don't ship a dark theme.** None is offered; the navy footer is a section style, not a theme.

## Rebuild

Everything derived regenerates offline from the raw readings (run from `systems/blueapron/`):

```sh
python3 tools/build_component_tokens.py        # raw/components-computed.json -> raw/component-tokens.json
python3 tools/build_tokens.py                  # -> tokens.json
python3 tools/build_style_guide.py             # -> style-guide.html
python3 tools/build_components_md.py           # -> components.md
node tools/capture/public/build-measurements.mjs  # -> raw/measurements.md
python3 tools/capture/quantize.py <raw-dir>    # full-colour PNGs -> screenshots/
```

Then `make brief && make design-md && make grade && make check` from the repo root refreshes the generated sections and validates the catalog.

Live recapture (needs the site; Playwright at `PLAYWRIGHT=~/.design-systems/pw/node_modules/playwright/index.mjs`):

```sh
node tools/capture/vars.mjs                    # stylesheet harvest -> raw/css-vars.json
node tools/capture/public/measure.mjs          # computed styles + crops -> raw/components-computed.json

```

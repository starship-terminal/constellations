## Brief

<!-- brief:start. Generated by tools/brief.py from catalog.json, the tokens file and this README; `make brief` rewrites it. Do not edit. -->

Read this before designing in this style. Take every value from [tokens.json](tokens.json), never from the screenshots; `python3 tools/catalog.py export polaris` prints them all with aliases resolved.

### Principles

1. Do keep the interface neutral and spend color on status.
2. Do give each decision one dark primary button.
3. Do keep critical red for destructive actions.
4. Do pair every badge tone with words.
5. Don't fake states with opacity.
6. Do put icons inside full-size buttons.

Each rule links the screenshot or crop that shows it, under [Do and don't](#do-and-dont).

## What to distrust

- **Two package versions.** The component rules, sizes and layout values are read from the archive source (React 13.10.1); the gallery and every image run the published 13.9.5. Only the spot checks listed under Sizing and focus ring compare the two, and they matched.
- **Hover was never shot.** It is read from CSS only. [components.md](components.md) names hover tokens only for the button, tab and tag-remove fills that focus also moves to; for text fields, selects, checkboxes and the rest it says hover has its own tokens without naming them.
- **States and tones not rendered.** Select and text area show only default and focus-visible (no error or disabled), radio has no disabled state, tabs have no disabled tab, and badges show seven tones: the `-strong` tones, `magic`, `read-only` and `enabled` exist in the CSS but are in no image. The range slider's focus ring sits on a pseudo-element computed style cannot read, so only its crop shows it.
- **Themes.** `light-mobile` and `light-high-contrast-experimental` are tokens only, never rendered. `dark-experimental` is marked experimental in the archive and is broken in places: typed text on inputs is 1.26:1 and the critical tokens do not change (see Theme coverage).
- **The scrim token is unused.** `color-backdrop-bg` (71% black) is a token, but the backdrop component draws a literal `rgba(0, 0, 0, 0.5)` (see Background roles).
- **The phone app shell is narrower than the phone.** At 390 px the shell specimen is a box about 316 px wide, and in [phone/14-app-shell](screenshots/phone/14-app-shell.png) the top bar's search field runs past its right edge. [phone/14-app-shell-nav-open](screenshots/phone/14-app-shell-nav-open.png) is a 316 by 621 px crop of that box showing only the navigation list: no top bar, page or backdrop.
- **The guide's own chrome is not Polaris.** Besides the sidebar and green panel, [01-overview](screenshots/01-overview.png) says "13 guide sections" (there have been 15 since App shell and States were added), and in full-page shots taller than 900 px the sidebar's grey background stops at 900 px.
- **The token parity file is thin.** [raw/token-parity.json](raw/token-parity.json) holds only the comparison's name and an empty list of differences, with no count of values compared, and no script in `tools/` writes it. The check you can rerun is in `tools/build.mjs`: the build stops if any colour alias does not equal the published value it replaces.
- **Some redraws disagree with the readings.** [textfield-focus.svg](components/textfield-focus.svg) draws a 1 px ring 3 px out and keeps the resting border and fill; the measured focus is a 2 px ring 1 px out, with the border turning `#1A1A1A` and the fill `#F7F7F7`. [card.svg](components/card.svg) has a 1 px `#DEDEDE` border, a colour no light token holds; the real Card has no border and uses `shadow-100` plus a bevel.
- **The board preview is mislabelled.** [previews/components-board.png](previews/components-board.png) is JPEG data under a `.png` name, and no script rebuilds it, so it can fall behind `boards/components-01.svg`.

## Fonts

The UI sans stack is **Inter**, -apple-system, BlinkMacSystemFont, San Francisco, Segoe UI, Roboto, Helvetica Neue, sans-serif. Code uses **ui-monospace**, SFMono-Regular, SF Mono, Consolas, Liberation Mono, Menlo, monospace. These are two role-based stacks, not a claim that all fallback fonts render simultaneously.

The four weight tokens are regular **450**, medium **550**, semibold **650**, bold **700**. Use variable Inter to preserve intermediate weights. The local preview font comes from Fontsource Variable Inter 5.2.8; the archived documentation sources Inter via inter-ui, so glyph versions can differ. Install the included Inter TTF for editable text imports or substitute your matching Inter version.

## Do and don't

1. **Do keep the interface neutral and spend color on status.** The canvas, surfaces, secondary buttons, selected tabs and pressed buttons are white and greys; the primary button and checked checkboxes, radios and the slider use the dark brand fill `#303030`. Hue goes to status (badges, banners, the critical and success buttons, the invalid field) and to links. See [05-buttons](screenshots/05-buttons.png), [07-forms](screenshots/07-forms.png), [08-feedback](screenshots/08-feedback.png) and [09-navigation](screenshots/09-navigation.png).
2. **Do give each decision one dark primary button.** The modal pairs a dark "Archive product" with a white, bordered "Cancel", and the empty state has a single dark "Add product". Other actions stay secondary (white with a border), tertiary (text only) or plain (blue link text). See [14-modal-open](screenshots/14-modal-open.png), [11-data](screenshots/11-data.png) and [05-buttons](screenshots/05-buttons.png).
3. **Do keep critical red for destructive actions.** "Delete product" is a filled red button and "Remove" a white button with red text. In the action menu only "Delete" is red; "Duplicate" and "Archive" stay neutral. See [05-buttons](screenshots/05-buttons.png) and [15-popover-open](screenshots/15-popover-open.png).
4. **Do pair every badge tone with words.** Badges communicate status and are not buttons: they are flat tinted chips with no border or shadow, unlike the bordered, bevelled buttons. Each tone carries a label ("Paid", "Overdue", "Unfulfilled"), and progress badges add an empty, partial or filled pip, so color is never the only signal. See [06-badges-tags](screenshots/06-badges-tags.png) and [01-overview](screenshots/01-overview.png).
5. **Don't fake states with opacity.** Hover, active, selected and disabled each have their own tokens. The disabled secondary button drops its border and bevel and turns pale grey with grey text, the disabled primary turns light grey with white text rather than a faded dark button, and pressed "Selected" and the selected "Day" segment take a darker grey fill. The disabled field loses its border and takes a grey fill. See [05-buttons](screenshots/05-buttons.png), [07-forms](screenshots/07-forms.png) and [02-colors](screenshots/02-colors.png).
6. **Do put icons inside full-size buttons.** A leading icon sits left of the label ("Add product", "Open") and the disclosure chevron sits right ("More actions"). The icon-only search button and the pagination arrows keep the same height as the text buttons, with their own border or fill around the icon, so icon size never stands in for the pointer or touch target. See [05-buttons](screenshots/05-buttons.png) and [09-navigation](screenshots/09-navigation.png).

## Rebuild

From the repository root, run `make dev` and open Polaris from the catalog. Or, from this directory, run `python3 -m http.server 8768 --bind 127.0.0.1` and open http://127.0.0.1:8768/style-guide.html. The page fetches its data, so opening it straight from disk does not work. `-m` runs Python's HTTP server module; `8768` is the port; `--bind 127.0.0.1` restricts access to this computer.

For changes, from `tools/`: `npm ci --ignore-scripts --no-audit --no-fund`, then `npm run build`. The flags disable package lifecycle scripts, security audit network requests, and funding notices respectively. The committed lockfile pins the dependencies. Existing bundled assets work without installing Node dependencies. `build.mjs` copies `icons/` and the two Shopify licences only when given a checkout of the archive, as `npm run build -- <path to checkout>` or `POLARIS_SOURCE=<path>`; without one they stay as committed. `node tools/screenshots.mjs` re-shoots `screenshots/` and rewrites `raw/focus-states.json` (it needs Playwright, which is not in the lockfile). `python3 tools/build_vectors.py` regenerates SVG references; it needs Pillow, fontTools and Brotli. The font conversion produces a convenience desktop TTF from the included variable WOFF2 under the same OFL license.

## Color

Use semantic tokens rather than choosing raw RGB values by appearance. Surface tokens are large containers, fill tokens are controls and compact status areas, text/icon tokens pair with their intended backgrounds, and border tokens separate regions.

The light canvas is `color-bg` (`#F1F1F1`), primary surface is `color-bg-surface` (`#FFFFFF`), primary text is `color-text` (`#303030`). The catalog retains original RGBA strings and transparent colors. Critical, warning, caution, info, success and magic have separate families. Badge attention uses caution tokens.

### Background roles

### Primitive ramps

[tokens.json](tokens.json) has a `core` set with the 14 primitive ramps the tokens package builds its themes from: `gray`, `azure`, `blue`, `teal`, `green`, `lime`, `yellow`, `orange`, `red`, `rose`, `magenta`, `purple`, plus `blackAlpha` and `whiteAlpha`. Each has 16 steps, `1` lightest to `16` darkest (`gray.1` is `#FFFFFF`, `gray.16` is `#1A1A1A`; `blackAlpha` runs from 0% to 90% black and `whiteAlpha` from 1% to 80% white). The package ships them in `dist/cjs/src/colors.js` but does not export them from its index; `tools/build.mjs` reads that file and also writes it unchanged to `raw/polaris-colors.raw.json`.

Every semantic colour in the four theme sets that names a ramp step is now an alias to it (`light.color.color-bg` is `{color.gray.6}`): 894 of 904 theme colours. The builder rebuilds the themes from source with each step replaced by a marker to find the step, then checks the alias resolves to the published value; all 1,812 theme tokens resolve to exactly the values they had before. The other 10 are `color-scheme` and `color-button-gradient-bg-fill` in each of the four sets (the gradient is `none` in `light-mobile`), and the two `dark-experimental` tooltip-tail borders, which are literal in the source. Ramp use across the four themes: gray 327 roles, blue 92, azure, green, red and purple 64 each, blackAlpha 62, yellow and orange 56 each, whiteAlpha 13, rose, magenta, lime and teal 8 each.

Every color is searchable on the Colors page. `raw/polaris-themes.raw.json` preserves all values grouped by theme and type; `raw/polaris-metadata.json` preserves source metadata. `tokens/light.css` provides `--p-*` custom properties. At a 16px root, all displayed rem-to-pixel conversions are arithmetic conversions, not a recommendation to hard-code pixels.

## Radius, border and layout

Radius scale: **0, 2, 4, 6, 8, 12, 16, 20, 30px**, plus a full radius token of 9999px. Medium buttons, badges, tags and inputs commonly use 8px. Card uses 12px from the small breakpoint upward; below it, the Card radius is zero. Desktop modal uses 16px. Keep component-specific rules rather than applying one radius everywhere.

Border widths include **0, 0.66, 1, 2, 4px**. Thin controls can use subpixel borders. Focus outlines typically use 2px with a 1px offset. Spacing tokens and width/height tokens are separate namespaces even when their values match. The Geometry page exposes the entire scale, shadows, motion, breakpoints and layering tokens.

Breakpoints: xs 0, sm 490, md 768, lg 1040, xl 1440px. Use these for responsive layout; component rules may use breakpoint-down mixins as well as min-width changes. Narrow-screen input type is larger than desktop type. Do not shrink touch controls to match desktop screenshots.

## Motion

Durations run 0 to 500ms in 50ms steps, plus `motion-duration-5000`. Easings: `motion-ease` `cubic-bezier(0.25, 0.1, 0.25, 1)` for most transitions, `motion-ease-in`, `motion-ease-out` `cubic-bezier(0.19, 0.91, 0.38, 1)`, `motion-ease-in-out` and `motion-linear`.

| Component | Motion | Duration | Easing |
|---|---|---|---|
| Popover | fade and 5px rise | `motion-duration-100` | `motion-ease` |
| Tooltip | fade and 4px rise, after a 100ms delay | `motion-duration-50` | `motion-ease-out` |
| Modal | fade and 200px rise | `motion-duration-200` | `motion-ease` |
| Toast | 150px rise and fade | `motion-duration-400` | `motion-ease-out` |
| Sheet, navigation drawer | slide | `motion-duration-300` | `motion-ease`, `motion-ease-out` |

## Import into Figma, Paper or similar

Import a board from [boards/](boards) or individual SVGs from [components/](components); original icon vectors live in [icons/](icons). Importers vary in text, clipping and font handling. Install Inter before importing. SVGs contain ordinary paths/rectangles/text, with no HTML foreignObject dependency. They are editable references, not native auto-layout components, variants or linked instances. Native Paper/Figma import was not exercised in this environment.

For Tokens Studio, import [tokens.json](tokens.json) as token sets, enable `light` and keep `core` enabled as a source: theme colours are aliases into the `core` ramps. Dimension values stay in source rem units. Complex shadows, motion strings and other unsupported values retain the `other` type rather than a misleading conversion. Use raw JSON/CSS for lossless source values. To create a production design library, map semantic tokens to your tool's variables and turn the imported redraws into native components with constraints and variants.

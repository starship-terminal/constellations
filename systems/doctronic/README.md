# Doctronic design reference

A token set and component reference for Doctronic's public signed-out surface — for building pages and chat-adjacent UI in the style of the real thing. It was read from **doctronic.ai** (canonical `www.doctronic.ai`) on **2026-11-13**, signed out, in headless Chromium at 1440 x 900 and 390 x 844. Captured: home, `/chat/` (collapsed and expanded rail, filled composer), the `?modal=signin` card, the symptom checker, the resource center, blog, telehealth, urology, our-philosophy, authors, careers, online-treatment, prescription-glp-1, Wall of Love, about, privacy-policy, the partnerships article, plus a 390px pass on home, chat, symptom checker and blog. The app surfaces were captured in both `light` and the site's real user-selectable `dark` theme (`localStorage.theme` → `data-theme`).

Doctronic is worth a capture because it pairs a paper-and-ink warmth no health-tech competitor uses with a rigorous token layer: a `#fdfdf7` warm canvas under `#1b1b18` ink, Fraunces display headings with *dashed* underlines (the same dashed hairline that divides the menu drawer), one `#2463eb` blue spent only on actions with a signature `rgba(36,99,235,.39)` brand-glow shadow, a lime `#beec4b` reserved for prompt tabs and tag pills, and a real eleven-step ramp set (neutral/blue/sage/lime/success/warning/error) redeclared for dark. Buttons are uniformly `span.content` pills — 32px radius for the bar family, 52px for the accent family — never plain elements. **Boundary:** the signed-in product (chat threads, health record, prescriptions, appointments), every submit action (Start chat, Send, Check My Symptoms, the starter chips) and every auth path (Log in, Sign up, OAuth, Create an account) were measured or photographed but never used.

## Brief

<!-- brief:start. Generated by tools/brief.py from catalog.json, the tokens file and this README; `make brief` rewrites it. Do not edit. -->

Read this before designing in this style. Take every value from [tokens.json](tokens.json), never from the screenshots; `python3 tools/catalog.py export doctronic` prints them all with aliases resolved.

### Principles

1. Do spend the blue on actions only.
2. Do glow the accent.
3. Do keep the two pill sizes.
4. Do use the lime sparingly.
5. Do draw hairlines dashed.
6. Do set display type in Fraunces.
7. Don't design the signed-in product from this package.
8. Don't paint the content pages dark from memory.

Each rule links the screenshot or crop that shows it, under [Do and don't](#do-and-dont).

## How the values were read

`tools/capture/public/public.mjs` is the screenshot pass: it loads each public route in headless Chromium (desktop 1440 x 900 at 1x, phone 390 x 844 at 2x, `localStorage.theme` set by an init script before navigation), hides the cookie/consent layers and the reCAPTCHA badge without ever answering them, and shoots default and toggled states plus bounded full pages (the eight-chunk cap is a documented boundary; home is ~6767px and Wall of Love ~8841px). Full-colour PNGs stay in the scratch dir `~/.design-systems/doctronic/raw-shots`; `tools/capture/quantize.py` stores the committed 256-colour copies in `screenshots/` and stitches `*.partN.png` tiles. `tools/capture/vars.mjs` harvests every custom property from the Next.js CSS chunks and inline styles, then resolves each name in a probe document carrying the real sheets once per theme — `data-theme="light"` and `data-theme="dark"`, the site's own mechanism. `tools/capture/public/measure.mjs` reads computed styles of each component and state (real hover, real keyboard focus, CDP-forced `:active`, typed-and-deleted text fields, the drawer's and rail's own toggles) into `raw/components-computed.json`, crops each to `components/crops/`, and `tools/capture/public/build-measurements.mjs` renders the tables in `raw/measurements.md`. `tools/build_component_tokens.py` writes the token spec from the harvest plus the readings, `tools/build_tokens.py` emits `tokens.json` (aliases kept, per-theme resolution, `$extensions.source` on every leaf), `tools/build_style_guide.py` renders `style-guide.html`, and `tools/build_components_md.py` renders `components.md`.

Nothing was signed into, created, submitted or sent. Send/Start chat, Check My Symptoms, the starter chips, Sign up/Log in/OAuth/Create-an-account and every external link were measured, never used.

## What to distrust

- **Seven entries measured the wrong element.** The capture's `.or()` fallbacks are unions resolved in DOM order, so an earlier node won: `nav-link` is the highlighted "New chat" row (the same node as `nav-link-current`), `input-card` the transparent wrapper, `chat-hero` the whole `main`, `logo` the 620 x 25 wrapper, `feature-card` the testimonial (the same card as `quote-card`), `signin-dialog` the transparent inner section, and `menu-item` the expandable "About Chat" row (the same node as `menu-item-expand`). components.md flags each; `light.component.dialog.width` (393px) is the inner section's width and says so. The input-card and dialog radius tokens read the painted `form` and `div.modal` layers and are unaffected. The script now prefers the intended node by `count()` (not re-run). Recapture needed.
- **Dark screenshots were requested, not checked.** The dark pass sets `localStorage.theme`; the committed shots were never checked for what painted. The script now skips a shot whose page ground does not match the requested theme (not re-run).
- **Automation was masked during capture.** Until 2026-11-20, `tools/capture/public/lib.mjs` hid `navigator.webdriver` in every page it opened, so every committed reading was taken with that mask. The mask is removed (a bot check is now recorded as a boundary, not bypassed); whether any page needed it to load is not known, and a recapture without it is the check.

## Do and don't

1. **Do spend the blue on actions only.** `#2463eb` (`accent.bg`) is Start chat, Send, Check My Symptoms, Log in with email, links and the highlighted nav row — never a background or a heading colour. See [start-chat-button](components/crops/start-chat-button-default.png) and [nav-link-current](components/crops/nav-link-current-default.png).
2. **Do glow the accent.** Every blue pill carries the brand-glow `rgba(36,99,235,.39) 0 4px 7px` under it; the near-black solid pills carry none. See [email-login-button](components/crops/email-login-button-default.png) and [signup-button](components/crops/signup-button-default.png).
3. **Do keep the two pill sizes.** The button family is `span.content` pills: 32px radius for bar/sidebar controls and secondaries, 52px for the accent submit family — chips and menu rows take 8px. See [send-button](components/crops/send-button-default.png) and [oauth-button](components/crops/oauth-button-default.png).
4. **Do use the lime sparingly.** `#beec4b`-family lime marks intent — the `What brings you in?` prompt tab and article tag pills — never buttons or links. See [brings-pill](components/crops/brings-pill-default.png).
5. **Do draw hairlines dashed.** Dividers and the headline underline are 1px *dashed* at 8% ink; solid borders live on cards only. See [menu-drawer](components/crops/menu-drawer-default.png) and [hero-title](components/crops/hero-title-default.png).
6. **Do set display type in Fraunces.** Headlines, dialog titles and author names are Fraunces at 400; UI text is Geist `label*`/`heading*` composites with negative tracking; body copy is the system stack. See [hero-title](components/crops/hero-title-default.png) and [signin-dialog](components/crops/signin-dialog-default.png).
7. **Don't design the signed-in product from this package.** Chat threads, health record, prescriptions and appointments are uncaptured; the sign-in card is evidence of the card, not the app behind it. See [chat-signin-light-signin](screenshots/chat-signin-light-signin.png).
8. **Don't paint the content pages dark from memory.** The Tailwind pages carry literal utilities; `data-theme="dark"` repaints only the token-driven app surfaces. See [d-input-card](components/crops/d-input-card-default.png) and [home-dark-default](screenshots/home-dark-default.png).

## Rebuild

Everything derived regenerates offline from the raw readings (run from `systems/doctronic/`):

```sh
python3 tools/build_component_tokens.py        # raw/components-computed.json -> raw/component-tokens.json
python3 tools/build_tokens.py                  # -> tokens.json
python3 tools/build_style_guide.py             # -> style-guide.html
python3 tools/build_components_md.py           # -> components.md
node tools/capture/public/build-measurements.mjs  # -> raw/measurements.md
python3 tools/capture/quantize.py <raw-dir>    # full-colour PNGs -> screenshots/
```

Then `make brief && make design-md && make grade && make check` from the repo root refreshes the generated sections and validates the catalog.

Live recapture (needs the site; Playwright at `PLAYWRIGHT=~/.design-systems/pw/node_modules/playwright/index.mjs`):

```sh
node tools/capture/vars.mjs                    # stylesheet harvest -> raw/css-vars.json
node tools/capture/public/measure.mjs          # computed styles + crops -> raw/components-computed.json
RAW=<scratch> node tools/capture/public/public.mjs   # screenshots -> <scratch> (incl. the drawer/rail/composer/modal states)
```

www.doctronic.ai loads headless from this client; each route gets its own context and `localStorage.theme` is set before navigation. The cookie/consent layers are hidden per capture, never answered. Everything behind the sign-in card stays uncaptured.

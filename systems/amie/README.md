# Amie design reference

A token set and component reference for Amie's public site — for building AI-product marketing and pricing surfaces in the style of the real thing. It was read from **amie.so** on **2026-11-11**, signed out, in headless Chromium at 1440 x 900 and 390 x 844: the home (with the Features flyout), pricing (billing toggle + FAQ), changelog, blog, stories, calendar, tools, templates, download and contact.

Amie is worth a capture because it is a current reference for a soft, colorful productivity-marketing surface: a cream #fafafa ground, a single action blue (`--color-blue-500` #11a8ff) against a red brand accent (`--color-accent` #fd2b38), full Tailwind `--color-*` ramps shipped as RGB triplets, rounded-12px CTAs, a floating 59px nav bar, and the product's own layout metrics (`--nav-width`, `--inbox-width`, calendar `--grid-*`) declared in the same bundle.

8. Don't shrink the FAQ rows.

## How the values were read

Every value came off the running signed-out site in headless Chromium:

- **Tokens.** [tools/capture/vars.mjs](tools/capture/vars.mjs) captured every stylesheet body from the network responses, re-parsed them with `CSSStyleSheet`, and wrote every custom property to [raw/css-vars.json](raw/css-vars.json) binned `app`/`theme`/`vendor`/`utility`/`tailwind`. The `--color-*` ramps are RGB triplets (`"253,43,56"`) for Tailwind's `<alpha-value>` utilities — [tools/build_tokens.py](tools/build_tokens.py) converts them to hex. Each name is resolved in a probe carrying the real sheets, light and with a `dark` class (only `--foreground` and the two wysiwyg shadows re-declare). [tools/build_component_tokens.py](tools/build_component_tokens.py) writes the spec.
- **Components.** [tools/capture/public/measure.mjs](tools/capture/public/measure.mjs) opens each route in a fresh context and reads `getComputedStyle`, painted layers and boxes per element in default, hover, focus-visible and a CDP-forced pressed state, plus `opened` on the Features flyout, billing toggle and FAQ accordion, and `focused` on the contact field (nothing typed). Results in [raw/components-computed.json](raw/components-computed.json) and [raw/measurements.md](raw/measurements.md).
- **Screenshots.** [tools/capture/public/public.mjs](tools/capture/public/public.mjs) takes viewport and full-page shots per route, including the opened flyout/toggle/accordion states, with `.capture.json` sidecars; [tools/capture/quantize.py](tools/capture/quantize.py) posterises them to 256 colours.
- **Fonts.** No custom `@font-face` ships on the marketing pages — the site runs the SF/Inter system stack.

Nothing was sent, downloaded, signed into or trialled. The public marketing surface plus the contact form was enough.

## What to distrust

- **Readings past a masked bot signal.** The committed screenshots and readings were taken with `navigator.webdriver` masked, the flag bot checks read to spot automation. The capture scripts no longer mask it (not run since), so a recapture may record a walled route as a boundary instead of a reading.
- **One painted theme.** `.dark` exists in the stylesheet but only re-declares `--foreground` and the two `--shadow-wysiwyg-*` vars; nothing on the captured routes sets it, so no dark set is emitted.
- **RGB triplets.** `--color-*` values are stored as `r,g,b` strings for `<alpha-value>` utilities; tokens carry the converted hex.
- **`component.*` tokens are measured**, not site variables.
- **No hamburger at 390px.** The mobile header collapses to the icon row — the `m-menu-*` entries are recorded missing.
- **`hero-title` missed its selector** on this pass (the headline isn't an `h1`); visible in screenshots.
- **Quantised screenshots.** `screenshots/` are 256-colour PNGs; read exact colours from the tokens.

## Fonts

Two webfonts ship on the marketing pages (declared in `raw/css-vars.json`): **Inter** — the UI face every measured control renders in (`Inter, "Inter Fallback"`) — and **Averia Serif Libre** (`--font-instrument-serif`) for display serif moments. The guide renders Inter's metric-compatible fallback first, then the system stack.

## Do and don't

1. **Do ground on the cream.** `#fafafa` page, `#262626` ink, white cards and fields. See [home-light-default](screenshots/home-light-default.png).
2. **Do use the blue for the one action.** `--color-blue-500` #11a8ff marks Get started and the primary CTA; Download and Select stay white/hairline. See [cta-primary-default](components/crops/cta-primary-default.png).
3. **Do keep radii generous.** Hero CTAs run rounded-xl (~12px) at 50px; nav controls rounded-lg at 32px. See [cta-primary-default](components/crops/cta-primary-default.png) and [nav-cta-default](components/crops/nav-cta-default.png).
4. **Do put the trial CTA in black, not blue.** The plan-level action is `#000` at 36px — a different recipe from the blue marketing CTA. See [plan-cta-default](components/crops/plan-cta-default.png).
5. **Don't spread the accent red.** `--color-accent` #fd2b38 is the brand dot and status hue, not a button colour. See [home-light-default](screenshots/home-light-default.png).
6. **Don't invent a dark theme.** `.dark` barely exists — the site ships light only.
7. **Don't expect Tailwind hex in the vars.** `--color-*` are RGB triplets for `<alpha-value>`; read the converted tokens.
8. **Don't shrink the FAQ rows.** The 68px hairline accordion is the pricing rhythm. See [faq-question-default](components/crops/faq-question-default.png).

python3 tools/build_style_guide.py                # style-guide.html
python3 tools/build_components_md.py              # components.md

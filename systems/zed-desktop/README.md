# Zed desktop design reference

A token set and component reference for Zed, the code editor, version 1.25.2 for macOS (`/Applications/Zed.app`), captured on 2026-10-25 with the owner's signed-in account (Free plan) on a scratch folder of sample files. Zed is native: its own GPUI framework draws every pixel with Metal, so there is no DOM or CSS to read. It was captured for [issue 107](https://github.com/c-wenlong/designs/issues/107). The editor, file tree, tabs, diagnostics, git gutter and diff, terminal, command palette and pickers, context menus, tooltips, the Settings window, extensions, onboarding and the agent panel (a Claude Agent thread with two harmless test prompts) were captured in the owner's two themes, One Dark and One Light, at the window size the app opened in: 1512 x 949 pt.

Zed is open source, and its built-in themes are published as JSON. Every colour here is the value One Dark or One Light declares in `assets/themes/one/one.json` at the v1.25.2 release commit, and a sample of them was checked against the window's pixels: all 38 comparisons agree to within 1 per channel. Sizes, radii, spacing and type sizes come from the 2x window captures. Use it to build a dense desktop editor or agent tool: three tiers of grey (chrome, panels, editor), one blue accent, ghost controls that change fill on hover, small radii and a monospace buffer.

This package contains no Zed code and none of its icons beyond the app icon (`icon.png`); the theme file is MIT-licensed (copyright GitHub Inc., from Atom's One theme) and is kept in `raw/` with its licence. The screenshots and the visual system they show are Zed Industries' ([docs/RIGHTS.md](../../docs/RIGHTS.md)). Borrow structure and proportions, not the brand.

## Brief

Read this before designing in this style. Take every value from [tokens.json](tokens.json), never from the screenshots; `python3 tools/catalog.py export zed-desktop` prints them all with aliases resolved.

### Principles

1. Do separate regions with three tiers of one grey, not with colour.
2. Do keep one accent for small things.
3. Do draw controls as ghosts that fill on hover.
4. Do join the active tab to the buffer.
5. Do put every command in one palette shape.
6. Don't colour git and diagnostic state anywhere but in place.

Each rule links the screenshot or crop that shows it, under [Do and don't](#do-and-dont).

## How the values were read

**Colours: Zed's own theme file.** The owner's theme setting is `{"mode": "system", "light": "One Light", "dark": "One Dark"}`. Both themes live in `assets/themes/one/one.json` in [zed-industries/zed](https://github.com/zed-industries/zed); `tools/capture/fetch_upstream.py` fetched it at the `v1.25.2` tag, commit `d25fa01ccd788d812f236810b71af4feff6b2e38` (released 2026-10-21, the version installed). `tools/build_tokens.py` copies each key into `theme.*`, `syntax.*` and `player.*` as Measured, with `{file, key}` in its source. Values are upper-cased and an opaque `ff` alpha is dropped (`#3b414dff` becomes `#3B414D`); translucent keys keep their alpha (`editor.active_line.background` is `#2F343EBF`). A key that is also the prefix of another becomes `<key>.default` (`border` is `theme.border.default`), since DTCG cannot hold both.

**The pixel check.** `tools/measure.py` reads flat fills off the full-colour captures (title bar, tab bar, active tab, panels, editor, gutter, active line, toolbar, status bar, both border tiers, the palette and its selected row, the terminal, the git gutter bars, a switch track) and two text colours. `build_tokens.py` compares each with the key it names, compositing translucent keys over the surface beneath them, and refuses to build if any differs by more than 2 per channel. All 38 comparisons (19 per theme) agree within 1: 34 exactly, `version_control.modified` reads `#D3B021` for `#D3B020`, and `text` reads `#DCE0E4` for `#DCE0E5` (dark) and `#24252A` for `#242529` (light), at the anti-aliased glyph pixel. The translucent active line composites to exactly the pixel (`#2D323B` dark, `#EFEFF0` light). See [raw/pixel-check.json](raw/pixel-check.json).

**Sizes, radii, spacing and type: pixels.** The captures are Zed's main window alone (`screencapture -o -l` on its window id, then `sips` from Display P3 to sRGB), at 2 px per pt. `measure.py` reads bar and control sizes as runs of one colour or border to border (Sampled, exact to half a point), corner radii by fitting a circle to the insets of a corner's first rows (Derived, plus or minus 0.5 pt), insets from an edge to the first ink (Sampled), and capital heights. The committed screenshots are the same captures quantised to 256 colours; no value was read from them.

**Fonts: settings.** `tools/capture/read_settings.py` parsed the owner's settings file and kept only `theme`, `ui_font_*`, `buffer_font_*` and three font-size keys (the file holds other keys, including a credential, and was never opened in Zed, printed or copied), plus the defaults and their comments from `assets/settings/default.json` at the same commit: [raw/settings-fonts.json](raw/settings-fonts.json). Type sizes are Derived from capital heights at IBM Plex Sans's 0.698 em cap height; Menlo's ratio was calibrated against the owner's declared 11 pt (an 8 pt capital).

**Driving.** Zed was opened with only the scratch folder, by passing the path as the app's own argument (`open -a Zed --args <folder>`), which makes Zed handle the path instead of restoring the last session. Keystrokes went through System Events (command palette, panels, menus), pointer moves and clicks through CGEvents, each sent only after a check in the same script that Zed was frontmost; `shot.sh` refused to capture unless Zed's window was frontmost and no window showed the settings file. Themes were switched by setting only `theme.mode` in the settings file to `"dark"`, then `"light"` (`tools/capture/set_mode.py` verifies nothing else changes), and the file was restored from a byte-for-byte backup afterwards (`cmp` clean). macOS appearance was not touched.

**Masking.** The extensions page lists extension authors with their email addresses; those addresses (six spans per theme, in `41-extensions`) were painted over with `sample.py mask` after sampling. The unmasked copies stay outside the repo. Names, the owner's avatar, account name and organisation, and the scratch paths are left as the app shows them (AGENTS.md).

## What to distrust

- **Light radii.** Corner fits on the palette, tooltip and menu come out 3 to 4 pt in light against 7 to 8 pt (palette, tooltip) and 5.5 pt (menu) in dark, because One Light's border barely differs from the surface and the shadow beside it. The radius tokens use the dark readings.
- **Type sizes** are Derived from one capital each and an assumed cap ratio, plus or minus 1 pt. Settings descriptions read 8.5 pt caps in dark and 9 pt in light, between 12 and 13 px; `typography.labelSmall` says 13. The agent panel's `agent_ui_font_size` is 16, but its replies measure about 14, the same as UI labels.
- **The switch's on colour** (`role.control.switchOn`, `#45607B` dark, `#BBC6F1` light) matches no theme key; it is a sampled value (91% of its box), probably the accent mixed with the track.
- **The confirmation dialog is not Zed's.** With Use System Prompts on, Zed asks through the macOS alert; its blue button and focus ring are the system accent.
- **One theme family.** Zed ships Ayu and Gruvbox too, and the owner can install others; these tokens are One Dark and One Light only. `version_control.conflict_marker.ours/.theirs` exist in One Dark only and are left out of both sets; `pane.focused_border` and `panel.focused_border` are declared null.
- **Hover is subtle.** The 'Restart to Update' hover capture shows no visible change; the icon-button and settings-row hovers do. No pressed state, keyboard focus ring or motion was captured.
- **No agent approval prompt.** The Claude Agent ran in its Auto mode and performed both test actions (list the folder, write one file inside it) without asking.
- **Screenshots are 256-colour PNGs.** Read values from tokens.json.

## Do and don't

1. **Do separate regions with three tiers of one grey, not with colour.** The title and status bars, the panels and tab bar, and the editor are three steps of the same blue-grey (`role.chrome`, `role.surface`, `role.page`), divided by a 1 pt `border` line; nothing else is tinted. See [01-editor-python](screenshots/dark/01-editor-python.png) and [01 light](screenshots/light/01-editor-python.png).
2. **Do keep one accent for small things.** The blue (`role.accent.default`) marks links, matched characters in pickers, the open dock's status-bar icon and the cursor; no button or bar is filled with it. See [06-command-palette-typed](screenshots/dark/06-command-palette-typed.png) and [13-terminal-panel](screenshots/dark/13-terminal-panel.png).
3. **Do draw controls as ghosts that fill on hover.** Icon buttons, tabs and rows have no fill until the pointer is over them, then take `ghost_element.hover`; selection takes `element.selected`. See [21-hover-icon-button](screenshots/dark/21-hover-icon-button.png) and [07-command-palette-selected](screenshots/dark/07-command-palette-selected.png).
4. **Do join the active tab to the buffer.** The active tab takes the editor's fill and drops the border under it; inactive tabs stay on the tab bar's tier. See [02-editor-markdown-tabs](screenshots/dark/02-editor-markdown-tabs.png).
5. **Do put every command in one palette shape.** Commands, files, themes, symbols and branches all open the same raised box: query, list, one selected row, bindings on the right, actions in a footer. See [05-command-palette](screenshots/dark/05-command-palette.png), [03-file-finder](screenshots/dark/03-file-finder.png) and [24-theme-selector](screenshots/dark/24-theme-selector.png).
6. **Don't colour git and diagnostic state anywhere but in place.** File names, gutter bars and diff lines carry `modified`, `created`, `deleted` and `error` where they apply; there are no banners or badges for them. See [01-editor-python](screenshots/dark/01-editor-python.png) and [15-project-diff](screenshots/dark/15-project-diff.png).

## Rebuild

From this folder. `measure.py` and the capture scripts need the full-colour captures, which live outside the repo in `~/.design-systems/zed-desktop/raw-shots/`; the other builders run from the committed files.

```bash
python3 tools/measure.py ~/.design-systems/zed-desktop/raw-shots
python3 tools/build_tokens.py          # also writes raw/pixel-check.json
python3 tools/build_style_guide.py
python3 tools/build_components_md.py
python3 tools/crops.py                 # needs Pillow
python3 -m unittest discover -s tools
git status --short .
```

To capture again: `python3 tools/capture/fetch_upstream.py`, then `python3 tools/capture/read_settings.py`; compile the helpers (`swiftc -O -o tools/capture/zwin tools/capture/zwin.swift`, the same for `mouse.swift` and `wins.swift`; the binaries are not committed), open Zed on a scratch folder with `open -a Zed --args <folder>`, set the theme with `python3 tools/capture/set_mode.py dark` (back up the settings file first and restore it after), and run `python3 tools/capture/drive.py dark <step> ...` (its steps are the shot list); `tools/capture/quantize.py <raw-shots>` writes `screenshots/`. From the repository root, `make design-md` regenerates DESIGN.md and the Brief.

**The user-menu clicks are unchecked (issue 408).** `user_menu` and `settings` in `drive.py` click the user menu and its Settings item at fixed points. A check of the item's accessibility title before the click is not possible: Zed 1.27.0 (checked 2026-11-07) exposes one `AXWindow` with no children, since GPUI draws the window itself, so neither the menu nor its items have an accessibility title. Look at the `zz-check` frame the `settings` step takes before its second click.

## Zed beside the other coding harnesses

Zed is the one native app in issue 107's set: the others are web views (Electron, or Tauri for Conductor). It is an editor first, like [cursor-desktop](../cursor-desktop/README.md), and its agent panel hosts external agents (Claude Agent, Cursor, OpenCode) over the Agent Client Protocol as well as Zed's own. It is filed under `ai-agent` with the other harnesses for that reason; as a product it is also a plain editor.

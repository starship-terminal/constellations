# Endless design reference

A token set and component reference for Endless's public signed-out surface — for building marketing pages and AI-product surfaces in the style of the real thing. It was read from **endless.app** (what endless.io redirects to) on **2026-11-13**, signed out, in headless Chromium at 1440 x 900 and 390 x 844. Captured: the home, pricing, contact, tools index, a free tool page (the AI image generator), the model catalog and model index, blog, brand, docs, radar, MCP, about, industries, compare and status pages in light and dark, plus a 390px mobile pass on home, pricing, the tool page and the model catalog.

Endless is worth a capture because it is a complete shadcn-style token layer worn by a real product. One Next.js + Tailwind v4 surface declares the whole system — semantic roles (`--background`, `--primary`, `--card`, `--muted`, `--ring`, `--sidebar-*`) that re-bind under a `.dark` class written by next-themes (system `prefers-color-scheme` or the footer Theme control), product palettes (`--label-*` tag hues, `--mode-*` modality colours, `--chart-*`/`--series-*` data ramps), a near-white neutral field (`#fcfcfc` light, `#000000` dark) with a single sky accent `#01bcff` doing all the brand work, and two served faces (TikTok Sans for everything, Geist Mono for code). The display voice is TikTok Sans 59.2px at ~1.08 with -1.9px tracking; the signature component is the home prompt composer, a 20px-radius card on a floating shadow with a model pill and prompt chips. **Boundary:** the workspace behind sign-up (s.endless.app, auth on clerk.endless.app) — chat, canvas, projects, files, MCP connections, billing, onboarding — was never reached; no form was ever submitted and no tool was ever run.

## Brief

Read this before designing in this style. Take every value from [tokens.json](tokens.json), never from the screenshots; `python3 tools/catalog.py export endless` prints them all with aliases resolved.

### Principles

1. Do paint the field near-white, not white.
2. Do make the primary action near-black.
3. Do ring focus in the accent.
4. Do run the display type tight.
5. Do let one accent do the brand work.
6. Do invert through the same roles in dark.
7. Do keep the composer's floating geometry.
8. Don't style the workspace from this package.
9. Don't flatten the translucent fills.
10. Don't invent a desktop dropdown.

Each rule links the screenshot or crop that shows it, under [Do and don't](#do-and-dont).

## How the values were read

Every value came off the running signed-out site in headless Chromium:

- **Tokens.** [tools/capture/vars.mjs](tools/capture/vars.mjs) captures every same-origin stylesheet body (the Next.js `/_next/static/css/*.css` chunks and inline `<style>` blocks re-parsed with `CSSStyleSheet`) and writes every custom property to [raw/css-vars.json](raw/css-vars.json), resolved on the home page once plain and once under `.dark` — the scope next-themes writes. The layer is genuinely declared — the shadcn-style `--background`/`--primary`/`--card`/`--sidebar-*` roles, the `--label-*`/`--mode-*`/`--chart-*`/`--series-*` palettes and the `--text-*`/`--radius-*` scales — so most tokens are declared variables; the values only painted surfaces carry (the header's 90% background veil, the field's 50% fill, the hero gradient stops, the 3px 30% focus ring) are measured computed values, labelled as such. [tools/build_component_tokens.py](tools/build_component_tokens.py) writes the spec, [tools/build_tokens.py](tools/build_tokens.py) the sets. LAB hero-gradient stops are converted to sRGB; Oklab and LAB lightness scales are handled separately.
- **Components.** [tools/capture/public/measure.mjs](tools/capture/public/measure.mjs) opens each route in a fresh context and reads `getComputedStyle`, painted layers and boxes per element in default, hover, focus-visible and a CDP-forced pressed state, plus the states the UI itself reaches: the Annual pricing segment, the mobile menu overlay, contact fields focused and filled-then-cleared, the tool prompt focused. Results in [raw/components-computed.json](raw/components-computed.json) and [raw/measurements.md](raw/measurements.md). Endless's cards and composer keep their fills on painted child layers, so the readings record painted layers rather than trusting the wrapper.
- **Screenshots.** [tools/capture/public/public.mjs](tools/capture/public/public.mjs) takes viewport and full-page shots per route with `.capture.json` sidecars, including the local UI toggles: the Annual/Monthly segment on /pricing, the mobile menu, a focused contact field and the tool prompt focused with sample text typed and deleted. Full-page shots are capped at eight texture-sized chunks. [tools/capture/quantize.py](tools/capture/quantize.py) posterises them to 256 colours.

Nothing was signed into, generated, sent or submitted: Sign in (clerk.endless.app) and Sign up (s.endless.app) were never followed; every tool's Generate action, the contact Send button and every CTA was measured, never pressed to effect; the billing segment, mobile menu, field focus and the prompt fill were local UI state only. Cookie/consent and chat overlays were hidden, never answered — no consent button was ever clicked.

## What to distrust

- **This is the public shell, not the product.** The Endless workspace — chat, canvas, projects, files, MCP connections, billing, onboarding — sits behind sign-up on s.endless.app and is uncaptured. Treat the product's own design system as unknown; the composer on the home page is a marketing surface, not evidence of the app's chat UI.
- **Generated tool output is not captured.** Every `/tools/*` page runs its free demo; the prompt field was focused and filled with deleted sample text, but Generate was never pressed, so result galleries, progress and share states are absent.
- **Dark is a class, re-bound.** `dark.*` is the same declared roles under `.dark` (system scheme or the footer Theme control), not a separate user-selectable product theme with its own values. The `-dark` screenshots emulate `prefers-color-scheme` — the same trigger.
- **There is no desktop Industries dropdown.** The header nav is flat links; `nav-dropdown` and `menu-link` are recorded missing, not measured. The mobile menu overlay is the real overlay.
- **`radar-search` does not exist.** The /radar page has no search input on the public surface; recorded missing.
- **Field fills are translucent.** Contact fields paint `rgba(229,229,229,.5)`-family fills, so the same token reads differently over different grounds — copy the alpha, not a flattened hex.
- **Quantised screenshots.** `screenshots/` are 256-colour PNGs; gradients band. Read exact colours from tokens or the raw files.
- **`composer-send` read the wrong control.** Its four states are the composer's "Add to prompt" attach button (36px icon button), not the send control; recapture needed. `component.icon-button.size` cites `m-menu-button` instead.
- **A few readings predate the selector fixes.** Where a component moved during capture, the surviving evidence is the earlier, sometimes larger, painted ancestor — noted on the entry rather than silently wrong.
- **Automation was masked during capture.** Until 2026-11-20, `tools/capture/public/lib.mjs` hid `navigator.webdriver` in every page it opened, so every committed reading was taken with that mask. The mask is removed (a bot check is now recorded as a boundary, not bypassed); whether any page needed it to load is not known, and a recapture without it is the check.

## Fonts

Two served faces do everything. **TikTok Sans** runs the whole UI — the 59.2px display headline, 16px body, 14px nav and labels, at weights 400/500/600. **Geist Mono** covers code and technical labels. Both are served through `next/font` from endless.app's own origin; neither is distributed with the package — the style guide falls back to system sans and mono.

## Do and don't

1. **Do paint the field near-white, not white.** Marketing surfaces sit on `#fcfcfc` (light) / `#000000` (dark); pure white is reserved for cards, fields and the composer. See [home-light-default](screenshots/home-light-default.png).
2. **Do make the primary action near-black.** Buttons are `#171717`-dark fills with near-white text at 8–12px radii — the sky accent is reserved for focus, links and tags, never the primary fill. See [nav-cta](components/crops/nav-cta-default.png).
3. **Do ring focus in the accent.** Keyboard focus paints the accent two ways: a 3px `rgba(1,188,255,.3)` shadow plus a `#01bcff` border on buttons and fields, and a 2px solid `#01bcff` outline on links and menu rows. See [field-email](components/crops/field-email-focused.png).
4. **Do run the display type tight.** Headlines are TikTok Sans at ~1.08 leading with up to -1.9px tracking (59.2px display, 48px h2); body runs 14–16px at 1.5. See [hero-title](components/crops/hero-title-default.png).
5. **Do let one accent do the brand work.** `#01bcff` appears on links, tag labels, the mode colours and focus — everything else is the neutral ramp. See [mode-pill](components/crops/mode-pill-default.png).
6. **Do invert through the same roles in dark.** `.dark` re-binds the same variables — black field, `#171717` cards, `#e5e5e5` primary fill with dark text, the accent unchanged. See [home-dark-default](screenshots/home-dark-default.png).
7. **Do keep the composer's floating geometry.** The prompt card is a 20px-radius white card on a multi-layer floating shadow with a 36px send well and pill-shaped accessory buttons. See [composer](components/crops/composer-default.png).
8. **Don't style the workspace from this package.** Every value is the public surface's; the app behind s.endless.app is uncaptured. See [home-light-default](screenshots/home-light-default.png).
9. **Don't flatten the translucent fills.** Field fills are ~50% neutrals and the header veil is ~90% background — flattening them to opaque hex loses the layering. See [field-name](components/crops/field-name-default.png).
10. **Don't invent a desktop dropdown.** The nav is flat links; the only menu overlay is the mobile one. See [mobile-home-light-menu](screenshots/mobile-home-light-menu.png).

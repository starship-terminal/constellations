# Hevy design reference

A token set and component reference for Hevy, the workout-logging app for iOS, for building a native iOS fitness app (SwiftUI) that borrows its proportions and structure: a dense set table, one accent colour, a pale grey fill for everything tappable, small corners and iOS 26 glass chrome. It was captured from the shipped app, version 3.1.16 on iOS 26, with a free account on 2026-10-10, through iPhone Mirroring, in light and dark mode. The device screen is 390 x 844 pt and the captures are 1 px = 1 pt, with the screen offset by (8, 38) px inside each PNG.

It holds 200 captures: 17 light captures of the main flows, 17 dark ones, and 166 detail pages, sheets, menus and dialogs (dark; the help-centre article in t130 and t131 is a light web page inside the dark app). No capture shows a toast or a loading state, although four are named for one (see [What to distrust](#what-to-distrust)). [page-tree.md](page-tree.md) lists every screen reachable in the app and whether it was opened.

This package contains no Hevy code, and no Hevy artwork has been redrawn. The screenshots and the visual system they show are Hevy's property ([docs/RIGHTS.md](../../docs/RIGHTS.md)). Borrow structure and proportions, not the logo, icons, exercise illustrations or brand colours.

## Brief

<!-- brief:start. Generated by tools/brief.py from catalog.json, the tokens file and this README; `make brief` rewrites it. Do not edit. -->

Read this before designing in this style. Take every value from [tokens.json](tokens.json), never from the screenshots; `python3 tools/catalog.py export hevy` prints them all with aliases resolved.

### Principles

1. Do fill blue only for the action that moves the task forward.
2. Do show selection by adding blue to the control's resting form.
3. Do draw charts in blue against grey.
4. Do mark a finished set across the whole row.
5. Do draw icons as plain single-colour outlines, never on a coloured tile.
6. Don't fill destructive actions red.

Each rule links the screenshot or crop that shows it, under [Do and don't](#do-and-dont).

## Masked regions

The captures come from the owner's own account. On 2026-10-12 every region
showing who the account belongs to or who it interacts with was painted over
with the surrounding fill: usernames, display names, avatars and photos, bio,
follower counts, workout and routine titles, dates of the owner's activity,
post and comment text, other people's names and photos, and body data. A
blank area in a screenshot is a mask, not part of Hevy's design. Exercise
names, illustrations, set tables and the UI chrome are untouched, except where
a mask runs under the glass tab bar: there the paint or blur also covers part
of the bar (t21, t86 and t98, for example). No token was read from a masked
area.

## How the values were read

Hevy is a native app, so there is no CSS to read. Every number came from the PNGs, which are lossless and 1 px = 1 pt. Surfaces were read from flat fills, which are exact. Text colours were read from the darkest (or lightest, in dark mode) anti-aliased pixel, so the true value is the same or slightly further from the background. Corner radii were estimated from the diagonal inset of each corner, and font sizes from letter height, so treat those as plus or minus 2 pt for radius and plus or minus 1 pt for size. Sizes and positions were read off pixel edges and are exact to the point.

The measured reference grades each value on four levels. They map onto the labels in [docs/EVIDENCE.md](../../docs/EVIDENCE.md) like this, and `$extensions.source.evidence` in `tokens.json` uses the right-hand column:

| Level in the measured reference | Label in tokens.json | Meaning here |
|---|---|---|
| measured (a surface, or a size read off pixel edges) | Sampled | An exact flat fill, or an exact edge position. A displayed sRGB value, not proof of the token behind it |
| measured (text) | Sampled (text) | Darkest anti-aliased pixel of the text. The true value is the same or slightly darker |
| estimated | Derived | Worked out from pixels (a radius from a diagonal inset, a font size from letter height), or a value filled in from the closest documented role |
| observed | Observed | Visible in a capture, no value read. Listed in `components.md` |
| unknown | Not captured | Not determinable from pixels. Used on `fontFamily.base` |

Where a value was documented in one theme only, the other theme is filled from the closest documented role and marked Derived, with the reason in `$description`. This happens for the light sheets and wheel band (the detail pages were captured in dark only), the light `surface.raised2`, the light medals and the failure and drop set types, and the dark `accent.glass`, `button.disabledGlass` and `state.live`. Three values were read from the captures while building this package because the measured reference gave no number: the two `switch.offTrack` greys (it says only "light grey") and the dark `divider`. Their `$description` says so. The sheet and wheel band values from the reference were re-checked against p10, p16, p18 and t70.

`capture` in each token's source is a path inside this package: the screenshot a value was read from, or a section of `raw/hevy-style-measured.md` where the value is a Derived scale step or has no single capture.

The logging screens were captured with throwaway workouts that were all discarded, and the appearance was switched between Light and Dark for the two sets. Other users, the owner's private profile values and nearby gyms are blurred in the captures.

## What to distrust

- **The font.** Hevy's face is unknown. It is a geometric sans with a circular "o" and a two-storey "a", and it is not SF Pro. A Behance concept board used Poppins, which has a similar shape, but that was the concept author's choice and is not confirmed for the shipped app. `fontFamily.base` is `"system"`: use the platform face and expect slightly different text widths. Font sizes are estimates, and no line heights were measured.
- **Long pages are only partly captured.** Scrolling inside iPhone Mirroring moves a few points at a time. 24 captures show a page below its top (`04-log-workout-scrolled`, `d03-settings-mid` and 22 tree-pass files named `mid` or `bottom`, such as t04 and t128), but the parts of a long page between captured positions are unseen.
- **No keyboard.** iPhone Mirroring takes typing from the Mac keyboard and hides the software keyboard, so no capture has one.
- **No network error state.** Turning off the phone's connection would also cut iPhone Mirroring.
- **No pressed or long-press states, no motion.** The captures are stills made with clicks. Swipe-only content (the image carousel's second page, share card templates 2 to 8) was unreachable.
- **Radii are estimates.** `radius.control` 8, `radius.button` 10 and `radius.card` 10 are good to plus or minus 2 pt.
- **Dark text and border ranges.** `text.secondary` and `text.tertiary` are ranges in the source (dark `#64666A` to `#696B6F` and `#4A4A4A` to `#626468`; light tertiary `#AAAFB2` to `#B7BABC`). Each token holds the first value of its range and says so.
- **The scrim.** The source gives black at about 70%, but the light dialog capture shows `#434343` over white, which works out nearer 74%. The token follows the documented 70%.
- **Screenshots are full-colour PNGs.** Each is 406 x 890 px, RGBA, with a transparent margin around the 390 x 844 screen, and holds between 1,590 and 24,906 distinct colours, so nothing was reduced to a palette. Flat UI colours are exact. Read values from the tokens, not the images.
- **Some captures are named for a state they do not show.** No capture shows a loading state or a toast. `t24-contacts-loading-spinner` is the same image as the empty state t25 apart from the tab bar. `t98-skeleton-loading-suggested` shows the Suggested Athletes cards loaded, with their contents masked and blue Follow buttons. `t130-faq-article-webview-loading` is the same as the loaded article t131 apart from the battery level. `t93-toast-link-copied` is the same as the share composer t91 apart from the clock. The toast, skeleton and spinner descriptions in [components.md](components.md) and in the "Feedback, loading and growth patterns" table of [raw/hevy-style-measured.md](raw/hevy-style-measured.md) come from the capture notes alone, and that file's line saying loading and toast states were captured is wrong. `04-log-workout-scrolled`, cited for the large title collapsing on scroll, shows the Log Workout page, which has no large title, so it cannot show that. The post in `t21-discover-post-trainer-tag` is masked, so its trainer tag does not show.
- **System glass.** The tab bar and nav bar buttons are iOS 26 glass. Their blur and tint come from the system, so the tokens only describe the colours Hevy puts under or on them.

## Do and don't

1. **Do fill blue only for the action that moves the task forward.** "Add Exercise" is blue while "Settings" and "Discard Workout" beside it sit on the grey fill, and a filter sheet pairs a grey "Clear Filters" with a blue "Show 74 results". Every other tappable word is blue text with no fill: exercise names, "Rest Timer", "Last 3 months", and the "Not now" under a paywall button. See [14-empty-workout](screenshots/light/14-empty-workout.png), [p11-filter-tile-selected](screenshots/pages/p11-filter-tile-selected.png), [03-log-workout](screenshots/light/03-log-workout.png) and [t113-upsell-bottom-sheet](screenshots/pages/t113-upsell-bottom-sheet.png).
2. **Do show selection by adding blue to the control's resting form.** A chosen filter tile or questionnaire answer keeps its shape and gains a blue border; picked exercise rows get a pale blue tint and a blue tick badge; an applied filter button turns solid blue with a clear (x). See [p11-filter-tile-selected](screenshots/pages/p11-filter-tile-selected.png), [t37-trainer-q1-selected](screenshots/pages/t37-trainer-q1-selected.png), [09-exercise-picker-selected](screenshots/light/09-exercise-picker-selected.png) and [p12-filter-active](screenshots/pages/p12-filter-active.png).
3. **Do draw charts in blue against grey.** Bars, workout days on the heatmap and "you" in a comparison are blue; the other person, the previous period and empty days are grey. See [p03-workout-detail](screenshots/pages/p03-workout-detail.png), [t16-compare-exercise](screenshots/pages/t16-compare-exercise.png) and [t106-calendar-year-heatmap](screenshots/pages/t106-calendar-year-heatmap.png).
4. **Do mark a finished set across the whole row.** Ticking the box tints the full row green, fills the box green, drops the input borders and turns the values bold. In these captures green appears only here and on the live-sync dot. See [15-sets-completed-rest-timer](screenshots/light/15-sets-completed-rest-timer.png), [d14-sets-completed-timer-focus](screenshots/dark/d14-sets-completed-timer-focus.png) and [14-empty-workout](screenshots/light/14-empty-workout.png).
5. **Do draw icons as plain single-colour outlines, never on a coloured tile.** Settings rows lead with a line icon in the text colour, buttons put a "+", clipboard or magnifier in their label colour, and the delete icon in an action sheet turns red with its label. Apart from blue on tappable items, the only coloured icons are small filled status glyphs: the streak flame, the rest-day moon and the records medal. See [13-settings](screenshots/light/13-settings.png), [02-workout](screenshots/light/02-workout.png), [p05-action-sheet](screenshots/pages/p05-action-sheet.png), [p24-calendar-month](screenshots/pages/p24-calendar-month.png) and [p03-workout-detail](screenshots/pages/p03-workout-detail.png).
6. **Don't fill destructive actions red.** "Discard Workout", "Delete Routine" and "Disconnect" are red text, with a red icon where there is one, on the neutral fill or on nothing. "Remove Set" is quieter still: a white label beside a red (x). See [d15-discard-dialog](screenshots/dark/d15-discard-dialog.png), [p05-action-sheet](screenshots/pages/p05-action-sheet.png), [p16-set-type-sheet](screenshots/pages/p16-set-type-sheet.png) and [p32-integrations-connected-states](screenshots/pages/p32-integrations-connected-states.png).

## Rebuild

`tokens.json` and `components.md` are written by hand from `raw/hevy-style-measured.md`, so there are no builders for them. The style guide is generated:

```bash
python3 tools/build_style_guide.py
```

`build_style_guide.py` reads `tokens.json` and writes `style-guide.html`, turning every token into a CSS custom property so the page cannot drift from the file. It is deterministic: a rebuild that changes nothing proves the page still matches the tokens.

```bash
python3 tools/build_style_guide.py && git status --short .
```

## Use in Figma and in SwiftUI

Import `tokens.json` with Tokens Studio and choose the Light or Dark theme, or read it with Style Dictionary. For SwiftUI, a colour asset per semantic key with a light and a dark variant maps one to one: the key names (`color.surface.raised`) are the contract, and the same keys exist in both sets. Sizes and radii in `core` are points. Use the standard iOS 26 components for the tab bar, nav bar buttons, sheets, switches and wheel pickers rather than redrawing them.

## Hevy's patterns in one place

- One accent colour does all the work. Everything else is navy-black text on white, with one pale grey-blue fill (`color.surface.raised`) for anything tappable that is not primary.
- Borders are rare. Separation comes from the grey fill, 16 pt margins and pale dividers. Routine cards and inputs are the exceptions, and dark mode drops the card border.
- Corners are small and consistent: about 8 for short controls, about 10 for buttons and cards, fully round for chips and badges.
- Lists are dense: 80 pt for two-line rows with an image, 60 pt for settings, a 47 pt pitch for set rows.
- Success green, destructive red and warm-up orange are slightly different in dark rather than reusing the light hex.

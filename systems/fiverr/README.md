# Fiverr design reference

A token set and component reference for Fiverr's public signed-out surface — for building freelance-marketplace surfaces in the style of the real thing. It was read from **fiverr.com**, signed out, in Chromium at 1440 x 900 (with a 390 x 844 mobile pass): the home page and its Browse-categories drawer, the /categories services directory, the creative-logo-design subcategory, /search/gigs results, a live gig page and its seller profile, /join and /login, and the /logo-maker, /about-us, /start_selling, /cp/how-fiverr-works and legal-portal marketing pages.

Fiverr is worth a capture because it is a current reference for marketplace chrome: a white sticky header with a Browse-categories drawer, the dark photographic hero band carrying the dark-skinned search form, the Macan brand face, gig cards with star ratings and localized "From S$xx" pricing, the Basic/Standard/Premium package tablist, and the honest edge cases — PerimeterX's press&hold gate at the edge and a hashed atomic-utility custom-property layer that declares values under hashed `--_<id>` names rather than a readable token layer.

## Do and don't

1. **Do keep the chrome white.** The header, the category strip and the footer are white bars on the white page; text runs #222325 ink to #62646a muted. See [home-light-default](screenshots/home-light-default.png).
2. **Do use the #222325 ink fill for primary actions.** Join, the search submit and Continue are dark ink pills with white text, not green. See [nav-join](components/crops/nav-join-default.png) and [hero-search-btn](components/crops/hero-search-btn-default.png).
3. **Do reserve the #1dbf73 green for the accent.** The brand green surfaces as the category-nav hover underline — an accent, not a button fill on the signed-out surface. See [cat-nav](components/crops/cat-nav-hover.png).
4. **Do let the hero be a dark photographic band.** The display headline runs white over the near-black media band with the white search field below it. See [hero-h1](components/crops/hero-h1-default.png).
5. **Don't invent a dark theme.** The hero band and the search form's `dark` class are component skins inside the single light theme. See [hero-search](components/crops/hero-search-default.png).
6. **Don't infer values from the hashed `--_<id>` stylesheet vars.** They are atomic utilities with no semantic names; every token is a measured computed style. See [raw/css-vars.json](raw/css-vars.json) and [mkt-header](components/crops/mkt-header-default.png).
7. **Don't treat the PerimeterX gate or localized pricing as defects.** Press&hold is the site's edge protection, and "From S$xx" is the live localized price. See [search-light-default](screenshots/search-light-default.png).

## How the values were read

- **Measured, not declared.** fiverr.com serves a hashed atomic stylesheet layer: ~1,290 custom properties on `:root`, all named by content hash (`--_103bn0w`, `--_14uh8ef`), plus a handful of component-scoped vars — a token-free layer with no semantic names to alias. `tools/capture/vars.mjs` records the whole harvest (including the Macan `@font-face` woff2 rules on npm-assets.fiverrcdn.com) in [raw/css-vars.json](raw/css-vars.json); every design token in tokens.json is therefore a computed style read off the running pages by `tools/capture/public/measure.mjs`, with the component and state named in `$extensions.source`.
- **Public only.** Nothing was signed into, bought or submitted. The hero search and the join/login fields were typed into then cleared and never sent; Continue, Contact me, Join, Sign in, Continue-with-* and every CTA were measured, never followed; the package tabs were not switched (switching re-prices the card). The only presses were local UI toggles — the Sidebar-menu drawer, a results filter trigger, the FAQ accordions.
- **PerimeterX.** fiverr.com gates some clients behind a press&hold challenge ("It needs a human touch"). The capture scripts now treat it as a boundary: they wait for the real document, never press or hold the challenge, never save or replay a clearance cookie, and log a page that stays challenged as blocked. The committed readings predate that change (see [What to distrust](#what-to-distrust)).
- **Hidden, never answered.** The UserWay accessibility widget and any consent/promo layer are hidden before every shot and reading; they were never clicked.
- **Provenance.** Every screenshot carries a `.capture.json` sidecar (URL, viewport, DPR, document bounds, clip) written by `tools/capture/screenshot.mjs`. Full-page shots are bounded at eight chunks; a page that reports an unbounded `scrollHeight` is truncated with the boundary recorded.
- **Localization.** Prices rendered localized to this client's currency (SGD) — the "From S$xx" strings and the footer's "S$ SGD" button are readings of the live page as served.

## What to distrust

- **Readings taken past a bot check.** Every committed screenshot, crop, [raw/components-computed.json](raw/components-computed.json) reading and the [raw/css-vars.json](raw/css-vars.json) harvest was taken by an earlier version of the capture scripts that held PerimeterX's press-and-hold button automatically, replayed the clearance cookies in later contexts and hid automation (a `navigator.webdriver` mask and the `AutomationControlled` flag). That code was removed on 2026-11-20. The values are the live pages as served, but a recapture with the current scripts stops wherever the challenge appears and records those pages as gaps.

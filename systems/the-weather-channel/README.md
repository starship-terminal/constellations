# The Weather Channel

Public signed-out pages on weather.com, captured 19 November 2026. The start URL redirected to a public locality forecast (Downtown Core, Singapore) with no account. Themes: light only. Widths: 1440 and 390 CSS pixels in the screenshots. The live attached page measured 1169 by 731 CSS pixels at device pixel ratio 2.

No account was created. The login form was opened and not submitted. No phone number, card, or home address was entered. No location search was submitted.

## How the values were read

Custom properties were read from the live weather.com page with `getComputedStyle(document.documentElement)` after walking stylesheets. Component colours, type, radii, padding, and heights were read with `getComputedStyle` on the elements named in [raw/computed.json](raw/computed.json). The attached preview tab was `https://weather.com/en-SG/sg/central-singapore-community-development-council/locality/downtown-core/today`.

`preview_snapshot` failed twice with "The browser is not producing screenshot frames". The same public URL then loaded in headless Playwright with status 200 and no Cloudflare challenge. Screenshots came from that session at 1440 by 900 and 390 by 844, device pixel ratio 2. Login, search, and privacy screenshots came from the same headless session. Hover and the login form styles were also read there, and they match the live token names.

## What to distrust

The hero fill is the computed `rgb(14, 29, 37)`, which matches `--color-teal-900`. A gradient may paint over that section in the screenshot. The token is the computed background, not a sample of the bitmap.

`--color-accent` in the page's Tailwind layer is a near-white lab colour. The blue used on selected tabs is `--color-brand-light` (`#3a61cc`). A second blue, `rgb(0, 126, 168)`, appears on 14 elements and is not a declared custom property. Both are recorded. Do not treat the Tailwind `--accent` as the brand blue.

The privacy page on trust.weather.com uses a system sans stack and a 60px heading. Those values are not in the forecast tokens.

weathercompany.com uses IBM Plex Sans, a `#001141` page, and `#0f62fe` buttons. It is a different site and is not in this package.

Radius `full` is the browser's pill value (`1.67772e+07px`), stored as `9999px`. Rem radii were converted at the measured 16px root.

Screenshots are full colour. Read colours from tokens.json, not from the PNGs.

## Fonts

The forecast page computes `Inter, "Inter Fallback"` on body, headings, and controls. Inter is the family named in the stylesheet. The package does not ship the font files. The fallback is the second family in that computed stack.

`--font-sans` on the root is a system stack and is not what the forecast text uses. trust.weather.com uses `-apple-system, system-ui, Segoe UI, Roboto, Helvetica Neue, Noto Sans, Arial`. weathercompany.com uses IBM Plex Sans and IBM Plex Mono.

## Do and don't

1. **Use the gray-900 fill for the location chip and Sign in.** The measured fill is `#252422`, with white text. The blue `#3a61cc` is for the selected tab and text links, shown in [today-light-default.png](screenshots/today-light-default.png).
2. **Set the condition hero on `#0e1d25` with a 16px radius and a 120px temperature.** That is the computed hero section in the same screenshot.
3. **Keep day tabs as 48px pills.** Selected is `#f2f2f2` with `#3a61cc` text. Idle tabs are transparent with `#252422` text.
4. **Do not copy weathercompany.com into this system.** That marketing site uses IBM Plex and a different blue. These tokens are weather.com.

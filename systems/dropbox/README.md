# Dropbox design reference

A token set and component reference for Dropbox's public surface — for building marketing pages and product landing pages in the style of the real thing. It was read from **dropbox.com** on **2026-11-13**, signed out, in headless Chromium at 1440 x 900 and 390 x 844. Captured: the home page, the `/dropbox` product page, the Replay, Sign and DocSend product pages, the business and enterprise landings, `/plans` pricing, `/features`, the `/login` and `/register` cards (measured, never submitted), and a 390px mobile pass. A **2026-11-22** pass refreshed the public tree from origin/main's existing `systems/dropbox/` package: homepage, product, pricing, features, desktop and mobile download, enterprise, early access, the 404 state, opened nav menus, the language dialog, the phone drawer, and the empty login and signup walls. That pass typed nothing and did not submit. `login-extracted` stays `not-started`.

Dropbox is worth a capture because the public site ships two complete token layers. The generated **DIG layer** (`@dropbox/dig-components` 25.1.0, foundations 7.1.0, served as `dig-components/tokens.css`) declares the whole system as `--dig-*` custom properties: the `--dig-color__*` role palette (`#0061fe` Dropbox blue, the `#050505` primary-CTA role, `#3080ff` focus ring, alert/attention/success/warning/disabled/selection/highlight/folder/fileicon families), the `--dig-spacing__dimension__*` 8px scale, the `--dig-type__*` ramp (Sharp Grotesk titles 40px → Atlas Grotesk text 20-10px), `--dig-radius__*` (4-24px + 999px pill), `--dig-motion__*` durations/easings, `--dig-breakpoint__*` and `--dig-utilities__*` (the 3px focus ring, box shadows, blurs). The **dwg layer** declares the `--DWG__TEMP__color__*` brand palette on `:root` — the coconut ramp (`#fff`→`#eee9e2`), the graphite ramp (`#2b2929`→`#000`) and the named accent hues — then rebinds it per painted section as `--dwg-theme__color__*` roles under `.dwg-theme--coconut` (the nav and cream fields), `.dwg-theme--graphite` (the dark in-page bands) and `.dwg-theme--navy`. Two font faces do everything: **Sharp Grotesk** for display and headings, **Atlas Grotesk Web** for body and controls — except the auth cards, which mix the older `lucida grande` susi sheet (wrappers and the email field) with Atlas Grotesk Web labels. **Boundary:** the product itself — the file dashboard, Paper, Dash, Replay and Sign workspaces, account, billing and checkout — sits behind the auth cards and was never reached; `dash.dropbox.com` and `app.reclaim.ai` are separate products on separate hosts that were never opened; nothing was signed into, purchased or submitted.

## Brief

<!-- brief:start. Generated by tools/brief.py from catalog.json, the tokens file and this README; `make brief` rewrites it. Do not edit. -->

Read this before designing in this style. Take every value from [tokens.json](tokens.json), never from the screenshots; `python3 tools/catalog.py export dropbox` prints them all with aliases resolved.

### Principles

1. Do paint the field coconut, not stark white.
2. Do make the primary action blue.
3. Do ring focus with a 3px blue shadow.
4. Do set titles in Sharp Grotesk, body in Atlas Grotesk.
5. Do rebind the palette per section.
6. Do keep the 8px grid and the 4-24px radii.
7. Do let the menu open on hover.
8. Don't mix the auth sheet with the marketing system.
9. Don't style the product from this package.
10. Don't read dark tokens as a user theme.

Each rule links the screenshot or crop that shows it, under [Do and don't](#do-and-dont).

## How the values were read

Every value came off the running signed-out site in headless Chromium:

- **Tokens.** [tools/capture/vars.mjs](tools/capture/vars.mjs) captures every stylesheet body during a live home load (the linked `cfl.dropboxstatic.com` bundles — `dig-components/tokens.css`, the dwg-components index, the warp page CSS — read from network responses because they are cross-origin to the CSSOM, plus the inline `<style>` blocks), re-parses them with `CSSStyleSheet`, writes every custom property to [raw/css-vars.json](raw/css-vars.json), and resolves each name on a probe document under five scopes: the painted `dig-Theme-vis2023--bright`/`dig-Mode--bright`, the declared-but-unpainted `vis2023--dark`, and the three painted `dwg-theme--*` section scopes (coconut, graphite, navy). [tools/build_component_tokens.py](tools/build_component_tokens.py) writes the spec — declared leaves carry `"var"` plus the `"resolve"` pass — and [tools/build_tokens.py](tools/build_tokens.py) emits the sets.
- **Components.** [tools/capture/public/measure.mjs](tools/capture/public/measure.mjs) opens each route in a fresh context and reads `getComputedStyle`, painted layers and boxes per element in default, hover, focus-visible and a CDP-forced pressed state, across the home, plans, business, features and sign pages, the auth cards and mobile. Results in [raw/components-computed.json](raw/components-computed.json) and [raw/measurements.md](raw/measurements.md).
- **Screenshots.** [tools/capture/public/public.mjs](tools/capture/public/public.mjs) takes viewport and full-page shots per route with `.capture.json` sidecars, including the local UI toggles: the Products mega-menu (it opens on pointer **hover** — a click closes it, measured behaviour), the mobile hamburger menu, and the Billed-monthly billing radio on /plans (the page defaults to yearly). dropbox.com mounts Lenis smooth-scroll and an intermittent CCPA consent iframe that scroll-locks the document; the kit aborts the consent iframe's requests (nothing answered) and releases scroll hijackers before tiling, bounding every full-page capture at 8 chunks. [tools/capture/quantize.py](tools/capture/quantize.py) posterises them to 256 colours.

Nothing was signed into, created, submitted or paid for: the login and register cards were captured as surfaces, their email fields focused and given sample text that was deleted again; every Try-for-free, Buy-now, Get-started and Continue action was measured, never followed; the billing radio, mega-menu and mobile menu were toggled as local UI state. ## What to distrust

- **This is the public shell, not the product.** The file dashboard, Paper, Replay and Sign workspaces, Dash, account and billing live behind the auth cards and are uncaptured. Treat the product's own design system as unknown.
- **Dark is declared, not painted.** `dark.*` in tokens.json is the `dig-Theme-vis2023--dark` scope the token layer ships — a real palette, never painted on the signed-out surface. The actual dark surfaces on the site are `dwg-theme--graphite` bands inside light pages; those painted roles live under `light.dwg.graphite.*`.
- **Declared and painted CTAs disagree.** The DIG layer declares `primary-cta` black (`#050505`), but the marketing CTAs paint `#0061fe` blue → `#0057e5` hover → `#0050d0` pressed — exactly the `--dwg-theme__color__primary__button--*` values. Use `core.measured.cta-fill*` for what a real button shows.
- **The auth cards mix in an older sheet.** /login and /register (the "susi" surfaces) run the wrappers and the email field on a `lucida grande` system stack at 13-16px, but the painted labels stay Atlas Grotesk Web — the SSO buttons at 14/16, Continue at 16/19.2 500. Sizes and radii differ from the marketing chrome; don't extrapolate the marketing system into them.
- **The mega-menu is pointer-driven.** It opens on hover and closes when keyboard focus moves; a menu link's focus-visible/pressed states are a documented gap, not measured absences.
- **`social-icon` is the wrong element.** Its selector's `href*="x.com"` also matches dropbox.com, so the entry holds the "Dropbox Sign" footer link's values; components.md marks it and no token reads it. The selector is fixed in `measure.mjs` (edited, not run); the entry needs a recapture.
- **Quantised screenshots.** `screenshots/` are 256-colour PNGs; read exact colours from tokens or the raw files.
- **A/B and regional variance.** The home hero rotates variants ("One place to store, share, and collaborate" / "Freedom to work your way"), prices render US$, and the CCPA banner mounts by region — all recorded as they painted.
- **Automation was masked during capture.** Until 2026-11-20, `tools/capture/public/lib.mjs` hid `navigator.webdriver` in every page it opened, so every committed reading was taken with that mask. The mask is removed (a bot check is now recorded as a boundary, not bypassed); whether any page needed it to load is not known, and a recapture without it is the check.

## Fonts

Two served faces run the marketing surface. **Sharp Grotesk** (500) paints display and headings — the 66px hero display down to 20px section titles — with ~-1px tracking on the largest step. **Atlas Grotesk Web** (400/500) paints body, nav, controls and actions — 20/30 lede down to 10/18. The auth cards mix the older `lucida grande` susi sheet (wrappers and the email field) with Atlas Grotesk Web labels — SSO 14/16, Continue 16/19.2. Mono exists in the token layer (`--dig-type__monospacefontstack`) but nothing public paints it. All faces are served from `cfl.dropboxstatic.com`; none is distributed with the package — the style guide falls back to system sans.

## Do and don't

1. **Do paint the field coconut, not stark white.** Marketing surfaces sit on `#f7f5f2` coconut-500 with white cards; graphite `#1e1919`-`#161313` bands carry the dark sections. See [home-light-default](screenshots/home-light-default.png).
2. **Do make the primary action blue.** Painted CTAs are `#0061fe` with `#f7f5f2` text at a 16px radius — `#0057e5` hover, `#0050d0` pressed, not the declared black `primary-cta` role. See [nav-cta](components/crops/nav-cta-default.png) and [plan-cta](components/crops/plan-cta-default.png).
3. **Do ring focus with a 3px blue shadow.** Keyboard focus paints a `0 0 0 3px #428bff` box-shadow ring, not an outline — on buttons and the email field alike. See [nav-cta](components/crops/nav-cta-focus-visible.png) and [email-field](components/crops/email-field-focused.png).
4. **Do set titles in Sharp Grotesk, body in Atlas Grotesk.** Display runs ~66px/1.08 at 500 weight with -1px tracking; body is Atlas 14-20px at 400, 500 for actions. See [hero-title](components/crops/hero-title-default.png) and [hero-sub](components/crops/hero-sub-default.png).
5. **Do rebind the palette per section.** A `dwg-theme--*` class swaps every `--dwg-theme__color__*` role at once — coconut fields, graphite bands, navy accents — never hand-pick a dark colour inside a section. See [graphite-band](components/crops/graphite-band-default.png).
6. **Do keep the 8px grid and the 4-24px radii.** Spacing steps run 4-128px; cards paint 12-24px radii, buttons 16px, pills 999px. See [plan-card](components/crops/plan-card-default.png).
7. **Do let the menu open on hover.** The Products mega-menu fades in a 480px two-column panel on pointer hover — no click. See [nav-dropdown](components/crops/nav-dropdown-default.png).
8. **Don't mix the auth sheet with the marketing system.** The login/register cards run `lucida grande`, 4px radii and 13px labels — an older surface. See [auth-card](components/crops/auth-card-default.png).
9. **Don't style the product from this package.** Every value is the public surface's; the dashboard, Paper and workspaces are uncaptured. See [login-light-default](screenshots/login-light-default.png).
10. **Don't read dark tokens as a user theme.** `dark.*` is declared but unpainted; the painted dark surfaces are `light.dwg.graphite.*`. See [replay-light-default](screenshots/replay-light-default.png).

# Curater

A measured reference for Curater's public web app, captured on 2026-11-21 from https://curater.org/, signed out, in headless Chromium. Desktop captures are 1440 x 900 at 1x. Phone captures are 390 x 844 at 2x. The product paints one light theme. Emulating `prefers-color-scheme: dark` left the page background at `oklch(1 0 0)`.

Curater is a public curation feed. Signed-out visitors can read the home digest, the feed, a curation, a public curator profile, a collection, the extension page, and the legal pages. Saving, creating, notifications, settings, and subscriptions stop at a Google sign-in wall. There is no email field on the site. This capture did not click Google, did not type a password, and did not enter onboarding.

## How the values were read

Custom properties were read from the live CSSOM on https://curater.org/ at 1440 x 900, signed out, on 2026-11-21. The product declares a `--Curater-*` brand palette and a shadcn-style semantic layer (`--background`, `--foreground`, `--primary`, `--radius`, `--sidebar-*`) on `:root`. Component metrics were read with `getComputedStyle` on the painted control: the home sign-in pill, the settings menu, the feed tabs, the feed search field, and the sign-in dialog scrim. Phone search was photographed; its fill is recorded as the `--primary` token because the computed desktop pill is white and the phone submit is the filled recipe.

Screenshots are 256-colour PNGs. Read colours from [tokens.json](tokens.json), not from the images.

## What to distrust

- **One theme.** Dark emulation did not change the painted page. There is no `dark` token set.
- **Hover did not move the pill.** The sign-in button's computed background stayed `oklch(1 0 0)` under hover. Pressed was not held.
- **Relative brand colours.** `--Curater-green-background`, `--Curater-green-dark`, `--Curater-red-dark`, and `--Curater-red-light` are stored as the declared `oklch(from …)` strings. The browser did not resolve them to a flat colour on `:root`.
- **Tailwind palette is not the product.** `--color-red-500` and the other `--color-*` ramps are the framework palette. They are in [raw/css-vars.json](raw/css-vars.json) only when they were kept; they are not semantic roles.
- **Signed-in product is absent.** Notifications, profile, create, settings, subscriptions, and add-to-taste all stop at the login wall. Those screens are not inferred.
- **Profile screenshot was a late paint.** The first profile capture was a spinner. The committed shot waited for `networkidle`.

## Fonts

Painted UI uses **ABCDiatype** at weights 400 and 500, with a system sans fallback. The declared `--font-sans` is `ui-sans-serif, system-ui, sans-serif` and is not what the buttons paint. `--font-mono` is the system mono stack. No public code sample was measured. The webfont files are not in this package.

## Do and don't

1. **Do keep the page white and the type near-black.** The ground is `oklch(1 0 0)` and the text is `oklch(0.141 0.005 285.823)`. See [screenshots/home-light-default.png](screenshots/home-light-default.png).
2. **Do use a white pill for the Google action.** Sign in is a 58px pill with a 1px border and a full radius, not a filled brand colour. See [components/crops/button-signin-default.png](components/crops/button-signin-default.png).
3. **Do use the filled pill only for the search submit.** The phone search button is the near-black primary. See [components/crops/button-search-default.png](components/crops/button-search-default.png).
4. **Do keep the sidebar as icons.** Desktop navigation is a 5rem icon rail. Phone collapses it into the header. See [screenshots/mobile-home-light-default.png](screenshots/mobile-home-light-default.png).
5. **Don't invent a signed-in screen.** Notifications, create, settings, and add-to-taste open the same Google wall. See [login-review.json](login-review.json).
6. **Don't treat the selection colours as UI chrome.** `--Curater-selection-*` is a highlight palette. It was not painted on the captured chrome.

# Elektron design reference

A token set and component reference for Elektron's public site — for building dark, instrument-grade music-hardware storefront and product surfaces in the style of the real thing. Tokens were read from **www.elektron.se** on **2026-11-13**, signed out, in headless Chromium at 1440 x 900 and 390 x 844. The public tree was mapped again on **2026-11-21**: header, footer, search, account drawer, cart drawer, region picker, cookie dialog, shop, catalog, product accordions, support, and the empty login wall. The control map is [site-tree.md](site-tree.md). The walls where the pass stopped are [login-review.json](login-review.json). Nothing was submitted.

Elektron is worth a capture because it is a rare fully inverted monochrome: a `#151515` ground under `#eeeef2` "paper" that is at once the text colour, the icon colour, the 2px stroke of every outline action and the fill those actions take on hover — the accent is the paper, not a brand hue. Everything is square (`--tdc-radius: 0`), spaced on a 7px rhythm, and set in Neue Haas Grotesk — Text Pro for the 14px UI, Display Pro for the 24-64px headings — with the hardware-flavoured **digi one v2** on block-button labels and **Analog One V2.** in the search field. Links hover by a `#333333` gradient underline-sweep; fields are light `#eeeef2` slabs on the dark page; modals are right drawers over a 50% scrim; and keyboard focus draws a double ring — a 2px white spread under a 2px black outline.

## Brief

<!-- brief:start. Generated by tools/brief.py from catalog.json, the tokens file and this README; `make brief` rewrites it. Do not edit. -->

Read this before designing in this style. Take every value from [tokens.json](tokens.json), never from the screenshots; `python3 tools/catalog.py export elektron` prints them all with aliases resolved.

### Principles

1. Do ground on #151515 and keep it monochrome.
2. Do let the paper do everything.
3. Do keep every corner square.
4. Do space on the 7px rhythm.
5. Do set UI text in Neue Haas Text and headings in Neue Haas Display.
6. Do label actions in digi one v2.
7. Do fill fields light.
8. Don't restyle the focus ring.
9. Don't invent a light theme or a colour accent.

Each rule links the screenshot or crop that shows it, under [Do and don't](#do-and-dont).

## How the values were read

Every value came off the running signed-out site in headless Chromium:

- **Tokens.** [tools/capture/vars.mjs](tools/capture/vars.mjs) read every stylesheet body — the same-origin `thedock` child theme, plugin and inline sheets — re-parsed them, and wrote every custom property to [raw/css-vars.json](raw/css-vars.json) binned `theme`/`app`/`vendor`, resolved on a probe carrying the real sheets under the site's one painted theme. The `:root` layers are named: `--thedock-*` (the #151515 ground, #1e1e1e surface, #eeeef2 text/action paper, #97979a muted, #363636 border, the 50% scrim, the font stacks) and `--tdc-*` (the same ground pair, the #212121 raised surface, #444444/#777778 borders, a 3.5px-based space ramp, 2px control strokes, the 1100px layout width). Where the measured surface paints a declared value, the token var-references it; the greys it does not declare (#cccccc secondary fill, #757575 placeholder, #333333 sweep, #808080 rule) are measured. [tools/build_component_tokens.py](tools/build_component_tokens.py) writes the spec [raw/component-tokens.json](raw/component-tokens.json) that [tools/build_tokens.py](tools/build_tokens.py) renders.
- **Components.** [tools/capture/public/measure.mjs](tools/capture/public/measure.mjs) opens each route in a fresh context and reads `getComputedStyle`, painted layers and boxes per element in default, hover, focus-visible and a CDP-forced pressed state, plus `focused`/`filled` on fields (sample text typed and deleted, nothing sent) and `opened` on the Search dropdown, Account drawer, Key Features accordion and mobile menu. Results in [raw/components-computed.json](raw/components-computed.json) and [raw/measurements.md](raw/measurements.md).
- **Screenshots.** [tools/capture/public/public.mjs](tools/capture/public/public.mjs) takes viewport and full-page shots per route, including the opened overlays, with `.capture.json` sidecars kept outside the repository; [tools/capture/quantize.py](tools/capture/quantize.py) posterises them to 256 colours for the repo.
- **Fonts.** 27 @font-face declarations sit in the theme sheets ([raw/css-vars.json](raw/css-vars.json) `fonts`): Neue Haas Grotesk Display Pro (12) and Text Pro (6), plus Elektron's own single faces — **digi one v2** (button labels), **Analog One V2.** (the search field), digi slim, octa one international 12px, skeleton, elektron — and the feather/brandicons/VideoJS icon fonts. The webfonts themselves are not committed.
- The `#thedock-cookie-banner` consent modal was hidden before every reading — never answered.

Nothing was sent, submitted, signed into, bought or downloaded. The only presses were local UI toggles: Search, Account, the Key Features accordion and the mobile menu button. ADD TO CART, EXPLORE, SUBMIT, CONTINUE SHOPPING, Send me a code and Create New Account were measured across their states, never pressed, and checkout was never reached.

## What to distrust

- **One painted theme.** Every captured route paints the same dark ground; the sheets declare no light variant, so the semantic set is emitted under `dark` (the spotify convention for a single painted dark surface).
- **The accent is the paper.** `#eeeef2` is simultaneously text, icon, border and action fill — a design that reads as inverted monochrome. Do not promote it to "white" or a brand colour; the declared `--thedock-*` names call it text/accent.
- **Focus is two rings, not one.** Focus-visible paints `#ffffff 0 0 0 2px` box-shadow *and* a `2px solid #000000` outline offset 2px (dark.focus-ring / dark.focus-outline). Reading only `outline` misses the white half; reading only `boxShadow` misses the black half.
- **The underline is a background-image.** Text links carry a `linear-gradient(#333333,#333333)` layer grown by `background-size` on hover — `text-decoration` stays `none`. Read the sweep as a paint layer, not a text property.
- **Fractional sizes are rem-resolved.** 17.99px, 24.01px, 30.8px, 44.39px and 64.05px are the 1440px resolutions of the theme's rem sizes; they will differ at other root sizes. The token values are the measured 1440px readings.
- **`component.*` tokens are measured**, not site variables — except `component.layout.width`, which var-references `--tdc-layout-width`.
- **Family names are literal.** The search field's family really is `"Analog One V2."` (trailing period) and the button face `"digi one v2"`.
- **Pressed is forced.** `pressed` states come from `CSS.forcePseudoState`; a mousedown-only state (if any) is missing. `product-card` and `accordion` would not hold a real keyboard focus — their focus look is uncaptured, not absent.
- **The WordPress furniture.** The `#21759b` skip-link and `#f1f1f1` skip-link slab in the cart drawer's paint list are WordPress core styling, not Elektron design — not tokenised.
- **Quantised screenshots.** `screenshots/` are 256-colour PNGs; read exact colours from tokens or the raw JSON — the unquantized captures are kept outside the repository.
- **Automation was masked during capture.** Until 2026-11-20, `tools/capture/public/lib.mjs` hid `navigator.webdriver` in every page it opened, so every committed reading was taken with that mask. The mask is removed (a bot check is now recorded as a boundary, not bypassed); whether any page needed it to load is not known, and a recapture without it is the check.

## Do and don't

1. **Do ground on #151515 and keep it monochrome.** Page, header, drawers and footer share the one near-black ground; raised surfaces step only to #1e1e1e/#212121. See [home-dark-default](screenshots/home-dark-default.png) and [account-modal-opened](components/crops/account-modal-opened.png).
2. **Do let the paper do everything.** `#eeeef2` is text, icon, the 2px action stroke and the fill those actions take on hover — the accent is the paper. See [submit-button-default](components/crops/submit-button-default.png) vs [submit-button-hover](components/crops/submit-button-hover.png).
3. **Do keep every corner square.** Buttons, fields, cards and drawers are 0px; the single rounded control on the site is the 7px search field. See [add-to-cart-default](components/crops/add-to-cart-default.png) and [text-field-default](components/crops/text-field-default.png).
4. **Do space on the 7px rhythm.** 7px icon/label gaps, 10.5/17.5px control padding, 21/35/70px section steps. See [header-default](components/crops/header-default.png).
5. **Do set UI text in Neue Haas Text and headings in Neue Haas Display.** 14px/400 for controls and nav, 24-64px Display at 450/500 for headings and the big links, tracking tightening below zero at display sizes. See [section-h2-default](components/crops/section-h2-default.png) and [footer-link-default](components/crops/footer-link-default.png).
6. **Do label actions in digi one v2.** Block-button labels (EXPLORE, ADD TO CART, SUBMIT, SEND ME A CODE) set in the pixel-flavoured digi face, capitals, 14px — never in Neue Haas. See [add-to-cart-default](components/crops/add-to-cart-default.png).
7. **Do fill fields light.** On the dark page the 42px inputs are #eeeef2 slabs with #151515 text; the login drawer's fields invert to #151515 on focus. See [text-field-default](components/crops/text-field-default.png) vs [magic-email-focused](components/crops/magic-email-focused.png).
8. **Don't restyle the focus ring.** Keyboard focus is a double ring — 2px white spread + 2px black outline offset 2px — on every control. See [nav-link-focus-visible](components/crops/nav-link-focus-visible.png).
9. **Don't invent a light theme or a colour accent.** The sheets declare none; every route paints the same dark ground, and no brand hue exists on the surface.

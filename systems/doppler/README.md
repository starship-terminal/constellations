# Doppler design reference

A token set and component reference for Doppler's public site — for building dark, developer-tools marketing, pricing and form surfaces in the style of the real thing. It was read from **www.doppler.com** on **2026-11-13**, signed out, in headless Chromium at 1440 x 900 and 390 x 844: home (with the Platform mega-menu opened), platform/secrets-manager, pricing, the demo request form, agents, integrations, customers, blog and about, plus the mobile captures of home (with the menu opened) and pricing.

Doppler is worth a capture because it is a current reference for the dark secrets-management/dev-tools surface: a warm-black `#1c1624` field with warm-white `#f1f0ec`/silver `#d0c9c4` text, one fluorescent-green CTA recipe (`#00f575` → `#00bf5b` on hover) repeated from the nav to the demo submit, lilac-to-carmine gradient headlines, `.interactive-card` tiles at a 4% warm-white veil with a diagonal sheen, 22px uppercase micro-label chips that flip to light-purple `#b997ff` when selected, the variable Doppler Repro face doing every weight at 450, and a Tailwind bundle that declares the whole palette in named utilities (`bg-warm-black`, `text-silver`, `text-h3`, `text-labelSm`) rather than custom properties.

## Brief

<!-- brief:start. Generated by tools/brief.py from catalog.json, the tokens file and this README; `make brief` rewrites it. Do not edit. -->

Read this before designing in this style. Take every value from [tokens.json](tokens.json), never from the screenshots; `python3 tools/catalog.py export doppler` prints them all with aliases resolved.

### Principles

1. Do ground on the warm black.
2. Do use one CTA recipe.
3. Do build cards as `.interactive-card`.
4. Do keep chips loud and tiny.
5. Don't invent a light theme.
6. Don't reach for a second accent.
7. Don't read a chip's fill off its root.
8. Don't flatten the header.

Each rule links the screenshot or crop that shows it, under [Do and don't](#do-and-dont).

## How the values were read

Every value came off the running signed-out site in headless Chromium:

- **Tokens.** [tools/capture/vars.mjs](tools/capture/vars.mjs) captured every stylesheet body and wrote the declarations to [raw/css-vars.json](raw/css-vars.json) and the named-utility rules (`.bg-warm-black`, `.text-silver`, `.text-h3`, `.text-labelSm`, `border-glow-stroke-light`, `text-code`, …) to [raw/utility-classes.json](raw/utility-classes.json). The bundle keeps only two real custom properties on `:root` — `--global-ease cubic-bezier(0.9, 0.1, 0.1, 0.9)` and `--global-transition 350ms` — so the palette, type scale and radii are read from the utility declarations and the measured components instead. [tools/build_component_tokens.py](tools/build_component_tokens.py) writes the spec [raw/component-tokens.json](raw/component-tokens.json) that [tools/build_tokens.py](tools/build_tokens.py) renders into `tokens.json`.
- **Components.** [tools/capture/public/measure.mjs](tools/capture/public/measure.mjs) opens each route in a fresh context and reads `getComputedStyle`, painted layers and boxes per element in default, hover, focus-visible and a CDP-forced pressed state, plus `focused`/`filled` on the form fields (sample text typed and deleted, nothing sent). The chip fills and card veils live on inner spans and `::before` layers rather than the control itself, so each entry also records the painted descendants (`paint`) and the first text node (`textStyle`). Results in [raw/components-computed.json](raw/components-computed.json) and [raw/measurements.md](raw/measurements.md).
- **Screenshots.** [tools/capture/public/public.mjs](tools/capture/public/public.mjs) takes viewport and full-page shots per route — including the header mega-menu opened by its own trigger's hover and the mobile menu opened by its own toggle — with `.capture.json` sidecars; [tools/capture/quantize.py](tools/capture/quantize.py) posterises them to 256 colours for the repo. The two mobile full pages exceeded the capture bound and were stitched from chunks before quantization.
- **Fonts.** 6 @font-face declarations sit in the bundle ([raw/css-vars.json](raw/css-vars.json) `fonts`), all self-hosted under `/_next/static/media`: **Doppler Repro** — a variable face painting every heading, nav item, button and most body text at computed weight 450/700 — **Doppler Repro Mono** — the inline code chips — and **Inter** — long-form copy such as the demo checklist. The webfonts themselves are not committed.

Nothing was sent, signed into, booked or bought. The only presses were local UI toggles: the Platform nav trigger's own hover, the mobile menu's own hamburger, and the pricing FAQ's resting open row. Start for Free and Sign In point off-site to `dashboard.doppler.com/register` and `/login` and were measured, never followed; the demo form's fields were focused and sample-filled then deleted, and Choose a Time was never pressed; the cookie-preferences banner was hidden before every shot, never answered.

## What to distrust

- **One painted theme.** Every captured route paints the same dark surface; the stylesheet declares no light variant and the vars probe resolved only `dark`, so the semantic set is emitted under `dark` (the bezi/spotify convention for a single painted dark surface).
- **The palette lives in utilities, not variables.** `--global-ease`/`--global-transition` are the only `:root` custom properties; every colour, type step and radius below is read from a named utility declaration or a measured computed value — each token names its source in `$extensions.source`.
- **Computed `color` vs painted text.** Component text is reported from the first text node (`textStyle`), and chip/card fills from painted descendants (`paint`) — a filter chip's own `background-color` is transparent; its `#2d2734` lives on an inner span.
- **A real keyboard focus is a UA ring.** Focus-visible draws Chromium's `auto` outline (`rgb(0, 95, 204)`), not a designed ring; `dark.focus` records it as measured.
- **`component.*` tokens are measured**, not site variables.
- **Font stacks are the hashed names the browser reads.** `core.font.family.*` now carry the computed `fontFamily` (`__DopplerRepro_a18e76, __DopplerRepro_Fallback_a18e76, sans-serif` and so on), which is what `@font-face` declares; the earlier tidied names ("'Doppler Repro'") were typed and no stylesheet declares them.
- **Two readings need a recapture.** `hero-cta` is an outlined "Start for Free" link, not the green hero CTA (its 45px height still feeds `dark.component.control.heightButton`, which says so); `agents-cta` was not found by the last run and its kept states feed `dark.component.control.gap` (`recaptureMissed`).
- **Pressed states are forced.** `:active` was applied with DevTools, so anything a real mousedown would add is unmeasured.
- **Quantised screenshots.** `screenshots/` and `components/crops/` are 256-colour PNGs; read exact colours from tokens or the raw JSON.
- **The dashboard mock-ups are imagery.** The product screenshots and the "Take a self-guided tour" affordance visible in several shots are baked into the marketing artwork, not DOM controls; the real workspace lives behind sign-in.
- **Automation was masked during capture.** Until 2026-11-20, `tools/capture/public/lib.mjs` hid `navigator.webdriver` in every page it opened, so every committed reading was taken with that mask. The mask is removed (a bot check is now recorded as a boundary, not bypassed); whether any page needed it to load is not known, and a recapture without it is the check.

## Do and don't

1. **Do ground on the warm black.** `#1c1624` page with every surface painted on it — header, footer sheet and menu panels all share the field. See [home-dark-default](screenshots/home-dark-default.png).
2. **Do use one CTA recipe.** The `#00f575` fill at 12px radius with warm-black 15/15 bold text — nav pill, hero button, plan CTA and demo submit all use it; hover drops to `#00bf5b`. See [nav-cta-default](components/crops/nav-cta-default.png) and [demo-submit-default](components/crops/demo-submit-default.png).
3. **Do build cards as `.interactive-card`.** The 4% warm-white veil at 20px radius with a diagonal sheen — never a solid panel. See [feature-card-default](components/crops/feature-card-default.png).
4. **Do keep chips loud and tiny.** 22px pills of 10px uppercase micro-labels at +1px tracking — resting `#2d2734`, selected `#b997ff` with black text. See [cat-chip-active-default](components/crops/cat-chip-active-default.png).
5. **Don't invent a light theme.** The bundle declares none; every captured route paints dark.
6. **Don't reach for a second accent.** Green marks CTAs and checks; light-purple marks section heads, selected chips and field focus; orange is reserved for code. They never trade places. See [code-chip-default](components/crops/code-chip-default.png).
7. **Don't read a chip's fill off its root.** The paint lives on inner spans and `::before` layers — the control's own background is transparent (`paint` in the raw JSON).
8. **Don't flatten the header.** The 72px bar floats 14px in from the edge with a `#55505b` glow stroke and 16px bottom corners — it is a separate sheet, not the page's top edge. See [header-default](components/crops/header-default.png).

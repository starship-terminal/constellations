# TokenTracker design reference

A token set, component and pattern reference for TokenTracker's dashboard: a quiet, dense, neutral usage dashboard with one green accent, a borderless sidebar and a rounded content panel. It was read on 2026-10-17 from TokenTracker v1.4.3, the dashboard its CLI serves on the local machine (`http://127.0.0.1:7680`), with no account signed in, in headless Chromium at 1440 x 900 and 390 x 844, both at 2x, in dark (its default) and light. Pages: Tokens (the dashboard), Sessions, Limits, Skills, Settings, Menu Bar & Widgets, Achievements, Pet, Service Status and the signed-out Cloud page, plus the first-run Tokens page from a second, empty install. It refreshes the 2026-10-11 capture of v1.3.5; every reading, screenshot and crop was taken again from v1.4.3.

It is the reference for Quiver's macOS app, which takes TokenTracker's look and most of its features (see "Using it in Quiver").

### Principles

1. Do let the surfaces carry the structure.
2. Do keep green for money and "on".
3. Do keep controls small and quiet.
4. Don't copy the uppercase labels.
5. Don't copy the missing focus ring.

Each rule links the screenshot or crop that shows it, under [Do and don't](#do-and-dont).

## How the values were read

The dashboard is React with Tailwind v3 and ships one same-origin CSS bundle. [vars.mjs](tools/capture/vars.mjs) parses that bundle and resolves every custom property with `<html>` and `<html class="dark">`, which is how TokenTracker switches theme. That gives the brand ramp (`--brand-50` to `--brand-950`, emerald), the status colours and the font stacks.

The rendered neutrals do not come from custom properties. Components use Tailwind classes such as `bg-oai-gray-900`, and `tailwind.config.cjs` maps those to plain hex (Tailwind's neutral: `#fafafa` to `#0a0a0a`). So every surface, text and border token is the computed style of a real element, read per state and theme by [measure.mjs](tools/capture/public/measure.mjs). Hover used the pointer, focus-visible a real keyboard Tab, pressed was forced through DevTools, a field was typed into and cleared.

[census.mjs](tools/capture/public/census.mjs) walks every visible element on ten pages in both themes and counts each colour, shadow, z-index, padding, gap, radius and font size, with where it appears. The spacing scale, the status colours and the z-index layers come from those counts, so a value seen once does not become a token. It also reads the stylesheet's media queries (breakpoints, reduced motion) and the Tailwind colour utilities the bundle ships, which give every ramp but neutral and brand its steps (red, amber, orange, sky, blue and the chart hues).

Look, don't act. Every capture browser aborts any request that is not a read (GET, HEAD, OPTIONS), so no click could save, sync, remove or send anything. The only interactions: period and table tabs, the sidebar chevron, filter selects (closed with Escape), the mobile menu, page sub-navigation, a search typed and cleared, Share then Copy image (drawn and copied inside the headless browser, which has no clipboard, so it reports a failure), one Skills row ticked then its Remove confirmation opened and cancelled with Escape, Skills' Refresh pressed with its requests aborted (to show the error notice), and the Network proxy switched to Manual in the page, an invalid host typed and checked with Test connection, then cleared and switched back without saving. The loading and error states are Sessions with its request held back or aborted in the capture browser. The first run is a second TokenTracker started with an empty home folder on port 7681.

The dashboard shows the owner's real usage. Before every screenshot, crop and reading, [lib.mjs](tools/capture/public/lib.mjs) replaces home-directory paths, session and project titles and installed skill names in the page, using a redaction file kept outside the repository. Usage figures, model names and plan names are left as they were. Leaderboard shows other people's names and photos, so only its avatar component was read: photo requests were blocked so each avatar fell back to the product's initials circle, every name and initial in the page was replaced, and no screenshot of the page was kept. Claude IP Check (the machine's IP address and location) was not captured.

Screenshots are 256-colour PNGs. Flat UI colours survive exactly; read values from the tokens, not the images.

## What to distrust

- **The green-tinted greys.** TokenTracker's own `DESIGN.md` and `styles.css` describe a green-tinted neutral ramp (`--oai-gray-*`, oklch hue 145). The components do not render it; they render plain Tailwind neutral hex. The tinted ramp is kept under `core.$extensions.notTokenised` and is not the look.
- **The source on disk is older than the app.** The running dashboard is v1.4.3; the TokenTracker checkout on this machine is 1.2.2. Where the two differ, the live readings win. Values from the source only are marked Derived: the 72px collapsed sidebar, the content widths and the 12-column Tokens grid.
- **Focus is mostly absent.** `styles.css` removes outlines and Tailwind rings on every element. Only the sidebar's theme toggle, star pill and collapse chevron, and the Cloud page's controls, draw a ring (2px solid, 2px out). Its colour is not the same on all four: the theme toggle and star pill draw it in the ink colour (`focus.ring`, #fafafa dark, #0a0a0a light), the Cloud button in #f5f5f5 dark and #171717 light, and the collapse chevron in #737373 in both themes, the chevron's own grey (`raw/components-computed.json`, `focus-visible`). Light text fields turn their border emerald on focus; dark ones do not change. Every other `focus-visible` reading equals its default.
- **The dark census missed most of Limits.** It counted 20 text elements there (the shell, the title and the subtitle) against 143 in light, though the dark screenshots show the full page. The size scale, the spacing scale and the counted type styles are all built from the dark census, so they leave out the Limits usage list. The light census passes the 10-element bar for `font.scale` at two more sizes: 9px (13 elements, on Limits and Pet) and 10.5px (11, Limits code blocks and buttons). Neither has a scale step; 10.5px is also `font.size.code`, which sits off the scale.
- **Status colours are uneven.** Danger has the full set: a solid fill (toast, danger button) and an error notice with surface, border and text (Skills, shown by pressing Refresh with its requests aborted). Warning has the Limits notice's amber surface and border; its text stays neutral. Success is green text only. Info (the sky update badge on Skills) appears only when a skill has an update, which none had, so it is not captured.
- **The toast is the failure toast.** Copy image cannot reach a clipboard headless, so the product showed "Couldn't generate image" in red. The success toast was not reached.
- **Light secondary text is just under AA on the wash.** `text.secondary` (`#737373`) is 4.34:1 on `bg.wash` (`#f5f5f5`) and passes on the panel and cards. That is the product's value.
- **Provider colours** (Claude orange, Codex blue, OpenCode purple) come from a JavaScript map, not CSS. They are not tokenised; the style guide's share bar uses illustrative values.

## Fonts

| Family | Used for |
|---|---|
| System UI (`-apple-system, BlinkMacSystemFont, "Segoe UI", Roboto, …`) | Everything. On macOS this is SF Pro. Numbers use `tabular-nums`. |
| SF Mono, then `ui-monospace`, Menlo | Code blocks and terminal copy on Limits, and one large figure on Achievements. |

No font file is needed. The bundle also declares Geist Mono faces, but no rendered element uses them. `font.family.sans` is the `--oai-font-sans` variable; most rendered text computes to `"OpenAI Sans", -apple-system, system-ui, …` instead, a face the bundle does not ship (its only `@font-face` rules are the 24 Geist Mono faces). About 510 elements per theme use Tailwind's `ui-sans-serif, system-ui` stack (`raw/census.json` `totals.*.family`). On a Mac without OpenAI Sans installed, all of them render the system font.

## Icons

Lucide, through `lucide-react` (declared as `^1.48.0` in the TokenTracker source's `dashboard/package.json`), licensed ISC according to the npm registry (`npm view lucide-react license`, read 2026-10-17). Stroke 2 (the sidebar's collapse chevron 1.5), drawn in `currentColor`, 15px in the sidebar and 14 to 16px in most controls (11px on an Achievements button, 13px on Skills' clear-search button). [icons/INDEX.tsv](icons/INDEX.tsv) lists each icon by name with its sizes, the pages it was seen on and its place (nav link, button, field). Provider logos, the pet and the menu bar art are brand material and were not collected ([RIGHTS.md](../../docs/RIGHTS.md)). The fonts are the operating system's own (SF Pro and SF Mono on macOS), so no font file or licence is needed; the fallback stacks are in `font.family.*`.

## Motion and reduced motion

Colour changes on hover run 150ms (`motion.duration.fast`: nav, tabs, selects, the primary, icon and retry buttons, the settings text field) or 200ms (`base`: the outlined, danger, cancel and Cloud buttons, tiles, the search field) on `motion.easing.standard`. The cost dialog eases in over 260ms (its opacity over 220ms) and the confirm dialog over 220ms, both on `motion.easing.emphasized`. Under `prefers-reduced-motion: reduce` the fade and modal keyframe animations stop, the Cloud page's action popup and backdrop drop their transitions and entry transform, and the plan cards' hover glow stops; spinners and the sidebar's width and position transitions only run under `no-preference`. Hover colour transitions do not change. The rules are listed in `core.$extensions.notTokenised.reducedMotion`.

## Do and don't

1. **Do let the surfaces carry the structure.** Wash, panel and card differ by one neutral step plus a hairline (in dark, panel and card are both #171717, so only the hairline separates them); the only resting shadow is `0 1px 2px` at 5%. See [dashboard-dark-default](screenshots/dashboard-dark-default.png) and [settings-light-default](screenshots/settings-light-default.png).
2. **Do keep green for money and "on".** Cost figures, the usage fill, switch tracks and the heatmap are green. The primary button is black in light and white in dark, never green; red is kept for the destructive confirm and failures. See [dashboard-light-default](screenshots/dashboard-light-default.png) and [skills-light-confirm](screenshots/skills-light-confirm.png).
3. **Do keep controls small and quiet.** Tabs, segments and the outlined Share button are 12/16 medium on 28 to 32px, 8px radius (table tabs 4px); the dialog buttons are 14/20 on 32px and the primary button 14/20 on 40px with a 12px radius. Hover changes colour only. See [settings-dark-segment-hover](screenshots/settings-dark-segment-hover.png).
4. **Don't copy the uppercase labels.** The older cards ("ACTIVITY HEATMAP", "USAGE TREND"), the hero label, sidebar group labels and Settings card titles use small tracked uppercase. TokenTracker's newer cards title themselves in sentence case at 14/500 primary. Use sentence case everywhere. See [dashboard-dark-full](screenshots/dashboard-dark-full.png).
5. **Don't copy the missing focus ring.** Most controls draw none. Give every control the ring the theme toggle already draws: 2px solid in the ink colour, 2px out (`focusRing.*`, `focus.ring`). See [theme-toggle-focus-visible](components/crops/theme-toggle-focus-visible.png).

## Criteria a capture cannot close

Five scorecard criteria stay at partly after two capture rounds (2026-10-17, [PR 11](https://github.com/c-wenlong/designs/pull/11) and [PR 20](https://github.com/c-wenlong/designs/pull/20)). Each gap comes from the product, so another capture would not change it; only a change to TokenTracker would.

| Criterion | Why it stays partly | What would close it |
|---|---|---|
| F1 Colour ramps | The stylesheet ships only the steps the product uses: red and amber stop at 8, several chart hues at 1 or 2. The missing steps would have to be invented | TokenTracker shipping fuller ramps |
| F6 Status colours | Info (the sky update badge on Skills) renders only when a skill has an update, and none had one. Success is green text only, with no fill or border anywhere | A skill update on this machine (then recapture Skills for info); success surfaces in the product |
| F8 Type scale | The scale holds the 9 sizes that at least 10 rendered elements use in dark; the rubric asks for 6 to 8. `figure` (20px) and `code` (10.5px) sit off the scale, and light passes 10 elements at two more sizes (9px, 10.5px) | TokenTracker consolidating its sizes |
| F15 Contrast | Light `text.secondary` (`#737373`) is 4.34:1 on `bg.wash` (`#f5f5f5`), under 4.5:1. That is the product's colour | TokenTracker darkening its secondary text |
| C3 Focus | `styles.css` removes the focus ring on every element; only the theme toggle, star pill, sidebar chevron and Cloud page draw one | TokenTracker restoring focus rings |

Before the next refresh, check whether a skill shows an update badge: that is the one gap a capture could still narrow.


```bash

```

```bash
python3 tools/build_components_md.py
```

The builders are deterministic: re-running them reproduces their files byte for byte. Edit the raw inputs or the builders, never the generated files. `build_components_md.py` reads `tokens.json`, so run it last.

To capture again, start TokenTracker's dashboard with `npx tokentracker-cli serve --no-open --no-sync`. Its first run installs hooks into Claude Code, Codex and OpenCode on the machine; remove them afterwards if they were not wanted. For the first-run screens, start a second one with an empty home folder: `HOME=<empty dir> npx tokentracker-cli serve --port 7681 --no-open --no-sync`. Put the redaction file at `~/.design-systems/tokentracker-redact.json` (shaped like the kit's `redact.example.json`). The crops are quantized by `python3` with Pillow, so put an environment that has it first on `PATH`. Then:

```bash
export PLAYWRIGHT=~/.design-systems/pw/node_modules/playwright/index.mjs
```

```bash
RAW=~/.design-systems/tokentracker/raw-shots node tools/capture/public/public.mjs && python3 tools/capture/quantize.py ~/.design-systems/tokentracker/raw-shots
```

```bash
node tools/capture/public/census.mjs && node tools/capture/public/measure.mjs && node tools/capture/public/build-measurements.mjs && node tools/capture/icons.mjs
```

`vars.mjs` reads a copy of the CSS bundle: fetch `/assets/*.css` from the running dashboard with curl, wrap it in `<style>` in `SNAPS/bundle.html`, then run `SNAPS=… node tools/capture/vars.mjs`.

## Brief

### Principles

1. Do separate surfaces with a 2px border and keep them flat.
2. Do give each card, dialog or footer at most one filled button.
3. Do keep uppercase for actions, navigation and small status labels.
4. Do mark selection in blue and save green for the verdict.
5. Do let the answer verdict recolour the whole lesson footer.
6. Do turn the button white on a coloured surface.

Each rule links the screenshot or crop that shows it, under [Do and don't](#do-and-dont).

## How the values were read

Duolingo writes its whole palette onto `<html>` as `--color-NAME: r, g, b` triplets and swaps them when `data-duo-theme` changes. The palette in [tokens.json](tokens.json) comes straight from the object in the app's JS bundle that holds both values for every name. The light values were checked against the live variables (300 of 300 match), and the dark values against every node that used them. Component measurements are computed styles: a script walked every visible element at each page and state, and the result was saved as a dump. Hover, focus, selected and disabled states were held live where possible. Pressed states, and anything a static page cannot hold, come from the app's own CSS rules, found by matching each element's hashed class names in the downloaded stylesheets. Every token and spec row names its source. Nothing was sampled from a screenshot, so no token is marked estimated. Values derived from CSS where no live capture existed say `derived, not captured`.

### The 2026-10-17 refresh

The refresh used the library's signed-in route ([docs/CAPTURE.md](../../docs/CAPTURE.md)): the owner signed in to the built-in browser pane, and Claude read values there and copied each state to disk with [tools/capture/signed-in/snapshot.js](tools/capture/signed-in/snapshot.js) (redaction applied by [unsnap.py](tools/capture/signed-in/unsnap.py), which refuses a copy that still holds a private string), then rendered the copies headless at 2x with [render.mjs](tools/capture/signed-in/render.mjs). The account's theme setting follows the system colour scheme, so light and dark were switched by emulating `prefers-color-scheme` in the pane; the account setting was never changed. The palette was read live in both themes from `<html style>` and matches tokens.json 300 of 300 in each (the two `refresh` entries are named `--color-daily_refresh*` live), so the dark values are now checked against the live variables too. Focus states were measured by pressing Tab for real and diffing the focused element against its resting styles ([components/focus.md](components/focus.md)). The onboarding flow was captured logged out, in a fresh headless browser with no account ([tools/capture/onboarding.mjs](tools/capture/onboarding.mjs)). New and changed tokens are applied by [tools/refresh_tokens_2026_10.py](tools/refresh_tokens_2026_10.py), and each names its source and evidence label (Measured or Derived).

The screenshots were converted from the display's P3 profile to sRGB and stored as 256-colour PNGs to keep the repo small. Flat UI colours are exact, but gradients in illustrations can band slightly, so read exact values from the tokens or the dumps, not from the images.

## What to distrust

- **Derived tokens.** `accent.*.hover` is the face colour put through the button's `filter: brightness(1.1)`, worked out from the palette; the product applies a filter, so the pixel colour can differ slightly where the face is anti-aliased. `ramp.*` groups palette colours Duolingo never groups into ramps: eight hues, 5 to 10 steps each in light, every step a colour the palette holds (none interpolated), ordered by CIE L* in each theme. Some steps carry feature names (`gray-text`, `eddy-radio`, `lily-radio`) because those are the only palette entries at that lightness. `border.strong` is hare, the one neutral edge darker than swan; Duolingo draws it on three rules only: the ghost avatar's dashed border, a chip's hover border and a 40%-opacity divider. `status.*Border`, `status.infoText` and `status.warningText` are roles assigned from the component that draws that colour; Duolingo has no status component with its own border.
- **Light warning and light wrong-answer colours** come from CSS and the palette, not from a light capture (no wrong answer was given, to keep the account's hearts).
- **Focus in [components/core.md](components/core.md).** Its state tables were written before the 2026-10 keyboard pass, so their focus rows still cite CSS rules or say not captured. The live readings are in [components/focus.md](components/focus.md), and they agree with those rows (no visible change) except on the Characters underline tabs: core.md lists their `:focus` rule (label and rule turn macaw), but the tabs take no keyboard focus, so that state never shows.
- **The 2026-10 screenshots are renders of page copies**, not window captures: scripts are removed, so animated illustrations are frozen where the snapshot caught them, and the fonts are the same CDN files the app loads, declared again by [lib.mjs](tools/capture/signed-in/lib.mjs). The 2026-09 screenshots carry the capture tool's orange edge glow and pointer.
- **Gem and XP totals** in the 2026-10 renders were replaced with round numbers by the redaction file; other learners' names and avatars are masked.
- **The Guidebook renders show an "Using an ad blocker?" card** in the right rail where other pages show the Super promotion. Duolingo showed it because ad requests did not load in the capture browser; it is the product's own UI, but a session with ads loading shows the Super card there. The 2026-09 captures show the same card lower in the rail on other pages (for example [shop-light-default](screenshots/shop-light-default.png)).
- **Onboarding** was taken from a logged-out session in a headless browser; the answer lists (for example "How did you hear about Duolingo?") are localised by region and shuffled per session.

## Fonts

The app uses `duolingo-sans` for all UI text (one variable upright file serving 400 and 700, plus an italic) and `feather` 700 as a display face, seen on the logged-out marketing page. Both are proprietary and are not committed. The stacks the app declares are `duolingo-sans, sans-serif` and `feather, sans-serif` (`core.fontFamily`). The app has no code or monospace role. The style guide looks for them in a local `fonts/` folder next to it (gitignored) and falls back to Nunito from Google Fonts, showing a notice when it does. [tokens-notes.md](tokens-notes.md#fonts) says which CDN file is which.

## Do and don't

1. **Do separate surfaces with a 2px border and keep them flat.** Resting cards, rail panels and tiles share the page fill and are outlined in `border.default`; every shadow in the token set is a zero-blur lip, and the quit modal sits on the 40% black scrim with no shadow of its own. See [learn-light-default](screenshots/learn-light-default.png), [quests-dark-default](screenshots/quests-dark-default.png) and [lesson-light-quit-modal](screenshots/lesson-light-quit-modal.png).
2. **Do give each card, dialog or footer at most one filled button.** The other action is an outline button or bold uppercase coloured text: SKIP beside CHECK, END SESSION under KEEP LEARNING, CANCEL beside REMOVE, VIEW LEAGUE on rail cards. Row actions such as REMOVE on the courses list are red uppercase text with no button frame. See [lesson-light-select-selected](screenshots/lesson-light-select-selected.png), [lesson-light-quit-modal](screenshots/lesson-light-quit-modal.png) and [settings-courses-light-remove-confirm](screenshots/settings-courses-light-remove-confirm.png).
3. **Do keep uppercase for actions, navigation and small status labels.** Buttons, sidebar items, text links and eyebrows ("COMPLETED!", "NEW WORD") are bold uppercase with 0.56 to 0.8px tracking. Page titles, card titles, settings labels and body copy stay in sentence or title case. See [settings-account-light-default](screenshots/settings-account-light-default.png) and [sections-dark-default](screenshots/sections-dark-default.png).
4. **Do mark selection in blue and save green for the verdict.** A picked choice card, the current sidebar item and the chosen settings card get the selected fill, a blue border and blue text in both themes. Green is the verdict: the same card turns green only after CHECK confirms the answer. See [lesson-light-select-selected](screenshots/lesson-light-select-selected.png), [lesson-light-feedback-correct](screenshots/lesson-light-feedback-correct.png) and [radio-card-selected-dark](components/crops/radio-card-selected-dark.png).
5. **Do let the answer verdict recolour the whole lesson footer.** After CHECK the footer band takes the verdict background, the title and the TOO EASY / REPORT links take the verdict colour, and CONTINUE turns green or red to match. See [lesson-light-feedback-correct](screenshots/lesson-light-feedback-correct.png) and [lesson-dark-feedback-incorrect](screenshots/lesson-dark-feedback-incorrect.png).
6. **Do turn the button white on a coloured surface.** On the green node popover the button is a white face with a green label (START +10 XP); on the Super cards it is white with a dark navy label (LEARN MORE, UNLOCK). On a unit banner the button is an outline in a darker shade of the banner (GUIDEBOOK). The original token builder read the full scratch inputs and is not shipped, so `tokens.json` is the source of record. `refresh_tokens_2026_10.py` applies the 2026-10 additions to it, `tokenize_specs.py` puts the token in front of every colour in `components/*.md` and `components/*.json`, and `build_focus_md.py` writes `components/focus.md` from the two focus logs; all three change nothing when run again. `build_style_guide.py` renders the page from `tokens.json` and `tools/style-guide.template.html`. `build_components_md.py` assembles `components.md` from `components/core.*` and `components/product.*` (JSON and Markdown), `icons.md`, `tokens-notes.md` and `raw/discovery.md`.

`tools/capture/` holds both capture kits. The 2026-09 one: the in-page extraction script (`extract.js`), the local sink that saved dumps to disk (`sink.py`), the window screenshot cropper (`shot.py`), a dump query helper (`q.py`) and the CSS parser (`parse_css.py`). The 2026-10 one: `live-measure.js` and `tab-pass.js` (pasted into the signed-in page; the second records the keyboard focus pass), `signed-in/` (snapshot, unsnap, render and `measure-copies.mjs`, adapted from the library kit by way of systems/linear), `onboarding.mjs` (the logged-out flow), `css_evidence.py` and `quantize.py`. The page copies, the downloaded stylesheets and the redaction file live in `~/.design-systems/`, outside the repository.

## Use in Figma

Import `tokens.json` with Tokens Studio and choose the Light or Dark theme. Set fonts to duolingo-sans (or Nunito as a stand-in). The one component rule to get right is the 3D button: a solid face with a same-hue darker lip underneath (4px on primary buttons, 2px border plus a 2px lip on outline buttons), which collapses by that amount on press. Anything the capture could not reach is listed under Gaps in [components.md](components.md#gaps).

# Base44 design reference

A token set and component reference for Base44's public site — for building AI-app-builder marketing, pricing and sign-in surfaces in the style of the real thing. It was read from **base44.com** on **2026-11-11**, signed out, in headless Chromium at 1440 x 900 and 390 x 844: the home page (with the Product menu opened), features, use cases, enterprise, blog, pricing (Yearly and Monthly), superagents and the sign-in page at app.base44.com/login.

Base44 is worth a capture because its bundle ships a complete, readable token system rather than utility soup: shadcn channel roles (`--background`, `--primary`, …) that carry the theme split, a named palette (`--ink-100..900`, `--blue-*`, `--orange-*`, `--cta-*`, `--text-*`, `--surface-*`), named scales for radius, space, elevation, motion and fonts, all on a warm paper ground (`#f9f8f6`) with Dazzed display type, near-black 38px CTAs, an orange `#ff773c` accent and a signature hero prompt composer.

## Brief

<!-- brief:start. Generated by tools/brief.py from catalog.json, the tokens file and this README; `make brief` rewrites it. Do not edit. -->

Read this before designing in this style. Take every value from [tokens.json](tokens.json), never from the screenshots; `python3 tools/catalog.py export base44` prints them all with aliases resolved.

### Principles

1. Do ground on warm paper.
2. Do use the dark CTA recipe.
3. Do reserve orange for action.
4. Do set display type in Dazzed.
5. Do compose the prompt box as a card.
6. Don't invent a painted dark theme.
7. Don't read the toggle's orange off the button.
8. Don't drop the focus ring.

Each rule links the screenshot or crop that shows it, under [Do and don't](#do-and-dont).

## How the values were read

Every value came off the running signed-out site in headless Chromium:

- **Tokens.** [tools/capture/vars.mjs](tools/capture/vars.mjs) captured every stylesheet body — the bundle ships as same-origin hashed chunks, so the CSSOM reads every rule — re-parsed them, and wrote every custom property to [raw/css-vars.json](raw/css-vars.json) binned `token`/`app`/`tw`/`utility`. Each name is resolved the way the browser resolves it in a probe carrying the real sheets: once on `:root` (light) and once inside a `.dark` wrapper (the bundle's declared-but-unpainted dark variant). The shadcn channel values (`40 20% 97%`, consumed as `hsl(var(--background))`) are resolved to sRGB in the probe. [tools/build_component_tokens.py](tools/build_component_tokens.py) writes the spec [raw/component-tokens.json](raw/component-tokens.json) that [tools/build_tokens.py](tools/build_tokens.py) renders: palette and semantic paints under `core.color.*`, the scales under `core.{radius,space,elevation,duration,easing,fontWeight,fontFamily,layout}`, composite type styles under `core.typography`, the channel roles under `light.*` and `dark.*`, and measured component metrics under `light.component.*`.
- **Components.** [tools/capture/public/measure.mjs](tools/capture/public/measure.mjs) opens each route in a fresh context and reads `getComputedStyle`, painted layers and boxes per element in default, hover, focus-visible and a CDP-forced pressed state, plus `opened` on the Product mega menu and the mobile menu, `expanded` on an FAQ item, and `focused`/`filled` on fields (text typed then deleted, nothing sent). Results in [raw/components-computed.json](raw/components-computed.json) and [raw/measurements.md](raw/measurements.md); each entry also carries the painted text child's style.
- **Screenshots.** [tools/capture/public/public.mjs](tools/capture/public/public.mjs) takes viewport and full-page shots per route, including the opened Product menu, the Monthly billing state and the mobile menu, with `.capture.json` sidecars; [tools/capture/quantize.py](tools/capture/quantize.py) posterises them to 256 colours for the repo.
- **Fonts.** Webfonts are declared in the bundle ([raw/css-vars.json](raw/css-vars.json) `fonts`): **Dazzed** (and Dazzed VF) for every display headline, **Geist** for UI text, **JetBrains Mono**, and **WixMadeforText** (the Wix house face) as a secondary UI stack.

Nothing was sent, downloaded, signed into or trialled. The only presses were local UI toggles: the Product nav menu, the billing segment, one FAQ item and the mobile menu. The prompt composer was never sent; the sign-in page's email field was focused and filled then cleared; the OAuth buttons and the disabled email submit were never pressed.

## What to distrust

- **Readings past a masked bot signal.** The committed screenshots and readings were taken with `navigator.webdriver` masked, the flag bot checks read to spot automation. The capture scripts no longer mask it (not run since), so a recapture may record a walled route as a boundary instead of a reading.
- **One painted theme.** Every captured route paints light; the `dark` token set is emitted from the bundle's declared `.dark` block (standard shadcn dark channels, charts and sidebar) and labelled declared-not-painted — no screenshot or component evidence exists for it.
- **App-side `--sem-*` vars.** Utility classes reference a second semantic layer (`--sem-text-icon-*`, `--sem-surface-*`, …) that is only declared inside the product app; on the marketing bundle those names resolve empty. They are recorded in css-vars.json but not tokenised.
- **`component.*` tokens are measured**, not site variables.
- **The billing segment's orange fill** rides on a sliding indicator element behind the buttons; the selected button itself stays transparent. `core.measured.toggle-shell` is the track colour.
- **Quantised screenshots.** `screenshots/` are 256-colour PNGs; read exact colours from tokens or the raw JSON.

## Fonts

Declared in `raw/css-vars.json` (`fonts`, 12 faces): **Dazzed** and **Dazzed VF** — every headline measured (`"Dazzed","Dazzed Fallback",sans-serif`, tracked −0.033em) — **Geist** — the UI and fields (`"Geist",system-ui,sans-serif`) — **JetBrains Mono** and **WixMadeforText**. The guide renders system fallbacks; the webfonts themselves are not committed.

## Do and don't

1. **Do ground on warm paper.** `#f9f8f6` (`light.background`), near-black `#0f0f0f` ink, white cards. See [home-light-default](screenshots/home-light-default.png).
2. **Do use the dark CTA recipe.** Near-black `#312f2f` (`color.cta.black`), 38px high, 8px radius, white text — nav, plan cards and the site all use it. See [nav-cta-default](components/crops/nav-cta-default.png).
3. **Do reserve orange for action.** `#ff773c` (`color.cta.orange`) paints the send button, the selected billing segment and the wordmark dot; `#3b51e5` blue paints links and badges. See [prompt-submit-default](components/crops/prompt-submit-default.png).
4. **Do set display type in Dazzed.** ~94px/600 hero tracked −0.033em, section titles the same recipe smaller. See [hero-title-default](components/crops/hero-title-default.png).
5. **Do compose the prompt box as a card.** White surface, small radius, a button row of icon buttons and the orange send — it is the site's signature control. See [prompt-box-default](components/crops/prompt-box-default.png).
6. **Don't invent a painted dark theme.** The dark set is declared tokens only; the public site never renders it.
7. **Don't read the toggle's orange off the button.** The selected segment's fill is a sliding indicator behind the buttons; the button itself stays transparent.
8. **Don't drop the focus ring.** Keyboard focus is a visible 2px `#1e1e24` outline offset 4px on every nav and card control (2px `#3b51e5` on the sign-in OAuth buttons).

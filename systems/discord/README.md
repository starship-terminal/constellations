# Discord design reference

A token set and component reference for Discord's public surface — for building chat-community apps, server-discovery grids, auth cards and marketing heroes in the style of the real thing. It was read from **discord.com** on **2026-11-15**, signed out, in headless Chromium at 1440 x 900 and 390 x 844. Captured: the marketing pages (/, /download, /nitro), the server-discovery pages (/servers, /servers/gaming), a /servers/<slug> detail page, the /login and /register auth cards, and 390px passes on the home page and discovery.

Discord is worth a capture because it ships its real design-token layer to the browser — and because the site is two products in one. The marketing pages are a Webflow build in Ggsans/ABC Ginto over the brand palette; the app surfaces run the real Discord design system: "gg sans" body text, "ABC Ginto Discord Nord" display type, `:root` hue scales (`--neutral-1..100`, `--blurple-1..100`, `--plum-0..26`, the `--*-new-1..100` families, `--illo-*`, `--opacity-*`, `--brand-*`, `--primary-*`) and class-scoped semantic blocks `.theme-light`/`.theme-darker`/`.theme-dark`/`.theme-midnight` carrying `--background-base-*`/`--background-surface-*`/`--background-mod-*`, `--text-*`, `--border-*`, `--badge-*`, `--button-*`, `--input-*`. 4,469 variables resolve per theme — and unlike most products, both themes really paint signed out: app surfaces carry `.theme-dark.theme-darker` while the marketing chrome injected into them sits under a `.theme-light` root. The app paints a `#121214`/`#202024` base with `#efeff1` ink, `#fbfbfb` strong text, `#5865f2` blurple on Join/Log In (`#4752c4` hover), `rgba(151,151,159,0.16)` selected pills, `#43b581` online green and 2px `#6aa8f4` focus rings; the auth card is an oklab `#26282c`-ish panel on the animated brand backdrop. **Boundary:** the whole client needs an account — /channels/* redirects to /login, invites are not accepted, and joining, sharing, and Nitro purchase gate on sign-in; every button was measured, never pressed. The app's standalone light surface (the account theme setting) and `.theme-dark`/`.theme-midnight` variants are declared but unpainted signed out.

### Principles

### Using tokens

| Role | light | dark |
|---|---|---|
| page | #ffffff `light.background.page` | #121214 `dark.background.page` |
| surface | #1a1a1e `light.background.card` | #202024 `dark.background.card` |
| text | #000000 `light.text.ink` | #efeff1 `dark.text.ink` |
| muted | #6c6d76 `light.text.muted` | #abacb2 `dark.text.subtle` |
| accent | #5865f2 `light.action.primary` | #5865f2 `dark.action.primary` |
| border | rgba(151, 151, 159, 0.28) `light.border.subtle` | rgba(151, 151, 159, 0.12) `dark.border.card-line` |

Fonts: `core.font.family.ui` is gg sans, then 5 fallbacks; `core.font.family.marketing-display` is Abcgintodiscord, then 1 fallback. Scales, counted as [DESIGN.md](DESIGN.md) holds them: no type styles under `core.typography`, 13 radius steps (`core.radius`), 27 spacing steps (`core.space`).

### Using components

Read [components.md](components.md) for the component inventory; [patterns.md](patterns.md) for how components combine into screens; 98 element crops in [components/crops/](components/crops); [style-guide.html](style-guide.html), which renders every token and the main components.

### Accessibility

| Theme | text on page | text on surface | muted on page | muted on surface |
|---|---|---|---|---|
| light | 21.00:1 pass | 1.21:1 fail | 5.13:1 pass | 3.37:1 fail |
| dark | 16.29:1 pass | 14.13:1 pass | 8.26:1 pass | 7.17:1 pass |

6 of 8 pairs pass 4.5:1 (WCAG AA for body text), the pairs the scorecard's F15 check grades. Focus tokens: `dark.focus.dark` #6aa8f4; `dark.focus.light` #6aa8f4; `light.focus.dark` #408eec; `core.focus.border` #00b0f4.

## How the values were read

1. **Harvest.** `tools/capture/vars.mjs` reads every served stylesheet across / and /servers (discord.com serves CSS same-origin), classifies each custom property (theme / app / skins / vendor), and resolves the `plain`, `.theme-light` and `.theme-darker` declarations in [raw/css-vars.json](raw/css-vars.json) — hsl()/oklab() colours normalise to hex.
2. **Measure.** `tools/capture/public/measure.mjs` opens each public route signed out at 1440 x 900 (390 x 844 for the mobile pass) and records computed styles plus a crop per state — default, hover, focus-visible, DevTools-forced pressed, plus focused/filled search and auth fields — into [raw/components-computed.json](raw/components-computed.json).
3. **Shoot.** `tools/capture/public/public.mjs` captures default viewport and `-full` shots per surface into [screenshots/](screenshots).
4. **Build.** `tools/build_component_tokens.py` turns the harvest + measurements into [raw/component-tokens.json](raw/component-tokens.json); `tools/build_tokens.py` writes [tokens.json](tokens.json) with `core`/`light`/`dark` sets; `tools/build_components_md.py`, `tools/build_style_guide.py` and `capture/public/build-measurements.mjs` generate the docs. Re-running the builders is a no-op by design.

**Automation was masked during capture.** Until 2026-11-20, `tools/capture/public/lib.mjs` hid `navigator.webdriver` in every page it opened, so every committed reading was taken with that mask. The mask is removed (a bot check is now recorded as a boundary, not bypassed); whether any page needed it to load is not known, and a recapture without it is the check.

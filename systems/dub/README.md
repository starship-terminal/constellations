# Dub design reference

A token set and component reference for Dub's public surface — for building marketing pages, docs surfaces and auth screens in the style of the real thing. It was read from **dub.co** on **2026-11-13**, signed out, in headless Chromium at 1440 x 900 and 390 x 844. Captured: the home, links, partners, pricing, customers, enterprise, compare, contact-sales, blog and changelog marketing pages, the login and register auth cards on the app.dub.co shell (measured, never submitted), a 390px mobile pass, and the Mintlify docs/help surface on `/docs` and `/help` — measured in both its light and dark themes through the page's own theme dropdown.

Dub is worth a capture because the public surface is three different stacks that share one restrained look. The marketing site is Next.js + Tailwind v4 declaring a real semantic token layer — Dub's own `--bg-*` / `--content-*` / `--border-*` set plus a shadcn `--background` / `--foreground` / `--primary` layer — while painting everything on a near-white `#fafafa` field with a black `#000` button fill, 8px radii and quiet `#e5e5e5` borders; its headings run Satoshi 48/55.2 at weight 500 over Inter body text. The auth cards paint the app.dub.co shell in a plain `ui-sans-serif` system stack — 38px fields at 6px radius that take a black border plus a 1px black ring on focus. The docs surface is Mintlify on a `--gray-50..950` ramp with `#155dfc` accents, oklab color-mix washes and the site's only real theme toggle. **Boundary:** the link-management workspace (links, analytics, domains, settings, billing) lives behind `/login` on app.dub.co and was never reached; nothing was filled, sent or submitted.

## Brief

<!-- brief:start. Generated by tools/brief.py from catalog.json, the tokens file and this README; `make brief` rewrites it. Do not edit. -->

Read this before designing in this style. Take every value from [tokens.json](tokens.json), never from the screenshots; `python3 tools/catalog.py export dub` prints them all with aliases resolved.

### Principles

1. Do paint the field near-white.
2. Do make the primary action black.
3. Do paint the halo on marketing and auth CTAs, not a darker fill.
4. Do give fields the quiet focus pair.
5. Do run Satoshi tight for display.
6. Do keep `#155dfc` inside the docs surface.
7. Do use the gray ramp for docs chrome.
8. Don't mix the three stacks.
9. Don't reach for shadows.
10. Don't style the workspace from this package.

Each rule links the screenshot or crop that shows it, under [Do and don't](#do-and-dont).

## How the values were read

Every value came off the running signed-out site in headless Chromium:

- **Tokens.** [tools/capture/vars.mjs](tools/capture/vars.mjs) captures every stylesheet body (the Next.js `/_next/static/immutable/chunks/*.css` bundles on dub.co and app.dub.co, the Mintlify `/_mintlify/assets/*.css` bundle, the api.fontshare.com sheet from network responses, inline `<style>` blocks re-parsed with `CSSStyleSheet`) and writes every custom property to [raw/css-vars.json](raw/css-vars.json), resolved in a probe carrying the real sheets once plain (`:root`/`.light`) and once with a `dark` class — the same class the docs theme toggle sets on `<html>`. Both layers are genuinely declared — Dub's semantic `--bg-*`/`--content-*`/`--border-*` + shadcn set and the Mintlify `--gray-*`/`--font-*`/`--twoslash-*` set — so most tokens are declared variables; the Tailwind neutral ramp and the oklab washes the pages actually paint are atomic classes and color-mixes with no variable, so those are measured computed values. [tools/build_component_tokens.py](tools/build_component_tokens.py) writes the spec, [tools/build_tokens.py](tools/build_tokens.py) the sets.
- **Components.** [tools/capture/public/measure.mjs](tools/capture/public/measure.mjs) opens each route in a fresh context and reads `getComputedStyle`, painted layers and boxes per element in default, hover, focus-visible and a CDP-forced pressed state (fields also `focused`/`filled` — sample text typed and deleted), across the marketing pages, the auth cards, the contact-sales form, the docs surface in both themes and mobile. Results in [raw/components-computed.json](raw/components-computed.json) and [raw/measurements.md](raw/measurements.md).
- **Screenshots.** [tools/capture/public/public.mjs](tools/capture/public/public.mjs) takes viewport and full-page shots per route with `.capture.json` sidecars, including the local UI toggles: the Product mega-menu on hover, the mobile menu, the Monthly/Yearly billing toggle on /pricing, and the docs theme dropdown for the dark shots (`docs-dark-dark-*`). [tools/capture/quantize.py](tools/capture/quantize.py) posterises them to 256 colours.

Nothing was signed into, sent or submitted: the login and register cards were captured as surfaces, never filled past a deleted sample and never submitted; every Sign-up, Start-for-free, Start-trial, Send-message and SSO action was measured, never followed or pressed; the mega-menu, mobile menu, billing toggle and docs theme dropdown were toggled as local UI state; the docs search palette and Mintlify AI assistant were never opened. Promo and consent overlays were hidden, never answered.

## What to distrust

- **This is the public shell, not the product.** Dub's workspace — link management, analytics, domains, tags, webhooks, integrations, billing — sits behind /login on app.dub.co and is uncaptured. Treat the product's own design system as unknown; the `demo-panel` under the home hero is a published mock, not the app.
- **Three stacks, not one system.** The marketing site (Next.js/Tailwind, Satoshi + Inter), the auth shell (app.dub.co, plain `ui-sans-serif`) and the docs surface (Mintlify, gray ramp + `#155dfc`) share a domain but are different codebases. `dark.*` is the docs toggle's `.dark` scope only — the marketing pages never paint it.
- **The neutral ramp isn't declared.** The marketing/auth surfaces paint Tailwind's neutral scale through atomic classes — `#000`/`#fff`/`#fafafa`/`#f5f5f5`/`#e5e5e5`/`#d4d4d4`/`#a3a3a3`/`#737373`/`#525252`/`#404040`/`#262626`/`#171717`/`#0a0a0a` — so `core.color.neutral.*` is measured values, labelled as such. The declared `--bg-*`/`--content-*`/`--border-*` roles resolve to neighbouring but not identical values (e.g. `--background` is `#fafafa`, `--bg-default` is `#ffffff`).
- **The docs washes were read as oklab.** Mintlify paints its translucencies as `color-mix`, which Chrome reports as `oklab()`. `color.wash.*` converts each to an sRGB `rgba()` (10% `#155dfc` active-nav wash, 3%/10% ink and white search-pill washes) and keeps the computed oklab string in `$extensions.authored`. `--twoslash-underline-color` (`currentColor`) and the em tracking steps `--tracking-tighter`/`--tracking-tight` have no DTCG form, so they are listed under each set's `$extensions.notTokenised` with their values.
- **Focus is two systems.** Buttons draw the browser-default `auto 1px rgb(0, 95, 204)` outline; the docs surface draws its own 1px `#155dfc` ring; the email field instead takes a black border plus a 1px black ring shadow. `hero-badge` and `sales-submit` recorded `via: focus failed` — their focus look is uncaptured, not measured as absent.
- **Readings to recapture.** `plan-price` caught the price row's wrapper, whose first text is "/month", not the price figure, so `core.font.tracking.price-tight` says so in its source; the selector is tightened in `measure.mjs` (edited, not run). `nav-dropdown` caught one card inside the Product mega-menu, not the panel, so `light.component.nav-dropdown.width` is that card's width. `docs-sidebar` and `dk-docs-sidebar` were not found by the 2026-11-13 re-run (`recaptureMissed`); the tokens read from them say they are the earlier run's readings.
- **Quantised screenshots.** `screenshots/` are 256-colour PNGs; read exact colours from tokens or the raw files.
- **`--primary` means two different colours.** The marketing shadcn sheet declares it `0 0% 9%` (a near-black `#171717`, `#fafafa` under the `.dark` scope); the docs inline sheet binds the same name to the Dub blue `21 93 252` (`#155dfc`). The tokens keep them apart — `light.marketing.primary`/`dark.marketing.primary` versus `light.primary.base`/`dark.primary.base` (the docs value) — and [raw/css-vars.json](raw/css-vars.json) lists the collision under `conflicts` with each surface's own resolution under `resolved.surfaces`. Never read a `--primary` value without checking which surface declared it.
- **`--primary-foreground` looks wrong on dark** (`#171717` on the unchanged `#155dfc`) — it is what the `.dark` scope declares, not a misread; the docs surface never paints a primary button there.
- **Automation was masked during capture.** Until 2026-11-20, `tools/capture/public/lib.mjs` hid `navigator.webdriver` in every page it opened, so every committed reading was taken with that mask. The mask is removed (a bot check is now recorded as a boundary, not bypassed); whether any page needed it to load is not known, and a recapture without it is the check.

## Fonts

Five stacks do everything. **Satoshi** (Fontshare variable) runs every marketing headline — 48/55.2 at weight 500 on desktop, 36/40 at 390 — and the docs h1s at 36/40 600. **Inter** runs the marketing and docs body, nav and button labels (self-hosted woff2 subsets). **Paper Mono** runs docs code (Mintlify bundle). **GeistMono** runs marketing code (next/font). The app.dub.co auth shell paints a plain `ui-sans-serif` system stack — no webfont on the card. None is distributed with the package; the style guide falls back to system sans.

## Do and don't

1. **Do paint the field near-white.** Marketing surfaces sit on `#fafafa` (`--background`) with `#f5f5f5` muted fills; pure white is reserved for cards, fields and bordered buttons. See [home-light-default](screenshots/home-light-default.png).
2. **Do make the primary action black.** Buttons are `#000` fills with white text at an 8px radius — the brand blue never appears on marketing chrome. See [nav-cta](components/crops/nav-cta-default.png).
3. **Do paint the halo on marketing and auth CTAs, not a darker fill.** The black buttons signal hover with a 4px `#e5e5e5` box-shadow halo, not a darkened fill — `nav-cta` and `email-submit` keep `#000` outright and `hero-cta` lifts only to a measured `#262626`. The docs surface plays a different game (its hovers are oklab washes). See [nav-cta](components/crops/nav-cta-hover.png).
4. **Do give fields the quiet focus pair.** A focused input swaps its `#d4d4d4` border for a darker one plus a matching 1px ring shadow over the 5%-black drop — `#000` on the login card, `#737373` on register and contact-sales — never a coloured ring. Docs controls use the `#155dfc` outline instead. See [email-field](components/crops/email-field-focused.png).
5. **Do run Satoshi tight for display.** Headlines are Satoshi 48/55.2 at weight 500 (36/40 at 390, 36/40 at 600 on docs); body is Inter 14-20px. See [hero-title](components/crops/hero-title-default.png).
6. **Do keep `#155dfc` inside the docs surface.** The Dub blue, its 10% active-nav wash and the docs focus ring belong to the Mintlify surface — the marketing pages never paint them. See [docs-nav-item](components/crops/docs-nav-item-default.png).
7. **Do use the gray ramp for docs chrome.** `#eef0f5` hairlines, `#707277` resting sidebar text, `#17191e` headings, `#dfe1e6` on dark — the `--gray-*` steps, not the Tailwind neutrals. See [docs-sidebar](components/crops/docs-sidebar-default.png).
8. **Don't mix the three stacks.** Satoshi belongs to marketing and docs headings, Inter to body, `ui-sans-serif` system to the auth shell, Paper Mono to docs code — putting Geist on a marketing page or Satoshi on the auth card is wrong. See [login-card](components/crops/login-card-default.png) versus [hero-title](components/crops/hero-title-default.png).
9. **Don't reach for shadows.** The surface is nearly elevation-free — fields carry only `rgba(0,0,0,.05) 0 1px 2px` and cards are flat with hairline borders. See [plan-card](components/crops/plan-card-default.png).
10. **Don't style the workspace from this package.** Every value is the public surface's; the product behind app.dub.co/login is uncaptured. See [login-light-default](screenshots/login-light-default.png).

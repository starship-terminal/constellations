# Cartesia design reference

A token set and component reference for Cartesia's public surface — for building marketing and voice-demo pages in the style of the real thing. It was read from **cartesia.ai** on **2026-11-12**, signed out, in headless Chromium at 1440 x 900 and 390 x 844. Captured: the marketing site (home, /sonic, /ink, /agents, /product/voice-cloning, /voices, /pricing, /tools, /mcp, /research, /blog, /contact, /customers), the Playground auth boundary (the Clerk sign-in and sign-up cards on play.cartesia.ai — the only playground surface reachable signed out), the Mintlify docs landing on docs.cartesia.ai, and a 390px mobile pass.

Cartesia is worth a capture because "the voice model for real-time agents" paints an unusually disciplined system: a declared `--cartesia-*` palette — verdant `#309d4b` actions, growth `#abd49e` tints, forest `#004e23` depths, warm neutrals (canvas `#e4e3db`, field `#f4f4f1`) under a `#fefefe` field — bound through a shadcn-style semantic layer (`--background`/`--foreground`/`--primary`/`--card`/`--control-*`/`--motion-*`/`--site-*`), with PP Kyoto display headlines over ABC Diatype body text, pill chips, a 245px Talk-to-Skylar voice orb, and `.dark` islands that re-bind the same roles (verdant becomes growth, borders become white alphas). Three surfaces signed out, three levels of access: the marketing site is fully public, the sign-in card is a Clerk boundary sharing the token layer, and the docs app is a separate Mintlify system kept out of the export. **Boundary:** the voice playground, console, cloning, agents, API keys and billing live behind sign-in on play.cartesia.ai and were never reached; the sign-in/sign-up forms were measured but never filled or submitted; the live-agent calls were never started; the voice demos were pressed only as far as their own play controls.

## Brief

<!-- brief:start. Generated by tools/brief.py from catalog.json, the tokens file and this README; `make brief` rewrites it. Do not edit. -->

Read this before designing in this style. Take every value from [tokens.json](tokens.json), never from the screenshots; `python3 tools/catalog.py export cartesia` prints them all with aliases resolved.

### Principles

1. Do keep the field warm and near-white.
2. Do make the one accent verdant.
3. Do run the display face in PP Kyoto.
4. Do keep controls 36-44px at an 8px radius.
5. Do give the voice demo full-circle controls.
6. Do let dark sections re-bind the roles.
7. Don't style the playground from this package.
8. Don't treat the docs app as this system.

Each rule links the screenshot or crop that shows it, under [Do and don't](#do-and-dont).

## How the values were read

Every value came off the running signed-out site in headless Chromium:

- **Tokens.** [tools/capture/vars.mjs](tools/capture/vars.mjs) captures every stylesheet body (the Astro/Tailwind CSS bundles from network responses plus inline `<style>` blocks, re-assembled in document order) and writes every custom property to [raw/css-vars.json](raw/css-vars.json). cartesia.ai declares a real design-token layer — the `--cartesia-*`/`--color-cartesia-*` palette, the shadcn-style semantic roles, `--control-*` sizing, `--motion-*` ramps and `--site-*` layout vars — so tokens are declared variables resolved the way the browser resolves them: once plain and once inside a `.dark` wrapper (the scope the pages declare but never bind page-wide). The play.cartesia.ai and docs.cartesia.ai sheets were harvested separately into [css-vars-play.json](raw/css-vars-play.json) and [css-vars-docs.json](raw/css-vars-docs.json); the sign-in card resolves the same layer, the Mintlify docs app is a different system and stays out of the export. [tools/build_component_tokens.py](tools/build_component_tokens.py) writes the spec, [tools/build_tokens.py](tools/build_tokens.py) the sets.
- **Components.** [tools/capture/public/measure.mjs](tools/capture/public/measure.mjs) opens each route in a fresh context, lazy-scrolls to mount deferred sections, and reads `getComputedStyle`, painted layers and boxes per element in default, hover, focus-visible, pressed, filled/selected and open states. Results in [raw/components-computed.json](raw/components-computed.json) and [raw/measurements.md](raw/measurements.md).
- **Screenshots.** [tools/capture/public/public.mjs](tools/capture/public/public.mjs) takes viewport and full-page shots per route, including the local UI toggles: the Products mega-menu (click, not hover), the mobile menu overlay, and the /sonic voice picker popover. [tools/capture/quantize.py](tools/capture/quantize.py) posterises them to 256 colours.

Nothing was signed into, generated, called or submitted: the sign-in and sign-up cards were captured as forms, never filled or submitted; the Talk to Skylar / Talk to Cartesia live-agent calls were never started; the voice demo's play, select and locale controls were pressed only to measure their states; the pricing FAQ disclosures and the nav/mobile menus were toggled as local UI state; the usage slider was measured, never dragged to a purchase; every Try Cartesia, Talk to Sales and plan CTA was measured, never followed. The consent island was hidden, never answered — no consent button was ever clicked.

## What to distrust

- **The accordion content reading is the trigger list; it needs a recapture.** The trigger's own `selected` state opened the section and a second click closed it, so `accordion-content` read the Cloud / On-premise / On-device trigger stack. The capture now clicks only when the section is closed (edited, not rerun).
- **Two components are kept from an earlier run.** `nav-dropdown` and `product-card` were not found by the 2026-11-12 recapture; the four tokens built from them (`menu-width`, `menu-pad`, `product-width`, `product-height`) say stale in their sources.
- **This is the public shell, not the product.** The voice playground, console, voice cloning and management, agents, API keys, usage and billing live behind sign-in on play.cartesia.ai and are uncaptured. Treat the app's own design system as unknown.
- **`.dark` is a declared scope, not a toggle.** The marketing sheets declare dark re-bindings, but the captured pages only paint them inside `.dark` islands — `tokens.json`'s `dark` set is that re-binding, not a user-selectable mode.
- **Docs is a different system.** docs.cartesia.ai is a Mintlify app in Inter with its own tokens; it was measured for reference (raw/css-vars-docs.json, the `docs-*` components, `core.font.family.docs`, `component.docs.*`) but never merged into the Cartesia token layer.
- **Computed colours serialise as lab()/oklab().** Modern Chrome returns lab/oklab for the Tailwind v4 palette; the builders map them back to the declared vars' resolved hex (`#a1a1a1` ring, `#309d4b` verdant) — the token file holds hex, the raw JSON holds both serialisations.
- **Quantised screenshots.** `screenshots/` are 256-colour PNGs; read exact colours from tokens or the raw files.
- **`plan-tab` is recorded missing** — the pricing plan tabs rendered zero-size/lazy-mounted at capture; an honest miss, not a measured absence.
- **rounded-full clamps.** `rounded-full` computes to a giant px radius (~33.5 million px); the token records the clamp at 9999px.
- **Captured with the automation flag masked.** The public capture (`tools/capture/public/`) hid `navigator.webdriver` from every page, so the committed readings and screenshots it took were taken past that mask. The scripts no longer hide it (edited, not run); a recapture that meets a bot check records it as a boundary.

## Fonts

Four declared faces do the marketing site. **ABC Diatype** runs body text, nav, buttons and most UI (`--font-sans`/`--font-abc-diatype`). **PP Kyoto** runs the display headlines — the 40px hero, product titles (`--font-display`/`--font-pp-kyoto`). **IBM Plex Mono** covers code and figures (`--font-mono`/`--font-ibm-plex-mono`). **Homemade Apple** is the handwriting accent (`--font-handwriting`). The docs app uses **Inter** (`core.font.family.docs`). None is distributed with the package — the style guide falls back to system sans.

## Do and don't

1. **Do keep the field warm and near-white.** `#fefefe` pages, `#f9f9f8` cards, `#f3f2ef` hover fills and `#e4e3db`/`#ededed` hairlines are the whole neutral story — restraint is the look. See [home-light-default](screenshots/home-light-default.png).
2. **Do make the one accent verdant.** `#309d4b` carries every action — Try Cartesia, Play, Continue, plan CTAs, selected markers — hovering at 90% of the fill; don't spread it to backgrounds. See [nav-cta](components/crops/nav-cta-default.png) and [pricing-light-default](screenshots/pricing-light-default.png).
3. **Do run the display face in PP Kyoto.** The 40px hero and 26px section heads are the display voice over ABC Diatype body — serif-flavoured, tight, never heavy. See [hero-title](components/crops/hero-title-default.png).
4. **Do keep controls 36-44px at an 8px radius.** Nav buttons, play buttons and CTAs are 36px; sign-in controls are 44px at 12px; chips and orbs go full-radius. See [play-btn](components/crops/play-btn-default.png) and [continue-btn](components/crops/continue-btn-default.png).
5. **Do give the voice demo full-circle controls.** The 245px orb, the 59px chooser ring, 81px globe play and 19px locale dots are the signature demo geometry. See [hero-orb](components/crops/hero-orb-default.png) and [voices-light-default](screenshots/voices-light-default.png).
6. **Do let dark sections re-bind the roles.** `.dark` islands flip the field to `#171715`, text to `#cdc8c1`, primary to growth `#abd49e` and borders to white alphas — the same tokens, re-bound, not a second palette. See the dark set in [tokens.json](tokens.json).
7. **Don't style the playground from this package.** Every value is the public surface's; the signed-in console is uncaptured.
8. **Don't treat the docs app as this system.** The Mintlify surface (Inter, its own palette) is measured evidence beside the export, not part of it.

## Rebuild

Everything derived regenerates offline from the raw readings (run from `systems/cartesia/`):

```sh
python3 tools/build_component_tokens.py        # raw/components-computed.json + css-vars.json -> raw/component-tokens.json
python3 tools/build_tokens.py                  # -> tokens.json
python3 tools/build_style_guide.py             # -> style-guide.html
python3 tools/build_components_md.py           # -> components.md
node tools/capture/public/build-measurements.mjs  # -> raw/measurements.md
python3 tools/capture/quantize.py <raw-dir>    # full-colour PNGs -> screenshots/
```

Then `make brief && make design-md && make grade && make check` from the repo root refreshes the generated sections and validates the catalog.

Live recapture (needs the site; Playwright at `PLAYWRIGHT=/path/to/playwright/index.mjs`):

```sh
node tools/capture/vars.mjs                    # stylesheet harvest -> raw/css-vars.json
node tools/capture/public/measure.mjs          # computed styles + crops -> raw/components-computed.json
RAW=<scratch> node tools/capture/public/public.mjs   # screenshots -> <scratch> (incl. the menu/voice-picker toggles)
```

cartesia.ai loads headless from this client; a first load can sit on a challenge — the scripts retry on a clean context. The playground stays behind sign-in.

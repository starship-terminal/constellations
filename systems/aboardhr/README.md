# Aboard HR design reference

A token set and component reference for Aboard's public marketing site, for building a clean product-marketing page in the style of a real HR product. It was read from aboardhr.com on 2026-11-10, signed out, in headless Chromium at 1440 wide and 390 wide: the home page, the three product pages (Everyday HR, Growth & feedback, Team culture), Pricing, the What's new index and the June 2026 release page, Book a demo, the Teamtailor-x-Aboard partner page, and the two legal pages. The look is flat and friendly: a `#fafafa` ground, everything set in the OS-ui stack (San Francisco on Apple), pastel card tints (blue, mint, pink, lavender), and one bright `#009cff` blue that every primary pill button carries.

aboardhr.com is a Framer site: its stylesheets are inline `<style>` blocks that declare hashed `--token-<uuid>` custom properties plus the `--framer-*` typography variables, and components carry `data-framer-name` attributes. Several brand fills paint in Display P3; the token file records the sRGB conversions. The HR product itself lives behind a sign-in at app.aboardhr.com and was never opened: this package covers the marketing surface only. Nothing was signed into, bought or submitted; the book-a-demo form was measured at rest and at focus only, and no consent strip ever rendered.

### Principles

1. Do set everything in the OS-ui stack.
2. Do keep the ground flat.
3. Do pill every CTA.
4. Do tint cards, don't outline them.
5. Don't invent state styles the site doesn't have.
6. Do keep forms quiet.

Each rule links the screenshot or crop that shows it, under [Do and don't](#do-and-dont).

## How the values were read

aboardhr.com is a Framer site, so its stylesheets are inline `<style>` blocks and fully readable (the one cross-origin sheet, Font Awesome's CDN, is skipped). [vars.mjs](tools/capture/vars.mjs) resolved every custom property at `:root`: the `--token-<uuid>` design tokens (the Framer palette) and the `--framer-*` typography variables, recorded in [raw/css-vars.json](raw/css-vars.json). Where a token's value is one of those variables, its leaf says `"var"` and the builder resolves it against that file; everything else is a literal measured off a computed style, and each leaf's `$extensions.source` names the component or variable it came from.

Component values are computed styles read per state with Playwright ([measure.mjs](tools/capture/public/measure.mjs)). Hover used the pointer, focus-visible a real keyboard Tab, and pressed was forced through DevTools (`CSS.forcePseudoState`), so no button was clicked for real. The only press was a local UI toggle: the mobile nav trigger. The demo form's first field was clicked into for its focus style but nothing was typed or sent. No consent manager ever rendered on the site, so nothing was hidden or answered.

Font sizes on this site are not fluid: Framer serves fixed px steps per breakpoint, so the 64px display at 1440 is the 48px display at 390, and both are recorded. Screenshots were lazily scrolled to settle lazy-loaded media, then stored quantised to 256 colours; the unquantised originals and per-capture metadata stay outside the repo.

## What to distrust

- **Readings past a masked bot signal.** The committed screenshots and readings were taken with `navigator.webdriver` masked, the flag bot checks read to spot automation. The capture scripts no longer mask it (not run since), so a recapture may record a walled route as a boundary instead of a reading.
- **Screenshots are 256-colour PNGs.** Gradients, photography and the pastel tints band slightly; read exact colours from tokens.json or the raw files.
- **Several brand fills paint in Display P3.** The token records the sRGB conversion (`#009cff` from `color(display-p3 0 0.599909 1)`, and so on); the P3 original is in the token's description and in css-vars.json, where unresolved P3 strings carry a "colour space not converted" note.
- **The pressed link colour is `#ff0000`.** Framer's stylesheet declares `a:active { color: red }`; the pressed rows show it. It is a framework default, not a design choice.
- **Focus rings are the browser's.** The site declares no `:focus-visible` style; the measured `#005fcc` 1px outlines are headless Chromium's default ring.
- **Hover and reveal motion is JS.** Framer animates with springs in script, so CSS transitions read 0s almost everywhere; hover diffs are colour-only.
- **The co-pilot chat is a marketing animation.** The home hero's assistant demo (the "Ask me anything" prompt) is canned content, not a live product.
- **`nav-bar` and `m-nav-bar` measure `box-shadow rgba(23,23,23,0.08) 0 0 0 0`.** A zero-offset, zero-blur shadow paints nothing; the header has no real shadow.
- **`m-nav-bar` measures 37 x 16.** The selector caught the trigger's hit area, not the 390-wide band; the band's real height is the fixed header's 64px (see [raw/layout.json](raw/layout.json)).
- **Mobile `-full` screenshots stitch viewport slices.** `mobile-*-light-full.png` are stitched from `*.partN.png` tiles in the scratch dir (`~/.design-systems/aboardhr/raw-shots`, outside the repo); the stitch seams can shift a pixel.
- **Billing toggle and demo submit button states.** The pricing page has no monthly/yearly switch (`billing-toggle` records missing); the demo submit was measured in all four states but never pressed.
- **`nav-cta` was read from the wrong elements.** `.last()` over every "Book a demo" link took the footer CTA for the default state (y=6854) and the hero CTA for the others (y=430), not the button in the nav. Needs a recapture; the script now searches inside the header (not run since). The CTA tokens now cite only the other CTAs (`cta-demo`, `cta-try`, `plan-cta` and the rest), which hold the same values.

## Do and don't

1. **Do set everything in the OS-ui stack.** Headlines, nav, buttons and body all use `system-ui, -apple-system, ...` semibold or medium; Inter only ever appears inside the demo form. Never introduce a display serif. See [hero-title-default](components/crops/hero-title-default.png) and [nav-link-default](components/crops/nav-link-default.png).
2. **Do keep the ground flat.** Sections sit on the same `#fafafa` with no borders or shadows between them; separation comes from pastel card tints, not chrome. The header's only "shadow" is a 0-offset declaration that paints nothing. See [home-light-default](screenshots/home-light-default.png).
3. **Do pill every CTA.** Buttons are 99px-radius, 48px-tall pills in 18px semibold: blue `#009cff` with white text for primary, light-blue `#e0f2fe` with deep-blue `#008ae8` text for secondary, frosted white over lavender for the ghost Learn-more. See [cta-demo-default](components/crops/cta-demo-default.png) and [cta-try-default](components/crops/cta-try-default.png).
4. **Do tint cards, don't outline them.** Product and plan cards carry flat pastel fills (`#afe4ff`, `#8df1ed`, `#fbcfe8`, white) at 24-32px radius with no border and no shadow; card headlines are 44px semibold tracked -0.28px. See [everyday-hr-card-default](components/crops/everyday-hr-card-default.png) and [price-card-default](components/crops/price-card-default.png).
5. **Don't invent state styles the site doesn't have.** Hovers are a colour wash at most (nav links pick up an 8% grey fill; footer links go #777 to #555); focus is the browser's `#005fcc` ring; pressed links paint `#ff0000` by Framer's rule. Match those rather than designing new ones. See [nav-link-hover](components/crops/nav-link-hover.png) and [footer-link-hover](components/crops/footer-link-hover.png).
6. **Do keep forms quiet.** The demo form is Inter labels at #888 over 40px controls filled ink-at-5% with 12px radius, and a submit that draws a 2px ink-at-10% ring instead of a fill. No floating labels, no coloured focus. See [demo-form-default](components/crops/demo-form-default.png) and [demo-submit-focus-visible](components/crops/demo-submit-focus-visible.png).

## Rebuild

```bash
python3 tools/build_tokens.py
```

```bash
python3 tools/build_style_guide.py
```

```bash
python3 tools/build_components_md.py
```

`build_tokens.py` reads `raw/component-tokens.json` and writes `tokens.json`; it refuses a value that is not the DTCG type it claims and an alias that points at nothing. `build_style_guide.py` renders `style-guide.html` from `tokens.json` and `tools/style-guide.template.html`, turning every token into a CSS variable so the page cannot drift from the file. `build_components_md.py` writes `components.md` from `raw/components-computed.json`, `raw/layout.json`, `tokens.json`, the screenshots and `icons/INDEX.tsv`. All three are deterministic: re-running them on this commit reproduces their files byte for byte. Edit the raw inputs or the builders, never the generated files.

`tools/capture/` holds the kit the captures came from. The Playwright scripts take `PLAYWRIGHT` as the path to a Playwright install's `index.mjs` when `playwright` is not resolvable from where they run.

```bash
PLAYWRIGHT=/path/to/playwright/index.mjs node tools/capture/public/public.mjs
PLAYWRIGHT=/path/to/playwright/index.mjs node tools/capture/public/measure.mjs home pricing mobile
```

`public.mjs` re-takes the screenshot set into `~/.design-systems/aboardhr/raw-shots` (outside the repo); `python3 tools/capture/quantize.py ~/.design-systems/aboardhr/raw-shots` stores the quantised copies in `screenshots/`. `measure.mjs` takes page names and merges into `raw/components-computed.json`; `node tools/capture/public/build-measurements.mjs` then rewrites `raw/measurements.md`. `vars.mjs`, `layout.mjs` and `icons.mjs` rewrite their raw or icon files whole. `lib.mjs` holds the shared helpers, including the generic overlay sweep (unused: no CMP renders); it no longer masks `navigator.webdriver`.

## Use in Figma

Import `tokens.json` with Tokens Studio and choose the Light theme. Set display type in SF/Segoe/Roboto semibold at 64/70.4 tracked -0.6px, UI text medium at 15-20px, paint the page `#fafafa`, and keep the pastel tints and `#009cff` pills to the measured values.

## The screen to get right

The home page is the screen to get right. A 90px fixed band holds the wordmark, three muted nav links, and a Sign-in link beside the light-blue "Book a demo" pill. Below, a centred 768px column sets the 64px semibold headline ("Run people operations. With clarity.") over the muted lead, the two CTAs (blue "Book a demo", tint "Try for free"), and the animated co-pilot chat demo inside a light-blue panel. Further down, pastel bands hold the 24px-radius product cards (blue Everyday HR, mint, pink Team culture) with 44px headlines and feature rows, and the page closes on the plain light footer: "Smooth sailing.", link columns in #777, and the Teamtailor credit. Everything the capture could not reach is listed under Gaps in [components.md](components.md#gaps).
